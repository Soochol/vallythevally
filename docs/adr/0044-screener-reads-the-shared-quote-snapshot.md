# 스크리너는 수집 데몬의 KRX 시세 스냅샷을 읽어 오늘 요약으로 쓰고 같은 조건의 결과를 다시 쓴다

[ADR 0014](0014-screener-includes-current-krx-day.md)는 스크리너가 실행할 때마다 전 종목 오늘 KRX 시세를 키움에서 새로 받아 오늘 봉으로 쓰기로 했다. 사용자가 늘면 실행 수만큼 키움 호출이 늘고, 호출 한 번이 전 종목(약 40번의 `ka10095`)이다. [ADR 0043](0043-collector-makes-shared-data-and-the-server-only-reads-it.md)은 공용 자료를 감독 데몬이 만들고 서버는 읽기만 하게 했고, 데몬은 KRX 시세 스냅샷을 30초마다 쓴다. 이 ADR은 스크리너의 오늘 요약을 그 스냅샷으로 바꾼다. 플랜은 [`docs/plans/collector-shared-data.md`](../plans/collector-shared-data.md)(확정 2, 결정 C2)이다. 사용자는 성능을 가장 중요하게 본다.

## 결정

- **오늘 요약의 출처**: `VALLY_SHARED_DATA_DIR`이 있으면 스크리너는 실행에서 키움을 부르지 않고 KRX 스냅샷 판(`snapshot-krx`)의 행을 오늘 요약으로 쓴다. ADR 0014의 "실행할 때 조회한 오늘 시세"가 "장중 최대 30초 전 스냅샷"이 된다. 변수가 없으면 ADR 0014 그대로 실행 때 받는다.
- **스냅샷 행을 요약으로 읽기**: 스냅샷 행을 실행 때 받는 요약과 같은 값으로 바꿔 판정한다. 행이 없거나 두 번 있으면 누락, 날짜가 오늘이 아니면 다른 날짜 응답, 읽을 수 없는 값이면 해석 실패다. 이 구분이 ADR 0014의 누락 수·`Unresolved`·새 봉 부재 판단에 그대로 쓰인다. 결과의 `collectionStartedAt`·`collectionCompletedAt`은 스냅샷 기준 시각(`asOf`)이다.
- **오늘 행을 합치는 때**: 스냅샷 행의 날짜가 저장소 마지막 날보다 뒤이고 오늘일 때만 오늘 봉으로 합친다. 마감 뒤에 저장소가 그날 봉을 이미 가졌으면 스냅샷 행을 더하지 않는다. 장 밖(08:00 전, 주말, 휴장일, 20:00 뒤)에는 데몬이 쓴 마지막 관측일 판(마감 판)을 그대로 쓰고, 그 행의 날짜가 달력의 직전 관측일과 저장소 기준일에 맞을 때 ADR 0014의 새 봉 부재 규칙으로 이전 봉을 유지한다. 새 봉 부재가 확인된 휴장일(주말, 08:00 전, 20:00 뒤의 달력)의 누락 수는 0이다. 평일 08:00~20:00에 달력에 오늘이 없으면 ADR 0014대로 휴장으로 추정하지 않고(`Unresolved`) 이전 날짜 행을 누락으로 센다.
- **관측일이 바뀌면 버림**: 스냅샷 관측일이 달력이 요구하는 날과 다르면 판정하지 않는다. 오늘 관측이 확인된 날에는 오늘 관측일 판, 새 봉 부재로 본 날에는 직전 관측일 판이어야 한다. 오늘 관측을 아직 알 수 없는 때(`Unresolved`)에는 직전 관측일보다 오래된 판을 받지 않는다. 데몬이 그날 첫 판을 쓰기 전이어서 지난 관측일 판만 있을 때도 같다. 스냅샷이 아직 없을 때와 함께 키움을 부르지 않고 "자료를 확인하지 못함"으로 답한다. 어제 자료를 오늘 자료 대신 넣지 않는다는 ADR 0014의 원칙이다.
- **수정주가 대조는 스냅샷으로도 성립한다**: [ADR 0010](0010-screener-reads-a-disk-daily-store.md)의 대조는 오늘 요약의 기준가를 저장 종가와 견준다(30% 규칙, 마지막 저장 봉과 마지막 거래 봉 둘 다와 다를 때만 감지). 스냅샷 행에도 기준가(`baseWon`)가 있고 값이 같은 `ka10095` 필드에서 왔으므로 같은 규칙을 그대로 건다. 상장 첫 봉 규칙도 같다.
- **메모리 판정**: 저장소의 봉은 세대마다 메모리 판으로 올려 두고(스크리너 메모리 판), 판정은 그 판과 스냅샷만 읽는다.
- **결과 재사용**: (조건식 정규화 값, 스냅샷 판, 저장소 세대·갱신 에폭, 오늘 날짜, 새 봉 부재 판단)이 같으면 판정하지 않고 결과를 준다. 조건식 정규화 값은 조건 목록과 시장·제외 집합이고 이름·id와 집합의 순서는 들지 않는다. 최근 64개를 메모리에 둔다. 스냅샷 판이 바뀌면 그 이전 판의 결과를 모두 버린다. 같은 키의 실행이 동시에 오면 하나만 판정하고 나머지는 그 결과를 기다려 쓴다. 판정한 수와 쓴 수를 센다(공개 계수는 공개 리스너의 임시 한도를 걷는 뒤 작업이 붙인다). 판정이 실패하면 결과를 남기지 않는다.
- **달력은 그대로**: 관측일 달력(코스피 일봉)은 지금처럼 키움에서 받고 5분 캐시를 상태 조회와 나눠 쓴다. 이 ADR은 전 종목 요약의 출처만 바꾼다.

## Considered Options

- **스냅샷 판마다 결과를 미리 판정해 두기**: 조건식 수가 한정되지 않아 데몬이나 서버가 쓰지 않을 판정을 계속 돌린다. 요청이 올 때 한 번 판정하고 같은 판 안에서 다시 쓰는 쪽이 일이 적다.
- **스냅샷 관측일이 어긋나도 판정하고 누락으로 세기**: 결과가 비어 보이지만 이유는 데몬이 늦은 것이다. 사용자가 원인을 모르고 다시 실행하게 되므로 실패로 알린다.
- **스냅샷을 실행마다 요약 수집기의 진행 중 수집처럼 나눠 쓰기**: 스냅샷은 이미 모두에게 같은 자료여서 수집 상태가 필요 없다.

## Consequences

- 스크리너 실행은 키움 요청을 보내지 않는다(달력 캐시가 비었을 때의 코스피 일봉 한 번 제외). 사용자 수와 실행 수가 키움 호출과 나뉜다.
- 오늘 봉의 값은 실행 시각이 아니라 스냅샷 시각(장중 최대 30초 전)의 시세다. ADR 0014의 "현재가로 계산한 교차나 돌파는 다음 조회에서 사라질 수 있다"는 말은 다음 스냅샷에서로 바뀐다.
- 같은 조건을 같은 판에서 여럿이 돌려도 판정은 한 번이다. 판이 바뀌는 30초마다 다시 판정한다.
- 서버가 `VALLY_SHARED_DATA_DIR`을 켜고 데몬이 스냅샷을 쓰지 않으면 스크리너 실행은 실패한다. 실행 때 받는 방식으로 자동으로 돌아가지 않는다(키움 호출이 다시 사용자 수에 비례하게 되기 때문이다).
- 요청마다 결과 한 벌을 복제해 준다. 64개의 결과는 행 수만큼만 메모리를 쓴다.

# 관심종목 그룹은 서로 겹칠 수 있다

[ADR 0017](0017-watch-groups-are-subsets-of-the-list.md)의 한 그룹 제한과 그룹 수 제한을 바꾼다. hoga-ops의 관심종목과 히트맵을 옮길 때 같은 종목의 여러 그룹 소속과 그룹별 순서를 보존해야 한다.

목록의 `symbols`는 순서가 있는 고유 종목 집합이다. `groups[].symbols`는 각각 순서가 있는 부분집합이고, 그룹끼리는 겹칠 수 있다. 같은 그룹 안에서는 종목이 중복될 수 없다. 실시간 구독은 목록의 `symbols`를 읽으므로 그룹 소속이 늘어도 구독은 늘지 않는다. 어느 그룹에도 속하지 않은 종목만 "그룹 없음"에 보인다.

화면의 행은 `(groupId, code)`로 식별한다. `groupId: null`은 그룹 없음의 행을 뜻한다. 정렬, 키보드 이동, 끌기, 초점 복원, 행 빼기, 다른 목록으로 이동은 이 문맥을 전달한다. 없어진 행을 가리키는 오래된 이벤트는 다른 소속을 바꾸지 않는다.

- "그룹에 추가"와 종목을 포함한 새 그룹 생성은 기존 소속을 유지한다.
- "그룹으로 옮기기"는 선택한 소속만 뺀 뒤 대상 그룹에 넣는다. 대상에 이미 있으면 중복으로 넣지 않는다.
- "이 그룹에서 빼기"와 그룹 행의 Delete, 휴대폰 지우기 버튼은 그 소속만 뺀다. 마지막 소속을 빼면 종목은 목록에 남아 그룹 없음에 보인다.
- "관심종목에서 빼기"는 목록과 모든 그룹에서 종목을 뺀다.
- 다른 목록으로 행을 옮기면 대상 목록에 종목을 넣고 선택한 소속만 뺀다. 원래 목록에 다른 소속이 없으면 원래 목록에서도 종목을 뺀다. 복사는 원래 목록을 유지한다.
- "그룹 풀기"는 종목을 모두 유지한다. "그룹 지우기"는 그 그룹에만 속한 종목을 목록에서 빼고 다른 그룹에도 있는 종목을 유지한다.
- 목록 복제는 모든 소속과 순서를 보존하고 그룹 id를 새로 만든다. 빼기 되돌리기는 편집 전 목록 전체를 저장해 원래 소속과 순서를 복원한다.

새 마이그레이션 0010은 `watch_group_items`를 다시 만들어 `UNIQUE(list_id, symbol)`만 제거한다. 기존 행, 위치, 외래 키, `(group_id, symbol)`과 `(group_id, position)`의 유일성은 유지한다. 마이그레이션은 관심종목 revision을 바꾸지 않는다.

서버와 웹은 목록마다 그룹 100개를 허용한다. 본문 한도는 기존 종목 본문 한도의 101배에 목록 20개와 그룹 2,000개의 최대 감싸개 크기를 더한다. GET과 성공한 PUT은 `X-Vally-Watchlists-Version: 2`를 보낸다. 가져오기 도구는 이 값이 없는 서버에 적용하거나 복원하지 않는다.

가져오기는 전체 문서 PUT 하나로 두 목록을 원자적으로 바꾼다. GET revision을 `r`이라고 할 때 정확히 `r + 1`을 보낸다. 그 사이 다른 쓰기가 있으면 서버의 기존 revision 검사로 거절된다. 도구는 충돌 때 새 revision으로 덮어쓰지 않는다. 적용 전에 원본 스냅샷, 대상 백업, 적용할 문서와 해시를 디스크에 기록하고 fsync한다. 응답 유실은 GET으로 확인한다. 복원은 가져오기 문서와 그 PUT의 정확한 revision이 현재 문서와 같을 때만 가능하다.

## 검토한 대안

- 프런트엔드에서 종목과 소속을 별도 저장소로 나누면 API 문서를 조립하는 두 번째 변경 주체가 생긴다. 기존 배열과 행 문맥으로 필요한 동작을 표현한다.
- 행마다 별도 영구 id를 만들면 `(groupId, code)`와 같은 정보를 중복 저장한다.
- 가져오기 전용 API와 `expectedRevision`은 기존 트랜잭션과 `r + 1` 검사를 중복한다.
- SQLite 직접 쓰기는 실행 중인 구버전 서버와 마이그레이션 경쟁을 만들므로 사용하지 않는다. 도구는 서버나 UI를 재시작하지 않는다.

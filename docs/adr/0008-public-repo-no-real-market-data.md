# 저장소를 이력 그대로 공개하고, 비밀값만 엄격히 막는다

2026-11-09에 코드 저장소 `Soochol/vallythevally`를 **이력 그대로** 공개로 바꿨다. 이 도구는 여전히 운영자 한 명만 쓴다(ADR 0001). 코드를 공개하는 것이지 서비스를 공개하는 것이 아니다.

## 공개 시점에 함께 공개된 것 (알고 받아들임)

- 제3자 원자료(Yahoo·FRED·한국은행)
  - `docs/research/2026-11-08-samsung-preview/raw*`
  - 이력에 남은 NAVER·Yahoo 원자료(kingfish 연구, 커밋 ce45080)
- 키움 실제 응답과 시세
  - `docs/kiwoom.md`의 표와 예시
  - 테스트 고정 입력의 실제 응답 JSON
  - `docs/verification/` 스크린샷
- 이슈와 PR의 본문·댓글, hoga-ops 관련 언급, 로컬 경로, 커밋 작성자 이메일

공개 직전에 실제 앱키·시크릿·토큰을 git 이력 전체와 PR 본문·댓글에 대조했다. **0건**이었다.

## 앞으로의 규칙

- **비밀값은 절대 커밋하지 않는다.** 이슈나 PR에도 쓰지 않는다. 앱키, 시크릿, 토큰, `.env`가 대상이다(ADR 0004).
- **권장**: 키움 실제 응답 JSON을 통째로 새로 커밋하는 것은 피한다. 새 테스트 고정 입력은 가능하면 실제 응답의 형태를 따른 합성 데이터로 만든다. 키움 약관 제5조③(시세의 제3자 제공 금지)을 어겼다고 판단될 경우의 최악(계좌 API 해지)을 줄이기 위해서다. 문서 속 숫자 몇 개, 검증 결과의 숫자, 스크린샷은 막지 않는다.
- 라이선스 파일은 아직 없다. 즉 "모든 권리 보유" 상태다. 필요해지면 정한다.

## Considered Options

- **정리한 현재 상태로 새 공개 저장소를 만들기**: GitHub는 PR 참조(`refs/pull/*`)를 지울 수 없다. 그래서 옛 자료를 확실히 빼려면 이 방법뿐이다. 하지만 작업량이 크고 이슈·PR 기록이 갈라진다. 사용자가 택하지 않았다.
- **실제 시세를 하나도 남기지 않는 엄격한 규칙**: 에이전트가 지키기 쉬운 분명한 선이다. 하지만 문서 숫자와 검증 기록까지 모두 손봐야 해서 얻는 것에 비해 비용이 크다고 보고 권장 수준으로 낮췄다.

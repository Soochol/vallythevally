# 한투 앱키는 vally 전용이고, 토큰·접속키·유량·오류는 앱 상태와 따로 쓸 수 있는 라이브러리로 둔다

한국투자증권(한투) Open API를 부르는 바닥(`crates/server/src/kis/`)을 만든다. 시세·주문 기능에 연결하는 것은 뒤 작업이 한다. 이 ADR은 그 바닥의 결정만 적는다. [ADR 0004](0004-dedicated-kiwoom-app-key.md)와 [ADR 0009](0009-kiwoom-errors-closed-categories.md), [ADR 0035](0035-kiwoom-queue-counts-each-tr-per-second.md)를 한투에 맞춰 옮긴 것이다. 다른 ADR에 개정 줄은 달지 않는다.

## 결정

- **키 출처**: 이 키는 원래 hoga-ops의 `KIS_APP_KEY`였고 2026-11-22에 옮겼다. 다른 프로그램과 공유하지 않는다. 같은 앱키로 실시간을 두 곳에서 열면 두 번째가 `OPSP8996`으로 거절되기 때문이다(hoga-ops 커밋 `027a6e286`, 2026-06-19).
  - 그래서 hoga-ops의 한투 기능(파생 야간 실시간, 종목 뉴스, 미국 지수)은 멈춘다. 사용자가 알고 골랐다.
  - 호가 복기 수집기의 한투 지원은 후속 플랜이다. 수집기가 쓸 한투 키는 이 키와 달라야 한다.
- **환경 변수**(값은 문서·PR에 적지 않는다)
  - `VALLY_KIS_APP_KEY`, `VALLY_KIS_APP_SECRET`: 둘 다 적거나 둘 다 비운다. 환경(`VALLY_ENV_FILE`이 가리키는 파일이나 프로세스 환경)에서 읽고 프로세스 환경이 앞선다.
  - `VALLY_KIS_BASE_URL`, `VALLY_KIS_WS_URL`: 공식 실전 주소(`https://openapi.koreainvestment.com:9443`, `ws://ops.koreainvestment.com:21000`)나 루프백(`http://`, `ws://`)만 받는다. 둘 다 적거나 둘 다 비우고, 둘 다 공식이거나 둘 다 루프백이어야 한다. 비우면 공식 주소다. 모의투자 주소(`openapivts…`)는 받지 않는다.
  - `VALLY_KIS_TOKEN_PATH`: 기본은 키움 토큰 파일(`VALLY_TOKEN_PATH`)과 같은 폴더의 `kis-token.json`이다. 기본 환경에서는 `$XDG_STATE_HOME/vallythevally/kis-token.json`이다.
  - 시험 시계(`VALLY_CLOCK_START`)는 한투를 설정했고(키나 주소를 적었고) 그 주소가 공식이면 뜨지 않는다. 한투를 설정하지 않았으면 상관없다.
- **토큰**: `POST /oauth2/tokenP`(`grant_type=client_credentials`, 본문 `appkey`·`appsecret`)로 발급한다. 응답의 `access_token`과 `access_token_token_expired`(KST `YYYY-MM-DD hh:mm:ss`)를 쓰고, 만료 시각이 없으면 `expires_in`을 쓴다.
  - **토큰 파일**: 저장소 밖 파일(디렉터리 700, 파일 600)에 앱키 해시(`sha256:…`), 토큰, 발급 시각, 만료 시각, 마지막 발급 요청 시각을 둔다. 둘 중 하나라도 다른 사용자에게 열려 있으면 읽지도 쓰지도 않는다. 키움 `private_file.rs`와 `credential_id`를 그대로 부른다.
  - 앱키가 바뀌면 파일의 토큰은 쓰지 않는다. 마지막 발급 요청 시각은 앱키와 상관없이 따른다.
  - **재시작은 발급이 아니다.** 파일에 같은 앱키의 토큰이 만료 10분 전보다 많이 남았으면 그대로 쓴다.
  - **요청 전에 시각을 기록한다.** 발급 요청 시각을 파일에 쓰지 못하면 발급 요청을 보내지 않는다. 파일이 있는데 읽지 못하면(권한, 깨진 JSON) 토큰 조회와 발급을 모두 멈춘다. 마지막 발급 요청 시각을 모르기 때문이다. 오류 문구에는 파일 경로만 있고 내용은 없다.
  - **발급 간격은 10분이다.** 한투 규칙은 1분에 1회(샘플·README)이고 6시간 안에 다시 받으면 같은 토큰이 오지만, 키움과 같은 값으로 둔다. 토큰은 24시간 쓰고 발급마다 알림톡이 가므로 간격을 좁혀 얻는 것이 없다. 간격 안이면 요청하지 않고 다시 시도할 시각(마지막 요청 + 10분)을 돌려준다. `EGW00133`(발급 1분 제한)도 같은 대기로 다룬다.
  - 토큰 무효 응답을 받으면 한 번만 다시 발급하고 그 요청을 한 번 다시 보낸다. 발급 간격 안이면 다시 발급하지 않고 그 요청이 대기 시각과 함께 실패한다. 새 토큰도 무효면 전체 멈춤이다.
  - 20:05 정기 재발급과 만료 10분 전 재발급을 언제 부를지는 이 바닥을 쓰는 쪽이 정한다. 이 바닥은 만료 10분 전부터 쓸 수 없는 토큰으로 보고 다음 요청에서 다시 발급한다.
- **접속키**: `POST /oauth2/Approval`(본문 `appkey`·`secretkey`)의 `approval_key`다. 실시간을 열 때마다 받고 메모리에만 둔다. 파일에 남기지 않는다. 유효기간과 발급 제한은 확인하지 못했다.
- **오류 범주**: 응답의 `rt_cd`와 코드(`msg_cd`, 토큰 발급은 `error_code`)를 경계에서 한 번만 읽어 닫힌 범주로 바꾼다. 정책은 아래 표 하나에서만 나온다. 코드는 영문자·숫자 16자 이하일 때만 담는다. 응답 본문 문장(`msg1`)과 원문은 담지도 로그에 남기지도 않는다.

  | 범주 | 정책 | 코드 | 뜻 |
  |---|---|---|---|
  | 한도 초과 | 그 요청만 창이 비는 시각에 다시 보낸다. 세 번째면 실패 | `EGW00201` | 초당 거래건수 초과 |
  | 토큰 무효 | 한 번 다시 발급하고 그 요청을 한 번 다시 보낸다. 새 토큰도 무효면 전체 멈춤 | `EGW00121`, `EGW00123` | 유효하지 않은 토큰, 기간이 만료된 토큰 |
  | 발급 제한 | 발급 간격 대기 | `EGW00133` | 접근토큰 발급 1분당 1회 |
  | 인증 차단 | 요청과 발급 전체 멈춤 | (표에 확인된 코드 없음. 토큰 발급 요청이 4xx로 거절되고 코드가 표에 없을 때) | 앱키·시크릿 오류 같은 인증 거절 |
  | 업무 거절 | 그 요청만 실패 | HTTP 200이고 `rt_cd`가 `0`이 아니면서 표에 없는 코드 | 조회 조건이나 업무 규칙의 거절 |
  | 알 수 없음 | 그 API 경로만 멈춤 | 위에 없는 나머지(HTTP 오류인데 표에 없는 코드, 읽을 수 없는 본문, `rt_cd` 없음) | |
  | 자리 초과 | 그 등록만 실패로 남김 | `OPSP0008` | 실시간 등록 한도(`MAX SUBSCRIBE OVER`) |
  | 다른 곳에서 사용 중 | 세션을 닫고 다시 잇지 않음 | `OPSP8996` | 같은 앱키로 이미 실시간 사용 중(`ALREADY IN USE appkey`) |

  - 실시간 제어 응답 성공은 `rt_cd` `0`(`OPSP0000`)이다. 실시간 거절 가운데 표에 없는 것은 알 수 없음으로 알리고 세션은 닫지 않는다.
  - 코드 근거는 공식 샘플·README(`EGW00201`)와 hoga-ops(`kis_client.py`의 `EGW00121`·`EGW00123`, ADR 0101의 `OPSP0008`, 커밋 `027a6e286`의 `OPSP8996`)이다. `EGW00133`은 샘플 주석과 README의 "1분당 1회"에서 가져왔고 코드 값 자체는 이 작업에서 실응답으로 확인하지 못했다. 확인하지 못한 코드는 알 수 없음이다.
- **REST 유량: 앱키 하나에 대기열 하나, 초당 15건**
  - 한투 유량은 TR마다가 아니라 앱키 전체다. 최근 1초 창(여유 50ms)의 전체 전송 수를 센다. 상수 `KIS_PER_SECOND_LIMIT` = 15다.
  - 근거는 hoga-ops ADR 0100(2026-07-10 실측)이다. 앱키 세 개를 각각 15/s로 120초 보냈을 때 한도 초과가 9%로 평탄했고 합산 성공이 단일 앱키의 3.03배였다. 앱키별 독립 약 15/s라는 뜻이다. 샘플의 실전 호출 간격 0.05초(초당 20건)보다 낮게 잡았다. 남는 약 9%는 대기열의 다시 보내기가 흡수한다.
  - 우선순위 다섯 단계(주문 → 화면 → 화면 뒤쪽 → 복구 → 배경)와 화면 몫 2칸 예약(최근 10초 안에 주문·화면 전송이 있으면 나머지는 13칸까지만)은 ADR 0035와 같다. 같은 요청은 합친다. 주문도 같은 창에 센다.
  - 한도 초과 응답을 받으면 그 요청만 창이 비는 시각에 다시 보낸다. 세 번째 한도 초과는 실패로 돌려준다. 결과를 받을 호출자가 모두 사라진 요청은 보내기 전에 버린다.
  - 이 작업의 시세 TR은 시험용 주식현재가(`FHKST01010100`) 하나다. 나머지는 `kis-market-rest`가, 주문·계좌 TR은 `kis-orders`가 `trading/`에 더한다. 열거형은 닫혀 있어 목록에 없는 TR은 보낼 수 없다.
- **실시간: 앱키 하나에 세션 하나, 등록 자리 40**
  - 한투는 연결 하나에 41건까지 받고 42번째가 `OPSP0008`이다. (TR, 종목) 한 쌍이 한 건이고 연결(접속키)마다 따로다(hoga-ops ADR 0101, 2026-07-10 실측). 공식 샘플 래퍼도 40건에서 막는다. 실측 41에서 하나를 남긴 `KIS_REALTIME_LIMIT` = 40이다. 체결통보를 받는 계좌면 그 한 자리를 먼저 잡는다. 자리를 계산해 40을 넘지 않게 하는 것은 `market-port-stream`의 일이고, 이 세션은 받은 등록을 그대로 보낸다.
  - 등록 목록이 바뀌면 해지를 먼저 보내고 등록을 나중에 보낸다(hoga-ops ADR 0101).
  - 세션은 접속, 등록(`tr_type` 1)과 해지(`2`), 응답 확인, `PINGPONG` 되돌려 보내기, 프레임(`0|tr_id|건수|^로 나눈 필드`) 나누기, 끊김 알림을 맡는다. 암호화 프레임(첫 칸 `1`, 체결통보)은 이 작업이 풀지 않는다. 필드 이름 매핑은 `kis-market-stream`이 한다.
  - 끊기면 알리고 1·2·5·10·30초로 물러서며 다시 접속하고 원하는 등록을 다시 보낸다. 접속키는 접속마다 새로 받는다.
- **`OPSP8996`은 다른 곳에서 이 앱키로 실시간을 쓰는 중이다.** 세션을 닫고 저절로 다시 잇지 않는다([ADR 0027](0027-kiwoom-connects-by-itself-when-a-key-is-present.md)처럼). 상태에 "다른 곳에서 사용 중"을 싣고 `InUseElsewhere` 이벤트를 한 번 보낸다. 다시 잇는 것은 사용자가 다른 쪽을 끈 뒤 새 세션을 만드는 것으로만 한다.
- **모의 프로세스는 한투 키를 거절한다.** `VALLY_KIWOOM_ENV=mock`인데 `VALLY_KIS_APP_KEY`나 `VALLY_KIS_APP_SECRET`이 있으면 뜨지 않는다([ADR 0030](0030-kiwoom-mock-trading-runs-as-its-own-server-process.md) 결정 1의 "투자구분은 프로세스 하나에 하나"). 문구에는 변수 이름만 있고 값은 없다. 한투 모의투자는 범위 밖이다.
- **앱 상태에 묶지 않는다.** 토큰 공급자(`KisAuth`), REST 대기열(`KisRest`), 실시간 세션(`KisStream`)은 자격 증명, 토큰 파일 경로, transport(`Transport`)·연결 교체점(`Connector`), 시계만 받는다. `AppState`나 `Adapters`를 모른다. 수집기가 `server::kis`를 라이브러리로 쓸 수 있게 하기 위해서다. 시험은 합성 transport와 합성 `Connector`만 쓰고 실제 한투를 부르지 않는다.
- **토큰을 쥔 프로세스는 키마다 하나다.** 이 라이브러리는 잠금 파일을 잡지 않는다. 서버가 같은 PC에서 하나만 뜨는 잠금(ADR 0004)은 연결하는 쪽이 지킨다.
- **비밀값은 출력하지 않는다.** 앱키, 시크릿, 토큰, 접속키는 `Secret`으로 감싸 `Debug`·`Display`가 `[가림]`만 낸다. 로그와 오류 문구에는 범주, HTTP 상태, 코드, 파일 경로만 있다.

## 실측하지 않았다

다음은 상수 하나나 닫힌 처리로 두었고, 병합 뒤 실사용에서 확인한다. 이 작업의 시험은 합성 응답만 쓰므로 한투의 실제 응답으로 확인한 것이 없다.

- 신규 주문이 NXT·SOR을 실제로 받는지(확정된 결정 7. 이 작업은 주문을 다루지 않는다)
- 한투 SOR의 시간대·종목별 배분 규칙
- 수정주가 파라미터 값의 뜻
- 접속키의 유효기간과 발급 제한
- 6시간이 지난 뒤 다시 받으면 이전 토큰이 즉시 폐기되는지
- 접속 IP 제한이 있는지
- 마스터 파일에 NXT 거래 가능 표시가 있는지
- 과거 분봉이 `NX`·`UN`을 받는지
- 멀티종목 조회의 종목 수
- 순위 11종의 요청 칸 값(`kis-rankings`). 샘플 독스트링에 값이 없거나 맞지 않아 정한 것이다
  - 등락률 순위 `FHPST01700000`의 상승·하락 정렬 코드(`FID_RANK_SORT_CLS_CODE`를 `0`·`1`로 보냈다. 샘플은 `0000`만 적는다)
  - 등락률 순위의 상한가 포함 여부(가격 구분 `FID_PRC_CLS_CODE`의 값을 몰라 `0`으로 두고, 응답의 전일 대비 부호가 상한·하한인 행을 서버가 뺀다)
  - 등락률 순위의 최소 거래대금(칸이 거래량 `FID_VOL_CNT`뿐이라 원 단위 값을 그 칸에 실었다. 단위가 맞는지 모른다)
  - 거래량 순위 `FHPST01710000`의 대상 구분 `FID_TRGT_CLS_CODE` 값(`0`)과 대상 제외 `FID_TRGT_EXLS_CLS_CODE`의 10자리 중 관리종목 자리(두 번째)
  - 호가잔량 순위 `FHPST01720000`의 대상 제외 값(제외하지 않으면 `0`, 관리종목 제외면 10자리)
  - 예상체결 순위 `FHPST01820000`의 장전·장마감 구분(`FID_MKOP_CLS_CODE`). 정오 전이면 `0`, 이후면 `1`로 보냈다
  - 시간외 거래량 순위 `FHPST02350000`의 응답 행 위치(`output2`)와 열, 시장 `NX` 거부 여부(`J`만 보낸다), 장전 값 유무
  - 신용잔고 순위 `FHKST17010000`의 `FID_OPTION` 값(`2`)과 응답 행 위치(`output2`)
  - 많이 본 종목 `HHMCM000100C0`의 응답이 종목코드·시장 구분만 주는 것(이름·가격·등락 열이 없어 가격을 비운다)
  - 투자자 순매수 `FHPTJ04400000`의 금액 단위(백만원으로 보았다)와 기타 구분의 열 조합(`etc_orgt`·`etc_corp`), 매수·매도 열이 없는 것
  - 순위 TR이 이어 받는 쪽(`tr_cont`)을 주는지. 한 번에 30행으로 알려져 있어 한 쪽만 받는다
- 약관상 시세 재배포 제약(이 앱은 시세를 사용자 PC에서만 다룬다, ADR 0023)
- 한투 순위 API의 최대 행 수, 업종 현재지수의 상승·하락 종목 수 칸, 종목 투자자 일별의 외국인 보유 열
- 실시간 체결의 매수·매도 방향 필드(`CNTG_CLS_CODE`, 1을 매수, 5를 매도로 읽는다)와 통합 체결(`H0UNCNT0`)의 거래소 표시(`MARKET_CLS_CODE`, 읽지 않아 통합 체결의 거래소는 비어 있다)
- 실시간 거래원 판(`H0UNMBC0`)의 필드 위치(공식 샘플 열 순서)와 시각(프레임에 시각이 없어 받은 시각을 쓴다), 회원사 이름(프레임의 이름을 쓰고 없으면 코드 그대로)
- 실시간 프로그램매매(`H0UNPGM0`)의 거래대금 단위(원으로 읽어 백만원으로 바꾼다)와 증감(앞 프레임과의 차이로 만든다), 호가 프레임(`H0STASP0` 계열)의 예상체결가·량 열(`ANTC_CNPR`, `ANTC_CNQN`)이 동시호가 때 채워지는지(전용 `…ANC0`은 자리를 더 쓰므로 등록하지 않는다)
- 업종 현재지수(`FHPUP02100000`)의 상승·하락·보합·상한·하한 종목 수 열(`ascn_issu_cnt` 등)은 공식 샘플의 열 목록에는 있으나 값 단위를 합성 응답으로만 확인했다. 2026-11-23 개정: 빈 값은 0이 아니라 "없음"으로 읽어 중립 타입과 API의 다섯 칸이 `Option<u32>`(웹 `number | null`)이고, 웹은 "-"로 그린다. 시장 개요 지수 일봉(`FHKUP03500100`)은 기간의 거래일 수(60일)를 채울 때까지만 `tr_cont`로 이어 받는다
- 종목 외국인 보유의 일별 이력 열(보유 수량·한도소진율)은 공식 샘플의 종목별 투자자매매동향(일별)에 없다. 그래서 현재가 응답의 현재 보유 수량(`frgn_hldn_qty`)과 외국인 소진율(`hts_frgn_ehrt`)만 오늘 한 행으로 싣고, 지분율(키움 `wght`)과 같은 값인지는 확인하지 못했다
- 시장별 투자자매매동향 두 TR(`FHPTJ04030000`·`FHPTJ04040000`)의 시장·업종 구분 코드(코스피 `0001`·`KSP`, 코스닥 `1001`·`KSQ`, 업종은 업종 코드), 금액 열이 백만원이라는 것, 시세용 응답이 행 하나로 오는지
- 프로그램매매 종합현황(시간)(`FHPPG04600101`)이 차익·비차익 열을 주지 않아 장중 표본의 프로그램 줄에 두 열이 없다는 것, 일별(`FHPPG04600001`)의 전체 순매수는 차익과 비차익 합계 순매수의 합으로 만든다는 것
- 종목별 투자자매매동향(일별)(`FHPTJ04160001`)이 국가·지자체 열을 주지 않아 `government`를 0으로 채운 것, 당일 행이 확정되는 시각(16:00으로 둔 값), 날짜를 커서로 거슬러 받는 연속조회가 맞는지
- 외인기관 추정가집계(`HHPTJ04160200`)의 입력 구분(1~4)이 클수록 늦은 집계라는 것과 개인·세부 기관 열이 없어 오늘 추정 행의 그 열이 0이라는 것
- 한투 업종 구분별 전체시세(`FHPUP02140000`)의 쪽 크기와, 업종 코드를 `FHPTJ04030000`에 그대로 넣어도 되는지
- 이 작업이 더한 것: 코드 `EGW00133`의 실제 응답 모양, 인증 차단이 되는 실제 코드(표에 없음), `rt_cd`가 `0`이 아닌 실제 업무 거절 코드, 실시간 제어 응답에서 `OPSP0008`이 오는 시점, 한투가 `tr_cont`를 `F`·`M`으로 주는 연속조회의 쪽 크기

## Considered Options

아래는 검토했지만 **고르지 않은 안**이다. 다시 꺼내려면 새 ADR로 이 결정을 바꾼다.

- **hoga-ops와 같은 앱키를 나눠 쓰기**: 같은 앱키로 실시간을 두 곳에서 열면 한쪽이 `OPSP8996`으로 거절된다. 호출 한도도 앱키 단위로 나눠 쓴다. 그래서 vally 전용으로 옮겼다.
- **토큰을 메모리에만 두기**: 재시작마다 발급하게 된다. 발급마다 알림톡이 간다. 그래서 키움과 같이 파일로 둔다.
- **발급 간격을 한투 규칙(1분)대로 두기**: 얻는 것이 없고 키움 쪽 규칙과 달라진다. 그래서 10분이다.
- **TR마다 따로 센 유량**(ADR 0035의 키움 방식): 한투 유량은 앱키 전체라 TR마다 세면 한도를 넘는다.
- **표에 없는 코드를 모두 알 수 없음으로 두기**: HTTP 200과 `rt_cd` 실패는 한투가 문서로 약속한 "요청 하나의 거절"이다. 코드를 모른다고 그 API 경로를 멈추면 흔한 조회 거절 하나가 시세 전체를 멈춘다. 그래서 `rt_cd`가 실패를 알리면 업무 거절로 두고, 읽을 수 없는 응답과 HTTP 오류만 알 수 없음으로 둔다.

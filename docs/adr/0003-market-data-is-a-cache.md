# 시세는 수집하지 않고, 키움을 원본으로 둔 메모리 캐시만 갖는다

시세의 원본은 언제나 키움 REST API와 WebSocket이다. 우리 쪽에는 키움에서 받은 확정 봉의 사본, 즉 캐시만 둔다. 캐시는 **서버 메모리에만** 둔다.

- 미리 수집하지 않는다.
- 캐시는 언제 통째로 지워도 된다. 서버를 다시 켜면 빈 상태로 시작하고, 차트를 열 때 키움에서 다시 받는다.
- 디스크에 시세를 남기지 않는다. 그래서 수정주가 반영, 오류 복구, 구조 변경을 모두 "버리고 다시 받기"로 처리한다.

## 규칙

- **계층**: 서버 메모리에 열려 있는 (종목, 봉 주기)의 확정 봉을 둔다. 그 시리즈를 보는 곳이 모두 사라지고 10분이 지나면 메모리에서 내린다. 실시간 구독(#4)이 생기기 전까지 서버는 보는 곳을 알 수 없어서 **마지막 요청에서 10분**으로 대신한다. #4부터는 구독이 있는 시리즈를 내리지 않는다. 10분은 보관 시간이지 신선도가 아니다. 확정 봉의 신선도는 07:45 비우기가 정한다. 브라우저도 시세와 지표 값은 메모리에만 둔다.
- **날마다 비우기**: 매일 07:45(NXT 프리마켓 전)에 메모리 캐시를 모두 버린다. 액면분할이나 권리락으로 과거 가격이 바뀌어도 다음 날 새로 받으면 수정주가로 온다. 그래서 수정주가 대조 로직을 두지 않는다. 키움이 수정주가를 언제 반영하는지는 실측으로 확인한다.
- **단위**: (종목, 거래소, 봉 주기)마다 따로 캐시한다(ADR 0007). 키움이 준 봉을 그대로 쓰고 다른 봉 주기에서 파생하지 않는다.
- **현재 봉**: 캐시하지 않는다. 서버가 봉 주기마다 실시간 체결로 직접 만든다. 다른 봉 주기의 봉에서 만들지 않는다.
- **실시간으로 만든 확정 봉**
  - 현재 봉이 확정되면 캐시에 붙이고 "실시간으로 만든 봉"이라고 표시한다.
  - 같은 구간을 키움에서 다시 받으면 키움 값으로 교체한다.
  - 실시간 연결이 끊겼던 구간(매일 07:50 강제 단절 등)은 다시 연결된 뒤 조회해서 덮어쓴다.
- **조회**
  - 서버 전체의 키움 조회를 대기열 하나로 모은다. 초당 4회로, 키움 한도 5회보다 낮게 둔다.
  - 같은 요청은 합친다.
  - 처음 열 때는 최근 500봉만 받고, 과거로 스크롤하면 더 받는다. 실측 결과 일봉·분봉은 1회, 주봉 2회, 월봉 3회 조회다.
- **분봉은 최근 1년만**: 키움은 분봉을 마지막 관측일로부터 1년까지만 준다. 그래서 분봉 차트는 최근 1년까지만 보여 준다.
- **실시간 구독**: 열린 칸의 종목, 관심종목, 켜진 알림의 종목을 구독한다. 아무 데서도 쓰지 않게 되면 30초 뒤 해지한다. 200종목을 넘으면 열린 칸 → 관심종목(목록의 위부터) 순으로 자리를 주고, 자리를 못 받은 관심종목은 처음 값만 두고 `실시간 아님`을 보인다. 실시간 갱신용 조회는 하지 않는다.
- **원천은 키움 하나**
  - 시세 원천은 키움뿐이다. 녹화 기능도, 녹화본을 흘려보내는 재생 원천도 두지 않는다.
  - 그래서 실시간 기능은 체결이 있는 시간(평일 08:00~20:00)에만 실제로 돌려 볼 수 있다.
  - 봉 집계와 알림 판단은 체결 목록을 받는 순수 함수로 만들고, 손으로 쓴 체결 목록으로 테스트한다.

## Considered Options

- **메모리 + Postgres 캐시 스키마**(이 ADR의 이전 버전)
  - 재시작해도 캐시가 남고, 키움이 응답하지 않을 때도 받아 둔 봉을 보여 줄 수 있다.
  - 하지만 다음 비용이 든다. 캐시 스키마 7개 테이블, 종목별 쓰기 잠금, 캐시 세대 번호, 트랜잭션 순서, 수정주가 대조 로직.
  - 이 안을 추천했던 근거는 "모의 키는 조회가 초당 1회라 재시작이 느리다"였다. 그런데 실계좌 키(초당 4회)로 바꿨고, 실측해 보니 한 번에 일봉 600·분봉 900개가 온다. 재시작 비용은 차트당 1~3회 조회(1초 안팎)로 줄었다.
  - 2026-11-08에 메모리만 두는 쪽으로 바꿨다. 키움 점검 시간에도 차트를 봐야 하거나 재시작이 잦아 불편해지면 디스크 계층을 다시 붙인다.
- **전 종목 시세를 미리 수집해 우리 DB를 원본으로 두기**: 리포트에는 유리하다. 하지만 개인 도구에서 보지도 않는 종목까지 수집하는 것은 낭비이고, 수정주가가 바뀔 때마다 과거 봉을 고쳐야 한다.
- **1분봉과 일봉만 받고 나머지 봉 주기를 파생하기**: 긴 기간의 60분봉을 보려면 키움 호출이 60배로 늘어난다. NXT 08:00 시작 같은 경계 규칙이 키움과 어긋날 위험도 있다.

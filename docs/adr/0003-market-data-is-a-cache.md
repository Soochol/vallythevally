# 시세는 수집하지 않고 키움을 원본으로 둔 캐시만 갖는다

시세의 원본은 언제나 키움 REST API와 WebSocket이다. 우리 쪽에는 키움에서 받은 확정 봉의 사본, 즉 캐시만 둔다.

- 미리 수집하지 않는다.
- 캐시는 언제 통째로 지워도 된다.
- 그래서 스키마 변경, 수정주가 반영, 오류 복구를 모두 "지우고 다시 받기"로 처리할 수 있다.

## 규칙

- **계층**: 서버 메모리에는 열려 있는 종목을 두고, 서버를 다시 켜도 남아야 하는 것은 Postgres의 별도 캐시 스키마에 둔다. 사용자 자료(레이아웃·드로잉·관심종목·알림)와는 스키마를 나눈다. 브라우저는 메모리에만 둔다.
- **단위**: 봉 주기마다 따로 캐시한다. 키움이 준 봉을 그대로 쓰고 다른 봉 주기에서 파생하지 않는다.
- **현재 봉**: 캐시하지 않는다. 서버가 실시간 체결로 만든다.
- **실시간으로 만든 확정 봉**: 현재 봉이 확정되면 캐시에 붙이고 "실시간으로 만든 봉"이라고 표시한다. 같은 구간을 키움에서 다시 받으면 키움 값으로 교체한다. 실시간 연결이 끊겼던 구간(매일 07:50 강제 단절 등)은 다시 연결된 뒤 조회해서 덮어쓴다.
- **수정주가**: 그날 처음 종목을 열 때 최근 확정 일봉 하나를 키움과 대조한다. 다르면 그 종목의 캐시를 모든 봉 주기에서 버린다.
- **조회**: 서버 전체의 키움 조회를 대기열 하나로 모은다(실계좌 초당 5회, 모의 초당 1회). 같은 요청은 합친다. 처음 열 때는 최근 500봉만 받고, 과거로 스크롤하면 더 받는다.
- **실시간 구독**: 열린 칸의 종목, 관심종목, 켜진 알림의 종목을 구독한다. 아무 데서도 쓰지 않게 되면 30초 뒤 해지한다. 200종목을 넘으면 관심종목 현재가는 1분마다 조회한다.

## Considered Options

- **전 종목 시세를 미리 수집해 우리 DB를 원본으로 두기**: 리포트에는 유리하다. 하지만 개인 도구에서 보지도 않는 종목까지 수집하는 것은 낭비이고, 수정주가가 바뀔 때마다 과거 봉을 고쳐야 한다.
- **1분봉과 일봉만 받고 나머지 봉 주기를 파생하기**: 긴 기간의 60분봉을 보려면 키움 호출이 60배로 늘어난다. NXT 08:00 시작 같은 경계 규칙이 키움과 어긋날 위험도 있다.

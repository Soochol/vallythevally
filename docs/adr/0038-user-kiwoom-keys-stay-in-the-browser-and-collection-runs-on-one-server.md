# 사용자 키움 키는 브라우저에만 두고 사용자 키로 하는 일만 브라우저가 키움에 직접 하며, 공용 자료와 수집은 운영 서버 한 곳이 맡는다

여러 사람이 쓰는 서비스로 열 때의 구조다. 사용자가 정했다(2026-11-22). 사용자는 자기 PC에 프로그램을 설치하지 않고 웹 화면만 연다. [ADR 0023](0023-connector-and-account-server.md)은 키움 키와 시세를 각 사용자 PC의 커넥터에 두었다. 이 ADR은 사용자 키와 사용자 키로 하는 일의 자리를 각 사용자의 브라우저로 바꾸고, 모두에게 같은 공용 자료는 운영 서버가 운영자 키로 만들어 주도록 나눈다. ADR 0023이 Considered Options에서 고르지 않은 (c)안에 수집 서버를 더한 모습이다.

## 정한 것

- **사용자 키는 브라우저에만 있다.** 사용자가 프론트엔드에서 키움 앱키와 시크릿을 입력하고, 그 PC의 브라우저에 저장한다. 키, 키움 토큰, 계좌번호는 서버로 보내지 않는다. 서버에는 이것을 받는 API가 없다.
- **공용 자료는 운영자 쪽이 운영자 키로 만들어 로그인한 모든 사용자에게 준다.** 종목 목록, 일봉 저장소, 스크리너, 재무, ETF, 순위, 시장 개요, 히트맵이 여기에 든다. 사용자는 이것을 받으려고 자기 키움 키를 쓰지 않는다. 사용자 수와 키움 호출 수가 나뉜다.
- **브라우저가 사용자 키로 키움에 직접 하는 일은 셋뿐이다.** (1) 내가 보는 종목의 실시간(WebSocket 체결·호가), (2) 계좌 실시간(WebSocket `00`·`04`), (3) 토큰 발급, 계좌 조회, 주문(REST). 키움 REST와 WebSocket은 다른 출처의 요청을 받는다(2026-11-10 확인).
- **수집은 운영 서버 한 곳에서만 한다.** 수집기와 감독 데몬은 지금의 서버 PC처럼 운영 서버에서만 돈다. 수집 키는 운영자의 키이고 그 서버에만 있다([ADR 0022](0022-hoga-replay-collects-quotes-on-disk.md), [ADR 0026](0026-collector-supervisor-collects-common-and-preferred-stocks.md)). 사용자 브라우저는 수집을 하지 않는다.
- **공용 자료를 만드는 주체는 수집 데몬이다.** 감독 데몬이 수집 전용 키(시세만 부르고 주문·계좌 API는 없다)로 정해진 주기에 키움을 불러 공용 자료를 만든다. `vally-server`는 그 자료를 읽어 주기만 하고 키움을 부르지 않는다. 이것이 가려는 방향이다.
- **첫 단계 동안의 임시 사실.** 공개 리스너([ADR 0040](0040-the-public-listener-serves-browser-logins-and-shared-data-apart-from-the-operator-listener.md))는 순위·시장 개요·히트맵을 운영자 시세 키로 직접 받는다. 그래서 공개 부하가 운영자 화면을 늦추지 않게 하는 한도 장치가 임시로 붙는다. 자료를 수집 데몬이 만들도록 넘기는 길, 수집 데몬의 키 배정표, 스냅샷 같은 설계는 다음 플랜 `collector-shared-data`의 ADR이 정한다. 방향은 이 ADR의 결정이고 설계는 아직 정해지지 않았으므로 이번에 따로 ADR을 더하지 않는다.
- **운영 서버가 맡는 일**: 웹 화면 서빙, 공용 자료 제공(일봉 저장소, 스크리너, 재무자료, ETF 구성, 순위, 시장 개요, 히트맵), 계정과 셋업 저장([ADR 0024](0024-setup-storage-and-sync.md)). 운영 서버는 사용자 키로 키움을 부르지 않는다. 운영자 키로 공용 자료를 받는 것은 이와 별개로 맞다.
- **ADR 0023에서 그대로 두는 것**: 로그인은 Google과 Naver OAuth뿐이고 비밀번호 로그인은 없다. 계정은 `(provider, subject)`로 식별하고 이메일로 잇지 않는다. 셋업에 시세와 시세에서 계산한 값은 들지 않는다.
- **ADR 0023에서 바뀌는 것**: 키와 시세를 커넥터에만 둔다는 결정, 그리고 그 전제 위의 루프백 로그인 흐름과 커넥터 토큰이다. 브라우저가 운영 서버를 직접 상대하므로 커넥터가 로그인 결과를 받을 이유가 없어진다. 새 로그인 흐름과 세션 방식은 ADR 0040이 정한다.
- **키 규칙은 키마다 그대로다.** 토큰을 다시 받으면 이전 토큰이 폐기될 수 있고 토큰 하나에 WebSocket 세션은 하나다([ADR 0004](0004-dedicated-kiwoom-app-key.md)). 키 목록과 시세 키([ADR 0037](0037-kiwoom-keys-are-a-list-with-one-market-key.md)), 발급 간격, 8050 차단도 키마다 지킨다. 이것을 지키는 주체가 서버 프로세스에서 브라우저로 바뀐다.

## 속도 확인

옮기기 전에 시제품으로 쟀다(2026-11-22). 가짜 키움 서버가 `REAL` 0B 형식(항목당 FID 약 40개)으로 100종목의 체결을 흘리고, 브라우저가 받아 1분봉을 만들어 캔버스에 그렸다. 개발 PC의 headless Chromium이다.

- 체결 한 건의 처리(JSON 파싱과 봉 갱신)는 4~11µs였다. 초당 3,000건에서도 CPU 1.3% 안쪽이었고 받은 수와 보낸 수가 같았다.
- 화면 반영 지연 p99는 약 17ms(한 프레임)였고 60fps를 지켰다. 그리기에 30ms를 더하면 메인 스레드와 Worker 모두 30fps였다. 병목은 그리기였다.
- 그래서 JS로 옮겨서 생기는 속도 문제는 결정 근거가 되지 않는다. 숨긴 탭, 실제 키움 네트워크, 휴대폰은 재지 않았다.

## Considered Options

- **각자 PC에 커넥터를 설치(ADR 0023)**: 사용자가 프로그램을 설치해야 한다. 사용자는 웹만 열면 쓰는 모습을 원한다.
- **사용자 키를 운영 서버에 보관**: 서버가 털리면 모든 사용자의 주문 가능한 키가 새어 나간다. 시세를 사용자별로 나누려면 백엔드를 크게 바꿔야 한다.
- **공용 자료도 각 사용자 브라우저가 사용자 키로 받기**: 같은 공용 자료를 사용자 수만큼 키움에서 되풀이해 받고, 사용자마다 키움 호출 한도를 따로 소모한다. 순위, 시장 개요, 히트맵, 스크리너는 모두에게 같은 자료라 운영자 쪽이 한 번 만들어 주는 편이 호출 수가 적다.
- **수집도 각 사용자 브라우저에서**: 수집은 탭이 닫혀도 돌아야 하고 전 종목을 다룬다. 지금처럼 운영 서버 한 곳에서 한다.

## Consequences

- 브라우저로 옮길 것은 사용자 키로 하는 셋으로 좁혀진다. 내가 보는 종목의 실시간, 계좌 실시간, 토큰·계좌 조회·주문이다(`crates/server/src/kiwoom`, `market`, `trading`, `ws.rs`의 해당 부분). 가장 큰 작업이다. 키움 규칙은 Rust 코어를 WASM으로 쓰고, 옮기는 순서와 방향은 [ADR 0041](0041-browser-keys-are-locked-by-default-and-the-kiwoom-engine-runs-in-the-browser-as-wasm.md)이 정한다.
- 순위, 시장 개요, 히트맵, 스크리너 같은 공용 자료는 서버가 준다. 차트 과거 봉처럼 미리 만들 수 없는 요청은 `collector-shared-data`의 사용자 결정이다. 수집 데몬의 예비 키로 요청을 받아 캐시할지, 브라우저가 사용자 키로 받을지 그 플랜에서 정한다. 현재가·당일 요약, 기본 정보, 투자자, 체결·호가·프로그램 조회도 같이 정한다.
- 같은 키로 탭이나 기기가 여러 곳에서 토큰을 받으면 서로의 세션을 끊는다. 한 브라우저 안에서는 연결 하나를 탭들이 나눠 쓰는 장치(SharedWorker나 대표 탭)가 필요하다. 같은 키로 PC와 휴대폰을 함께 쓰는 문제는 아직 풀리지 않았다.
- 키를 브라우저에 두므로 화면에 끼어든 스크립트(XSS)가 키를 읽을 수 있다. 기본은 브라우저가 알아서 거는 자동 잠금이고 잠금 비밀번호는 고를 수 있으며 패스키는 나중에 한다. 외부 스크립트를 쓰지 않는 엄격한 CSP와 함께 ADR 0041이 정한다(플랜 D17~D19).
- 브라우저는 숨긴 탭의 타이머를 늦춘다. 탭이 열려 있지 않으면 사용자 실시간 알림이 오지 않는다.
- 키움 키는 IP를 등록해야 하므로 IP가 자주 바뀌는 휴대폰에서는 쓰기 어렵다.
- 개인 캐시는 브라우저 저장소(IndexedDB) 크기와 수명에 묶인다. 공용 자료는 운영 서버가 주므로 개인 캐시는 작게 둔다.
- 운영 서버를 공개 주소로 여는 방법은 ADR 0040이 정한다. 운영자용 tailnet 접속은 [ADR 0036](0036-remote-access-goes-through-tailscale-serve-and-a-configured-tailnet-name.md) 그대로다. 호스팅과 자기 도메인은 이 결정 밖이다.
- 로컬 전용 모드의 커넥터는 옮기는 동안 그대로 둔다. 언제 거두는지는 뒤 플랜에서 정한다.

# 브라우저 시험은 애플리케이션 응답으로 시작한다

브라우저 시험마다 외부 자료를 수집하면 화면과 관계없는 요청 간격·수집량·재시작 대기가 반복된다. 별도 키움 에뮬레이터를 유지하면 원천 프로토콜과 애플리케이션 시험 자료가 함께 늘어난다.

Playwright는 현재 UI를 정적 호스트에서 실행하고, 생성된 DTO 타입의 HTTP·WebSocket 응답을 브라우저 문맥에 주입한다. 한 시험의 문서 저장 상태만 탭 사이에 공유한다. 알 수 없는 API와 외부 통신을 거절한다. 브라우저 fixture는 원천 계산이나 수집기를 구현하지 않는다.

서버 시험은 실제 애플리케이션 구성·서비스·SQLite·DuckDB에 합성 transport를 주입한다. 키움 실시간 상태 기계는 비공개 채널 connector와 가상 시계로 검증하고 실제 HTTP·WebSocket·TLS 어댑터는 좁은 loopback 시험으로 남긴다. 종료·재시작 시험은 소유한 runtime 전체를 종료한 뒤 같은 임시 DB를 다시 연다.

별도 fake-kiwoom 크레이트·실행 파일·관리 API는 제거한다. DB 사본으로 수집을 우회하거나 공통 가짜 서버를 공유하지 않는다. 실제 키움을 시험에서 호출하지 않는 규칙과 ADR 0004의 운영 인증 규칙은 유지한다.

실제 DART 확인은 명시적인 `web.py live`에서만 재무 전용 `dart-smoke`를 사용한다. 자동 시험은 합성 입력과 loopback만 사용한다. 화면·계산·프로토콜의 검증 책임은 [시험 책임 이동](../testing-migration.md)에 기록한다.

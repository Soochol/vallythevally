# 브라우저 키움 키는 기본으로 자동 잠금하고, 키움 엔진은 Rust 코어를 WASM으로 브라우저에서 돌린다

[ADR 0038](0038-user-kiwoom-keys-stay-in-the-browser-and-collection-runs-on-one-server.md)에 따라 사용자 키움 키는 브라우저에서 입력해 브라우저에만 저장하고, 서버로 보내지 않는다. 브라우저가 사용자 키로 하는 일은 내가 보는 종목의 실시간, 계좌 실시간, 토큰·계좌 조회·주문 셋뿐이다. 이 ADR은 그 키를 어떻게 지키고, 그 셋을 하는 엔진을 어떤 모양으로 브라우저에 두는지의 방향을 정한다. 공개 서버는 [ADR 0040](0040-the-public-listener-serves-browser-logins-and-shared-data-apart-from-the-operator-listener.md)이 다룬다. 첫 단계는 키를 저장하는 데까지다. 엔진은 다음 단계이며, 그 구현은 다중 증권사 플랜의 시세·주문 이전 작업이 병합된 뒤에 한다.

## 정한 것

### 키 보호

- **기본은 자동 잠금이다.** 처음 키를 저장할 때 `crypto.subtle.generateKey`로 꺼낼 수 없는(`extractable: false`) AES-GCM-256 키를 만들어 IndexedDB에 둔다. 키움 앱키·시크릿과 (엔진 단계의) 토큰을 그 키로 암호화한다. 쓸 때마다 새 12바이트 IV를 쓴다. 사용자 입력은 없다. 평문 키가 저장소 내보내기, 로그, 실수로 새지 않게 하는 것이 목적이다.
- **잠금 비밀번호는 고를 수 있다.** 켜면 PBKDF2-SHA256(600,000회, 16바이트 솔트)으로 만든 키로 다시 암호화하고 자동 잠금 키를 지운다. 비밀번호는 저장하지도 서버로 보내지도 않는다. 엔진이 다시 뜰 때마다 묻는다. 잊으면 키를 모두 지우고 다시 넣는다. 끄면 자동 잠금으로 돌아간다. 어느 방식이든 키는 서버로 가지 않는다.
- **패스키(WebAuthn PRF)는 다음 단계로 미룬다.** 패스키는 rpId가 출처에 묶여서 출처를 옮기면 쓸 수 없다. PRF 지원은 브라우저마다 다르고 e2e로 시험할 수 있는지도 확인하지 않았다. 호스트 이름과 자기 도메인 이전 시점이 정해진 뒤에 한다. 그때를 위해 보관 형식에는 **잠금 방식 칸**을 둔다.
- **자동 잠금이 막는 것과 막지 못하는 것.** 자동 잠금은 평문이 저장소와 로그로 새는 것을 막는다. 꺼낼 수 없는 키라서 암호문만 복사해 다른 곳에서 푸는 것도 막는다. 그러나 같은 출처의 스크립트는 그 키를 써서 풀 수 있고, 브라우저 프로필 전체를 읽는 사람도 마찬가지다. 비밀번호는 잠긴 동안 그 두 경우를 막는다. 다만 비밀번호로 바꾼 뒤에도 브라우저 저장소에 옛 키·암호문 조각이 남을 수 있다(받아들일 한계). 그래서 화면은 자동 잠금을 "잠금"이라고 과장하지 않는다.
- **키 목록 규칙은 [ADR 0037](0037-kiwoom-keys-are-a-list-with-one-market-key.md)(`0037-kiwoom-keys-are-a-list-with-one-market-key.md`) 그대로다.** 키는 최대 5개이고, 별칭은 1~20자이며, 같은 앱키는 한 번만 받는다. 키 ID는 `k1`부터 매기고 다시 쓰지 않는다. 시세 키는 하나이고 기본은 첫 줄이다. 브라우저에 환경 키는 없다. 번호 0037의 파일이 둘이라 파일 이름으로 적는다.
- **CSP와 보안 헤더.** 공개 리스너는 엄격한 CSP를 낸다: `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self' https://api.kiwoom.com wss://api.kiwoom.com:10000; worker-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'`. 함께 `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Cross-Origin-Opener-Policy: same-origin`을 낸다. 정책 문장은 `crates/server/src/public/csp.txt` 하나에 두고 서버와 e2e가 같이 읽는다. 자동 잠금 키를 쓰거나 풀린 키를 읽는 길은 화면에 끼어든 스크립트이므로 그것을 막는 것이 첫 방어다. `style-src`가 부족하면 `'unsafe-inline'`만 더하고 그 사실을 보고한다. `script-src`는 넓히지 않는다.
- **시크릿을 화면 모듈에 주지 않는다.** 화면 코드가 받는 값은 별칭, 가린 앱키, 상태뿐이다. 시크릿을 꺼내는 함수는 엔진용 모듈 하나에만 두고, 화면 모듈이 그 모듈을 import하지 않는다는 것을 시험으로 확인한다.
- **첫 단계의 키 화면은 저장만 한다.** 키를 쓰는 곳이 없는 단계에 주문 가능한 키를 받으므로, 화면에 "이번 단계는 저장만 합니다. 키를 쓰는 기능은 다음 단계에 나옵니다"라는 안내를 붙인다. 기능을 숨기는 플래그는 두지 않는다. 엔진 단계 전에 저장 형식과 화면을 실제로 써 보게 하기 위해서다.

### 엔진 방향

- **`kiwoom-core`를 WASM으로 쓴다.** 키움 규칙(실시간 해석, 계좌·주문 TR, 오류 분류, 발급 판단)은 Rust 코어(`kiwoom-core`)로 모으고 `kiwoom-wasm`으로 브라우저가 쓴다. 규칙을 TypeScript로 다시 짜지 않으므로 서버와 브라우저가 어긋나지 않는다. 체결·호가 집계(`domain`)도 WASM으로 쓴다.
- **연결은 SharedWorker 하나가 키별로 맡는다.** 토큰 하나에 WebSocket 세션은 하나이고, 같은 키로 탭이 여럿이면 서로의 세션을 끊는다([ADR 0004](0004-dedicated-kiwoom-app-key.md)). 그래서 한 브라우저 안에서는 SharedWorker가 연결을 쥐고 탭들이 나눠 쓴다. 키마다 Web Locks로 한 곳만 토큰을 발급하게 한다. 발급 기록과 키별 대기열은 IndexedDB에 둔다. 키 규칙(발급 간격, 8050 차단, 시세 키)은 ADR 0037대로 키마다 지키고, 지키는 주체가 서버 프로세스에서 브라우저로 바뀐다.
- **배포 사이에는 물러난다.** 새 화면 빌드가 배포되면 옛 빌드의 SharedWorker와 새 빌드의 탭이 같은 키를 두고 다툴 수 있다. 연결을 쥔 쪽이 새 빌드에 자리를 내주고 물러나는 절차를 둔다.
- **대표 탭 대체.** SharedWorker를 쓸 수 없는 환경은 대표 탭 방식으로 대체한다.
- **방향의 순서.** 엔진(코어, WASM, Worker, Web Locks, 발급 기록) → 브라우저 실시간(체결·호가 WebSocket, 구독 관리, `/api/ws`와 같은 `ServerMessage`, 숨긴 탭 시험, 실시간 알림) → 브라우저 계좌·주문(계좌·주문 TR, 주문 사용 스위치, 주문 명령 기록, 계좌 실시간 `00`·`04`, [ADR 0029](0029-order-window-sends-cash-limit-orders.md)를 따른다). 이 일은 다중 증권사 플랜의 `market-port-stream`과 `kis-orders`가 병합된 뒤에 한다. 둘이 `crates/server/src/kiwoom/`, `trading/`, `market/`을 다시 짜고 있기 때문이다. 속도는 시제품으로 확인했다. 체결 한 건의 처리는 4~11µs이고 화면 병목은 그리기였다(ADR 0038의 속도 확인).

## Considered Options

- **암호화 없이 저장**: 평문 앱키·시크릿이 브라우저 저장소 내보내기, 개발자 도구, 로그에 그대로 남는다. 자동 잠금은 사용자 입력이 없으므로 비용 없이 평문을 없앤다.
- **비밀번호를 기본으로**: 엔진이 다시 뜰 때마다 비밀번호를 물어야 하고, 잊으면 키를 모두 지워야 한다. 사용자가 정한 기본은 입력이 없는 자동 잠금이다. 더 강하게 지키려는 사용자만 고른다.
- **TypeScript로 새로 짜기**: 서버의 Rust 코드와 규칙이 두 곳에 생겨 어긋난다. 오류 분류, 발급 판단, 실시간 해석을 다시 검증해야 한다. 속도 확인에서 JS로 옮겨서 생기는 속도 문제는 보이지 않았다.
- **대표 탭만 쓰기**: 탭이 닫히거나 숨어서 타이머가 늦춰지면 대표를 다시 뽑는 사이 연결이 끊긴다. SharedWorker는 탭의 수명과 떨어져 있어 연결이 끊기지 않으므로 기본으로 두고, 대표 탭은 대체로만 둔다.

## Consequences

- 키를 브라우저에 두므로 화면에 끼어든 스크립트(XSS)가 키를 읽을 수 있다. 엄격한 CSP가 첫 방어이고, 외부 스크립트를 쓰지 않는다.
- 호스트 이름이나 출처를 바꾸면 IndexedDB 키 보관소가 비므로 사용자가 키를 다시 넣어야 한다. 패스키를 미루는 이유도 같다.
- 같은 키를 여러 기기에서 쓰는 문제와 휴대폰 지원은 풀리지 않는다. 키움 키는 IP를 등록해야 하므로 IP가 자주 바뀌는 휴대폰에서는 쓰기 어렵다.
- 브라우저는 숨긴 탭의 타이머를 늦춘다. 탭이 열려 있지 않으면 사용자 실시간 알림이 오지 않는다.
- 한투 키는 [ADR 0039](0039-kis-key-and-token-are-vally-only.md)대로 서버의 키이고 이 ADR의 범위가 아니다.
- 키 화면은 이번 단계에서 저장만 한다. 키를 쓰는 기능이 나오기 전까지 사용자가 받는 이득은 없다.

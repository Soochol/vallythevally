# 서버는 켜질 때 키움을 부르지 않고, 사용자가 시스템 설정에서 누를 때만 연결한다

2026-11-18 [ADR 0027](0027-kiwoom-connects-by-itself-when-a-key-is-present.md)이 "연결은 수동뿐"을 바꿨다. 아래는 기록이다.

서버는 켜질 때 키움에 아무것도 보내지 않는다. 토큰 발급, 종목 목록(ka10099), WebSocket 접속, 스크리너 시작 갱신, 20:05 토큰 재발급, 07:45 종목 목록 갱신이 모두 여기에 든다. 이 동작은 **연결됨** 상태에서만 돈다. 연결 안 함 상태에서는 타이머가 건너뛴다. 키가 없어도 서버는 켜진다. 사용자가 정했다(2026-11-16). 2026-11-09에 8050을 겪었고, 서버를 켤 때마다 발급이 나가는 구조였으며, 화면은 "고친 뒤 서버를 다시 켜야 합니다"만 보였다. 서버를 다시 켜는 일은 키움에 아무 보호도 주지 않는다.

- **연결은 사용자가 시스템 설정에서 누르는 한 번의 동작이다.** 한 번에 발급은 최대 1회다. 서버가 단일 작업(single-flight)으로 처리하므로 단추를 연타하거나 탭 둘이 눌러도 발급 요청은 하나다. 서버는 순서대로 판단한다.
  1. 키가 없으면 거절한다. 키움 호출은 없다.
  2. 8050 인증 차단 상태이고 사용자의 확인 체크 두 칸이 없으면 거절한다. 8050이 아닌 인증 차단은 새 키를 저장하기 전까지 거절한다.
  3. 토큰 파일에 같은 앱키의 유효한 토큰이 있으면 발급 0회다. 그 토큰을 쓴다(ADR 0004 "재시작은 발급이 아니다").
  4. 마지막 발급 요청에서 발급 간격(10분)이 지나지 않았으면 발급 0회다. 대기 상태와 다시 시도할 수 있는 시각을 돌려준다.
  5. 위를 모두 넘으면 발급 1회다. 성공하면 종목 목록, 실시간 순으로 잇는다. 스크리너는 `VALLY_SCREENER_UPDATE_ON_START`가 켜져 있으면 뒤처졌을 때만 한 번 갱신한다.
  6. 실패하면 ADR 0009의 정책 표가 정한다. 연결 단추가 정책을 우회하는 길은 없다.
- **연결 끊기는 토큰을 지우지 않는다.** 실시간을 닫고 새 조회를 받지 않는 연결 안 함 상태로 돌아간다. 토큰은 파일에 남고, 다음 연결은 그 토큰이 유효하면 발급하지 않는다. 끊기와 다시 연결이 발급을 늘리지 않는다.
- **키움에 닿지 못한 발급 시도도 발급 간격을 쓴다.** 요청을 보내기 전에 시각을 기록하는 지금 방식을 유지한다. 화면은 이때 "다시 시도" 대신 발급 간격 대기를 보인다. 키움의 반복 발급 잠금 규칙을 저장소가 모르므로 간격을 줄이지 않는다.
- **키 입력 경로**: 환경(`.env` 또는 프로세스 환경)의 `VALLY_KIWOOM_APP_KEY`·`VALLY_KIWOOM_APP_SECRET`이 화면 저장 파일보다 앞선다. 환경에 있으면 화면은 출처와 가린 값만 보이고 편집을 막는다. 화면에서 저장한 키는 저장소 밖 키 파일에 둔다. 위치는 `$XDG_STATE_HOME/vallythevally/kiwoom-key.json`이고 `VALLY_KIWOOM_KEY_PATH`로 바꾼다. 디렉터리 700, 파일 600이며 둘 중 하나라도 열려 있으면 읽지도 쓰지도 않는다. 서버는 키와 시크릿을 어떤 응답이나 로그에도 되돌려 주지 않는다.
- **8050 뒤 풀기**: 서버를 다시 켜지 않는다. 사용자가 "포털에 지금 공인 IP를 등록했습니다"와 "반복 발급 잠금이 풀렸는지 확인했습니다" 두 칸을 확인하고 발급 간격이 지나면 화면에서 다시 연결한다. 8050은 키가 아니라 IP나 발급 잠금 문제라서 키를 바꿔도 이 확인이 있어야 풀린다.
- **8050이 아닌 인증 차단**(8001·8002 등)은 새 키를 저장하면 풀린다. 코드별 뜻의 근거가 저장소에 없으므로 문구는 "앱키·시크릿을 확인하세요" 하나다. 풀린 뒤에도 발급 간격은 지킨다.
- **연결 전 조회**는 서버가 사유 `not_connected`로 바로 답한다(ADR 0009).

## Considered Options

아래는 검토했지만 **고르지 않은 안**이다. 다시 꺼내려면 새 ADR로 이 결정을 바꾼다.

- **서버를 다시 켜야 8050이 풀린다**(현행): 서버를 끄고 켜는 일은 사용자가 터미널에서 해야 하고 키움에 보호를 주지 않는다. 서버를 켜자마자 발급이 나가므로 재시작이 곧 재시도였다. 확인 체크 두 칸과 발급 간격이 더 강한 보호다.
- **연속 8050이 N회면 24시간 단추 잠금**: 계정 잠금이 길어질 위험에는 맞다. 하지만 키움의 잠금 규칙을 저장소가 모르고, 근거 없는 상한은 정상 사용자를 막는다.
- **서버 시작 때 자동 연결하는 스위치**(대기가 끝나면 자동으로 한 번 연결하는 체크 포함): 번거로움은 줄지만 서버를 켤 때마다 발급이 나가는 문제가 되살아난다. 토큰이 있을 때만 켜게 하는 조건도 만료되면 깨진다. 연결은 수동뿐이다.
- **키를 SQLite나 OS 키체인에 저장**: SQLite(ADR 0006)는 작업 폴더에 있고 권한이 umask를 따라, 백업을 파일 복사로 하면 키가 같이 복사된다. 키체인은 서버가 클라우드나 헤드리스로 갈 때 깨지고 의존성이 는다. 토큰 파일과 같은 별도 파일이 이미 ADR 0004에서 인정된 수준이다.
- **화면 저장값이 환경보다 앞서기**: 편하지만 `.env`를 고쳤는데 안 먹는 혼란이 생긴다. 자동화와 시험 환경(루프백 가짜 키움)이 화면 저장값에 흔들리게 된다.

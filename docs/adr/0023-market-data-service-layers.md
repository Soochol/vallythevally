# 시세 서비스는 수집 계층·정규화 이벤트·API 서버로 나누고, 시세 원천은 어댑터로 바꿔 끼운다

vallythevally를 여러 사용자가 로그인해 쓰는 시세 서비스로 키운다. 사용자가 정했다(2026-11-17). 틱·호가·프로그램매매·거래원을 전 종목에서 받아 저장하고, API 서버가 이를 읽어 기능으로 만들고 클라이언트에 필요한 만큼 보낸다. 이 ADR은 ADR 0001(운영자 한 명만 쓰는 도구)을 대체한다.

## 결정

- **세 계층으로 나눈다.**
  - **수집 계층**(`crates/collector`를 키운다): 감독자가 키마다 세션 하나를 띄우고, 종목을 키마다 200개 이하로 나눈다. 세션이 죽으면 다시 띄우고, 한 키가 8050이면 그 키만 멈추고 종목을 남은 키로 옮긴다. 키마다 토큰 파일·잠금·발급 간격을 따로 둔다(ADR 0004·0009 규칙을 키 단위로). 원문 파일은 지금처럼 남긴다(ADR 0022).
  - **정규화 이벤트**: 원천과 상관없는 공통 형식이다. `Trade`(틱), `Book`(10단계), `Program`, `Broker`이고 수신 시각·거래소(KRX·NXT)·원천을 가진다. 이 경계 뒤의 코드는 원천을 모른다.
  - **API 서버**(`crates/server`를 키운다): 로그인과 권한, 지난 데이터 REST, 장중 WS 구독을 맡는다. 클라이언트에는 구독한 종목의 필요한 부분만 보내고 원문을 통째로 넘기지 않는다.
- **시세 원천은 어댑터 하나로 바꿔 끼운다.** 수집 세션은 원천 어댑터가 낸 정규화 이벤트만 다룬다. 지금 어댑터는 키움 하나다.
- **저장은 네 층이다.**

  | 층 | 용도 | 형태 |
  |---|---|---|
  | 원문 보관 | 재처리, 대조 | 원문 파일(zstd) |
  | 분석 저장소 | API 서버의 질의 | 날짜·종목 파티션. 처음은 DuckDB, 커지면 Parquet |
  | 복기 구간 | 호가창 재생 | 구간 파일(`hoga-format`) |
  | 장중 메모리 | 실시간 기능 | 종목별 링 버퍼 |

- **수집 계층과 API 서버는 다른 프로세스다.** 장중 이벤트는 수집 계층에서 API 서버로 스트림 하나로 흐른다. 처음은 루프백 소켓, 노드가 갈리면 메시지 버스로 바꾼다. API 서버를 다시 켜도 수집은 끊기지 않는다.
- **사용자는 키움 키를 넣지 않는다.** 시세는 서비스가 받는다. ADR 0021의 키 입력 칸은 운영자용으로 남는다.
- **다른 사용자에게 시세를 보내는 것은 출시 관문을 지난 뒤다.** 키움 오픈 API 이용약관(2026-06-01 개정) 제5조③은 시세를 "고객이 직접 사용할 목적"에 한하고 제3자 제공을 금지한다. 실시간과 지연을 가리지 않고, 수집·가공한 시세도 같다. 그래서 키움 어댑터로 받은 시세는 운영자만 본다. 다른 사용자에게 여는 것은 정식 계약 원천(코스콤 정보이용계약 [옵션 3] 웹사이트 체결가서비스용 등, KRX 승인 필요)의 어댑터로 바꾼 뒤이고, 거래원·프로그램매매가 그 계약 범위에 드는지도 그때 확인한다. 원문: https://download.kiwoom.com/deploy/AG001/pdf/AG001_110_20260601.pdf (2026-11-08 확인)
- **출시 관문 전의 접근 경계는 지금 그대로다.**
  - 서버는 로컬에서 `127.0.0.1`, 클라우드에서는 사설망(VPN) 주소에만 묶인다. 공인 주소면 시작하지 않는다.
  - 로그인이 생기기 전까지 키를 받는 쓰기 API(`/api/system/*`)는 `Content-Type: application/json`만 받고, `Host`가 `127.0.0.1`·`localhost`·`[::1]`의 이 서버 포트가 아니면 거절하며, `Origin`이 있으면 같은 출처여야 한다(ADR 0021). 다른 사이트의 요청과 DNS 리바인딩을 막는다.
  - 공인 IP 확인은 사용자가 단추를 누를 때만 외부 서비스를 한 번 부른다.
- **키는 운영자 명의로 늘린다.** 다른 사람 명의의 키를 받아 쓰는 것은 제5조②(앱키 위임 금지)에 걸릴 소지가 있다. 키마다 공인 IP를 등록해야 하므로 수집 노드의 IP를 고정한다. 전 종목(약 4,000)은 키 약 20개다.

## 단계

| 단계 | 내용 | 원천 | 보는 사람 |
|---|---|---|---|
| P0 | 여러 키 수집 계층(지금 있는 키 5개, 약 1,000종목), 정규화 이벤트, 분석 저장소 | 키움 | 운영자 |
| P1 | API 서버가 분석 저장소를 읽는 기능 하나(프로그램·거래원 흐름), 장중 스트림 | 키움 | 운영자 |
| P2 | 로그인, 여러 사용자 자료 저장소, 종목 구독, 호가 복기 창 | 키움 | 운영자 |
| 출시 | 계약 원천 어댑터, 공개 주소 | 계약 원천 | 사용자 |

각 단계에서 범위가 바뀌는 ADR(0003·0004·0006·0022)은 그 단계에서 새 ADR로 고친다.

## Considered Options

아래는 검토했지만 **고르지 않은 안**이다. 다시 꺼내려면 새 ADR로 이 결정을 바꾼다.

- **운영자 한 명만 쓰는 도구로 남기기(ADR 0001)**: 약관 위험이 없다. 사용자는 서비스로 키우기로 정했다.
- **각자 자기 PC에 자기 인스턴스를 띄우기(셀프 호스팅)**: 각자 자기 키와 IP를 쓴다. 전 종목 수집과 그 데이터로 만든 기능을 사용자마다 다시 해야 한다.
- **우리 서버에 사용자 키를 보관**: 제5조②에 걸릴 소지가 있고, 서버가 털리면 모든 사용자의 주문 가능한 키가 새어 나간다.
- **키는 브라우저에만, 브라우저가 키움을 직접 부름**: 키움 REST는 `Access-Control-Allow-Origin: *`이고 WebSocket도 다른 출처를 받는다(2026-11-10 확인). 다만 캐시와 실시간을 브라우저로 옮겨야 하고 휴대폰은 IP 등록 때문에 어렵다.
- **키는 사용자 PC의 커넥터, 화면과 사용자 자료는 우리 서버**: 약관과 보안 위험은 낮다. 배포물이 둘이 되고 Private Network Access와 휴대폰 문제가 남는다. [계정 로그인 플랜](../plans/multi-user-oauth.md)이 이 안이다.
- **수집기를 API 서버 하위 프로세스로**: 장애는 나뉘지만 수명이 묶여 서버를 다시 켤 때 수집이 끊긴다.
- **키움 어댑터로 받은 시세를 출시 전에 다른 사용자에게 보내기**: 제5조③에 걸린다.

## Consequences

- ADR 0001을 지운다. 그 ADR을 근거로 든 곳은 이 ADR을 가리킨다.
- 수집 계층과 API 서버가 두 배포물이 되고, 키 수만큼 IP 등록과 토큰 관리가 는다.
- 출시 관문까지 다른 사용자는 시세를 받지 않는다. 그동안 로그인·구독·화면은 운영자 계정으로 만들고 시험한다.
- [계정 로그인 플랜](../plans/multi-user-oauth.md)은 사용자 PC에서 각자 시세를 받는 전제로 쓰였다. 이 ADR의 방향과 다르므로 P2에서 다시 정한다.

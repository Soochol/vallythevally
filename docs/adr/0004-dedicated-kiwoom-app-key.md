# 키움 실계좌 앱키 하나를 전용으로 쓰고, 그 토큰은 언제나 한 프로세스만 갖는다

키움 접근토큰을 다시 발급받으면 기존 토큰이 폐기될 수 있다(FAQ25). 또 토큰 하나에 WebSocket 세션은 하나뿐이다(공지 49). 그래서 같은 키로 두 곳에서 토큰을 받으면 서로의 실시간 연결을 끊는다.

- **키는 하나**: vallythevally는 실계좌 앱키 하나(`VALLY_KIWOOM_APP_KEY`, `VALLY_KIWOOM_APP_SECRET`, `VALLY_ENV_FILE`이 가리키는 파일. 로컬에서는 메인 체크아웃 루트의 `.env`)만 쓴다. 모의투자 키는 쓰지 않는다.
  - 이 키는 원래 hoga-ops의 `KIWOOM_APP_KEY_6`이었다. 2026-11-08에 옮겼고, hoga-ops `.env`에서는 주석 처리했다.
  - 다른 어떤 프로그램과도 공유하지 않는다.
- **토큰을 가진 프로세스는 언제나 하나**
  - 서버가 생기기 전에는 키움 실측 프로그램이, 생긴 뒤에는 서버가 그 하나다.
  - 둘을 동시에 돌리지 않는다.
  - 서버는 잠금 파일(`flock`)을 잡아 같은 PC에서 하나만 뜨게 한다. 잠금을 못 잡으면 바로 종료한다. 클라우드로 옮길 때(#9)는 로컬 서버를 끄는 것을 운영 절차로 지킨다.
  - 키움 실측 프로그램도 같은 잠금 파일을 잡는다. 그래서 실측 프로그램과 서버가 동시에 토큰을 쓰는 일이 구조적으로 생기지 않는다.
  - 여러 에이전트가 일할 때도 키움에 접속하는 에이전트는 하나로 정한다.
- **시세 API만 호출한다**
  - 실계좌 키는 주문도 넣을 수 있는 키다.
  - 그래서 키움 클라이언트는 시세용 API만 허용 목록으로 갖는다. 토큰 발급(au10001), 차트·종목정보 조회, 실시간 시세가 여기에 든다.
  - 주문(`/api/dostk/ordr`)과 계좌(`/api/dostk/acnt`) API는 코드에 넣지 않는다.
- **토큰은 파일에 두고 다시 쓴다**(2026-11-10 개정)
  - 받은 토큰은 만료 시각(`expires_dt`), 발급 시각과 함께 **저장소 밖 파일**에 둔다. 위치는 `$XDG_STATE_HOME/vallythevally/token.json`이고, 기본은 `~/.local/state/vallythevally/token.json`이다. 파일 권한은 600, 디렉터리 권한은 700이다. 둘 중 하나라도 다른 사용자에게 열려 있으면 읽지도 쓰지도 않는다.
  - 파일에는 토큰을 받은 앱키의 해시를 함께 둔다. 앱키가 바뀌면 그 토큰은 쓰지 않는다. 마지막 발급 요청 시각은 앱키와 상관없이 따른다.
  - 발급 요청 시각을 파일에 쓰지 못하면 발급 요청을 보내지 않는다. 파일이 있는데 읽지 못하면 조회와 발급을 멈춘다. 마지막 발급 요청 시각을 모르기 때문이다.
  - 서버와 키움 실측 프로그램이 같은 파일을 쓴다. 잠금 파일을 쥔 프로세스만 읽고 쓴다.
  - 서버를 다시 켜도 파일의 토큰이 유효하면 그대로 쓴다. **재시작은 발급이 아니다.**
- **발급은 이때만 한다**
  - 파일에 유효한 토큰이 없을 때
  - 매일 장이 끝난 뒤(20:05). 토큰은 24시간 유효하므로 이렇게 하면 만료가 장중에 오지 않는다.
  - 키움이 토큰 무효(8005)라고 답할 때
  - 만료 10분 전(안전장치)
- **발급 사이 최소 10분**: 마지막 발급 시각을 파일에 남긴다. 재시작해도 10분이 지나기 전에는 다시 발급하지 않는다.
- **8050(지정단말기)이면 즉시 멈춘다**
  - 모든 재시도와 발급을 멈춘다. 로그와 화면에 원인과 조치를 보인다: IP 미등록이면 키움 포털에 지금 공인 IP를 등록하고, 반복 발급 잠금이면 해제를 확인한다.
  - 사람이 원인을 고치고 서버를 다시 켜야 다시 시도한다.
  - 2026-11-09에 IP 미등록으로 8050을 실제로 겪었다.
- **비밀값은 출력하지 않는다**: 앱키, 시크릿, 토큰을 로그나 문서, 대화에 내보내지 않는다.

## Considered Options

- **토큰을 메모리에만 두기**(2026-11-10 이전 규칙, decisions-r1 D11): 비밀값이 디스크에 남지 않는다. 하지만 재시작할 때마다 발급하게 된다. 일꾼들이 검증하며 서버를 자주 켜고 끄는 환경에서는 발급이 재시작 횟수만큼 늘었다. hoga-ops에는 반복 발급이 계정 단위 8050 잠금을 일으킨 전례가 있다. 그래서 파일 보관으로 바꿨다. 파일은 `.env`와 같은 수준(저장소 밖, 권한 600)으로 다룬다.

- **모의 키로 실측·개발하고 실계좌 키는 운영에만 쓰기**(이 ADR의 첫 버전): 키 두 개를 관리해야 한다. 모의 키는 조회가 초당 1회라 느리다. 로컬에서 혼자 쓰는 동안에는 얻는 것이 적어서 바꿨다.

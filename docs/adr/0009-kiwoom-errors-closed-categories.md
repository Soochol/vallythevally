# 키움 오류는 경계에서 닫힌 범주로 바꾸고, 정책 표 하나로 대응한다

키움 REST와 WebSocket의 응답은 **경계에서 한 번만** 파싱해 닫힌 범주로 바꾼다. 재시도, 물러서기, 중단, 토큰 재발급, 브라우저 표시 같은 대응은 **정책 표 하나**에서만 나온다. 판정은 `return_msg`의 **상세 코드 `[NNNN]`를 먼저** 보고, HTTP 상태와 `return_code`는 보조 정보로 보존한다. 설계 근거와 전체 표는 `docs/design/kiwoom-errors-proposal.md`에 있다.

## 범주와 정책
- **한도 초과**(1700 등): 공유 대기열 전체를 물러서게 한다.
- **토큰 무효**(8005): 시세 조회에서 받으면 한 번 다시 발급하고 그 요청을 한 번 다시 보낸다. 새 토큰으로 보낸 요청도 8005면 **전체 멈춤**이다. 자동 재발급은 **8005에서만** 한다. 8031·8103으로는 넓히지 않는다. 발급 요청이 8005를 받으면 인증 불확실의 발급 단계 정책을 따른다.
- **인증 차단**(8050 등): 즉시 키움 요청과 발급을 모두 멈춘다. 서버를 다시 켜서 풀지 않는다(2026-11-16 개정, ADR 0021). 8050은 사용자가 확인 체크 두 칸을 하고 발급 간격이 지난 뒤 화면에서 다시 연결해야 풀린다. 8050이 아닌 인증 차단은 새 키를 저장하면 풀린다. 어느 쪽이든 발급 간격은 지킨다. (2026-11-18 개정, ADR 0027) 인증 차단은 토큰 파일에 남아 서버를 다시 켜도 이어진다. 8050은 키와 상관없이, 그 밖의 인증 차단은 같은 앱키일 때 복원한다.
- **인증 불확실**(8003·8006·8009 등 모호한 인증 실패): 즉시 반복하지 않는다. 단계마다 다르게 멈춘다.
  - 시세 단계: 조회 전체의 **관문**을 10분 닫는다. 10분이 지난 뒤 들어온 요청 하나만 **확인 요청**으로 나간다. 타이머가 스스로 확인 요청을 보내지는 않는다. 확인 요청도 인증 불확실이면 전체 멈춤이다.
  - 발급 단계: 다시 발급하지 않는다. 발급 간격(10분)이 지난 뒤 다음 발급을 한 번만 허용하고, 또 실패하면 발급 경로를 **경로 멈춤**으로 둔다.
- **업무 거절**(`[2000]`, 2026-11-19 개정): 키움 계좌 업무 시스템의 거절을 감싸는 공통 바깥 코드다. 실제 사유는 `[2000](571489:…)`처럼 괄호 안 6자리로 온다. 조회 단계는 재시도도 정지도 없이 그 요청만 실패하고 브라우저에는 사유 `business_rejected`, `manualActionRequired`는 false다. 발급 단계는 경로 멈춤이다. 주문 쓰기(kt10000~3)에서는 확정 거절이다. 안쪽 6자리 사유는 숫자로만 남기고(실패 증거와 `키움 조회` 로그) 원문은 담지 않는다. 알려진 사유(571489 장이 열리지 않는 날, 571455 매도할 잔고 부족 등)에는 우리가 쓴 고정 문구를 붙여 화면과 로그에만 보인다. 정책은 사유와 상관없이 같다. 표에 없는 6자리도 숫자로 남기고 업무 거절로 다룬다.
- **알 수 없음**: 그 경로만 멈춘다(경로 멈춤). REST면 그 API 경로, 실시간 제어면 실시간, 토큰과 로그인이면 인증 경로다. 자동으로 반복하지 않는다. 운영자가 원인을 고치고 서버를 다시 켜면 풀리고, 브라우저에는 `manualActionRequired`로 알린다. 처음부터 전체 멈춤인 것은 알려진 인증 차단뿐이다.
- **1999**: 키움 쪽 일시 장애로 잠정 분류한다. 조회에만 제한된 재시도를 허용하고, 토큰 발급에는 적용하지 않는다.
- **실시간 등록 한도·제어 거절**: 같은 입력으로 다시 접속하지 않는다. 등록 집합을 다시 계산하고, 상태가 불명확할 때만 한 번 다시 구성한다. 그래도 반복되면 실시간만 멈춘다.
- **반복 예산**: 요청 하나의 총 전송은 화면 요청 4회, 나머지 6회로 제한한다. 한도 초과와 일시 장애가 반복되면 30초 동안 관문을 닫는다. 관문은 조회 전체가 함께 쓰는 하나이고, 경로마다 따로 두지 않는다. 시각이 지나면 확인 요청 하나만 내보낸다. 확인이 3회 실패하면 간격을 5분으로 늘린다. 바깥 타이머도 같은 관문을 지난다.
- **브라우저**: `ApiError` 코드는 그대로 둔다. 사유(`reason`), 재개 시각(`retryAt`), 사람 조치 필요 여부(`manualActionRequired`)를 더한다. 키움에 연결하기 전의 조회는 서버가 사유 `not_connected`로 바로 답한다(2026-11-16, ADR 0021). 프런트는 키움 숫자 코드를 다시 판정하지 않는다.
- **목록**: 공식 REST 37개와 실측 추가분을 명시 목록으로 삼는다. 목록에 없는 코드는 "알 수 없음" 정책으로 처리한다. WebSocket 오류는 공식 전체표가 공개돼 있지 않아 따로 조사해 늘린다.

## Considered Options

아래는 검토했지만 **고르지 않은 안**이다. 다시 꺼내려면 새 ADR로 이 결정을 바꾼다.

- **오류를 만날 때마다 그 자리에서 처리**(지금까지): 처리가 흩어져서 빈틈이 생겼다. au10001이 HTTP 403과 `[8050]`을 주면 판정이 HTTP 200일 때만 멈춰서, 11초에 토큰을 8번 발급했다.
- **숫자 범위로 묶기**(예: 8000번대는 모두 인증 차단): 공식 의미가 서로 다른 코드를 뭉갠다. 그래서 명시 표로 바꿨다.
- **HTTP 상태를 먼저 보기**: 같은 상세 코드가 여러 HTTP 상태로 온다. 그래서 상세 코드를 먼저 본다.

# 키움 오류는 경계에서 닫힌 범주로 바꾸고, 정책 표 하나로 대응한다

키움 REST와 WebSocket의 응답은 **경계에서 한 번만** 파싱해 닫힌 범주로 바꾼다. 재시도, 물러서기, 중단, 토큰 재발급, 브라우저 표시 같은 대응은 **정책 표 하나**에서만 나온다. 판정은 `return_msg`의 **상세 코드 `[NNNN]`를 먼저** 보고, HTTP 상태와 `return_code`는 보조 정보로 보존한다. 설계 근거와 전체 표는 `docs/design/kiwoom-errors-proposal.md`에 있다.

## 범주와 정책
- **한도 초과**(1700 등): 공유 대기열 전체를 물러서게 한다.
- **토큰 무효**(8005): 한 번 다시 발급한다. 자동 재발급은 **8005에서만** 한다. 8031·8103으로는 넓히지 않는다.
- **인증 차단**(8050 등): 즉시 키움 요청과 발급을 모두 멈춘다. 사람이 원인을 고치고 서버를 다시 켜야 풀린다.
- **인증 불확실**(8003·8006·8009 등 모호한 인증 실패): 즉시 반복하지 않는다. 10분 뒤 한 번만 확인하고, 다시 실패하면 사람이 재개한다.
- **알 수 없음**: 그 경로만 멈춘다. REST면 그 API 경로, 실시간 제어면 실시간, 토큰과 로그인이면 인증 경로다. 사람이 재개할 때까지 자동으로 반복하지 않는다. 서버 전체를 멈추는 것은 알려진 인증 차단뿐이다.
- **1999**: 키움 쪽 일시 장애로 잠정 분류한다. 조회에만 제한된 재시도를 허용하고, 토큰 발급에는 적용하지 않는다.
- **실시간 등록 한도·제어 거절**: 같은 입력으로 다시 접속하지 않는다. 등록 집합을 다시 계산하고, 상태가 불명확할 때만 한 번 다시 구성한다. 그래도 반복되면 실시간만 멈춘다.
- **반복 예산**: 요청 하나의 총 전송은 화면 요청 4회, 나머지 6회로 제한한다. 한도 초과와 일시 장애가 반복되면 30초 공유 관문으로 확인 요청 하나만 내보낸다. 확인이 3회 실패하면 간격을 5분으로 늘린다. 바깥 타이머도 같은 관문을 지난다.
- **브라우저**: `ApiError` 코드는 그대로 둔다. 사유(`reason`), 재개 시각(`retryAt`), 사람 조치 필요 여부(`manualActionRequired`)를 더한다. 프런트는 키움 숫자 코드를 다시 판정하지 않는다.
- **목록**: 공식 REST 37개와 실측 추가분을 명시 목록으로 삼는다. 목록에 없는 코드는 "알 수 없음" 정책으로 처리한다. WebSocket 오류는 공식 전체표가 공개돼 있지 않아 따로 조사해 늘린다.

## Considered Options
- **오류를 만날 때마다 그 자리에서 처리**(지금까지): 처리가 흩어져서 빈틈이 생겼다. au10001이 HTTP 403과 `[8050]`을 주면 판정이 HTTP 200일 때만 멈춰서, 11초에 토큰을 8번 발급했다.
- **숫자 범위로 묶기**(예: 8000번대는 모두 인증 차단): 공식 의미가 서로 다른 코드를 뭉갠다. 그래서 명시 표로 바꿨다.
- **HTTP 상태를 먼저 보기**: 같은 상세 코드가 여러 HTTP 상태로 온다. 그래서 상세 코드를 먼저 본다.

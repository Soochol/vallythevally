# 사용자는 각자 계정으로 로그인하고, 시세는 각자 PC의 커넥터에서만 다룬다

2026-11-22 [ADR 0038](0038-user-kiwoom-keys-stay-in-the-browser-and-collection-runs-on-one-server.md)이 이 결정의 일부를 바꿨다. 사용자 키움 키와 사용자 키로 하는 일(내가 보는 종목의 실시간, 계좌 실시간, 토큰·계좌 조회·주문)은 커넥터가 아니라 각 사용자의 브라우저에 둔다. 순위·시장 개요·히트맵 같은 공용 자료는 운영 서버가 운영자 키로 만들어 모든 사용자에게 준다. 루프백 로그인 흐름과 커넥터 토큰은 새 로그인 ADR로 다시 정한다. IdP, 계정 식별, 셋업 범위는 그대로다.

여러 사용자가 각자 계정으로 로그인해 자기 셋업으로 쓴다. 사용자가 정했다(2026-11-17). 키움 키와 시세는 각 사용자 PC의 **커넥터**에만 두고, 셋업만 **계정 서버**에 계정별로 둔다. 로그인은 Google과 Naver OAuth만 지원한다. 비밀번호 로그인은 없다. 셋업의 저장과 동기화는 [ADR 0024](0024-setup-storage-and-sync.md)가 다룬다.

## 구조

- **커넥터**는 지금의 `vally-server`(`crates/server`)다. 사용자 PC에서 돈다. 키움 연결, 시세 캐시, 실시간, 스크리너 일봉 저장소, 재무자료, 화면 파일 서빙, 로컬 셋업 사본이 모두 여기에 있다. 새 바이너리를 만들지 않는다.
- **계정 서버**는 새 크레이트 `crates/account-server`(바이너리 `vally-account`)다. 공개 주소에서 받는다. 로그인, 커넥터 토큰, 계정별 셋업 저장만 맡는다.
- 브라우저는 커넥터가 서빙하는 `127.0.0.1` 화면만 상대한다. 계정 서버와는 커넥터가 이야기한다. 계정 서버 API는 커넥터만 부른다(서버 대 서버). CORS 헤더를 내지 않는다. 브라우저는 로그인 시작과 IdP callback에만 최상위 이동으로 계정 서버에 온다.
- 커넥터에 계정 서버 주소(`VALLY_ACCOUNT_SERVER_URL`)가 없으면 **로컬 전용 모드**다. 지금처럼 로그인 화면 없이 돈다. 주소가 있으면 로그인해야 화면을 쓴다.

## 시세는 사용자 PC에서만 다룬다

- 키움 키, 토큰, 시세 캐시, 실시간, 스크리너 일봉 저장소, 재무자료, 지표 계산은 커넥터에만 있다. 키를 계정 서버에 보관하지 않는다.
- 계정 서버는 시세를 거치거나 저장하지 않는다. 사용자 사이에 시세 캐시를 나누지 않는다.
- 이것을 의존성 그래프로 보이게 한다. `account-server`는 `server`·`collector`·`domain` 크레이트에 의존하지 않는다. 키움 코드와 DuckDB가 계정 서버 바이너리에 들어가지 않고, `cargo tree`로 확인할 수 있다. 계정 서버는 셋업 문서 본문을 해석하지 않고 문서 종류가 닫혀 있어서(ADR 0024) 시세를 받을 길도 구조로 없다.
- 드로잉 좌표의 가격과 관심종목의 종목 코드는 사용자가 만든 셋업이지 시세가 아니다. 그래서 계정 서버에 둘 수 있다. 시세 자체와 시세에서 계산한 값은 셋업에 들지 않는다.

## 로그인

- 지원하는 IdP는 Google과 Naver뿐이다. client secret과 callback은 계정 서버에만 둔다.
- **루프백 흐름**(RFC 8252). 커넥터가 `state`와 PKCE(S256) 쌍을 만들고 브라우저를 계정 서버의 시작 주소로 보낸다. 계정 서버는 IdP를 거쳐 돌아온 뒤 일회용 코드(60초, 한 번만, `code_challenge`에 묶음)를 만들어 `http://127.0.0.1:<포트>/auth/complete?code=…&state=…`로 보낸다. 커넥터는 `state`가 자기가 시작한 로그인인지 확인하고 `code_verifier`로 코드를 장기 토큰으로 바꾼다. `state` 확인이 남의 로그인 결과를 받는 일(로그인 CSRF)을 막고, PKCE가 다른 로컬 프로그램이 코드를 가로채도 쓰지 못하게 한다.
- 계정 서버는 돌아갈 주소의 호스트를 `127.0.0.1`로 고정하고 포트(1024~65535)만 받는다. 다른 호스트나 경로로는 보내지 않는다. 열린 리다이렉트를 구조로 막는다.
- 계정 서버는 시작 때 `__Host-` 쿠키에 난수를 두고 IdP callback에서 같은 브라우저인지 확인한다. 쿠키는 로그인 흐름에만 쓰고 세션 쿠키는 없다.
- Google은 authorization code 흐름에 scope `openid`만 쓴다. id_token은 토큰 엔드포인트에서 TLS로 직접 받으므로 서명 대신 `iss`·`aud`·`exp`·`nonce`를 확인하고 `sub`만 쓴다(OpenID Connect Core 3.1.3.7). Naver는 접근 토큰으로 회원 프로필 API를 한 번 불러 `response.id`만 쓴다. IdP의 접근 토큰은 저장하지 않는다.
- 계정은 `(provider, subject)`로 식별한다. 이메일로 계정을 자동 연결하지 않는다. 한 계정에는 identity가 하나이고, 같은 사람이 Google과 Naver로 따로 들어오면 다른 계정이다.
- **커넥터 토큰**은 32바이트 난수의 불투명 문자열이다. 계정 서버는 SHA-256 해시만 저장하므로 계정 서버 DB가 새도 토큰을 쓸 수 없다. 90일 동안 쓰지 않으면 만료하고, 로그아웃하면 폐기한다. 커넥터는 이 토큰을 저장소 밖 상태 파일(`$XDG_STATE_HOME/vallythevally/account.json`, `VALLY_ACCOUNT_STATE_PATH`로 바꿈)에 키 파일과 같은 `private_file` 규칙(디렉터리 700, 파일 600)으로 둔다.
- **계정 삭제**(`DELETE /v1/account`)가 있다. identity, 토큰, 셋업을 모두 지운다. 커넥터는 로컬 사본을 지우지 않고 소유 표시만 지운다. 로컬 사본은 사용자 PC의 자료다.
- **받아들인 한계(루프백)**: 같은 PC에서 도는 악성 프로그램이 자기 `state`와 `code_challenge`로 시작 주소를 만들어 사용자 브라우저로 열고, 자기 포트로 일회용 코드를 받을 수 있다. 계정 서버는 돌아갈 포트를 시작 요청에서 받으므로 이 요청을 커넥터의 것과 구별할 수 없다. 같은 사용자로 도는 프로그램은 상태 파일(`account.json`, 600)도 직접 읽을 수 있으므로 이 길이 새 능력을 주지 않는다. Google은 `prompt=select_account`로 계정 고르기 화면이 한 단계 더 보인다. 이 위협은 막지 않는다.
- 시험은 가짜 IdP를 주입한다. IdP 엔드포인트 주소를 설정으로 바꿀 수 있고, 시험은 루프백 가짜 IdP 서버를 띄워 실제 어댑터 코드를 그대로 돈다. 실제 Google·Naver·키움은 호출하지 않는다.

## Considered Options

아래는 검토했지만 **고르지 않은 안**이다. 다시 꺼내려면 새 ADR로 이 결정을 바꾼다.

- **(b) 우리 서버에 여러 사용자, 키를 서버에 보관**: 서버가 털리면 모든 사용자의 주문 가능한 키가 유출된다. 시세를 사용자별로 완전히 나눠야 해서 백엔드를 크게 바꿔야 한다.
- **(c) 키는 브라우저에만, 브라우저가 키움을 직접 부름**: 키움 REST와 WebSocket이 다른 출처를 받아 기술적으로는 가능하다(2026-11-10 확인). 다만 키움 연결, 캐시, 실시간을 브라우저로 옮겨야 하고, 휴대폰은 IP 등록 때문에 어렵고, 알림은 탭이 열려 있을 때만 된다.
- **브라우저가 계정 서버에 직접 로그인하는 세션 쿠키 방식**: 브라우저는 커넥터가 서빙하는 `127.0.0.1` 화면만 상대하므로 계정 서버의 세션이 필요 없다. 계정 서버가 CORS와 세션을 다뤄야 하고, 로그인 결과를 커넥터가 받을 길이 따로 필요해진다.
- **이메일로 계정 연결**: 같은 이메일이어도 IdP가 이메일 소유를 같은 수준으로 보증하지 않아 계정 탈취 길이 된다. 다른 provider를 붙이는 것은 로그인한 상태에서 명시적으로 하는 길뿐이고, 첫 구현에 필요하지 않다.
- **JWKS로 id_token 서명 검증**: 토큰 엔드포인트에서 TLS로 직접 받은 id_token은 TLS 서버 검증으로 서명 검증을 대신할 수 있다. 키 순환을 따라가는 JWKS 관리가 없어진다.
- **계정마다 로컬 DB를 따로 여는 방식**: 계정을 바꿀 때 실행 중에 DB를 바꿔 열어야 해서 복잡하다. 대신 로컬 사본은 한 계정의 것으로 두고 소유 계정을 적는다(ADR 0024).

## Consequences

- 배포물이 둘이 된다(커넥터, 계정 서버). 실제 배포(호스팅, 도메인, TLS, 백업, 설치본)는 이 결정 밖이다. 계정 서버를 띄우고 운영하는 절차는 [계정 서버 운영](../account-server-operations.md)에 있다.
- ADR 0004의 키 하나, ADR 0021의 연결 규칙, ADR 0022의 수집기는 그대로 유효하다.
- 브라우저가 로컬 커넥터에 접근하는 제약과 휴대폰에서 쓰기는 풀리지 않는다. 커넥터가 PC에서만 돈다.

# 사용자 자료는 SQLite 파일 하나에 둔다

관심종목, 레이아웃, 화면 상태, 드로잉, 알림과 울린 기록은 SQLite 파일 하나(`data/vally.db`, git 제외)에 둔다. 서버 프로세스 안에서 sqlx로 열고, 마이그레이션도 sqlx로 한다. WAL 모드를 쓴다.

이 자료의 성격은 다음과 같다.

- 사용자는 한 명이다(ADR 0001).
- 서버는 잠금 파일로 하나만 뜬다(ADR 0004).
- 양은 많아야 수 MB다.
- 쓰기는 자동 저장으로 1초에 한 번 정도다.

그래서 여러 프로세스가 동시에 쓰는 Postgres의 강점을 쓸 일이 없다. SQLite로 하면 따로 띄울 DB 서버(Docker, 포트, 볼륨)가 없어지고, 백업은 파일 복사로 끝난다.

## Considered Options

아래는 검토했지만 **고르지 않은 안**이다. 다시 꺼내려면 새 ADR로 이 결정을 바꾼다.

- **Postgres(Docker)**
  - 처음 계획이었다. 시세 캐시를 함께 둘 생각이었는데, 캐시는 메모리로 옮겼다(ADR 0003).
  - 남은 사용자 자료만 보면 별도 서버를 운영할 이유가 없다.
  - 여러 사람이 쓰거나 서버를 여러 대 띄우게 되면 다시 검토한다.
- **DuckDB**
  - 열 단위 분석용이라 작은 행을 자주 고치는 자동 저장에 맞지 않는다.
  - sqlx가 지원하지 않는다.
  - 미뤄 둔 종목 분석 리포트(#10)의 분석용으로는 그때 따로 검토한다.
- **임베디드 KV(redb 등)**: 조금 더 빠르지만 체감할 수 없다. 반면 조회와 구조 변경을 모두 직접 짜야 한다.

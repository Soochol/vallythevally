# 키움 모의투자는 별도 서버 프로세스로 띄우고, 모의 키·모의 주소·모의 상태만 쓴다

사용자는 실계좌로 소량 주문을 확인하기 전에 키움 모의투자로 주문·정정·취소·계좌 조회를 먼저 확인하려 한다(2026-11-18 "모의투자 해줘 .env나 hogaops .env에 모의투자 계정있어."). [새 창 다섯 개 플랜](../plans/new-windows.md)의 사용자가 정해야 하는 결정 7은 "모의투자: 쓰지 않음"이었다. 이 ADR이 그 결정을 바꾼다. [ADR 0004](0004-dedicated-kiwoom-app-key.md)의 "모의투자 키는 쓰지 않는다"와 [ADR 0029](0029-order-window-sends-cash-limit-orders.md) "키와 토큰"의 같은 문장에는 개정 줄을 단다.

ADR 0029의 결정 대부분(허용 목록, 주문 사용 스위치, 서버 검사, 명령 저널)은 모의투자에서도 그대로다. 바뀌는 것은 키·토큰·주소·상태 경로와 모의의 제약이다. 그래서 0029를 고쳐 쓰지 않고 모의 규칙을 이 문서에 모은다. 구체 근거와 작업 분담은 [모의투자 플랜](../plans/mock-trading.md)에 있다.

## 맥락

- 설정에 모의 키 자리가 없었다. `Config`는 실전 키 변수 둘만 읽었다.
- 주소 판정이 실전과 모의를 가르지 않았다. `*.kiwoom.com`이면 모두 "실제 키움"으로 받았다. 그래서 `mockapi.kiwoom.com`을 적으면 서버가 떴지만, 그때 서버는 실전 키·토큰 파일·주문 사용 스위치·명령 저널을 그대로 썼다. 실전 키로 모의 주소에 발급을 요청하면 키움은 `8030`(투자구분이 달라 앱키를 쓸 수 없음)으로 답한다. 이 코드는 인증 차단이고([ADR 0009](0009-kiwoom-errors-closed-categories.md)), [ADR 0027](0027-kiwoom-connects-by-itself-when-a-key-is-present.md)에 따라 차단이 토큰 파일에 남는다.
- 모의투자는 같은 TR을 초당 1회만 받고(공식 유량 안내, [docs/kiwoom-intraday-snapshot-api.md](../kiwoom-intraday-snapshot-api.md)), 주문 거래소 제약이 있을 수 있다. 서버가 아직 이를 모른다.

확인한 사실:

| 질문 | 답 |
|---|---|
| 모의 REST 주소 | `https://mockapi.kiwoom.com`. 키움 공식 REST 명세의 각 API "모의투자 도메인"이다 |
| 모의 WebSocket 주소 | `wss://mockapi.kiwoom.com:10000` + `/api/dostk/websocket` |
| 모의에서 지원하지 않는 API | 명세에 적힌 것은 일별잔고수익률(`ka01690`) 하나이고 이 저장소는 쓰지 않는다. 지원하지 않는 API를 부르면 `8104`가 오고 서버는 이미 `Unsupported`로 분류한다 |
| 실전 키와 모의 주소를 섞으면 | 앱키를 섞으면 `8030`, 토큰을 섞으면 `8031`. 둘 다 인증 차단이다 |
| 모의 주문 거래소 | 명세는 제약을 적지 않았다. hoga-ops는 모의 계좌의 주문 거래소를 KRX 하나로 제한한다 |

## 결정

1. **투자구분은 서버 프로세스 하나에 하나다.** 설정 `VALLY_KIWOOM_ENV`는 `real`(기본)이나 `mock`이다. 다른 값이면 서버가 뜨지 않는다. 모의 프로세스는 시세·계좌·주문을 모두 모의 서버에서 받는다. 시세는 실전, 주문만 모의로 받는 섞은 구성은 만들지 않는다. 그러면 키 둘, 토큰 둘, WebSocket 세션 둘이 한 프로세스에 있어야 하고, ADR 0029의 "키 하나·토큰 하나·세션 하나" 구조를 다시 짜야 하며, 주문이 어느 쪽으로 나가는지가 요청마다 갈린다. 프로세스 단위로 가르면 "모의 모드에서 실서버 주소·키를 쓰지 않음"이 구조로 선다.
2. **모의 키는 `VALLY_KIWOOM_MOCK_APP_KEY`·`VALLY_KIWOOM_MOCK_APP_SECRET`로만 받는다.** 서버 설정은 모두 `VALLY_` 접두사이고 프로세스 환경은 그 접두사로 거른다. 이름 하나만 예외로 두지 않는다.
   - 둘 다 적거나 둘 다 비운다. 실전 키와 같은 규칙이다.
   - 모의 프로세스는 실전 키 변수(`VALLY_KIWOOM_APP_KEY`·`_SECRET`)가 있으면 뜨지 않는다. 오류 문구에는 변수 이름만 쓰고 값은 쓰지 않는다.
   - 모의 프로세스는 키 파일(`kiwoom-key.json`)을 읽지 않는다. 화면의 키 저장·삭제는 닫힌 오류(`conflict`)로 거절하고 키 파일을 쓰지 않는다.
   - 실전 프로세스는 모의 키 변수를 읽지 않는다. 있어도 무시한다.
3. **주소는 투자구분마다 정확한 호스트만 받는다.** 실전은 `api.kiwoom.com`이나 루프백, 모의는 `mockapi.kiwoom.com`이나 루프백이다. 그 밖의 `*.kiwoom.com`은 거절한다. 주소를 비우면 투자구분의 공식 주소를 쓴다. REST와 WebSocket 주소는 같은 종류여야 하고, 시험 시계(`VALLY_CLOCK_START`)는 루프백 주소와만 뜬다. 이 규칙으로 실전 키가 모의 주소에 붙어 `8030` 차단이 남는 길이 설정 단계에서 막힌다.
4. **모의 프로세스의 상태는 따로 둔다.** 기본 경로가 투자구분을 따른다. 명시한 값이 기본값보다 앞선다.

   | 설정 | 실전 기본 | 모의 기본 |
   |---|---|---|
   | `VALLY_LOCK_PATH` | `$XDG_RUNTIME_DIR/vallythevally/server.lock` | `$XDG_RUNTIME_DIR/vallythevally/mock/server.lock` |
   | `VALLY_TOKEN_PATH` | `$XDG_STATE_HOME/vallythevally/token.json` | `$XDG_STATE_HOME/vallythevally/mock/token.json` |
   | `VALLY_KIWOOM_KEY_PATH`(주문 사용 스위치·IP 기록 파일이 같은 폴더) | `$XDG_STATE_HOME/vallythevally/kiwoom-key.json` | `$XDG_STATE_HOME/vallythevally/mock/kiwoom-key.json` |
   | `VALLY_DB_PATH` | `data/vally.db` | `data/mock/vally.db` |
   | `VALLY_SCREENER_DB_PATH` | `data/screener.duckdb` | `data/mock/screener.duckdb` |
   | `VALLY_FINANCIAL_DB_PATH` | DB 옆 `financials.db` | DB 옆 `financials.db` |
   | `VALLY_BIND` | `127.0.0.1:8080` | `127.0.0.1:8081` |
   | `VALLY_SCREENER_UPDATE_ON_START` | `on` | `off` |

   - 모의의 계좌 참조 소금·주문 사용 스위치·명령 저널·토큰이 실전 파일과 섞이지 않는다. 포트가 달라 브라우저 저장소(origin)도 갈린다.
   - 잠금이 달라 실전 서버와 모의 서버를 같은 PC에서 함께 띄울 수 있다. 키가 다르므로 ADR 0004의 "토큰을 가진 프로세스는 키마다 하나"는 그대로 선다.
   - 스크리너 시작 갱신은 모의에서 기본 꺼짐이다. 전 종목 일봉을 같은 TR로 초당 1회씩 받으면 몇 시간이 걸리고, 그동안 주문 확인용 조회와 대기열을 나눠 쓰게 된다.
5. **경로를 잘못 겹쳐도 섞이지 않게 파일에 투자구분을 적는다.**
   - 토큰 파일과 주문 사용 스위치 파일: 레코드에 `environment`를 둔다. 표시가 없는 기존 파일은 `real`이다. 표시가 있는데 읽을 수 없으면(깨졌거나 모르는 값) 읽기·쓰기 모두 거절하고 덮어쓰지 않는다. 지금 프로세스와 다르면 읽지도 쓰지도 않는다. 토큰 파일은 "파일이 있는데 읽지 못함"과 같이 다룬다(조회·발급 멈춤, ADR 0004). 스위치 파일은 꺼진 것으로 본다.
   - 사용자 자료 SQLite(`vally.db`, 명령 저널이 있다): 마이그레이션이 만드는 한 줄 표(`kiwoom_environment`)에 투자구분을 남긴다. 새로 만든 DB에는 지금 투자구분을 적는다. 자료가 있는데 표시가 없는 DB는 `real`로 본다. 표시만 없고 사용자 자료가 없는 DB(첫 열기가 중간에 끊긴 것)는 지금 투자구분으로 표시한다. 다르면 서버가 뜨지 않는다.
6. **계정 서버 동기화는 모의에서 쓰지 않는다.** `VALLY_ACCOUNT_SERVER_URL`을 모의와 함께 주면 뜨지 않는다. 셋업 동기화([ADR 0024](0024-setup-storage-and-sync.md))가 실전과 모의의 레이아웃·설정을 한 문서로 합치기 때문이다. 모의의 기본 계정 상태 파일 경로는 없다(로컬 전용 모드).
7. **모의 유량: 같은 TR은 1초에 한 번만 보낸다.** 모의 프로세스의 REST 대기열은 지금의 전체 간격(260ms)에 더해 TR마다 마지막 전송 뒤 1초를 기다린다. 기다리는 TR이 줄 앞에 있어도 다른 TR은 먼저 나간다. 우선순위(주문 → 화면 → 복구 → 배경)는 그대로다. 실전의 동작은 바뀌지 않는다. 한도를 넘어 오는 `1700`은 ADR 0009 정책 표가 처리한다.
8. **모의 주문 경로는 KRX만이다.** 모의 프로세스는 NXT와 SOR(화면 값 `combined`) 경로의 신규 주문을 보내기 전에 거절한다. 거절 사유는 닫힌 값 `mock_krx_only`다. 정정·취소는 원주문의 경로를 따르므로 KRX다. 공식 명세에는 모의의 거래소 제약이 없다. hoga-ops가 모의를 KRX로 제한했고, 확인되지 않은 경로로 모의 주문을 보낼 까닭이 없다. 실전의 경로 선택은 바뀌지 않는다.
9. **화면은 모의를 늘 보인다.**
   - 서버는 투자구분(`real`/`mock`)을 키움 연결 상태(`KiwoomLinkStatus`, `/api/system/kiwoom`과 WebSocket `kiwoom_link`)와 시스템 설정(`SystemSettings`)에 싣는다.
   - 모의 프로세스의 화면은 상단 막대에 늘 보이는 "모의투자" 표시와 탭 제목 앞의 "[모의]"를 갖는다. 호가주문창의 계좌 띠에 "모의" 표시를 두고, 주문 경로 고르기에서 SOR·NXT를 끈 채 "모의투자는 KRX 주문만 됩니다"를 보인다. 시스템 설정 키움 탭은 키 저장 칸 대신 "모의투자 키는 환경 설정에서만 받습니다"를 보인다. 실전 화면은 지금과 같다.
10. **모의에서 지원하지 않는 기능은 그 기능의 자리에서 알린다.** 알려진 것(주문 경로 NXT·SOR)은 결정 8·9대로 화면이 먼저 막고 서버도 거절한다. 알려지지 않은 것(키움이 `8104`로 답하는 TR)은 지금처럼 `Unsupported` 범주로 그 API 경로만 멈춘다. 브라우저는 지금과 같은 사유 `unsupported`를 받고, 모의 프로세스의 화면은 이 사유의 문구를 "모의투자에서 지원하지 않는 기능입니다"로 보인다. 프런트는 키움 숫자 코드를 다시 판정하지 않는다(ADR 0009). 실시간 등록 거절은 지금의 실시간 멈춤 상태로 보이고 새 처리를 더하지 않는다.

구현 분담: 결정 1~6과 9의 서버 쪽은 작업 `mock-config`, 결정 7·8은 `mock-limits`, 결정 9·10의 화면은 `mock-web`이 한다. 투자구분 값은 `Config`와 앱 상태(`SystemState::environment`)에 있다.

## 시험

[AGENTS.md](../../AGENTS.md)의 합성 transport 규칙 그대로다. 자동 시험은 합성 transport·세션과 루프백 가짜 키움만 쓰고 고정 입력의 키는 `FAKE-` 합성 값이다. 실제 모의 서버로 하는 확인은 자동 시험이 아니다. 사람이(또는 허락을 받은 오케스트레이터가) [docs/kiwoom-mock-trading.md](../kiwoom-mock-trading.md)의 절차대로 돌린다.

## Considered Options

- **시세는 실전, 주문만 모의**: 결정 1의 이유로 접었다.
- **같은 DB에 투자구분 열을 더해 저널을 나누기**: 화면의 최근 명령·`unknown` 막음·계좌 참조가 모든 조회에서 열을 걸러야 한다. 하나를 빠뜨리면 섞인다. 파일을 가르면 빠뜨릴 곳이 없다.
- **주소만 보고 투자구분을 정하기**: 주소 한 줄을 잘못 적으면 키·상태가 엇갈린다. 투자구분을 먼저 정하고 주소와 키를 거기에 맞춘다.
- **메인 `.env`의 `KIWOOM_MOCK_APP_KEY`를 그대로 읽기**: 서버 설정은 모두 `VALLY_` 접두사이고 프로세스 환경은 접두사로 거른다. 이름 하나만 예외가 된다.
- **투자구분 표시 없이 기본 경로만 가르기**: 경로를 덮어쓰면 모의가 실전 토큰·스위치·저널을 열 수 있다. 파일에 표시를 두면 경로가 겹쳐도 열리지 않는다.

# 앱 서버는 새 창이 연 종목에 호가·프로그램·거래원 실시간을 더 받고, 체결을 건 단위로 보낸다

체결·10호가·프로그램 체결·거래원 입체분석 창([GLOSSARY](../../GLOSSARY.md) `## 화면`)은 0B 체결과 0J 지수만 받던 서버 세션으로는 그릴 수 없다. [ADR 0003](0003-market-data-is-a-cache.md)의 "실시간 구독"에 새 창 보유자와 받는 종류를 더한다. 계획은 [새 창 다섯 개 플랜](../plans/new-windows.md)이다.

## 결정

- **받는 종류와 보유자**
  - 서버 세션은 종목마다 받을 실시간 종류의 집합(`DesiredFeeds`: 종목 → 종류 집합)을 받는다. 주식은 0B·0D·0w·0F 가운데서, 지수는 0J만 받는다. 종목이 받을 수 없는 종류와 빈 집합은 세션이 받기 전에 버린다.
  - 0B는 지금처럼 열린 칸·관심종목·알림 종목에 걸리고, 새 창 다섯의 종목도 0B를 잡는다.
  - 0D는 10호가창·호가주문창, 0w는 프로그램 체결창, 0F는 거래원 입체분석창이 연 종목에만 건다. 관심종목 200개에 0D를 걸면 메시지가 수십 배로 늘기 때문이다. 새 창의 보유자는 차트 칸과 같은 순위로 자리를 받는다.
  - 보유자와 자리를 정하는 쪽은 허브다. 브라우저는 `subscribe_feed`(구독 id, 종목, 흐름 종류, 체결이면 거래소)로 새 창 보유자(`Holder::Feed`)를 만들고 `unsubscribe`로 놓는다. 보유자가 있는 종목에 그 종류만 더 원하고, 마지막 보유자가 빠져도 종류마다 30초 유예를 둔다.
  - 서버 메시지는 `feed_subscribed`, `feed_trades`(100ms 묶음, 건마다, 수량 부호가 방향), `feed_book`(묶음마다 가장 새 값), `feed_program`, `feed_brokers`, `feed_link`(끊김·이어짐)다. 지수 구독은 `bad_request`다.
- **자리 계산**: 종목 단위 그대로다. 키움 등록 한도는 종목 단위이고 종류 수와 무관하다(hoga-ops 2026-07-16 실측, [조사](../research/2026-11-15-kiwoom-al-realtime-types.md)). `REALTIME_LIMIT`의 계산은 바뀌지 않는다.
- **등록**
  - 종목마다 `_AL` 하나다. 종류를 더하거나 빼면 그 종목의 그 종류만 REG/REMOVE 한다. 한 REG에 종류마다 항목을 하나씩 싣고, REMOVE는 종류 하나만 싣는다(0B와 0J를 섞으면 105112로 실패하는 규칙을 종류 전체로 넓혔다).
  - 200개가 찬 상태에서도 해지가 먼저다. 연결이 끊겼다 이어지면 종목마다 원하는 종류를 모두 다시 REG 한다.
- **거래소**: 0D는 키움이 KRX·NXT를 합친 호가이고 거래소 필드가 없다. 0F 수량도 합이다. 0w 증감 행의 거래소 구분은 확인되지 않았다. 그래서 호가·프로그램·거래원 창은 통합 값만 보이고, 앱 전체 거래소(ADR 0020)가 KRX·NXT이면 머리에 읽기 전용 "통합" 표시를 붙인다. 체결창만 0B `9081`로 거래소를 가른다.
- **보내는 단위**: 체결은 100ms 묶음에 건마다 빠짐없이 순서대로 보낸다. 호가는 묶음마다 가장 새 값 하나만 보낸다. 프로그램매매(종목당 분당 약 8건)와 거래원(분당 약 1건)은 받은 행을 모두 보낸다.
- **지난 시간과 끊김**
  - 지난 시간은 당일만, 디스크 없이 채운다. 호가 첫 화면은 ka10004, 체결의 당일 앞부분은 ka10003, 프로그램의 당일 시간대는 ka90008로 받는다. 거래원은 서버가 그 종목의 0F를 받기 시작한 뒤의 스냅샷을 메모리에 둔다. 그 종목의 보유자가 모두 빠지고 유예 30초가 지나면 버리고, 07:45 비우기 때 버린다. ADR 0003 "디스크에 시세를 남기지 않는다"를 지킨다.
  - 끊긴 시간은 메우지 않고 보인다. 연결이 다시 이어지면 체결·프로그램·거래원 창에 "끊김" 구분 줄을 넣는다. 호가는 다시 이어진 뒤의 첫 0D로 바꾼다.
- **필드**: 체결강도는 0B FID 228이고 프레임에 없거나 읽지 못하면 비워 둔다. 상·하한가는 ka10001 `upl_pric`·`lst_pric`이다. 0D·0w·0F의 FID는 [조사](../research/2026-11-15-kiwoom-al-realtime-types.md)와 수집기 파서(`crates/collector/src/parse.rs`)의 규칙을 따른다. 서버는 `collector` 크레이트에 의존하지 않고 같은 규칙으로 서버 안에서 읽는다. 0F는 시각 필드가 없어 수신 시각을 쓴다.
- **새 시세 TR**: ka10004, ka10003, ka90008은 ADR 0004의 시세 허용 목록에 든다.

## Considered Options

- **관심종목 전체에 0D를 거는 안**: 메시지 양이 수십 배가 된다.
- **체결을 봉처럼 가장 새 값만 보내는 안**: 체결창이 건 단위 표라서 안 된다.
- **끊긴 구간을 REST로 메우는 안**: 같은 체결이 두 번 들어갈 수 있고 키움 시각(초 단위)만으로는 겹침을 가릴 수 없다.
- **거래원 지난 시간을 수집기 자료로 채우는 안**: ADR 0025가 정리가 끝난 날만 읽게 해서 장중에는 읽을 수 없다.

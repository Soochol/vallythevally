# 키가 있으면 서버가 저절로 키움에 연결하고, 차단과 끊어 둠은 재시작 뒤에도 남긴다

[ADR 0021](0021-kiwoom-connects-only-when-the-user-asks.md)의 "연결은 수동뿐"을 바꾼다. 사용자가 정했다(2026-11-17 "내가 원하는건 연결을 안눌러도 연결되어야지!", 2026-11-18 "2번은 처음부터 자동"). 사용자는 서버를 다시 켤 때마다 시스템 설정에서 "연결"을 눌러야 했고, 이를 "저장한 키가 유지되지 않는다"로 느꼈다. 키 파일은 남아 있었고 풀리는 것은 연결뿐이었다.

(2026-11-22 개정) 키가 여러 개이면 키마다 이 규칙대로 자동 연결한다. 시세 키의 연결이 종목 목록과 실시간 시세까지 잇고, 다른 키는 토큰과 계좌 실시간 세션까지다. 한 키의 실패가 다른 키를 멈추지 않는다. [ADR 0037](0037-kiwoom-keys-are-a-list-with-one-market-key.md).

ADR 0021의 판단 순서(키 없음 → 차단 → 유효한 토큰 → 발급 간격 → 발급 1회 → 실패는 [ADR 0009](0009-kiwoom-errors-closed-categories.md) 정책 표)는 그대로다. 자동 연결은 새 발급 경로가 아니라 지금의 연결(`connect(false)`)을 한 번 더 부르는 것이다. 그래서 자동 연결이 정책을 우회하는 길이 구조로 없다.

## 결정

- **언제 연결하나**
  - 서버가 켜질 때(`serve`가 상태를 만든 직후)와 화면에서 키를 저장할 때다. 기다리지 않는다. 키 저장은 연결을 시작하고 바로 답한다.
  - 그 키로 연결한 적이 없어도 처음부터 자동이다.
  - 환경(`.env`) 키는 화면에서 저장할 수 없으므로 키 저장 경로가 없고, 켤 때만 해당한다.
- **켤 때의 판단**: 키가 없으면 아무것도 하지 않는다. 차단 상태(복원한 인증 차단, 토큰 파일을 읽지 못함)이면 아무것도 하지 않는다. 끊어 둠 기록이 지금 키의 해시와 같으면 아무것도 하지 않는다. 그 밖에는 `connect(false)`를 한 번 부른다.
- **실패하면 저절로 다시 시도하지 않는다.** 네트워크 실패도 같다. 반복은 ADR 0009 정책 표가 정한다. 화면의 "다시 시도"가 바로 잇는다.
- **끊어 둠을 기억한다.**
  - 사용자가 `POST /api/system/kiwoom/disconnect`로 끊으면 지금 키의 앱키 해시를 토큰 파일에 쓴다. 다음 시작에서 그 키는 자동 연결하지 않는다.
  - 연결이 연결됨에 이르거나, 키를 저장하거나 지우면 기록을 지운다.
  - 키 저장·삭제가 안에서 부르는 끊기는 사용자 끊기가 아니며 기록을 쓰지 않는다.
  - 기록을 쓰지 못하면 경고 로그를 남기고 연결 상태는 바꾸지 않는다.
- **인증 차단을 기억한다.**
  - 인증 차단(8050과 그 밖의 `AuthBlocked`)으로 멈출 때 상세 코드, 앱키 해시, 시각을 토큰 파일에 쓴다. 시작 때 기록이 있으면 인증 차단으로 켜고 키움에 아무것도 보내지 않는다.
  - 8050은 키와 상관없이 복원한다. 확인 체크 두 칸과 발급 간격 뒤의 연결이 연결됨에 이르면 기록을 지운다. 새 키를 저장해도 8050 기록과 차단은 남는다. 키를 저장할 때의 자동 연결도 확인 없이는 발급하지 않는다.
  - 그 밖의 인증 차단은 같은 앱키 해시일 때만 복원한다. 새 키를 저장하면 풀리고 기록도 지운다.
  - 복원한 실패의 상태는 8050 직후와 같다. 상세 코드만 가지고 만든 실패라, 8050이 아닌 코드의 `message`에 쓰는 증거 줄(API ID, HTTP 상태, `return_code`)은 원래 응답보다 짧다.
  - 기록을 쓰지 못하면 그 프로세스 안에서는 지금처럼 멈추고 오류 로그를 남긴다. 다음 시작에 기록이 없으면 자동 연결은 발급 간격만 지킨다. 손으로 연결하는 지금과 같은 위험이다.
- **발급 간격 안이면 기다렸다가 저절로 잇는다.**
  - 확인 없이 부른 연결이 토큰 없이 발급 간격 안에 있으면 연결 중의 한 단계(`issueInterval`)로 바꾸고 다시 시도할 시각(`retryAt`)을 상태에 싣는다. 그 시각까지 기다리다 판단 순서 처음부터 다시 간다. 기다리는 동안 키움에는 아무것도 보내지 않는다.
  - 끊기·키 교체·키 삭제가 오면 그만둔다. 다른 연결 요청은 같은 연결에 붙는다.
  - 8050을 확인하고 부른 연결의 간격 대기는 지금처럼 간격 대기 실패로 끝낸다. 차단을 푸는 동작은 사람이 마지막으로 누른다. 종목 목록 단계의 간격 대기도 지금 처리를 유지한다.
  - `POST /api/system/kiwoom/connect`는 연결이 끝나거나 대기 단계에 들어가면 그때의 상태로 답한다. 이후 변화는 WebSocket `kiwoom_link`로 간다.
- **상태가 시작 때의 동작을 알린다.** 연결 상태의 `atStart`는 키가 없으면 `null`이고, 키가 있으면 `connects`(다음 시작 때 자동 연결함) 또는 `keptDisconnected`(사용자가 끊어 둠)다.
- **시험 하네스의 `VALLY_KIWOOM_CONNECT`는 시험 전용으로 남는다.** `start`는 운영과 같은 시작 함수를 부른다. 시작 때 자동 연결을 끄는 운영 스위치는 없다. 끊기가 그 역할을 한다.

## 서버를 켤 때마다 발급하던 문제가 되살아나지 않는 근거

ADR 0021 이전에는 서버를 켜면 무조건 발급했다. 2026-11-09에 8050을 겪었고 그때 화면은 "서버를 다시 켜야 합니다"만 보였다. 이 결정은 그 구조로 돌아가지 않는다.

- 토큰은 파일에 남고 24시간 유효하다. 연결됨 상태에서는 매일 20:05에 다시 받는다. 대부분의 재시작은 발급 0회다. ADR 0004의 "재시작은 발급이 아니다"가 자동 연결에도 선다.
- 발급이 필요해도 마지막 발급 요청에서 10분 안이면 보내지 않는다. 그 시각은 요청 전에 파일에 쓴다. 서버를 몇 번 켜고 꺼도 발급은 10분에 1회를 넘지 않는다.
- 인증 차단은 재시작 뒤에도 남는다. 8050 뒤에는 자동 연결도, 손 연결도, 키 저장도 확인 체크 두 칸 없이는 발급하지 않는다. ADR 0021보다 강하다. 전에는 8050 뒤 재시작하면 확인 없이 발급이 나갔다.
- 새 키의 첫 발급이 8050이면 그 한 번에서 멈춘다. 차단 기록이 남으므로 재시작도 다시 발급하지 않는다.
- 연결은 single-flight다. 시작 한 번에 발급은 최대 1회다. 시작 연결, 키 저장 연결, 손 연결이 같은 연결에 붙는다.
- 실패 뒤 반복은 정책 표가 정한다. 자동 연결은 시작 때나 키 저장 때 한 번이고 실패하면 다시 시도하지 않는다. 저절로 이어 가는 것은 발급 간격 대기뿐이고, 간격이 끝난 뒤 한 번 이어 갈 뿐이다.
- 검증 실행과 시험은 루프백 가짜 키움과 합성 transport만 쓴다.

## 남는 위험

- 토큰 파일은 서버와 키움 실측 프로그램이 함께 쓴다. 새 필드를 모르는 프로그램이 파일을 다시 쓰면 끊어 둠·차단 기록이 사라진다. 이 경우 지금과 같이 발급 간격만 지킨다.
- 8050을 확인하고 연결했을 때 이번 연결이 새 토큰을 받기 전에 실패하거나 끊기면(네트워크 실패, 저장된 토큰을 쓰다 실패 등) 8050 차단이 메모리에 다시 선다. 그래서 시작 연결, 키 저장 연결, 발급 간격 뒤 이어 가기가 확인 없이 발급하는 길은 없다. 같은 키로 사람이 확인 두 칸을 다시 하고 누르는 손 연결만 발급 간격 뒤 풀린다.
- 8050을 확인하고 토큰을 받은 뒤 종목 목록 같은 뒤 단계에서 실패하면 그 프로세스에서는 8050이 풀린 채 남는다. 발급은 성공했기 때문이다. 파일의 기록은 연결됨에 이를 때까지 남으므로 다시 켜면 8050 차단으로 켜진다. 더 보수적인 쪽이다.
- 발급 간격을 기다리는 연결은 기다리는 동안 다른 연결(끊기 제외)이 만든 토큰을 보지 않는다. 시각이 되면 처음부터 판단해 그 토큰을 쓴다.

## Considered Options

아래는 검토했지만 **고르지 않은 안**이다. 다시 꺼내려면 새 ADR로 이 결정을 바꾼다.

- **그 키로 한 번 연결에 성공한 뒤부터 자동**: 첫 연결은 늘 손이 가고, 새 키를 저장한 사용자가 같은 문제를 겪는다. 사용자가 처음부터 자동으로 정했다. 첫 발급이 8050이어도 차단 기록이 남아 한 번에서 멈춘다.
- **끊기와 상관없이 늘 자동**: 사용자가 끊어 둔 뜻을 재시작이 뒤집는다.
- **유효한 토큰이 있을 때만 자동**: 만료되면 깨지고, 사용자가 겪은 첫 연결과 하루 뒤 연결이 다시 수동이 된다.
- **시작 때 네트워크 실패를 자동으로 다시 시도**: 반복은 ADR 0009 정책 표가 정한다. 새 반복 경로를 만들지 않는다.
- **별도 자동 연결 스위치(환경 변수나 설정)**: 끊기가 그 역할을 한다. 스위치가 둘이면 어느 쪽이 이기는지 설명해야 한다.

# 창은 같은 종류를 여러 개 둘 수 있게 하고, 개체 목록 창은 없앤다

사용자가 창의 기본 컨셉을 정했다(2026-11-18 "기본 컨셉은 창은 중복해서 여러개 띄울 수 있다."). 지금은 차트 창만 여러 개 열 수 있고 나머지 종류는 한 레이아웃에 하나뿐이다([ADR 0019](0019-layout-is-windows-and-placement.md)). 근거와 작업 분담은 [같은 종류 창 여러 개 플랜](../plans/multi-window.md)에 있다. 이 문서는 작업이 나뉜 순서대로 이어 쓴다. 지금은 개체 목록 창을 없애는 절과 같은 종류 창을 여러 개 허용하는 절이 있다.

## 개체 목록 창을 없앤다

사용자가 첫 플랜을 본 뒤 "개체목록 창 제거"를 골랐다. 개체 목록에만 있던 기능 넷(숨긴 드로잉 하나 다시 보이기, 드로잉 이름 바꾸기, 목록에서 드로잉 고르기, 범위별 드로잉 수 보기)을 어떻게 할지 묻자, 숨긴 드로잉을 되살릴 길이 없어진다는 설명을 본 뒤에도 "모두 없앰"을 골랐다.

- **창 종류 `objects`가 없어진다.** 서버 `WindowContent::Objects`, 웹 `WINDOW_KINDS`·`WINDOW_CONTENT`와 생성 타입에서 뺀다. 창 더하기 메뉴, 캔버스 빈 화면 단추, 기본 레이아웃, 드로잉 도구 막대의 "개체 목록 열기" 단추도 함께 없어진다. 서버는 `objects`가 든 레이아웃을 `PUT /api/layouts/:id`에서 400으로 거절한다.
- **없어지는 기능 넷은 다른 곳에 새로 만들지 않는다.** 다시 보이기 메뉴 항목도 만들지 않는다. 저장된 이름(`style.objectName`)은 지우지 않는다. 새 드로잉의 스타일을 이어받을 때와 "기본 스타일로"를 눌러도 이름은 남는다. 이름을 보여 주거나 바꾸는 화면이 없을 뿐이다. 모든 드로잉 숨기기(`prefs.hideAll`, `Ctrl+Alt+H`), 잠그기, 지우기, 순서 옮기기는 차트 우클릭 메뉴와 떠 있는 스타일 막대에 그대로 있다.
- **드로잉 하나 숨기기도 없앤다.** 다시 보이기가 없으면 숨긴 드로잉은 차트에서 고를 수도 지울 수도 없는 막다른 상태가 된다. 그래서 고른 드로잉 우클릭 메뉴의 "숨기기"를 지우고, 화면은 드로잉의 `hidden`을 보지 않고 그리고 고른다.
- **숨겼던 드로잉은 되살린다.** 마이그레이션 `0019_remove_objects_window.sql`이 `drawings`의 `hidden = 1`을 모두 `0`으로 바꾼다. `revision`은 그대로 두고 `updated_at`만 바꾼다. 그래야 [ADR 0019](0019-layout-is-windows-and-placement.md)가 "이 칸" 범위를 넓힐 때 정한 것과 같이 브라우저가 다음 번호로 저장한 것을 받아들인다.
- **`hidden`은 쓰지 않는 필드이고, 서버가 언제나 `false`로 저장한다.** 드로잉 API·DB·셋업 묶음·생성 타입에는 필드를 남긴다. 드로잉 자료 모양과 API 경로·형식을 바꾸면 계정 서버에 올려 둔 셋업과 옛 브라우저가 어긋나기 때문이다. 대신 서버가 드로잉을 저장할 때(`PUT /api/drawings/:id`와 셋업 묶음 가져오기) 들어온 `hidden` 값과 상관없이 `false`로 저장하고 응답한다. 다른 기기, 계정 서버의 셋업 문서, 브라우저의 아직 안 보낸 변경에 남은 `hidden: true`가 드로잉을 다시 숨기지 못한다.
- **마이그레이션이 개체 목록 창 행을 지운다.** `layout_windows`의 `kind = 'objects'` 행을 모두 지운다. 창은 1개 이상, 차트 창은 1개 이상이라는 규칙은 차트를 지우지 않으므로 그대로 지켜진다. 배치(`placement`)에 남은 그 창의 자리는 화면이 읽을 때 지운다([ADR 0019](0019-layout-is-windows-and-placement.md)의 규칙).

### 옛 레이아웃에서는 `objects` 창만 빼고 받는다

셋업 묶음([ADR 0024](0024-setup-storage-and-sync.md))으로 들어오는 레이아웃과 브라우저의 미저장본에 `objects` 창이 있으면 그 창만 빼고 받아들인다. 계정 서버에 올려 둔 옛 레이아웃을 내려받을 때 거절하면 그 기기의 동기화가 막히기 때문이다. 사용자가 할 수 있는 일이 없고, 다음 동기화도 같은 문서에서 다시 막힌다.

이것은 ADR 0019의 "옛 모양을 받아 주는 호환 코드는 두지 않는다"와 다르다. 0019의 옛 모양은 칸 배치와 칸 목록이어서, 받는 쪽이 어느 창에 어느 종목을 둘지 새로 정해야 했고 사용자의 기존 서버 자료는 마이그레이션이 한 번에 옮겼다. 이번에는 서버 자료가 아니라 이미 기기 밖에 나가 있는 문서가 문제이고, 빼면 되는 것이 창 하나뿐이어서 호환 코드가 한 줄 필터다. 빼는 것은 `objects` 한 종류뿐이다. 그 밖의 모르는 종류(`nope` 같은 값)는 지금처럼 문서 하나의 오류로 묶음 전체를 거절한다.

## 같은 종류 창을 여러 개 둘 수 있다

[ADR 0019](0019-layout-is-windows-and-placement.md)의 "차트가 아닌 종류는 종류마다 하나 이하"를 바꾼다. 서버 `check_layout`, 웹 `WINDOW_KINDS`·`restore.ts`, 셋업 묶음이 같은 규칙을 쓴다.

- **지표만 레이아웃에 하나까지다.** 지표 창은 언제나 활성 칸을 보이므로 둘이면 같은 내용이다. 서버는 지표 창이 둘이면 400으로 거절하고 웹은 그 레이아웃을 읽지 않는다.
- **나머지 종류는 종류별 개수 제한이 없다.** 관심종목, 스크리너, 체결, 10호가, 프로그램 체결, 거래원 입체분석, 호가주문은 창 전체 상한만 받는다. 차트는 지금처럼 1~8개다.
- **창 전체 상한은 50개다.** 서버(`MAX_WINDOWS`)와 웹(`MAX_WINDOWS`)을 함께 올렸다(12 → 50). 알림 문구 "창은 50개까지 둘 수 있습니다"는 상수에서 만든다. 셋업 묶음과 레이아웃 본문의 크기 상한은 차트 수로 정해지고 차트가 아닌 창은 창마다 수십 바이트라 바꾸지 않는다. 창 50개가 모두 따로 묶음이거나 떠 있어도 배치(`placement`)는 64KB 상한 안에 든다(웹 단위 시험이 도킹·캔버스 최악의 모양으로 확인한다).
- **차트는 8개로 둔다.** 차트는 탭에 숨어도 늘 그려 두고 봉을 구독한다. 상한을 함께 올리면 숨은 차트만으로 브라우저가 무거워진다. 차트가 아닌 창은 보이는 탭일 때만 그리고 구독하므로 50개 상한을 받는다. 캔버스는 모든 창을 그리므로 시세 창을 많이 열면 구독과 그리기가 그만큼 는다. 이 비용은 사용자가 창을 여는 만큼만 든다.
- **서버 시세 구독은 바꾸지 않는다.** 구독이 이미 창(구독 id) 단위다. 같은 종목·같은 종류를 두 구독이 잡다가 하나를 풀어도 남은 구독이 그 종류를 등록 목록에 지킨다는 것을 허브 시험이 확인한다.
- **창 이름에 번호가 붙는다.** 같은 종류가 둘 이상일 때만 창 목록 순서로 같은 종류 안에서 1부터 센다("체결 1", "체결 2"). 탭 이름, 창 머리 제목, 닫기·크게 보기·붙이기 단추의 접근성 이름, 닫기 알림, 도킹 탭 메뉴에 쓴다. 하나뿐이면 종류 이름 그대로여서 기존 접근성 이름이 바뀌지 않는다. 차트의 이름은 바꾸지 않는다. 번호는 저장하지 않고 창 목록에서 매번 센다. 가운데 창을 닫으면 뒤 창의 번호가 당겨진다.
- **창 더하기는 언제나 새 창이다.** 창 더하기 메뉴와 캔버스 종류 단추에서 여러 개 허용 종류를 고르면 새 창을 더한다. 메뉴 힌트는 열린 수가 1 이상일 때 "N개 열림"이다. 창이 50개면 막고 이유를 보인다. 지표는 지금처럼 "열려 있음"이고 고르면 그 창으로 간다.
- **단축키·명령·도구 단추는 첫 창으로 간다.** 관심종목 단축키, 스크리너 명령, 지표 "차트 옆"처럼 종류를 가리키는 호출(`showWindow`)은 창 목록 순서의 첫 창을 앞으로 가져오고, 없으면 지금처럼 만든다. "마지막으로 고른 창"을 기억하려면 새 상태가 필요하고, 이 호출들은 어느 창이든 뜻이 같다.
- **복제를 도킹 탭 메뉴에 더한다.** 차트가 아닌 여러 개 허용 종류에서만 보인다. 연동 색과 종류별 내용(지금은 호가주문의 주문 경로)을 옮긴 새 창을 같은 묶음의 그 탭 바로 오른쪽에 놓고 고른다. 창 더하기와 같은 배치 기록이라 되돌리기 한 단계로 되돌린다. 캔버스 창에는 메뉴가 없어 복제를 두지 않는다.
- **탭을 고르면 탭 줄 안에 보인다.** 새 창, 복제, 단축키, 탭 메뉴로 탭이 골라지면 그 탭이 탭 줄 안으로 스크롤된다. 탭 넘침 메뉴 같은 새 부품은 만들지 않는다.
- **화면 안 고정 DOM id를 `useId`로 바꾼다.** 같은 창이 둘이면 `label`의 `htmlFor`와 `aria-describedby`가 엉뚱한 창을 가리키기 때문이다.

### 검토한 선택지

| 선택지 | 판단 |
|---|---|
| 모든 종류를 여러 개 허용 | 지표 창은 활성 칸만 따르므로 둘이 같은 내용이다. 지표는 하나로 둔다 |
| 연동 색으로만 구분 | 같은 종류 창을 이름으로 가를 수 없어 탭·닫기 알림·접근성 이름이 똑같아진다. 번호를 붙인다 |
| 지금대로(차트만 여러 개) | 사용자가 정한 기본 컨셉("창은 중복해서 여러개 띄울 수 있다")과 어긋난다 |
| 창 상한 12 유지 | 종류가 아홉이고 같은 종류를 여럿 두면 12개는 곧 찬다. 사용자가 50개를 골랐다 |

## 이 문서가 아직 정하지 않은 것

창마다 다른 상태(관심종목의 목록, 스크리너의 조건식, 시세 창의 고정 종목)는 다음 작업이 이 문서에 이어 적는다. 같은 종류 창 둘은 지금 같은 목록·같은 조건식을 보이고, 시세 창은 연동 색으로만 종목을 가른다.

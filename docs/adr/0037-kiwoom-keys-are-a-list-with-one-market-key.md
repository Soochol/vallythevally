# 키움 키는 실전에서 최대 5개를 목록으로 두고, 시세는 시세 키 하나만 받는다

[ADR 0004](0004-dedicated-kiwoom-app-key.md)는 실전 투자구분의 키를 하나로 정했다. 사용자는 호가주문에서 계좌를 고르고 시스템 설정에서 키를 여러 개 입력하기를 원한다([호가주문 UX 플랜](../plans/ladder-order-ux.md) D7·D9·D10). 키는 계좌와 키움 호출 한도의 단위이므로 키가 여러 개여야 계좌가 여러 개다. 이 ADR은 "키는 하나"만 바꾼다. 토큰 파일, 발급 간격, 8050 차단, 비밀값 규칙은 키마다 그대로 적용한다.

(2026-11-23 개정) 키 목록에 한투 키도 든다. 키는 증권사마다 5개이고, 같은 앱키를 두 번 등록하지 않는 규칙은 증권사 안에서 따진다. 한투 환경 키 줄의 ID는 `env-kis`다. **시세 키**는 **시세 공급원 키**로 넓어져 어느 증권사 키든 될 수 있다. [ADR 0043](0043-market-source-is-one-key-of-either-broker-and-switching-drops-the-cache.md). 아래 "최대 5개", "`broker`는 지금 `kiwoom`뿐", "키움 키" 문구는 이 개정 전의 결정이다.

## 결정

- **키 목록**
  - 실전 투자구분은 키를 최대 5개 저장한다. 환경(`.env`) 키가 있으면 그 키도 5개에 든다.
  - 키마다 안정된 키 ID(`k1`, `k2`, …. 환경 키는 `env`), 별칭(사용자가 붙인 1~20자), 증권사(`broker`, 지금은 `kiwoom`뿐), 앱키, 시크릿을 갖는다. 같은 앱키는 두 번 등록하지 않는다. 앱키로 판단한다.
  - 지운 키의 ID는 다시 쓰지 않는 쪽으로 쓴다(남은 키 ID 가운데 가장 큰 번호의 다음 번호).
- **시세 키**
  - 시세 REST와 실시간 시세는 **시세 키** 하나만 쓴다. 대기열 사용량 표시도 시세 키 기준이다. 시세 키는 목록에서 하나이고 사용자가 바꾼다. 기본은 목록 첫 줄이다.
  - 나머지 키는 계좌·주문 TR과 자기 계좌의 실시간(주문체결 `00`, 잔고 `04`)만 쓴다. 토큰 하나에 WebSocket 세션 하나(공지 49)이므로 키마다 자기 세션을 연다.
  - 시세 키를 바꾸면 옛 시세 키의 시세 구독을 내리고 새 키로 시세를 다시 잇는다. 토큰 발급 간격과 8050 차단 규칙은 그대로 지키며, 파일에 같은 앱키의 유효한 토큰이 있으면 다시 받지 않는다.
  - 시세를 받지 않는 키를 고른 계좌의 시세는 시세 키 그대로다(D9 기본안). 고른 키로 시세도 전환하는 안은 고르지 않았다. 키를 하나씩만 연결해야 하고 바꿀 때마다 실시간 재연결과 토큰 발급 간격이 걸리기 때문이다.
- **키마다 따로인 것**: 토큰 파일, 발급 간격, 8050 차단과 끊어 둠 기록, 자동 연결 상태, 키움 요청 대기열([ADR 0035](0035-kiwoom-queue-counts-each-tr-per-second.md)), 포털 등록 IP 확인 기록이다. 키움 호출 한도가 앱키 단위이기 때문이다. 한 키의 실패(8050, 네트워크)는 다른 키를 멈추지 않는다.
- **연결**: 서버를 켤 때와 키를 더할 때 [ADR 0027](0027-kiwoom-connects-by-itself-when-a-key-is-present.md)의 규칙대로 키마다 연결한다. 시세 키의 연결이 지금의 연결(종목 목록, 실시간 시세)이다. 다른 키는 토큰 발급과 계좌 실시간 세션을 여는 데까지다. 계좌 실시간 구독은 키마다 자기 세션에 붙는다. 주문 사용이 켜진 키만 `00`·`04`를 등록한다. 시세 키를 바꾸면 두 키의 연결이 서로 바뀌므로 두 키의 계좌 실시간 등록과 마지막 계좌 확인을 새 연결에 맞춰 다시 정한다.
- **저장**
  - 화면에서 저장한 키는 키 목록 파일(`kiwoom-keys.json`, `VALLY_KIWOOM_KEY_PATH`와 같은 폴더)에 둔다. 디렉터리 700, 파일 600이고 둘 중 하나라도 열려 있으면 읽지 않는다.
  - 옛 한 개짜리 `kiwoom-key.json`은 목록 파일이 없을 때 첫 키(별칭 "키 1", 시세 키)로 옮기고, 옮긴 뒤 지운다. 옮기다 실패하면 옛 파일을 남기고 오류로 키 없이 켠다.
  - 환경 키는 읽기 전용이고 목록 첫 줄이며 시세 키 기본이다. 화면에서 다른 키를 더할 수 있다. 시세 키를 파일 키로 바꿀 수도 있다.
  - 토큰 파일과 등록 IP 기록은 앱키를 따라간다. 설정이 정한 파일(`token.json`, `kiwoom-ip.json`)은 그 파일에 적힌 앱키 해시가 같은 키가 쓰고, 아무도 안 쓰던 파일이면 목록 첫 키가 쓴다. 나머지 키는 앱키 해시 앞 8자를 붙인 이름(`token.<해시>.json`, `kiwoom-ip.<해시>.json`)을 쓴다. 키마다 겹치지 않는다. 키 ID나 환경 키가 생기고 없어지는 것에는 따르지 않으므로, 키를 지웠다 같은 앱키로 다시 넣거나 환경 키를 나중에 켜도 그 키의 8050 차단과 발급 간격 기록이 그대로 따라온다. 키를 지울 때 그 키의 토큰 파일은 지우지 않는다.
  - 주문 사용 스위치 파일(`kiwoom-orders.json`)은 키 ID마다 한 칸씩 담는다(2026-11-22 개정, `order-accounts`). 옛 한 칸짜리 파일은 서버를 켤 때의 시세 키 칸으로 읽고 다음에 쓸 때 키 ID 칸으로 옮긴다. 키를 지우면 그 칸은 꺼진 것으로 바뀐다. 스위치에 적힌 계좌와 그 키의 계좌가 다르면 지금 규칙대로 불일치로 다룬다([ADR 0029](0029-order-window-sends-cash-limit-orders.md)).
- **그대로인 것**: 모의투자 서버는 환경의 키 하나만 쓰고 키 목록 파일을 읽지 않으며 화면에서 키를 바꿀 수 없다([ADR 0030](0030-kiwoom-mock-trading-runs-as-its-own-server-process.md)). 수집 키([ADR 0022](0022-hoga-replay-collects-quotes-on-disk.md))와 감독 데몬은 건드리지 않는다. 시세 API만 허용하는 목록과 주문·계좌 API를 `trading` 모듈에만 두는 규칙도 그대로다.

## 증권사에 묶이지 않게 두는 두 원칙

사용자는 키움과 한국투자증권을 함께 지원하고 시세 공급원을 어느 쪽으로든 고를 수 있기를 원한다. 한투 지원은 이 ADR이 아니라 이 작업이 병합된 뒤 별도 플랜(`plan-multi-broker`)이 한다. 이 작업은 한투 코드와 증권사 공통 추상 계층을 더하지 않는다. 다만 이름과 저장 형식이 키움 하나로 굳지 않도록 두 원칙을 지킨다.

1. **시세 공급원과 주문 계좌는 다른 축이다.** 시세 연결은 하나이고 계좌·주문 연결은 여러 개다. "시세 키"는 시세 연결을 지닌 키이지 계좌의 한 종류가 아니다. 시세 키를 바꾸는 것과 주문 계좌를 고르는 것은 서로 영향을 주지 않는 두 결정이다.
2. **계좌는 증권사와 계좌번호로 식별한다.** 키 목록 파일과 키 API가 키마다 `broker`를 갖는다. 키 ID는 증권사 이름을 담지 않는다. 계좌를 가리키는 값(계좌 참조)을 정할 때는 증권사를 함께 넣을 수 있게 둔다.

이 원칙을 지키느라 이 작업의 범위가 늘면 그 부분은 하지 않고 미해결 사항에 남긴다.

## 결과

- 키 목록 형식이 처음 생겨서 파일 이름이 바뀌고, 서버 이전·되돌리기 절차의 파일 목록이 바뀐다(`docs/server-operations.md`).
- 시세 키를 바꾸면 시세 연결이 잠깐 끊겼다가 새 키로 다시 이어진다. 시세 키였던 키는 계좌용 연결로 내려가며, 그 키의 토큰은 파일에서 다시 읽어 쓴다. 바꾸는 순간 토큰을 받는 중이던 요청의 결과는 버린다. 그 키는 발급 간격이 지난 뒤 다시 받는다.

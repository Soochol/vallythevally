# 수집 저장소 형식

수집기 `finalize`가 하루 원문을 정리해 만드는 Parquet 파일의 계약이다. 앱 서버는 수집기 코드를 가져다 쓰지 않고 이 문서만 보고 DuckDB로 읽는다([ADR 0025](adr/0025-collector-stores-closed-days-for-the-app.md) "수집 저장소"). 코드의 열 정의와 아래 열 표는 시험(`crates/collector/tests/finalize.rs`)이 견준다.

형식 버전은 1이다. 열을 지우거나 열의 형·뜻을 바꾸거나 정렬·파일 배치·버킷 규칙을 바꾸면 버전을 올리고 이 문서에 이력을 적는다. 열만 더하는 것은 버전을 올리지 않는다. 읽는 쪽은 열을 이름으로 고른다.

## 폴더와 파일

```
store/<YYYYMMDD>.tmp/        정리 중인 날. finalize가 쓴다.
store/<YYYYMMDD>/            정리가 끝난 날. 앱이 읽는다.
  <타입>/<버킷 번호>.parquet   예: 0B/056.parquet
  verify.json               원문 대조 결과(아래 "verify.json")
```

- 앱은 `store/<YYYYMMDD>/`만 읽는다. `.tmp` 폴더는 쓰는 중이라 읽지 않는다. 정리 완료 표시(`complete.json`)와 `.tmp` 이름 바꾸기는 이 문서 밖의 뒤 작업이 정한다.
- `<타입>`은 키움 실시간 타입 코드다. 대소문자를 구분한다. 받는 열한 가지는 `0B`·`0D`·`0w`·`0F`·`1h`·`0H`·`0E`·`0g`·`0J`·`0U`·`0s`다. 그날 행이 없는 타입은 폴더가 없다.
- `<버킷 번호>`는 세 자리 0 채움 정수다. 종목 하나의 행은 한 타입에서 파일 하나에만 있다. 행이 없는 버킷은 파일이 없다. 타입 폴더의 `*.parquet`를 모두 읽으면 그 타입의 전부다.
- 버킷은 `symbol`의 UTF-8 바이트에 FNV-1a 64비트(오프셋 `0xcbf29ce484222325`, 소수 `0x100000001b3`)를 적용한 값을 버킷 수로 나눈 나머지다. 기본 버킷 수는 64다. 종목 하나의 파일만 읽으려면 이 규칙으로 번호를 구한다. 예를 들어 `005930_AL`은 64개일 때 56번이다.
- 버킷 수와 형식 버전은 각 파일의 Parquet 키-값 메타데이터에도 있다: `vally.format_version`, `vally.type`, `vally.bucket`, `vally.buckets`.

## 행

- 키움 `REAL` 프레임의 `data` 항목 하나가 행 하나다. 프레임 하나에 여러 항목이 올 수 있다.
- 파일 안 순서는 `symbol`(바이트 사전순), `recv_ms`, 원문 줄 순서, 프레임 안 항목 순서다. 같은 종목·같은 `recv_ms`의 행은 받은 순서를 지킨다.
- 묶음(row group)은 122,880행이다. 압축은 zstd 3이고, `recv_ms`와 정수 열은 `DELTA_BINARY_PACKED`다.

### 공통 열

| 열 | 형 | 뜻 |
|---|---|---|
| `symbol` | 문자, 빈 값 없음 | 원문 항목의 `item` 글자 그대로다. 종목은 등록한 글자인 `<종목코드>_AL`(예: `005930_AL`)이다. `0J`·`0U`는 업종 코드(예: `001`)이고 `0s`는 빈 문자열이다. |
| `recv_ms` | 정수(`BIGINT`), 빈 값 없음 | 수집기가 프레임을 받은 시각이다. 유닉스 시각(UTC 1970-01-01 기준) 밀리초다. KST 날짜는 9시간을 더해 구한다. 같은 프레임의 항목은 `recv_ms`가 같다. |

### 값 열

- 항목의 `values`에 든 FID마다 열 `f<FID>`가 있다. 열 목록은 아래 열 표가 정한다. 키움 명세로 정했고 원문을 훑어 정하지 않는다. 한 FID가 한 행에 없으면 그 칸은 `NULL`이다.
- 형은 정수(`BIGINT`), 실수(`DOUBLE`), 문자(`VARCHAR`)다. 키움 명세는 모든 값을 문자열이라 적는다. 형은 열 표 아래 "형을 정한 방법"을 따른다.
- 원문 값이 JSON 숫자이면 적힌 글자 그대로를 값으로 본다(`1.50`은 글자 열에서 `1.50`이다). 숫자 열은 앞뒤 공백을 뗀 글자를 읽는다. 빈 글자는 `NULL`이다. 정수 열에서 `-0`은 `0`이다. 문자 열은 원문 글자 그대로이고(공백 한 칸도 그대로) 빈 글자는 빈 문자열이다.
- 부호 처리는 다음과 같다. 키움은 숫자에 `+`나 `-`를 붙인다. `-`는 수의 일부로 저장한다. 값이 가격인 FID에서 부호는 등락 방향이므로(`현재가 -20800`은 20,800원이고 전일 종가보다 낮다) 가격으로 쓰려면 절댓값을 취한다. 거래량 `15`에서 `+`는 매수 체결, `-`는 매도 체결이다. `+`는 정수·실수 값으로 남지 않는다(`+82`와 `82`가 같다). 그래서 정수·실수 열마다 `f<FID>_plus`(`BOOLEAN`, 빈 값 없음)가 있다. 원문 글자(공백을 떼기 전)가 `+`로 시작하면 `true`이고, 부호가 없거나 앞이 공백이거나 값이 없으면 `false`다. 문자 열에는 `_plus`가 없다.
- FID 키는 앞자리 0과 부호가 없는 십진수 글자여야 한다. `+10`이나 `010`은 명세 밖 FID다. 한 항목에 같은 FID가 두 번 나오면 뒤의 값을 저장하고 `unparsable_value`로 센다. 명세에 없는 FID는 열이 없다. 명세 밖 FID가 든 프레임은 정리 못 한 줄로 세고(`verify.json`) 원문에만 남는다. 그 항목의 나머지 FID는 행으로 저장된다.

### 시각의 기준

- `recv_ms`는 수신 시각이고 모든 행에 있다. 정렬과 구간 조회의 기준이다.
- FID `20`(`체결시간`)과 `21`(`호가시간`)은 거래소가 알린 사건 시각이다. `HHmmss` 여섯 글자 문자열이고 KST다. 날짜와 밀리초가 없다. 수신 시각보다 보통 0.04~1.09초 앞선다([키움 실시간 조사](research/2026-11-15-kiwoom-al-realtime-types.md)). 같은 초 안의 순서는 `recv_ms`와 파일 순서가 정한다.
- `0F`는 시각 FID가 없다. `recv_ms`를 쓴다.

### 거래소 구분

- 종목 흐름은 `_AL`(KRX·NXT 통합)로 받는다. `0B`는 체결마다 FID `9081`(`f9081`)이 `KRX`나 `NXT`다. `0D`에는 거래소 필드가 없고 합친 호가가 온다. 거래소별 잔량은 FID `6044`~`6087`(KRX·NXT 각 매도·매수 10단계와 총잔량) 열에 있다. `0F`는 FID `337`(`f337`)이 있고 명세가 값의 뜻을 적지 않는다. 원문에서는 숫자 글자였다.

## verify.json

`finalize`가 정리 끝에 같은 폴더에 쓴다. 원문 대조 결과이고 뒤 작업이 `complete.json`에 옮겨 쓴다. 시각은 적지 않는다. 같은 원문이면 같은 파일이 나온다.

| 키 | 뜻 |
|---|---|
| `format_version`, `date`, `buckets` | 형식 버전, 날짜(`YYYYMMDD` 수), 버킷 수 |
| `passed` | Parquet을 다시 읽은 종목·타입별 행 수와 첫·끝 `recv_ms`가 원문에서 센 값과 모두 같으면 `true`. 파일이 종목·시각 순이 아니거나 종목이 자기 버킷 파일에 있지 않거나 파일을 읽을 수 없어도 `false`다. |
| `lines` | 원문 줄을 셋으로 나눈 개수. `finalized`(정리됨: 줄의 모든 내용이 Parquet에 든 실시간 프레임), `control`(제어: LOGIN·REG 응답, `live`·`down` 사건), `unfinalized`(정리 못 함). `total`은 셋의 합이다. |
| `lines.unfinalized` | `total`과 종류별 `kinds`. 줄 하나는 한 종류로만 센다. 아홉 종류가 늘 있다(0이어도 적는다). |
| `unknown_realtime_types` | 모르는 실시간 타입 코드 → 항목 수 |
| `unknown_fids` | 타입 → 명세에 없는 FID(글자) → 나온 횟수 |
| `unparsable_values` | 타입 → FID → 형대로 읽을 수 없어 `NULL`로 저장한 값의 횟수 |
| `rows` | 타입 → 종목 → `rows`·`first_recv_ms`·`last_recv_ms`. Parquet을 다시 읽어 센 값이다. `passed`이면 원문 값과 같다. |
| `symbol_messages` | `item`별 `REAL` 항목 수(타입을 가리지 않고 모르는 타입도 센다). 다음 날 수집 계획이 부하로 쓴다. |
| `mismatch_count`, `mismatches` | 다른 곳의 수와 처음 100개. `kind`는 `rows`(행 수나 `recv_ms`가 다름), `order`, `bucket`, `schema`, `unreadable_file`이다. |
| `files` | 파일 상대 경로, 행 수, 바이트 수 |

`lines.unfinalized.kinds`의 종류는 다음과 같다. 하나라도 0이 아니면 그날 원문에는 Parquet에 온전히 옮겨지지 않은 내용이 있다.

| 종류 | 줄 |
|---|---|
| `malformed_realtime_frame` | `trnm`이 `REAL`인데 `data`가 배열이 아니거나 항목에 `type`·`item`·`values`가 없다 |
| `unknown_realtime_type` | 받는 열한 타입이 아닌 항목이 든 프레임 |
| `unknown_fid` | 명세에 없는 FID가 든 프레임 |
| `unparsable_value` | 값을 열의 형으로 읽을 수 없는 프레임 |
| `other_frame` | `trnm`이 `REAL`·`LOGIN`·`REG`가 아니거나 `trnm`이 없는 JSON. REST 원문이 여기 든다 |
| `non_json_text` | JSON이 아닌 글자 줄 |
| `broken_line` | 줄 모양이 깨진 줄 |
| `truncated_file`, `unreadable_file` | 줄이 아니라 읽지 못한 파일 하나를 센다 |

`--verify-only`는 버킷 수를 Parquet 파일의 메타데이터에서 읽는다. 파일이 하나도 없는 날은 `--buckets` 값을 쓴다.

`finalized`는 프레임의 `trnm`·`data`와 항목의 `type`·`item`·`values`를 모두 저장했다는 뜻이다. 그 밖의 필드(`name` 등)는 읽지 않고 버린다. `values`가 객체가 아니거나, 키 하나를 글자로 풀 수 없거나(짝 없는 서로게이트 이스케이프), 필드가 없거나 `null`이면 그 항목은 `malformed_realtime_frame`이고 행이 없다. `symbol_messages`는 항목의 `type`이 글자이고(없거나 `null`이어도 된다) `item`이 글자이며 같은 필드가 두 번 없을 때 그 `item`을 센다. `type`이 글자가 아니거나 같은 필드가 두 번 있으면 세지 않는다.

한 줄에 문제가 둘 이상이면 표 위쪽 종류로 센다(`malformed_realtime_frame`이 가장 앞). 줄에 여러 항목이 있으면 문제 없는 항목은 행으로 저장된다. 줄은 정리 못 함으로 센다.

### 형을 정한 방법

- 키움 공식 명세(Kiwoom-Securities/Kiwoom-REST-API `c7a3d25449ed4b4238bef378780c41103c67b9e9`의 `kiwoom/_data/kiwoom_api_spec.json`) 실시간시세 절에서 FID 표를 가져왔다. 가져오는 명령은 `python3 scripts/kiwoom_realtime_fids.py <명세 파일> --json`이고 결과는 `crates/collector/src/finalize/realtime_fids.json`이다. 이 문서의 열 표는 같은 스크립트의 `--markdown` 출력이다.
- 형은 FID 이름과 명세 예시로 정했다. 문자: 시각·거래원 이름·코드·색깔·종목 코드·종목명·구분 코드·`ticker`·종목정보류. 실수: 이름이 `율`이나 `강도`를 포함하는 FID(등락율, 비율, 괴리율, 체결강도)와 `0J`·`0U`의 지수 값(`10`·`11`·`16`~`18`). 나머지는 정수다.
- 실제 원문(`0B`·`0D`·`0w`·`0F` 십만여 줄)에서 모든 FID가 이 형으로 읽혔고 명세 밖 FID는 없었다. 나머지 일곱 타입(`1h`·`0H`·`0E`·`0g`·`0J`·`0U`·`0s`)은 실제 원문이 없고 명세 예시만으로 정했다. 형이 틀려 읽지 못한 값은 `NULL`로 저장하고 `unparsable_values`로 센다. 틀린 형은 이 문서와 `realtime_fids.json`을 함께 고친다.

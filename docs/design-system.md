# UI 테마와 공통 컴포넌트 바꾸기

[라임 다크 UI 스펙 #181](https://github.com/Soochol/vallythevally/issues/181)과 [차트 중심 UX 스펙 #200](https://github.com/Soochol/vallythevally/issues/200)의 적용 방법을 설명한다. 색과 겹침 표면은 [플로트 스타일 스펙 #270](https://github.com/Soochol/vallythevally/issues/270)을 따른다. 설계 배경은 [설계 맵 #178](https://github.com/Soochol/vallythevally/issues/178)에 있다.

## 테마 바꾸기

1. `web/src/styles/tokens.css`에서 배경, 표면, 글자, 간격, 반지름과 글자 크기를 바꾼다. 이 파일을 테마 값의 원본으로 사용한다.
2. 주요 행동과 선택에는 `--accent`를 사용한다. 경고는 `--warning`, 오류와 삭제는 `--danger`, 성공은 `--success`를 사용한다. 상승과 하락의 `--up`, `--down`은 상태 메시지에 사용하지 않는다.
3. 차트 전용 색도 같은 파일에서 바꾼다. `readThemeTokens`가 격자, 봉, 거래량, 지표 기본색과 비교 종목 색을 읽는다. 새 토큰을 추가하면 `web/src/chart/theme.ts`와 Tailwind 연결이 필요한 `web/src/styles/index.css`에도 연결한다.
4. 앱을 다시 빌드해 차트와 지표, 드로잉, 대화상자, PNG 내보내기를 확인한다. 사용자 지정 HEX 색은 테마가 바뀌어도 유지한다.

현재 UI는 다크만 제공한다. 첫 HTML부터 `color-scheme: dark`를 적용한다. `parseUiState`는 과거 `light` 설정을 `dark`로 읽고 다른 설정을 보존한다. 서버의 과거 테마 값 수용 범위는 바꾸지 않는다.

## 화면과 대화상자 추가하기

1. 기존 버튼의 `tb-btn`, `seg-btn`, `icon-btn`, `btn-primary`를 사용한다. 크기와 상태 표현을 새 화면마다 다시 정의하지 않는다.
2. 입력에는 `ui-field`, 대화상자에는 `DialogFrame`을 사용한다. 머리와 하단 행동은 `ui-dialog-head`, `ui-dialog-foot`에 맞춘다. 설정 항목에는 `Row`, 짧은 선택에는 `Segment`, 검증 메시지에는 `Errors`를 사용한다.
3. 탭은 `ui-tabs`와 `tablist`, `tab`, `tabpanel` 역할을 함께 사용한다. 좌우 화살표, Tab, Escape와 닫은 뒤 포커스 복귀를 확인한다.
4. 화면 높이가 줄면 내용 영역 안에서 스크롤하게 한다. 대화상자 하단의 저장과 취소는 내용 밖에 둔다. 페이지 자체의 크기를 늘리거나 필요한 조작을 잘라 숨기지 않는다.

데스크톱 셸은 차트를 창 전체에 깔고 그 위에 섬 두 개를 띄운다(#270). 위 막대는 높이 48px, 오른쪽 패널은 창 높이를 쓰며 둘 다 가장자리에서 12px(`--island-gap`) 떨어진 `.ui-island`다. 차트 칸은 패널 섬만큼 오른쪽을 비워 가격축이 패널 왼쪽에 온다. 범례는 `--chart-inset-top`만큼 내려 위 막대 섬을 피한다. 창 폭이 1280px보다 좁으면 위 막대가 창 폭을 쓰고 패널은 그 아래에서 시작한다. 넓게 보는 스크리너는 위 막대 아래 전체를 불투명하게 덮는다. 드로잉 도구는 차트 아래 가운데의 알약 모양 도크(`.drawing-toolbar.ui-island`)다. 패널 섬을 뺀 차트 영역의 가운데에 두고, 가격축 방식 버튼과 겹치지 않게 최대 폭을 줄여 넘치면 도크 안에서 가로로 스크롤한다. 상태 줄(`StatusBar`)은 패널 섬 바닥에 있고, 패널을 숨기면 차트 왼쪽 아래, 도크보다 한 줄 위의 작은 띠로 옮긴다. 휴대폰 머리는 첫 줄에 종목 이름·코드와 재무자료·캡처, 둘째 줄에 가격과 거래소 묶음, 셋째 줄에 연결 상태와 출처를 둔다. 휴대폰 아래 탭은 알약 모양 섬이다. 가격축 방식(자동·로그·%)은 `AxisMode`가 차트 칸의 가격축 옆 아래에 그린다. 오른쪽의 관심종목·스크리너·개체·지표 탭은 `RightPanel`이 소유한다. 지표 탭은 지표 창이 차트 옆 방식일 때만 레일에 보인다. `UiPrefs.rightPanel`에 선택 탭, `watchCollapsed`에 숨김, `rightPanelWidth`에 기본/넓은 너비를 저장한다. 숨긴 탭은 위 막대 버튼이나 Alt+W로 다시 연다. 스크리너는 기존 `ScreenerPanel`을 탭 안에서 재사용하고, 결과를 골라도 왼쪽 차트를 유지한다. 조건식 편집의 저장, 충돌 처리와 조건 검사는 기존 로직을 유지한다.

위 막대 섬은 왼쪽부터 로고, 종목 버튼(이름·코드, 종목 검색을 연다), 봉 주기(분봉 버튼과 일·주·월·분기·연), 지표, 비교를 두고 오른쪽에 재무자료, 캡처, 차트 설정, 검색 아이콘을 둔다. 차트 설정 버튼(슬라이더 아이콘과 글자)은 버튼 아래에 폭 320px의 `ChartSettingsPopover`를 연다. 팝오버는 보이는 봉 수(자동·60·120·240·480과 10~2000 직접 입력), 화면 내 최고·최저 스위치, 봉 모양, 가격 축, 지표 창 방식(가운데 창·차트 옆)을 차례로 두고, 확인 버튼 없이 활성 칸에 바로 반영한다. 가격 축은 `AxisMode`와 같은 규칙(`pressScale`, 비교 종목이 있으면 % 고정)을 쓴다. 화면 내 최고·최저 꼬리표는 `ChartController`가 가격 패널 위에 DOM(`.chart-extreme`)으로 얹고, 오른쪽 가장자리에 가까우면 왼쪽으로 뒤집는다. 차트 이미지에는 넣지 않는다. 재무자료 버튼은 전체 업데이트 상태를 점(진행 중은 강조색, 완료는 성공색, 멈춤·실패는 경고색)과 진행률로 보이고, 누르면 버튼 아래에 배경 없는 상태 창을 연다. 상태 창은 제목·진행 막대·정지 사유·경고와 실행 버튼만 먼저 보이고 `자세히`에서 전체 현황과 실패 목록을 편다. 휴대폰에서는 같은 내용을 아래 시트로 연다.

거래소 선택은 범례 머리의 `venueAnchor`에 기존 `VenuePicker`를 연결한다. 상태 막대의 재무 표시는 차트의 재무 조회 캐시를 구독하며 별도 수집 요청을 시작하지 않는다. 장 상태와 시계는 HTTP 응답으로 맞춘 서버 기준 한국 시각을 사용한다.

관심종목 패널 머리는 목록 메뉴, 종목 수, "+ 그룹", 종목 넣기 버튼 순서다. 관심종목 그룹(ADR 0017)이 있으면 그룹마다 머리 줄(접기 화살표, 이름, 종목 수 배지, 그룹 메뉴)을 두고 그 아래에 그룹의 종목을 보인다. 마지막에 그룹 없음 머리와 남은 종목을 둔다. 그룹 없음은 접지 않고 남은 종목이 없으면 머리를 감춘다. 그룹이 하나도 없으면 그룹 머리 없이 한 목록으로 보인다. 그룹 메뉴는 이름 바꾸기, 위로 옮기기, 아래로 옮기기, 그룹 풀기, 그룹 지우기이고 지우기는 `confirmAction`으로 확인한다. 종목 우클릭 메뉴의 "그룹으로 옮기기"는 그룹들과 그룹 없음을 라디오로, 맨 아래에 "새 그룹…"을 둔다. 휴대폰 편집에서는 그룹이 있을 때 종목 줄에 그룹으로 옮기기 버튼을 더한다. Alt+↑↓·맨 위로·끌어 놓기는 같은 그룹 안에서만 순서를 바꾼다. 접힘은 `UiPrefs.collapsedWatchGroups`에 저장한다.

## 색상 선택 연결하기

1. 팝업으로 고를 때는 `features/color/ColorPicker.tsx`를 사용한다. `label`, 현재 CSS 색, 선 굵기와 `onChange`를 전달한다. 작은 도구 막대에서는 `compact`를 켠다. 드로잉이 이 방식을 쓴다.
2. 폼 안에 펼쳐 고를 때는 `features/color/ColorTable.tsx`를 사용한다. 테마 줄(선택), 색상표, 최근 줄, HEX 표시와 "직접 고르기"를 그린다. "직접 고르기"는 `ColorDialog`의 사용자 지정 화면을 연다. 지표 설정이 이 방식을 쓰고 `theme`에 `ind-1`~`ind-5`를 넘긴다.
3. 입력이나 저장소에서 온 색은 `normalizeHex` 또는 `isHexColor`로 검사한다. 선택기가 반환한 `HexColor`는 정규화된 `#RRGGBB`이다.
4. 색상표는 `lib/colors.ts`의 `COLOR_TABLE`이다. 열 10개(빨강·주황·노랑·라임·초록·청록·하늘·파랑·보라·분홍)와 줄 4개(밝게·기본·진하게·무채색)다. 두 선택기의 표는 같은 `ColorGrid`이고, 스와치는 `aria-label`(색 이름과 HEX)과 `aria-pressed`를 갖는다. 값을 바꾸면 개수, 중복과 색 변환 시험을 실행한다.
5. 최근 8색은 `vv.recent-colors.v1`에 저장한다. 선택창에서 취소하면 부모의 색은 바뀌지 않는다. 지표의 색과 굵기는 지표 추가 또는 변경 적용 때 차트 설정에 저장한다.

지표의 테마 줄에서 고른 색은 `ind-1`부터 `ind-5` 토큰으로, 색상표·최근 줄·직접 고르기에서 고른 색은 HEX로 저장한다. 이 구분은 [ADR 0013](adr/0013-indicator-theme-and-custom-colors.md)을 따른다.

## 선 굵기 검증하기

지표와 드로잉은 1부터 5까지 제공한다. Lightweight Charts의 기본 선 타입은 4까지만 허용하므로 지표 선은 공통 사용자 렌더러를 사용한다. 가격 패널은 주 종목 종가를 퍼센트 기준으로 사용하고, 아래 지표 패널은 지표 값만 축 범위에 넣는다. `OverlayLineView`를 바꾸면 두 축 규칙, 굵기 5와 PNG 내보내기를 함께 확인한다.

## 변경 확인하기

저장소 루트에서 `python3 scripts/web.py check`와 관련 `python3 scripts/web.py e2e e2e/<파일>`을 실행한다. 도구가 WASM과 개발용 서버·가짜 키움을 준비하고 컴파일 잠금을 관리한다. 변경 없는 WASM은 재사용한다. E2E는 이번 실행의 웹 산출물과 임시 DB를 사용하며 결과는 `target/web-runs/` 아래에 분리한다. 자세한 절차는 [웹 검사](web-checks.md)를 따른다.

1024×768, 1280×720, 1440×900과 높이 300px 창에서 문서가 넘치지 않는지 확인한다. 낮은 창에서는 드로잉 도구를 내부 스크롤로 끝까지 열 수 있어야 한다. 화면 변경 시에는 390×844도 확인한다.

## 겹침 화면 추가하기 (#200·#202)

`features/overlay/Popover.tsx`를 사용한다. `anchor`에 연 버튼의 ref, `onClose`에 닫기 동작을 전달한다. 컨텍스트 메뉴에는 `point`, 이동하는 도구 막대에는 `follow`를 전달할 수 있다. `anchor`는 위치 기준과 실제 여는 버튼이며, 닫은 뒤 돌아갈 대상이 다르면 `focusTarget`을 별도로 전달한다. 좌표로 연 메뉴는 여는 버튼 없이 메뉴 표면만 내부로 보고, 차트는 포커스 복귀 대상으로만 사용한다. 위치를 직접 지정하는 absolute 메뉴나 별도 portal을 만들지 않는다.

- HTML Popover API의 맨 위 층에 렌더링한다. `position.ts`가 가장자리에서 반대쪽을 선택하고 화면 안으로 맞춘다. 내용 크기·창 크기·스크롤이 바뀌면 다시 계산한다.
- Esc와 바깥 누르기는 맨 위의 조작 가능한 화면만 닫고 연 버튼으로 포커스를 돌린다. 배경이 있는 창은 `backdrop`을 전달하며 직접 배경 닫기 핸들러를 달지 않는다. 바깥 pointerdown과 뒤따르는 click은 하나의 입력으로 소비해 부모의 버튼을 함께 실행하지 않는다. 중첩 색상 선택기에서 Esc를 누르면 부모 설정창은 남는다.
- 공통 표면은 `.ui-popover`와 `.ui-dialog`다. 유리 바탕(`--glass`), 흐림(`--glass-blur`), 반경 16, 테두리를 겸한 그림자(`--shadow`)를 여기서 한 번 정한다. 화면마다 이 값을 재정의하지 않고, Popover의 `className`에는 크기와 안쪽 여백만 준다. `backdrop-filter`를 못 쓰거나 `prefers-reduced-transparency`이면 `--glass-solid`로 불투명하게 그린다.
- 명령 입력창(종목 검색·지표)의 배경은 투명하다. 어두운 배경(`--scrim`)은 일반 대화상자와 확인 창만 쓰고, 배경을 흐리게 하지 않는다.
- 묶음 버튼(`seg-btn`)의 선택은 `--accent` 채움과 `--accent-ink` 글자다. 가리킴은 `--hover`를 쓴다.
- 메뉴 행은 높이 32px이고 왼쪽 14px 아이콘·체크 칸, 오른쪽 단축키 칸(`hint`)을 쓴다. 지우기는 맨 아래에 `danger`로 둔다. 실제로 동작하는 단축키만 `hint`에 적는다.
- 차트 빈 곳의 우클릭 메뉴(`drawingMenu`)는 머리에 누른 가격과 날짜(봉이 없는 곳이면 가격만)를 두고, 이 가격에 수평선·관심종목에 넣기·축 자동 맞춤·차트 이미지 복사를 먼저, 드로잉 일괄 동작을 아래 묶음에 둔다. 붙일 것이 없으면 붙여넣기를 보이지 않는다.
- 일반 메뉴는 `features/menu/Menu.tsx`의 `MenuItem`으로 만든다. `radio`·`check`·`action`·`heading`·`separator`를 지원한다. ↑↓·Home·End·Enter·Space·글자 입력으로 이동/선택한다. 메뉴 키보드는 차트 단축키로 전파하지 않는다.
- 폼의 선택 항목은 `Select`에 `label`, 현재 값, `options`, `onChange`를 전달한다. 브라우저 기본 select를 새로 만들지 않는다. 분봉은 `MinuteMenu`를 쓴다. 버튼은 마지막 분봉을 보이고, 활성 칸이 분봉이 아니면 누를 때 그 분봉으로 바꾸며, 분봉이면 1·3·5·10·15·30·60분을 한 줄씩 두고 오른쪽에 단축키를 적은 세로 목록을 연다. 자석 세기는 버튼의 우클릭·길게 누르기 메뉴를 쓴다.
- 일반 대화상자는 `DialogFrame`을 사용한다. 되돌릴 수 없는 작업은 `confirmAction(문구, { action, danger })`의 결과를 기다린다. `action`에는 무엇을 하는지 적고(예: `목록 지우기`), 지우는 일에는 `danger`를 켠다. 기본 포커스는 취소다. 일반 알림은 `showToast(문구)`를 사용한다. 드로잉 삭제는 `DrawingSync.commitWithUndo(칸, 변경, 문구)`를 사용해 삭제 당시의 history 객체를 작업 식별자로 묶는다. 기록이 바뀌거나 취소된 알림의 되돌리기는 비활성화되고, 실행 시에도 같은 식별자인지 다시 검사한다. 알림의 되돌리기에 Ctrl+Z가 실제로 동작하는 경우(드로잉 삭제)만 `ToastUndo.shortcut`으로 키 칩을 보인다. 칩은 `aria-hidden`이고 `aria-keyshortcuts`로 알려 접근성 이름은 `되돌리기` 그대로다. 메뉴 항목에 단축키 힌트를 붙이면 접근성 이름이 바뀌므로 시험이 정확한 이름으로 찾는 항목에는 붙이지 않는다. 알림은 6초 동안 보인다.
- `TooltipHost`는 기존 `title`을 공통 툴팁으로 표시한다. `이름 (키)` 모양의 title은 이름과 단축키 칩으로 나눠 그린다. 단축키가 있는 버튼의 title에는 키도 적는다. 기존 aria-label과 title은 바꾸지 않는다.
- 차트 키 처리에는 `ownsChartKeyboard`를 먼저 검사한다. 열린 조작 표면이나 그 안의 이벤트를 차트 단축키가 가로채지 않는다. 알림만 `blockChartKeys={false}`를 사용해 차트의 Ctrl+Z를 유지한다.
- React 밖에서 만드는 화면은 `topLayer.ts`의 `mountLayer`를 사용하고 반환한 정리 함수를 화면 제거 시 호출한다. 재무 보고기간의 `domSelect`도 같은 위치·닫기·포커스 처리를 쓴다.

상태 화면은 `Skeleton`, `EmptyState`, `ErrorState`를 사용한다. 빈 상태에는 다음 행동, 오류에는 회복 동작을 함께 전달한다. 목록과 차트, 드로잉 패널의 상태를 이 부품으로 표시한다.

## 공통 아이콘과 치수

`features/icons.tsx`의 `Icon`이 24×24·1.5px·currentColor 규칙을 소유한다. 드로잉도 `Icon`에 `path`를 전달한다. 공통 드로잉 그림은 `DRAWING_ICONS`에 두며 도구가 제공하는 기존 `tool.icon` 문자열도 그대로 전달할 수 있다. 새 도구나 아직 쓰지 않는 아이콘은 미리 추가하지 않는다.

DOM 범례는 `iconMarkup("gear" | "eye" | "eyeOff" | "close" | "up" | "down")`으로 같은 그림을 문자열로 얻는다. 이 결과에는 고정된 아이콘 데이터만 들어가며 사용자 문자열을 HTML에 넣지 않는다. 버튼의 title·aria-label은 버튼에 둔다.

`tokens.css`의 반경은 7/9/16/18, 최소 글자는 11px이며 숫자는 전역 `tabular-nums`를 상속한다. `ui.css`와 `colors.css`의 치수는 `--size-*` 토큰을 참조하고 간격은 4px 배수를 사용한다. 색 토큰 값은 #270을 따른다. `--line`과 `--grid`는 반투명 흰색이므로 색 문자열을 직접 가공하지 않는다. 마지막 분봉은 `UiPrefs.lastMinute`로 저장하고, 단축키·휴대폰 칩까지 잡도록 메뉴가 아니라 활성 칸의 봉 주기를 지켜보는 `followLastMinute`에서 바꾼다. 분봉이 아닌 값은 읽기 경계에서 3분으로 바꾸고, 옛 `pinnedMinutes`는 읽을 때 버려 다시 저장하지 않는다. 서버 API는 바꾸지 않는다.

시안 원본 9장은 [docs/mockups/ux-overhaul](mockups/ux-overhaul/)에, 플로트 시안은 [docs/mockups/float](mockups/float/)에 보관한다. 기능 규칙은 시안보다 #200과 #181이 우선이며 색상 선택기의 색상표(10색 4줄)·최근 8색·HEX·선 샘플과 굵기 1~5를 유지한다.


## 드로잉 조작 연결하기

`DrawingToolbar`는 등록된 도구만 그룹으로 표시한다. 고른 도구(선택·그룹·고정 도구)는 `--accent`로 채우고, 자석·연속 그리기 같은 켜짐 표시는 옅은 강조 면을 쓴다. 그룹 펼침 메뉴와 단축키 도움말은 도크 위로 연다. 펼침 메뉴의 별표는 `UiPrefs.drawing.pinnedTools`에 저장하며, 읽을 때 구현되지 않은 도구와 중복을 제외한다. 고정 도구와 연속 그리기 상태는 별개다.

고른 드로잉의 작은 막대는 공통 색상 선택기와 선 굵기·선 모양 선택을 사용한다. 좌표·글자·주기 등 나머지 설정은 `DrawingDetails` 팝오버에 있다. 초안은 차트에 미리 보이고 확인으로 저장하며, 취소·Esc·바깥 누르기는 초안을 버린다. 드로잉 삭제는 기존 `DrawingSync.commitWithUndo`를 사용한다.

개체 탭은 현재 종목의 `DrawingScope`에 따라 이 칸·이 레이아웃 공통·이 종목 모든 칸 공통으로 나눈다. 모든 종목에 걸친 드로잉은 지원하지 않는다. 이름은 `style.objectName`, 순서는 `z`에 저장한다. 이름은 차트 글자인 `text`와 별개이며 복제할 때 함께 복사한다. 기본 스타일로 되돌릴 때 이름을 유지하고, 새 드로잉의 스타일을 기억할 때는 이름을 제외한다.

## 차트 안 조작 요소의 입력 경계

범례·머리에 만드는 실제 조작 요소에는 `data-chart-control`을 붙인다. React 밖에서 만드는 버튼·summary와 조작 팝오버도 같은 표식을 쓴다. `DrawingSurface`는 부모 capture 단계에서 이벤트 경로의 표식을 검사해 드로잉 입력에서 제외한다. 버튼의 bubble 단계에서 전파만 막는 방식으로 대체하지 않는다.

차트 위의 종목명은 `pointer-events: none`으로 십자선·휠·끌기를 통과시킨다. 이름은 말줄임하되 heading의 `aria-label`에 전체 이름을 제공한다. 입력을 소유하는 것은 거래소 같은 실제 조작 요소이며 이 요소에만 `pointer-events: auto`를 준다.

## 범례 설정과 패널

`IndicatorSettingsForm`은 맨 위의 선 미리보기 띠와 두 구역을 그린다. **설정값**은 지표 종류별 입력이고 **선**은 굵기와 `ColorTable`이다. 폼 폭이 600px 이상이면 두 구역을 좌우로, 좁으면 위아래로 쌓는다(컨테이너 쿼리). 굵기는 선 견본 1~5로 고른다. 이동평균 기간에는 자주 쓰는 값(5·20·60·120)을 둔다. `IndicatorPopover` 머리에서 숨기고 지운다. `Draft`, 현재 색, 검사 오류와 `onChange`를 받아 범례 팝오버와 지표 추가 창에서 함께 쓴다. `IndicatorPopover`는 열 때의 설정을 보관하고 유효한 변경을 즉시 적용한다. Esc는 처음 설정으로 되돌리고, 바깥 클릭과 닫기는 변경을 유지한다. 중첩 색상 선택기의 Esc는 색상 선택기만 닫는다. 공통 Popover의 닫기 사유는 `escape`와 `outside`다.

패널의 높이 비율과 접힘은 `ChartSettings.panels`의 `stretch`와 `collapsed`에 저장한다. 과거 설정에서 `collapsed`가 없으면 펼친다. 접힌 패널은 최신 값과 이름만 한 줄에 표시하고 이름이나 행을 누르면 펼친다. 펼칠 때 저장한 높이 비율을 복원한다. `PanelControls`의 경계 손잡이는 포인터 끌기와 위·아래 화살표를 지원하며 `data-chart-control`로 드로잉 입력에서 제외한다. 재무 패널의 상태 점은 제목 옆에 두고 자세한 상태와 보고기간 선택은 팝오버에 모은다. 결산월은 첫 재무 범례에 한 번 표시한다.

패널 두 개의 현재 높이 합이 최소 높이 합보다 작으면 손잡이는 높이를 바꾸지 않는다. 조절 가능한 경우 인접 두 패널의 stretch 합을 유지하며 비율을 나눈다. 저장할 때 소수점 세 자리로 반올림하지 않아 다른 패널의 높이가 달라지지 않게 한다. 저장된 0·음수 높이는 읽기 경계에서 그 패널의 기본 비율로 복구하고 다른 설정은 보존한다.

열린 지표의 이름·설정 버튼을 다시 누르면 편집 시작값을 유지한다. 다른 지표 버튼은 현재 값을 확정하고 새 설정창으로 바로 전환한다. 이 버튼 묶음만 공통 Popover의 `isInside`로 추가하며, 같은 차트의 나머지 영역은 기존 바깥 클릭 동작을 유지한다.

## 스크리너 조건식

조건 문장은 줄마다 번호 배지(CSS 카운터)를 두고, 고르는 값은 회색 알약, 숫자는 강조색 알약으로 그린다. 오른쪽 탭의 `SentenceEditor`는 조건 요약(조건 문장 최대 3줄과 대상·제외 한 줄), 실행, 편집 버튼만 보인다. 편집 버튼은 공통 `Popover`로 `조건 편집 창`을 패널 왼쪽에 열고, 그 안의 `SentenceFields`에서 문장으로 편집한다. 이 창은 `blockChartKeys={false}`를 써서 차트 단축키를 막지 않고, 창 밖을 누르면 닫히면서 그 클릭도 그대로 실행된다. 스크리너 패널 안을 누르는 것은 `isInside`로 창 밖으로 보지 않아 창을 연 채 실행하고 결과를 고를 수 있다. Esc·닫기 버튼으로도 닫으며 포커스는 편집 버튼으로 돌아간다. 창 안에서 Ctrl+Enter는 실행, Ctrl+S는 저장, N은 조건 추가다. 이름은 창 머리의 입력이나 조건식 메뉴의 이름 바꾸기로 고친다. 검증에 실패한 실행·저장은 창을 열고 잘못된 값에 포커스를 둔다. 새 조건식을 만들면 창이 바로 열린다. 넓게 보기는 창이 결과 표를 가리므로 창을 쓰지 않고, 한 줄 요약에서 조건 펼치기로 `SentenceFields`를 그 자리에 편다. `ConditionFields`는 휴대폰 편집창과 문장 편집이 함께 사용하는 조건별 입력이다. 숫자는 `NumberToken`의 팝오버에서 입력하고 Enter로 적용한다. 봉 수에는 일·주·월과 자주 쓰는 값을 함께 제공하며 Escape는 적용 전 입력을 취소한다.

`editorState`는 조건식별 draft와 저장 기준 revision을 메모리에 보관한다. 탭이나 조건식을 바꿔도 draft는 유지한다. 변경이 없는 세션은 최신 저장본을 따르고, 편집 중인 세션은 draft와 충돌 기준 revision을 보존한다. 개수 제한은 최신 목록으로 검사한다. 창을 닫거나 조건을 접어도 draft는 남고 패널은 `변경됨`을 보인다. 저장 버튼은 창이 열려 있으면 창 바닥에, 아니면 패널 머리에 하나만 둔다. 넓게 보기의 왼쪽 목록에도 미저장 식을 표시한다. 실행 버튼과 Ctrl+Enter 명령은 기존 `checkDraft`로 검증한 draft를 실행한다. 저장 충돌에서는 최신 목록을 저장 기준으로 삼고 편집 내용은 남겨 다시 저장할 수 있다.

## 지표 창

`I`, 위 막대의 지표·비교, 명령 검색과 휴대폰 지표 버튼은 `features/indicator-command/open.ts`의 `openIndicatorCommand(slot, mode?, indicatorId?)`를 호출한다. 이 함수가 `UiPrefs.indicatorWindow`(기본 `"dialog"`)와 `DESKTOP_QUERY`를 보고 가운데 창이나 차트 옆 인스펙터를 연다. 데스크톱이 아니면 설정과 상관없이 가운데 창이다. 탭은 `current`(이 칸에 띄운 지표), `add`(지표 추가), `compare`(비교 종목)이다. 모드를 주지 않으면 띄운 지표가 있을 때 `current`, 없을 때 `add`로 연다. 위 막대의 비교 버튼은 `compare`로 연다. 종목 검색과 같은 `CommandFrame`을 쓰며 크기는 976×656px, 왼쪽 목록은 300px이다. 휴대폰 폭에서는 목록과 편집 영역을 위아래로 쌓는다. `DialogFrame`의 command 변형은 배경을 칠하지 않아 차트가 그대로 보인다. 입력 중인 가격 패널 지표는 `CellView.previewIndicator`로 전달해 같은 색의 옅은 후광(굵기 8, 불투명도 18%)과 함께 그린다.

`commandRows`가 탭마다 목록을 만든다. `current`는 띄운 지표만 가격 패널·아래 패널로 묶고 색 점과 숨기기·지우기를 둔다. `add`는 `parseIndicatorInput` 후보만 가격 패널·아래 패널·재무지표로 묶고, 입력이 비면 모든 종류를 보인다. `compare`는 기존 검색 API가 반환한 종목만 보이고 3개 제한·중복 방지와 % 축 규칙을 유지한다. `current` 탭은 열 때 첫 지표를 골라 편집 미리보기를 띄우고, Enter는 변경 적용이다. `current` 탭에서 글자를 치면 `add` 탭으로 넘어간다. 탭을 바꾸면 입력을 비운다. 두 지표 탭의 오른쪽 편집 영역은 같은 `IndicatorEditor`이고 주 버튼 문구만 `primaryLabel`을 따른다. 입력·선택·확정은 `useIndicatorCommand`, 초안·미리보기·확정은 `useIndicatorDraft`가 소유한다.

`parseIndicatorInput`은 한글 이름·영문 약어·초성을 종류에 연결하고 뒤의 숫자를 `KINDS` 필드 순서로 읽는 순수 함수다. `이평 20`, `bb 20 2`, `rsi`, `roe`를 지원한다. 숫자가 생략되면 기본값을 쓰고 잘못된 숫자는 설정 오류로 표시한다. 오른쪽 설정은 범례와 같은 `IndicatorSettingsForm`이다. Enter는 확정 후 계속 추가하고, Shift+Enter는 확정 후 닫는다. Tab은 설정으로 이동하며 Esc와 바깥 누르기는 미확정 미리보기를 버린다.

미리보기는 `useIndicatorPreview`가 소유하고 `ChartCell`이 저장된 설정과 합쳐 컨트롤러에만 전달한다. layout store와 autosave에는 미리보기를 쓰지 않는다. 추가·편집 확정 때만 `executeCommand`가 layout을 바꾼다. 지표 창을 닫거나 후보가 바뀌면 이전 미리보기를 제거한다. 과거 `IndicatorDialog`·`ComparePanel`과 전용 스타일은 제거했다.

차트 옆 방식(5-B)은 오른쪽 패널의 `indicators` 보기에 `IndicatorInspector`를 연다. 머리에 제목과 검색창, 아래에 밑줄형 탭 세 개를 두고, 목록과 입력 규칙은 가운데 창과 같은 `useIndicatorCommand`·`commandRows`를 쓴다. 줄을 누르면 그 자리에서 설정을 하나만 펼치고, 접힌 줄에는 `specName`의 설정값 요약을 보인다. 띄운 지표는 범례 팝오버와 같은 `useLiveIndicatorDraft`로 값을 바로 반영하고 Esc는 펼친 뒤의 변경을 되돌리고 접는다. 지표 추가는 `useIndicatorDraft`로 차트에 미리 그리고 추가 버튼이나 Enter로 확정한다. 비교 종목은 가운데 창과 같은 `CompareSection`을 쓴다. 차트가 미리보기이므로 선 미리보기 띠는 그리지 않는다. 범례의 설정 버튼은 차트 옆 방식에서 범례 팝오버 대신 인스펙터의 그 지표를 펼친다. 열기 요청(탭, 펼칠 지표)은 `useSelectionStore.inspector`에 한 번만 남기고 인스펙터가 받아 검색창에 초점을 준다. 가운데 창으로 되돌리면 `rightPanel`이 `"indicators"`일 때 `"watch"`로 바꾸고, 저장값을 읽을 때도 같은 규칙을 적용한다.

# 종목 생애 보조패널 배치 조사

확인일: **2026-11-08**(전 항목). 정적 검토: **자료 처리·커서 상태를 분리하면 가능**하다.

**코드 근거.** [템플릿](report-template.html)의 `renderCaseChart()`는 선택을 모으고, `renderChart()`는 주별 SVG를 만든다(90~108·115·141~146행). `describe()`와 커서는 호출 내부 변수라 패널 간 공유되지 않는다. 8사례·지수 포함 10계열에는 분기 시계열·관측값별 발표/수정 이력은 없다. `populatePeers()`의 종목 전환 시 비교 선택 초기화도 고려한다. [데이터](report-data.json)

**우선 배치안(제안).** 기본 3단은 가격→매출·영업이익→상대강도(RS), 시장환경은 접는 4단으로 두고 경제지표는 원천 확인 후 하나만 선택한다. 종목·기간·지수·커서를 공유하여 선택/테마 변경 때 전 패널을 갱신한다. 기간은 유지하고 커서는 범위 밖일 때만 보정한다. 커서는 주별 표본이 아닌 날짜·발표일 기준이다. 모든 패널은 같은 달력 날짜→x 변환·좌우 여백을 쓰고, 단위가 다른 y축은 각각 둔다. [SVG2](https://www.w3.org/TR/SVG2/coords.html)로 좌표만 확인했다.

**빈도와 공개 시점.** 현재 `align()`은 모든 계열의 날짜 교집합이므로 재무를 넣으면 가격 관측 대부분과 비거래일 발표가 빠진다(항상 전부 소실하지는 않음). 일별 가격/RS·분기 재무·일정 이벤트는 날짜 영역만 공유한다. 발표일부터 계단형으로 나타내는 ‘당시 알려진 최근 값’과 결산분기의 실적 막대는 구분한다. 막대도 공개 전에는 가리고 누적/단독분기 여부를 확인한다. 선의 forward-fill은 **공개 후에만**, 실제 관측일·발표일·마지막 값 유지임을 라벨에 남기며 첫 공개 전은 공백으로 둔다.

**미래가리기.** `renderStudy()`는 가격 종료일과 `asOf`를 제한하고 빌더는 메모 출처의 `published`를 검사하지만, 새 재무의 공개 가능성까지 보증하지 않는다. `period_end`, `published_at`, 수정본의 공개시각·접수번호를 분리 보존하고 커서 시점까지 공개된 버전만 선택한다. 현시점 수정재무를 과거에 소급하지 않는다. 최초 공시본이 없으면 ‘당시 수치 미복원’으로 가리고, 정정 후 복기 모드에서만 보여준다. [빌더](build-report.py) `main()`의 양수 검증과 `renderChart()`의 100기준·양수/로그 축은 손실·결측 재무에 별도 처리가 필요하다.

**작은 화면·조작.** 현재 `1060×340` SVG·`height:auto`는 모바일에서 문자도 축소한다. 패널별 최소 높이·HTML 값 표·세로 스크롤을 쓰고 `100vh`는 피한다. 공통 커서 한 곳에 포커스를 두고 좌우·상하·Home/End와 날짜 직접 입력으로 전 패널 값을 읽도록 제안한다. 현행은 좌우·Home/End만 지원한다. `aria-valuetext`로 날짜·단위·결측을 읽고 터치 보조기기를 검증한다. [W3C Slider](https://www.w3.org/WAI/ARIA/apg/patterns/slider/)

**용량·미확인.** 현재 HTML은 **413,539바이트**, 빌더의 512KiB 미만 검사까지 여유는 **110,749바이트**다. 분기 원자료만 압축 저장하고 일별 채움 배열·중복 지수는 피한다. native chat은 ‘512KB 미만·인라인·네트워크 요청 불가’ 안내이므로 보수적으로 512,000바이트 아래를 목표로 최종 실측한다. [앱 안내](/home/dev/.local/opt/orca/squashfs-root/resources/native-chat-visuals/skills/orca-chat-visuals/SKILL.md) 추가 용량은 미측정. 공식 문서·기존 파일만 확인했고 새 금융/API 표본은 미수집이다. 원천·인증은 다른 담당 범위이며 동작·성능·예측력·인과는 미검증이다.

```text
                └ 공통 날짜 눈금 + 관측일/발표일/값 표
```

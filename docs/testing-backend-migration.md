# Rust backend migration ledger

All existing assertion bodies remain with their test unless the row names an explicit split. `ScriptedTransport` implements the production `Transport` trait directly; it owns only fixture pages/scripts/request observations. It has no listener, HTTP/admin routes, broker session implementation, or subprocess. KRX/investor files are pure typed fixture generation and page serialization, retained for deterministic actual-service calculations.

The production `app::application` graph is shared by runtime and integration fixtures. `common::Server` owns a dedicated test-thread Tokio runtime and real in-process Axum application with injected transport and detached stream; HTTP contract tests still traverse actual middleware/router. Direct fundamentals use Router::oneshot; summary and yearly services use paused Tokio time. SQLite/network integration cases keep normal Tokio time to avoid auto-advance racing SQL pool/thread I/O.

## Accepted implementation reconciliation

The production service graph is extracted once into ApplicationInputs/application; initial token policy, initial symbol loading, and daily maintenance are shared entry points. Integration fixtures own a dedicated current-thread Tokio runtime on a test-owned thread because aborting only Axum leaves detached production collection tasks running across a simulated restart. Dropping the entire runtime before reopening files preserves the old process lifecycle contract while keeping tests in-process. Real HTTP/SQLite integration assertions keep actual Tokio time; direct collection and bar-service assertions use paused time. The app’s blocking store-open task receives the test’s scoped trace dispatcher so migration/error-log assertions remain real observations. No production shutdown/debug API was added for test convenience.

## Financial observation synchronization

The former request-observation helpers polled every 5–20 ms and required a selected request within 5–10 wall-clock seconds. That time included preceding production requests, each subject to the real shared DART interval, along with SQLite checkpoints and concurrent test load. The request history is append-only, so the timeout was not a lost-event race. A paused-time regression reproduced the failure while earlier requests continued to arrive.

The synthetic source now notifies observers whenever it records a request. Waiters register before checking the persistent request history, allow ten seconds without source progress, and retain a sixty-second overall watchdog. An idle source still fails promptly, with endpoint and report/company scope diagnostics that omit credentials. Production pacing, bounded retries, durable pause/restart outcomes, and one-second price-availability assertions remain unchanged. The recommended four test threads bound concurrent real HTTP/SQLite fixtures.

A separate correction-restart test previously waited six seconds by counting polling iterations. Its failed run still showed planning at 12 of 28 symbols, before the selected report could be requested. It now uses the same source barrier. Whole-job completion observes both source calls and public job progress, fails after sixty seconds without either, and has a 180-second overall watchdog; source pacing and checkpoint work no longer consume a fixed sixty-second completion deadline. The company-read helper waits for the real terminal job and asserts that the company is no longer collecting.

The new paused-time regressions are `source_observation_waits_while_earlier_paced_requests_are_progressing` and `source_observation_stops_when_no_source_request_progresses`. The first failed under the former global deadline and passed with progress synchronization; the second preserves prompt failure for a stalled source.

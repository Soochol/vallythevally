# 구간 거래량 프로파일을 분봉 기준으로 계산하기 (2026-11-14)

작성일 2026-11-14. 승인 시점의 기록이며 구현 중 바뀐 것은 반영하지 않는다.

## 사용자가 풀려는 문제

사용자의 말(그대로): "미뤄둔것도 진행하자"

드로잉 2차에서 미뤄 둔 것 가운데 이 플랜이 맡는 것은 하나다. 구간 거래량 프로파일(`web/src/chart/drawings/tools/volprofile.ts`)은 지금 차트의 봉으로 계산한다. 봉 하나의 거래량을 그 봉의 저가~고가에 고르게 나누므로, 일봉 차트에서는 가격대별 거래량이 실제보다 뭉개진다. 차트의 봉 주기보다 짧은 분봉을 따로 받아 계산하게 한다.

## 지금 상태 (코드에서 확인한 것)

| 항목 | 상태 | 근거 |
|---|---|---|
| 구간 조회 API | 없다. `GET /api/bars`는 `before`와 `limit`(기본 500, 최대 1000)으로 최신에서 과거로 넘기는 페이지뿐이다 | `crates/server/src/api.rs`의 `BarsPage`, `crates/server/src/bars.rs`의 `page_with` |
| 분봉의 과거 한도 | 키움은 분봉을 최근 1년까지만 준다 | `crates/server/src/bars.rs`의 `reached_origin`, `web/src/chart/ChartController.ts`의 `intradayEnd` |
| 과거 구간으로 건너뛰기 | 주식은 못 한다. 과거 날짜로 바로 조회하면 권리발생이 빠진 가격이 와서, 언제나 오늘부터 연속조회를 따라 내려간다. 1분봉 1년이 191페이지다 | `crates/server/src/bars.rs`의 `extend_older` |

| 서버 캐시 | 시리즈는 10분 동안 요청이 없으면 내려가고, 실시간 구독이 잡은 시리즈는 남는다 | `crates/server/src/bars.rs`의 `evict_idle` |

| 스타일 저장 | 서버는 스타일을 JSON 그대로 저장하고, 도구의 `parseStyle`이 없는 항목을 기본값으로 채운다. 항목을 더해도 마이그레이션이 없다 | `crates/server/src/drawing_api.rs`, `web/src/chart/drawings/tools/volprofile.ts` |
| E2E의 봉 응답 | 합성 시세가 어느 봉 주기든 `before`까지 답한다 | `web/e2e/fixtures/scenario.ts` |

## 확정된 결정

- 구간 거래량 프로파일을 분봉 기준으로 계산한다.
- 실제 키움은 호출하지 않는다. 시험은 주입한 `FetchPage`와 E2E의 합성 시세를 쓴다.
- 지시서의 파일 경로는 저장소 루트 기준 전체 경로로 적는다.

## 스스로 정한 결정과 이유

1. **서버는 바꾸지 않는다.** 구간 조회 API를 더해도 주식은 오늘부터 따라 내려가야 해서 키움 호출 수가 줄지 않는다. 웹이 `before` 페이지를 구간의 시작까지 넘기면 된다.
2. **용어 "세부 봉"을 둔다.** 드로잉을 계산하려고 차트의 봉 주기보다 짧은 분 단위 봉 주기로 따로 받은 봉이다. 차트에는 그리지 않는다. 코드 이름은 `fine`을 쓴다.
3. **세부 봉은 칸마다 한 곳이 가진다.** 새 파일 `web/src/chart/fineBars.ts`가 (종목, 거래소, 세부 봉 주기)마다 `BarFeed` 하나를 두고, 요구된 가장 이른 시각까지 과거 페이지를 받는다. `ChartController`가 만들고 `ChartHost`로 드로잉에 넘긴다. 비교 종목과 같은 방식이라 세대 관리, 재동기화, 실패 처리를 새로 짜지 않는다.
4. **도구 규격은 동기 그대로 둔다.** `ToolContext`에 읽기 함수 하나(`fineBarsIn(t1, t2)`)를 더한다. 결과는 `ready`(봉과 봉 주기), `loading`, `failed`, `none`(쓸 세부 봉 주기가 없음) 가운데 하나다. 도구는 받은 만큼으로 그리고, 자료가 오면 표면이 다시 그린다.
5. **무엇을 받을지는 도구가 선언하고 표면이 모은다.** `ToolSpec`에 선택 항목 `fineRange(d, ctx)`를 둔다. `DrawingSurface`는 저장된 드로잉의 구간만 모아 저장소에 넘긴다. 점을 찍는 중이거나 핸들을 끄는 중의 미리보기는 요구에 넣지 않는다. 끄는 동안 포인터가 움직일 때마다 조회가 나가지 않게 하려는 것이다. 미리보기는 이미 받은 세부 봉이 구간을 덮으면 그것으로, 아니면 차트의 봉으로 그린다.
6. **세부 봉 주기는 드로잉마다 "오늘부터 구간 시작까지"의 봉 수로 고른다.** 키움 호출 수는 구간의 길이가 아니라 구간 시작이 오늘에서 얼마나 먼지로 정해진다. 1·3·5·10·15·30·60분 가운데 아래를 모두 지키는 가장 짧은 것을 쓴다.
   - 차트의 봉 주기보다 짧다. 차트가 분봉이면 그 분 수를 나누어떨어지게 한다(10분봉 차트는 1·5분, 15분봉 차트는 1·3·5분).
   - 구간 시작부터 지금까지의 평일 수 × 720분 ÷ 분 수가 10,000 이하다. 720분은 가장 긴 거래 시간(08:00~20:00)이라 실제 봉 수는 이보다 적다.
   - 구간 시작이 1년 안이다.

   이 규칙으로 통합 시세 기준 1분은 약 14거래일, 5분은 약 69거래일, 15분은 약 208거래일, 30분·60분은 1년 전체를 덮는다.
7. **한도는 세부 봉 10,000개다.** 웹 페이지 20개(500봉씩)이고 비교 종목의 한도와 같다. 키움 호출로는 12번 안팎, 초당 4회 한도에서 3초쯤이다. 한도까지 받고도 구간 시작에 닿지 못하면 받기를 멈추고 차트의 봉으로 계산한다.
8. **받는 동안과 받지 못했을 때는 차트의 봉으로 계산해 그린다.** 지금과 같은 그림이 먼저 보이고, 세부 봉이 오면 바뀐다. 빈 틀을 보이지 않는다.
9. **무엇으로 계산했는지 틀 안에 작은 글자로 적는다.** 그림이 말없이 바뀌면 어느 쪽인지 알 수 없다. 문구는 `5분봉 기준`, `일봉 기준 · 분봉 받는 중`, `일봉 기준 · 분봉을 받지 못함`, `일봉 기준 · 분봉은 최근 1년까지`, 차트가 1분봉이면 `1분봉 기준`이다. 스타일에 "계산 기준 라벨" 켬·끔을 더하고 기본은 켬이다.
10. **실패하면 스스로 다시 받지 않는다.** 구간을 바꾸거나 새로 그리거나 종목·봉 주기를 다시 열 때 다시 받는다. `BarFeed`의 과거 페이지 규칙과 같다.
11. **세부 봉도 실시간으로 받는다.** 요구가 있는 동안 비교 종목처럼 소켓에 구독한다. 구간이 현재 봉에 닿으면 장중에 프로파일이 따라 움직여야 하고, 같은 종목이라 실시간 등록 자리를 더 쓰지 않는다. 요구가 없어지면 구독과 봉을 놓는다.
12. **프로파일 계산식은 그대로 쓴다.** `volumeProfile`은 봉의 거래량을 저가~고가에 나눈다. 넣는 봉만 세부 봉으로 바뀐다. 틀의 좌우와 핸들은 지금처럼 차트의 봉 자리를 쓴다.
13. **기준봉 VWAP과 회귀 채널은 바꾸지 않는다.** 두 도구는 차트의 봉으로 계산하는 것이 통례이고, 기준봉 VWAP은 구간이 언제나 지금까지라 세부 봉 한도에 먼저 걸린다. 읽는 길은 `ToolContext`에 있으므로 나중에 도구 파일만 고치면 쓸 수 있다.
14. **ADR은 쓰지 않는다.** 저장 형식과 서버 계약이 바뀌지 않아 되돌리기 쉽다. 용어집과 `docs/design-system.md`만 고친다.

순차로 둔 이유: `volprofile-fine`이 `fine-bars`가 만든 읽기 함수와 선언 항목을 쓴다(한쪽이 다른 쪽의 결과를 쓴다).

고치는 곳:

- `fine-bars`: 새 파일 `web/src/chart/fineBars.ts`와 그 시험, `web/src/chart/drawings/` 안의 새 순수 함수 파일과 시험. 기존 파일은 `web/src/chart/ChartController.ts`, `web/src/chart/extensions.ts`, `web/src/chart/drawings/DrawingSurface.ts`, `web/src/chart/drawings/anchor.ts`, `web/src/chart/drawings/toolSpec.ts`에 몇 줄씩 더한다. `ToolContext`를 손으로 만드는 시험 파일 약 30개에 새 함수 한 줄이 든다.
- `volprofile-fine`: `web/src/chart/drawings/tools/volprofile.ts`와 시험, `web/e2e/drawing-tools-measure.spec.ts`, `GLOSSARY.md`, `docs/design-system.md`.

### 진행 중인 다른 작업과의 순서

- **`fine-bars`는 `layout-store`가 `main`에 병합된 뒤에 시작한다.** `layout-store`(`docs/plans/layout-free.md`)는 드로잉 범위를 slot에서 창 id로 바꾸면서 `web/src/chart/drawings/DrawingSurface.ts`의 `build`와 `web/src/chart/ChartController.ts`를 고친다. `fine-bars`도 `build`에 요구를 모으는 줄을 넣으므로 같은 함수에서 부딪힌다.
- `win-shell` 이후의 레이아웃 작업과는 병렬이다. `sync-crosshair`가 `web/src/chart/ChartController.ts`에 줄을 더하므로 두 쪽 모두 최소 변경으로 한다.
- `dock-pinned-fit`(도구 막대 CSS), `search-flake`(툴팁, 검색 E2E)와는 겹치는 파일이 없다.

## 위험

- **키움 호출이 는다.** 프로파일 하나가 처음 그려질 때 최대 12번쯤 나간다. 드로잉마다 세부 봉 주기가 다르면 주기마다 따로 받는다. 화면 조회와 같은 줄에 서므로 그동안 다른 조회가 조금 늦어질 수 있다.
- **먼 과거의 구간은 정밀도가 낮다.** 열 달 전의 닷새 구간도 30분봉으로 계산한다. 주식은 오늘부터 따라 내려가야 해서 생기는 한계다.
- **1년보다 오래된 구간은 지금과 같다.** 분봉이 없어 차트의 봉으로 계산한다.

## 범위 밖

- 서버의 구간 조회 API, 분봉의 디스크 저장.
- 기준봉 VWAP·회귀 채널의 세부 봉 계산.
- 세션 거래량 프로파일, 보이는 구간 거래량 프로파일.
- 세부 봉 주기를 사용자가 직접 고르는 설정, 세부 봉 계산을 끄는 설정.
- 차트 이미지(`snapshot`)의 변경.

## 사용자가 정해야 하는 결정

모두 권장안을 적용해 두었으므로 답이 없어도 진행한다.

1. **어느 봉 주기에서 세부 봉을 쓰는지.** 권장(적용): 1분봉을 뺀 모든 봉 주기에서 쓰고, 세부 봉 주기는 위 6번 규칙으로 자동으로 고른다. 다른 선택지: 일봉 이상에서만 쓴다.
2. **받아 올 양의 한도.** 권장(적용): 드로잉 하나에 세부 봉 10,000개. 올리면 최근 구간이 더 정밀해지고 키움 호출과 기다림이 는다(20,000개면 1분봉이 약 28거래일, 키움 호출 약 23번).
3. **받는 동안과 받지 못했을 때.** 권장(적용): 차트의 봉으로 계산한 그림을 보이고 계산 기준 라벨에 상태를 적는다. 다른 선택지: 받는 동안 틀만 보인다.
4. **계산 기준 라벨.** 권장(적용): 기본으로 보이고 스타일에서 끌 수 있다. 다른 선택지: 고른 동안에만 보인다.
5. **기준봉 VWAP 등 다른 봉 도구.** 권장(적용): 바꾸지 않는다. 원하면 도구마다 작업 하나를 더한다.

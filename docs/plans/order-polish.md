> 호가창 체결내역에서 / 여기는 시간 필요없어. 제거해줘
>
> SOR / KRX / NXT / 이거 설정으로 넣어주고 기본은 SOR
>
> 100만 / 500만 / 1000만 / 5000만 / 이거 주/금액 오른쪽으로 이동시켜주고 해당 라인은 줄여줘
>
> 하단에 매도접수, 매수접수 제거하고
>
> 매수매도 호가주문버튼 아래에 동일한 버튼의 호가주문 버튼을 만들고 여기에 총물량(접수건수) 이렇게 해줘
>
> 그리고 설정버튼(톱니바퀴) 이것도 배치도 더 세련되게 배치해줘

## 확정된 결정

1. 사다리 안 체결 행에서 시각을 없앤다(요청).
2. 주문 경로 SOR·KRX·NXT는 입력 줄에서 빼고 ⚙ 설정 창 항목으로 옮긴다. 기본은 SOR이다(요청).
3. 수량·금액 프리셋은 주/금액 토글 오른쪽으로 옮기고 그 줄을 없앤다(요청).
4. 맨 아래 "매도 접수·매수 접수" 띠를 없앤다(요청).
5. 매도·매수 주문 칸 열 맨 아래에 주문 칸과 같은 모양의 칸을 두고 "총물량 (건수)"를 보인다(요청).
6. ⚙ 자리를 더 정돈된 곳으로 옮긴다(요청). 자리는 확정된 결정 9다.
7. 상태 줄의 기본 문구 "호가 칸을 더블클릭해 주문합니다"와 사다리 위 "장 마감 · 마지막 호가입니다"를 없애고, 그 줄이 차지하던 높이도 없앤다(요청).

플랜 첫 판의 미리보기를 본 사용자가 정할 것 3·4·5를 골랐다. 나머지(1·2·6)는 추천안으로 간다.

8. **주문 경로는 모든 호가주문창 공통이다**(정할 것 1, 추천안). 앱 설정 `orderSettings`에 두고, 레이아웃의 창마다 `venue`는 읽지 않는다. 필드와 DB 열은 남긴다(ADR 0020이 차트 거래소에서 한 방식). ADR 0029의 "주문 경로 기본값은 KRX다"를 고친다. 기존 창이 KRX로 저장돼 있어도 모두 SOR로 시작한다.
9. **⚙는 입력 둘째 줄 오른쪽 끝에 지금 경로 이름과 톱니를 합친 단추("SOR ⚙")로 둔다**(정할 것 3, 사용자가 고름). 누르면 설정 창이 열린다.
10. **경로가 NXT인데 NXT 미거래 종목이면 경로 단추를 경고색으로 보이고, 더블클릭하면 "NXT에서 거래되지 않는 종목입니다" 알림만 띄우고 보내지 않는다**(정할 것 2, 추천안). 그 종목만 KRX로 보내는 안은 실제 주문이 고른 경로와 다른 곳으로 가서 고르지 않았다.
11. **접수 합계 칸은 사다리 마지막 행 바로 아래 별도 줄의 양 끝(매도·매수 주문 칸 열)에 두고, 총잔량 띠는 그 아래 줄에 둔다**(정할 것 4, 사용자가 고름). 그 줄의 가운데는 비운다. 칸을 누르면 그 쪽 접수 주문을 가격·수량·"취소"로 보이는 메뉴와 맨 아래 "매도(매수) 모두 취소"를 연다(추천안). 지금의 펼침 목록 줄은 없앤다.
12. **주문 결과·오류는 상태 줄 없이, 알릴 것이 있을 때만 사다리 아래쪽 가장자리에 겹쳐 뜬다**(정할 것 5, 사용자가 고름). 사다리가 움직이지 않는다. 접수는 4초 뒤 사라지고, 거절은 다음 주문 동작이나 닫기까지 남고, 결과 미확인·줄 서는 중은 풀릴 때까지 남는다.
13. **ETF·ETN 15:30 뒤 안내 줄은 없애고, 그 시간에 주문 칸을 더블클릭하면 알림으로 그 문구를 보이고 주문은 보내지 않는다**(정할 것 6, 추천안).

## 스스로 정한 결정과 이유

1. **체결 시각은 호가주문창과 10호가창 모두에서 없앤다.** 두 창이 같은 부품(`tradeSlot`)을 쓰고, 10호가창 캡처에서도 시각과 가격이 겹친다. 사용자는 앞 플랜에서 체결 목록을 "호가체결창, 체결창, 프로그램 체결창 모두 동일하게" 하라고 했다. 체결창(`features/trades`)의 시각 열은 이 요청의 "호가창 체결내역"이 아니므로 그대로 둔다.
2. **경로를 입력 줄에서 빼도 지금 경로는 화면에 남긴다.** 실제 주문이 어느 경로로 나가는지가 안 보이면 위험하다. 확정된 결정 9의 단추가 경로 이름을 보인다.
3. **입력 영역은 두 줄이다.** 첫 줄: 수량 칸 · 주/금액 · 프리셋 4개. 둘째 줄: 예상 주문금액 · 전체 호가 · 현재가 · (⚙ 자리). 모의투자 안내("모의투자는 KRX 주문만 됩니다")는 입력 줄에서 빼고 설정 창의 주문 경로 항목 아래에 둔다.
4. **접수 합계 칸의 글자는 숫자만이다.** "12 (2)"처럼 총 미체결 수량과 건수를 보이고, 화면 읽기용 이름은 "매수 접수 12주 2건"이다. 64px에 들어가지 않는 수량은 만 단위로 줄인다. 칸의 가로 위치와 폭은 사다리의 주문 칸과 같다.
5. **10호가창의 배치는 체결 시각 말고는 바꾸지 않는다.** 나머지 요청은 모두 호가주문창이다.
6. **모의투자는 지금처럼 KRX로만 보낸다.** 설정 창의 SOR·NXT는 모의투자에서 꺼 둔다.

### 순서와 겹침

- `order-entry`는 `order-route` 뒤다. 둘 다 `QuantityRow.tsx`의 같은 줄(프리셋·경로 줄)과 `OrderWindow.tsx`의 도구 줄을 다시 짠다.
- `order-totals`는 `order-route`·`order-entry`와 병렬이다. `OrderWindow.tsx`에서 고치는 곳이 사다리와 총잔량 띠 사이의 새 줄과 맨 아래 접수 띠뿐이다. 셋 다 `OrderWindow.tsx`와 `web/src/styles/order-window.css`를 고치므로 지시서에 자기 영역만 최소 변경으로 고치라고 적었다.
- `ladder-trade-time`은 `features/market-window`만 고쳐 다른 작업과 겹치지 않는다.

### 다른 플랜과 겹치는 곳

- `mw-allow`(PR #593, 열림): `QuantityRow.tsx`의 수량 칸 `id`를 `useId`로 바꾸고 `stores/layout.ts`를 고친다. `order-route`·`order-entry`는 그 병합 뒤 main에서 시작하거나 그 위에 다시 맞춘다.
- `mw-state`·`mw-pin`(multi-window 플랜): `stores/layout.ts`의 창 상태 타입과 `MarketWindowGate.tsx`를 고친다. `order-route`는 `layout.ts`에서 쓰이지 않게 된 `orderVenue`·`setOrderVenue`만 지우고 창 상태 타입·`DEFAULT_ORDER_VENUE`는 건드리지 않는다.
- `pm-0e-web`(premarket-book 플랜): 총잔량 띠의 숫자 요소(`order-total-ask`·`order-total-bid`)에 시간외 잔량을 넣는다. `order-totals`는 띠를 고치지 않고 사다리와 띠 사이에 줄을 하나 더한다. 같은 파일의 이웃한 곳이라 먼저 병합된 쪽 위에 다른 쪽이 다시 맞춘다.

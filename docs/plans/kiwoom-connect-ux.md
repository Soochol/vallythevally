# 키움 자동 연결 플랜

작성일 2026-11-17. 승인 시점의 기록이며 구현 중 바뀐 것은 반영하지 않는다.

기준: `origin/main` dbde15b1.

## 사용자가 풀려는 문제

사용자는 시스템 설정에서 키움 키를 저장했다. 그런데 서버를 다시 켤 때마다 키가 사라진 것처럼 보였다.

> 저장된 키, 이거 시스템설정에서 내가 저장했는데 왜 유지를 못해 ?

실제로 키 파일(`~/.local/state/vallythevally/kiwoom-key.json`)은 남아 있다. 풀리는 것은 연결뿐이다. [ADR 0021](../adr/0021-kiwoom-connects-only-when-the-user-asks.md)에 따라 서버는 켜질 때 키움을 부르지 않고, 사용자가 시스템 설정에서 "연결"을 눌러야 연결된다. 그래서 재시작할 때마다 손으로 다시 연결해야 했고, 이 상태가 "키가 유지되지 않는다"로 읽혔다. 연결 규칙을 설명하자 사용자는 UX 개선 플랜을 요청했고, 이어서 이렇게 정했다.

> 내가 원하는건 연결을 안눌러도 연결되어야지!

## 확정된 결정

1. **키가 저장돼 있으면 서버가 켜질 때 사용자가 누르지 않아도 키움에 연결한다.** 사용자가 정했다(2026-11-17). 이 플랜의 핵심이다. ADR 0021의 "연결은 수동뿐"을 바꾸므로 새 ADR이 ADR 0021을 대체한다. 화면 진입점과 문구 개선은 보조다.
2. **자동 연결도 기존 보호를 그대로 지킨다.**
   - 파일에 같은 앱키의 유효한 토큰이 있으면 발급은 0회다.
   - 발급 간격(10분)은 재시작과 상관없이 지킨다. 간격 안이면 기다렸다가 저절로 잇는다.
   - 8050 인증 차단과 그 밖의 인증 차단 상태에서는 자동 연결하지 않는다. 지금처럼 사용자의 확인을 기다린다.
   - 연결은 단일 작업(single-flight)으로 둔다.

## 스스로 정한 결정과 이유

1. **자동 연결은 서버 시작 때 지금의 연결 동작을 한 번 부르는 것이다.** 새 발급 경로를 만들지 않는다. ADR 0021의 판단 순서(키 없음 → 차단 → 유효한 토큰 → 발급 간격 → 발급 1회 → 실패는 ADR 0009 정책 표)를 그대로 지나간다. 그래서 자동 연결이 정책을 우회하는 길이 구조로 없다.
2. **인증 차단 기록을 토큰 파일에 남긴다.** 지금 8050 차단은 메모리에만 있다. 서버를 다시 켜면 사라지고, 그 뒤의 연결은 확인 두 칸 없이 발급을 보낸다. 자동 연결을 넣으면 이 빈틈이 사용자가 누르지 않아도 열린다. 그래서 인증 차단(8050과 그 밖의 인증 차단)을 받으면 그 코드와 앱키 해시를 토큰 파일에 쓰고, 시작 때 읽어 차단 상태로 켠다.
   - 토큰 파일에 두는 이유: 발급을 막는 정보(`last_request_at`)가 이미 이 파일에 있다. 파일을 읽지 못하면 조회와 발급을 모두 멈추는 처리와 "파일 다시 확인" 화면도 이미 있다. 새 경로, 새 환경 변수, 새 권한 검사를 만들지 않는다.
   - 푸는 규칙은 지금과 같다. 8050은 확인 두 칸을 하고 발급 간격이 지난 뒤 연결에 성공하면 풀린다. 그 밖의 인증 차단은 새 키를 저장하면 풀린다.
   - 차단 기록을 쓰지 못하면 그 프로세스 안에서는 지금처럼 멈추고 오류를 로그에 남긴다. 다음 시작 때 파일에 기록이 없으면 자동 연결은 발급 간격만 지킨다. 디스크 쓰기가 실패하는 드문 경우이고, 손으로 연결을 누르는 지금과 같은 위험이다.
3. **자동 연결은 그 키로 한 번 연결에 성공한 뒤부터 켜진다.** 연결에 성공하면 토큰 파일에 "시작 때 연결할 키"로 그 앱키 해시를 적는다. 시작 때 지금 키의 해시와 같을 때만 자동 연결한다.
   - 이유: 키를 처음 저장한 직후에는 포털에 공인 IP를 아직 등록하지 않았을 수 있다. 설정 마법사도 키 저장 → IP 등록 → 연결 순서다. 이때 저절로 발급하면 8050을 부를 수 있다. 첫 연결은 사용자가 마법사나 시스템 설정에서 누르고, 그 뒤 재시작부터는 누르지 않는다. 사용자 결정 2로 바꿀 수 있다.
   - 키를 바꾸면 해시가 달라지므로 새 키로 한 번 연결할 때까지 자동 연결하지 않는다. 키를 지우면 기록도 지운다.
4. **사용자가 "연결 끊기"를 누르면 다음 시작 때도 자동 연결하지 않는다.** 끊기는 기록을 지운다. 다시 "연결"을 눌러 성공하면 다시 켜진다. 사용자가 일부러 끊은 상태를 재시작이 뒤집지 않게 한다. 키 저장·삭제가 안에서 부르는 끊기는 사용자 끊기가 아니다. 사용자 결정 1로 바꿀 수 있다.
5. **발급 간격 안이면 연결이 기다렸다가 저절로 잇는다.** 지금은 간격 안에서 연결을 누르면 "발급 간격 대기"로 끝나고 다시 눌러야 한다. 이제는 연결 중의 한 단계("발급 간격 대기", 다시 시도할 시각 포함)로 기다리고 시각이 되면 이어 간다. 시작 때 자동 연결과 사용자가 누른 연결 모두 같다. 기다리는 동안 끊기를 누르면 그만둔다. 연결 요청(`POST /api/system/kiwoom/connect`)은 대기 단계에 들어가면 바로 답하고, 이후 상태는 WebSocket `kiwoom_link`로 보낸다. 8050을 확인하고 누른 연결은 지금처럼 간격이 지난 뒤 사용자가 다시 누른다. 차단을 푸는 동작은 사람이 마지막으로 누르게 둔다.
6. **화면이 시작 때의 연결 방식을 알린다.** 연결 상태에 "시작 때 연결" 값(자동으로 연결함 / 처음 한 번 연결 필요 / 끊어 둠)을 더한다. 연결 안 함 상태의 문구가 이 값에 따라 "키는 저장돼 있습니다"와 함께 다음에 무엇이 일어나는지 말한다. 사용자의 "키가 유지되지 않는다" 오해를 문구로 푼다.
7. **연결 안 함과 네트워크 실패 상태에서 시스템 설정을 열지 않고 바로 연결할 수 있게 한다.** 차트 칸의 "키움 연결 안내" 카드와 아래 상태 줄에 "연결" 단추를 둔다(미리보기 안 B). 인증 차단, 키 확인 필요, 파일 사용 불가처럼 사람이 원인을 봐야 하는 상태는 지금처럼 시스템 설정으로 이끈다.
8. **작업은 둘로 나누고 순서대로 한다.** 화면 작업은 서버가 내보내는 연결 상태 타입(`KiwoomLinkStatus`, 생성 TS 타입)의 새 값을 쓴다. 한쪽이 다른 쪽의 결과를 쓰므로 순차다.

## 서버를 켤 때마다 발급하던 문제가 되살아나지 않는 근거

ADR 0021 이전에는 서버를 켜면 무조건 발급했다. 11-09에 8050을 겪었고 그때 화면은 "서버를 다시 켜야 합니다"만 보였다. 이 플랜의 자동 연결은 다음 이유로 그 구조로 돌아가지 않는다.

- 토큰은 파일에 남고 24시간 유효하다. 연결됨 상태에서는 매일 20:05에 다시 받는다. 그래서 대부분의 재시작은 발급 0회다. ADR 0004의 "재시작은 발급이 아니다"가 자동 연결에도 그대로 선다.
- 발급이 필요해도 마지막 발급 요청에서 10분 안이면 보내지 않는다. 그 시각은 요청 전에 파일에 쓴다. 서버를 몇 번 켜고 꺼도 발급은 10분에 1회를 넘지 않는다.
- 인증 차단은 이제 재시작 뒤에도 남는다. 8050 뒤에는 자동 연결도 손 연결도 확인 두 칸 없이는 발급하지 않는다. 지금보다 강하다.
- 자동 연결은 그 키로 연결에 성공한 적이 있을 때만 한다. 새 키, IP 미등록 상태의 첫 발급은 사람이 누른다.
- 실패 뒤 반복은 ADR 0009 정책 표가 정한다. 자동 연결은 시작 때 한 번이고 실패하면 다시 시도하지 않는다(사용자 결정 4). 저절로 다시 잇는 것은 발급 간격 대기뿐이고, 그 대기도 간격이 끝난 뒤 한 번 이어 갈 뿐이다.

## 범위 밖

- 실제 키움 호출. 시험은 합성 transport·세션만 쓴다.
- 발급 간격 길이, 8050 확인 두 칸, ADR 0009 정책 표의 변경.
- 수집기(`crates/collector`)의 수집 키 연결. ADR 0026이 다룬다.
- 시작 때 자동 연결을 끄는 별도 스위치나 환경 변수. 끊기가 그 역할을 한다. 시험 하네스의 `VALLY_KIWOOM_CONNECT`는 시험 전용으로 남는다.
- 검증을 약하게 하는 변경(검증 단계 삭제, 시간 제한 증가, `paths` 축소)은 없다.

## 사용자가 정해야 하는 결정

1. **"연결 끊기"를 누른 뒤 서버를 다시 켜면 자동 연결할지.** 권장: 하지 않는다. 끊기를 누른 상태를 기억하고, 다시 "연결"을 누르면 다음부터 자동 연결한다. 대안: 끊기와 상관없이 늘 자동 연결한다. 이때 "연결 끊기"는 지금 켜져 있는 동안만 끊는다.
2. **새 키를 저장한 뒤 첫 연결을 손으로 누르게 할지.** 권장: 그렇다. 처음 한 번은 설정 마법사나 시스템 설정에서 누르고, 성공한 뒤부터 자동이다. IP를 등록하기 전에 저절로 발급해 8050을 부르는 일을 막는다. 대안: 키만 있으면 첫 시작부터 자동 연결한다.
3. **토큰이 만료돼 있으면 시작 때 저절로 발급할지.** 권장: 발급한다(발급 간격을 지키고, 시작 한 번에 최대 1회). 서버를 하루 넘게 꺼 두면 토큰이 만료되는데, 이때 손으로 눌러야 하면 사용자가 겪은 번거로움이 그대로 남는다. 대안: 유효한 토큰이 있을 때만 자동 연결하고, 만료면 지금처럼 수동이다.
4. **시작 때 자동 연결이 네트워크 실패로 끝나면 저절로 다시 시도할지.** 권장: 하지 않는다. ADR 0009 정책 표를 그대로 두고, 상태 줄과 연결 안내 카드의 "다시 시도" 단추로 바로 잇는다. 대안: 발급 간격이 끝날 때 한 번 더 시도한다.
5. **바로 연결 단추의 위치.** 권장: 안 B(차트 칸 연결 안내 카드와 상태 줄 둘 다). 안 A는 카드에만, 안 C는 지금처럼 시스템 설정에만 둔다.

# 키움 자동 연결 플랜

작성일 2026-11-18. 승인 시점의 기록이며 구현 중 바뀐 것은 반영하지 않는다.

기준: `origin/main` dbde15b1.

## 사용자가 풀려는 문제

사용자는 시스템 설정에서 키움 키를 저장했다. 그런데 서버를 다시 켤 때마다 키가 사라진 것처럼 보였다.

> 저장된 키, 이거 시스템설정에서 내가 저장했는데 왜 유지를 못해 ?

실제로 키 파일(`~/.local/state/vallythevally/kiwoom-key.json`)은 남아 있다. 풀리는 것은 연결뿐이다. [ADR 0021](../adr/0021-kiwoom-connects-only-when-the-user-asks.md)에 따라 서버는 켜질 때 키움을 부르지 않고, 사용자가 시스템 설정에서 "연결"을 눌러야 연결된다. 그래서 재시작할 때마다 손으로 다시 연결해야 했고, 이 상태가 "키가 유지되지 않는다"로 읽혔다. 연결 규칙을 설명하자 사용자는 UX 개선 플랜을 요청했고, 이어서 이렇게 정했다.

> 내가 원하는건 연결을 안눌러도 연결되어야지!

플랜 초안의 "정할 것" 다섯 가지에는 이렇게 답했다(2026-11-18).

> 승인, 2번은 처음부터 자동

## 확정된 결정

1. **키가 있으면 사용자가 누르지 않아도 키움에 연결한다.** 서버가 켜질 때와 화면에서 키를 저장할 때 모두다. 처음부터 자동이다. 이 키로 연결에 성공한 적이 없어도 자동 연결한다. 이 플랜의 핵심이다. ADR 0021의 "연결은 수동뿐"을 바꾸므로 새 ADR이 ADR 0021을 대체한다. 화면 진입점과 문구 개선은 보조다.
2. **자동 연결도 기존 보호를 그대로 지킨다.**
   - 파일에 같은 앱키의 유효한 토큰이 있으면 발급은 0회다.
   - 발급 간격(10분)은 재시작과 상관없이 지킨다. 간격 안이면 기다렸다가 저절로 잇는다.
   - 8050 인증 차단과 그 밖의 인증 차단 상태에서는 자동 연결하지 않는다. 지금처럼 사용자의 확인을 기다린다.
   - 연결은 단일 작업(single-flight)으로 둔다. 시작 한 번에 발급은 최대 1회다.
   - 새 키의 첫 자동 발급이 8050이면 차단 상태로 멈추고, 저절로 반복하지 않는다.
3. **사용자가 "연결 끊기"를 누르면 다음 시작 때도 자동 연결하지 않는다.** 끊어 둔 상태를 기억한다. 다시 "연결"을 누르거나 키를 새로 저장하면 그때부터 다시 자동이다.
4. **토큰이 만료돼 있으면 시작 때 저절로 발급한다.** 발급 간격을 지키고, 시작 한 번에 최대 1회다.
5. **시작 때 자동 연결이 실패하면 저절로 다시 시도하지 않는다.** 네트워크 실패도 같다. 반복은 ADR 0009 정책 표가 정한다. 상태 줄과 연결 안내 카드의 "다시 시도" 단추로 바로 잇는다.
6. **바로 연결 단추는 차트 칸 연결 안내 카드와 상태 줄 둘 다에 둔다**(미리보기 안 B).

## 스스로 정한 결정과 이유

1. **자동 연결은 지금의 연결 동작을 한 번 부르는 것이다.** 서버 시작 때와 키를 저장할 때 부른다. 새 발급 경로를 만들지 않는다. ADR 0021의 판단 순서(키 없음 → 차단 → 유효한 토큰 → 발급 간격 → 발급 1회 → 실패는 ADR 0009 정책 표)를 그대로 지나간다. 그래서 자동 연결이 정책을 우회하는 길이 구조로 없다.
2. **인증 차단 기록을 토큰 파일에 남긴다.** 지금 8050 차단은 메모리에만 있다. 서버를 다시 켜면 사라지고, 그 뒤의 연결은 확인 두 칸 없이 발급을 보낸다. 자동 연결을 넣으면 이 빈틈이 사용자가 누르지 않아도 열린다. 그래서 인증 차단(8050과 그 밖의 인증 차단)을 받으면 그 코드와 앱키 해시를 토큰 파일에 쓰고, 시작 때 읽어 차단 상태로 켠다.
   - 토큰 파일에 두는 이유: 발급을 막는 정보(`last_request_at`)가 이미 이 파일에 있다. 파일을 읽지 못하면 조회와 발급을 모두 멈추는 처리와 "파일 다시 확인" 화면도 이미 있다. 새 경로, 새 환경 변수, 새 권한 검사를 만들지 않는다.
   - 푸는 규칙은 지금과 같다. 8050은 확인 두 칸을 하고 발급 간격이 지난 뒤 연결에 성공하면 풀린다. 그 밖의 인증 차단은 새 키를 저장하면 풀린다. 8050은 새 키를 저장해도 풀리지 않으므로, 키를 저장할 때의 자동 연결도 확인 두 칸 없이는 발급하지 않는다.
   - 차단 기록을 쓰지 못하면 그 프로세스 안에서는 지금처럼 멈추고 오류를 로그에 남긴다. 다음 시작 때 파일에 기록이 없으면 자동 연결은 발급 간격만 지킨다. 디스크 쓰기가 실패하는 드문 경우이고, 손으로 연결을 누르는 지금과 같은 위험이다.
3. **끊어 둔 상태는 토큰 파일에 앱키 해시와 함께 기록한다.** 사용자가 "연결 끊기"를 누르면 지금 키의 해시로 "끊어 둠"을 쓴다. 연결에 성공하거나 키를 저장하거나 지우면 기록을 지운다. 키 저장·삭제가 안에서 부르는 끊기는 사용자 끊기가 아니다. 차단 기록과 같은 파일, 같은 이유다.
4. **키 저장 화면에 "저장하면 바로 연결합니다. 포털에 지금 공인 IP를 먼저 등록하세요"를 적는다.** 처음부터 자동이므로, IP를 등록하기 전에 키를 저장하면 첫 발급이 8050이 될 수 있다. 서버는 그때 한 번에서 멈추지만, 사용자는 확인 두 칸과 10분 대기를 겪는다. 저장 전에 알리는 편이 싸다.
5. **설정 마법사의 IP 확인 단계를 키 단계 앞으로 옮긴다.** 지금 마법사는 로그인 → 키움 키 → IP 확인 → 연결 → 기본 셋업 순서다. 키를 저장하는 순간 연결하므로 이 순서로는 IP 등록 전에 발급이 나간다. IP 확인과 포털 등록 기록은 키가 없어도 된다. 그래서 로그인 → IP 확인 → 키움 키 → 연결 → 기본 셋업으로 바꾼다. 연결 단계는 누르는 단계가 아니라 자동 연결의 진행과 결과를 보이는 단계가 된다. 실패하면 거기서 다시 시도한다.
6. **발급 간격 안이면 연결이 기다렸다가 저절로 잇는다.** 지금은 간격 안에서 연결하면 "발급 간격 대기"로 끝나고 다시 눌러야 한다.
   - 이제는 연결 중의 한 단계("발급 간격 대기", 다시 시도할 시각 포함)로 기다리고, 시각이 되면 이어 간다. 자동 연결과 사용자가 누른 연결 모두 같다.
   - 기다리는 동안 끊기를 누르면 그만둔다.
   - 연결 요청(`POST /api/system/kiwoom/connect`)은 대기 단계에 들어가면 바로 답한다. 이후 상태는 WebSocket `kiwoom_link`로 보낸다.
   - 8050을 확인하고 누른 연결은 지금처럼 간격이 지난 뒤 사용자가 다시 누른다. 차단을 푸는 동작은 사람이 마지막으로 누르게 둔다.
7. **화면이 시작 때의 연결 방식을 알린다.** 연결 상태에 "시작 때 연결" 값을 더한다. 값은 "자동으로 연결함"과 "끊어 둠" 둘이고, 키가 없으면 비어 있다. 연결 안 함 상태의 문구는 "키는 저장돼 있습니다"와 함께 다음에 무엇이 일어나는지 말한다. 사용자의 "키가 유지되지 않는다" 오해를 문구로 푼다.
8. **바로 연결 단추는 사람이 원인을 볼 필요가 없는 상태에만 둔다.** 끊어 둠과 네트워크 실패다. 인증 차단, 키 확인 필요, 파일 사용 불가처럼 원인을 봐야 하는 상태는 지금처럼 시스템 설정으로 이끈다.
9. **작업은 둘로 나누고 순서대로 한다.** 화면 작업은 서버가 내보내는 연결 상태 타입(`KiwoomLinkStatus`, 생성 TS 타입)의 새 값과 키 저장 뒤 자동 연결을 쓴다. 한쪽이 다른 쪽의 결과를 쓰므로 순차다.

## 서버를 켤 때마다 발급하던 문제가 되살아나지 않는 근거

ADR 0021 이전에는 서버를 켜면 무조건 발급했다. 11-09에 8050을 겪었고 그때 화면은 "서버를 다시 켜야 합니다"만 보였다. 이 플랜의 자동 연결은 다음 이유로 그 구조로 돌아가지 않는다.

- 토큰은 파일에 남고 24시간 유효하다. 연결됨 상태에서는 매일 20:05에 다시 받는다. 그래서 대부분의 재시작은 발급 0회다. ADR 0004의 "재시작은 발급이 아니다"가 자동 연결에도 그대로 선다.
- 발급이 필요해도 마지막 발급 요청에서 10분 안이면 보내지 않는다. 그 시각은 요청 전에 파일에 쓴다. 서버를 몇 번 켜고 꺼도 발급은 10분에 1회를 넘지 않는다.
- 인증 차단은 이제 재시작 뒤에도 남는다. 8050 뒤에는 자동 연결도, 손 연결도, 키 저장도 확인 두 칸 없이는 발급하지 않는다. 지금보다 강하다.
- 새 키의 첫 발급이 8050이면 그 한 번에서 멈춘다. 차단 기록이 남으므로 재시작도 다시 발급하지 않는다. 키 저장 화면과 마법사 순서가 IP 등록을 먼저 하게 이끈다.
- 실패 뒤 반복은 ADR 0009 정책 표가 정한다. 자동 연결은 시작 때나 키 저장 때 한 번이고, 실패하면 다시 시도하지 않는다. 저절로 다시 잇는 것은 발급 간격 대기뿐이고, 그 대기도 간격이 끝난 뒤 한 번 이어 갈 뿐이다.
- 일꾼의 검증 실행은 저장소 규칙대로 루프백 가짜 키움을 쓴다. 실제 키를 가진 서버를 자주 켜고 꺼도 위 두 줄(토큰 재사용, 발급 간격)이 발급 수를 묶는다.

## 범위 밖

- 실제 키움 호출. 시험은 합성 transport·세션만 쓴다.
- 발급 간격 길이, 8050 확인 두 칸, ADR 0009 정책 표의 변경.
- 수집기(`crates/collector`)의 수집 키 연결. ADR 0026이 다룬다.
- 시작 때 자동 연결을 끄는 별도 스위치나 환경 변수. 끊기가 그 역할을 한다. 시험 하네스의 `VALLY_KIWOOM_CONNECT`는 시험 전용으로 남는다.
- 검증을 약하게 하는 변경(검증 단계 삭제, 시간 제한 증가, `paths` 축소)은 없다.

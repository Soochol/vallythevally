# 연동 색 메뉴 다시 그리기와 닫기 버튼 고정 플랜

작성일 2026-11-17. 승인 시점의 기록이며 구현 중 바뀐 것은 반영하지 않는다.

기준: `origin/main` dbde15b1. 대상 메뉴는 직전 플랜 `docs/plans/ui-polish.md`의 3번 작업(`link-color-menu`, PR #479, cbd1fdaa)이 만들었다.

## 사용자가 풀려는 문제

사용자의 말(그대로):

> [첨부 이미지: 연동 색 메뉴 캡처] 이거 ui다시 제안
>
> 그리고 A를 클릭하면 팝오버가 나오고, 이때 x 닫힘 버튼이 움직여 , 안움직이게

캡처의 메뉴는 머리 "연동 색 · 같은 색 창끼리 종목을 맞춥니다", 줄 "끔"(빈 고리), "✓ A  창 2개"(강조색 글자), "B  없음", "C  없음"이다.

두 가지다. 연동 색 메뉴의 모양을 다시 제안하고, 탭의 연동 색 점을 눌러 메뉴가 열릴 때 그 탭의 닫기(x) 버튼이 움직이지 않게 한다.

## 미리보기

사용자의 요청대로 구현 전에 미리보기를 만들었다. "지금"은 기준 커밋을 격리된 샌드박스(verify-vally, 오프라인·루프백, 가짜 키움)로 띄워 1440×860 창에서 찍은 캡처에 번호를 단 것이다. 안 A·B·C는 제품의 색 토큰과 치수로 그린 목업이고 눌러 볼 수 있다. 닫기 버튼은 지금과 고친 뒤를 눌러 비교한다. 미리보기 파일은 저장소에 넣지 않는다. 아래 그림은 권장안을 글자로 옮긴 것이다.

```
연동 색 메뉴   지금: 머리 한 줄, 끔만 빈 고리, A·B·C 줄에 색 점 없음(결함)
               제안 A: 머리 "연동 색" + 설명 한 줄, 줄마다 12px 색 점, 오른쪽에 같은 색 창 수
               ┌────────────────────────────┐
               │ 연동 색                    │
               │ 같은 색 창끼리 종목을 맞춥니다 │
               │    ○ 끔                    │
               │ ✓  ● A              창 1개 │
               │    ● B                없음 │
               │    ● C                없음 │
               └────────────────────────────┘
닫기 버튼      지금: 메뉴가 열린 동안 x가 점 쪽으로 11px 붙음      제안: 열려도 닫혀도 제자리
```

## 확인한 사실

### 1. 색 점이 빠진 결함

- `LinkDot.tsx`의 `Swatch`는 끔이면 `shadow-[inset_0_0_0_2px_var(--line-strong)]`, 색이면 `` `bg-[var(--link-${link})]` ``를 클래스로 쓴다. 뒤쪽은 런타임에 조립한 이름이라 Tailwind가 소스에서 찾지 못해 규칙을 만들지 않는다.
- 이 저장소의 UI를 빌드한 CSS(`target/verify-vally/ui/assets/index-*.css`)에 `bg-[var(--link-` 규칙은 0건이다. `--link-a`·`--link-b`·`--link-c`를 쓰는 규칙은 탭 점의 `.link-dot[data-link=…]` 셋뿐이다.
- 샌드박스에서 메뉴를 열고 줄마다 점 요소의 계산된 스타일을 읽었다. 끔은 `--line-strong` 고리, A·B·C는 배경이 `rgba(0, 0, 0, 0)`이다. 자리(10px)는 차지하므로 A·B·C 이름이 끔 이름과 같은 자리에서 시작하고 그 왼쪽이 비어 보인다.
- 승인된 결정(ui-polish 3번)은 "항목마다 색 점"이었다. 시험(`win-link.spec.ts` 등)은 메뉴 항목의 이름과 값만 보고 색은 보지 않아 이 결함을 잡지 못했다.
- 같은 꼴(대괄호 임의값 안에 `${…}`)의 클래스는 `web/src` 안에서 이곳 하나다.
- 고른 줄의 글자가 강조색(연두)인 것은 공용 `Menu`의 `aria-checked:text-accent` 규칙이다. 모든 라디오 메뉴가 같다.

### 2. 닫기 버튼이 움직이는 버그

- 도킹 탭 한 칸은 `.dock-tab-group` 안에 탭 버튼, `LinkDot`, 닫기 버튼(`.dock-tab-close`)이 형제로 놓인다(`DockGroup.tsx`). 닫기와 점 사이 간격은 `ui.css`의 `.link-dot + .dock-tab-close { margin-left: calc(var(--size-29) - var(--size-18)) }`(11px)이 준다.
- `LinkDot`은 열린 동안 `<Menu>`를 점 바로 뒤에 그린다. `Menu`의 `Popover`는 `popover="manual"`로 최상위 층에 띄워 자리를 차지하지 않지만 DOM에서는 점과 닫기 사이의 형제다. 그래서 열린 동안 `+`(바로 다음 형제) 규칙이 풀려 margin-left가 0이 된다.
- 샌드박스(1440×860, 칸 1 탭)에서 쟀다. 점은 x=75로 그대로이고, 닫기는 포인터를 올린 때 x=105(margin-left 11px), 메뉴를 연 때 x=94(margin-left 0px, 앞 형제 `ui-popover`), 닫은 뒤 x=105다. 끔·A 두 상태에서 같았다.
- 같은 화면에서 규칙만 `.link-dot ~ .dock-tab-close`로 바꿔 넣자 관심종목 탭의 닫기가 열기 전·연 동안·닫은 뒤 모두 x=1124로 같았다.
- 닫기는 포인터를 올리거나 초점이 탭 묶음 안에 있을 때만 보인다(`--close-shown`). 메뉴의 초점은 같은 묶음 안의 팝오버에 있어 열린 동안에도 보인다.
- 캔버스·떠 있는 창 머리(`WindowHeader.tsx`의 `.window-actions`)에는 점 뒤 형제에 기대는 규칙이 없다.
- E2E `win-manage.spec.ts`의 "닫기 버튼은 탭이나 연동 색 점에 가리지 않고 버튼 전체가 눌린다"는 메뉴가 닫힌 상태만 본다.

## 스스로 정한 결정

### 1. 연동 색 메뉴

미리보기에 안 세 개를 그렸다. A는 색 점을 살린 세로 메뉴, B는 탭 점 모양의 28px 가로 색 견본 네 개와 설명 한 줄, C는 A에서 오른쪽 힌트를 같은 색 창 이름으로 바꾼 것이다. A를 권장안으로 지시서에 적용했다.

| 결정 | 이유 |
|---|---|
| 줄마다 그 색의 12px 점을 보인다. 끔은 같은 크기의 `--line-strong` 빈 고리다. | 색이 이 메뉴의 핵심 정보다. 지금 10px는 탭 점(18px)과 견주기에 작다. |
| 점의 색은 정적인 규칙으로 칠한다. 클래스 이름을 런타임에 조립하지 않는다. 탭 점처럼 `data-link` 속성과 `ui.css` 규칙을 쓰거나 색마다 고정 문자열 클래스를 쓴다. | 결함의 원인이다. 탭 점이 이미 `data-link` 규칙을 쓴다. |
| 머리를 이름 "연동 색"과 설명 "같은 색 창끼리 종목을 맞춥니다" 두 줄로 나눈다. 공용 `Menu`의 머리 항목에 설명 한 줄을 더하는 선택 필드를 둔다. | 한 줄 머리가 메뉴 폭을 정하고 길다. 다른 메뉴의 머리는 그대로다. |
| 줄 이름(끔·A·B·C), 오른쪽 힌트("창 1개", 없으면 "없음"), 체크, 고르면 `setLink`, 키보드와 초점은 지금 그대로다. | 지난 결정과 시험의 선택자(`menuitemradio` 이름 "A…")를 지킨다. |
| 고른 줄 글자의 강조색은 그대로 둔다. | 공용 메뉴 전체의 규칙이다. 색 점이 돌아오면 줄의 색은 점이 보인다. |
| 메뉴 항목의 점이 그 색으로 칠해졌는지 E2E로 확인한다. | 지금 시험은 색을 보지 않아 결함을 놓쳤다. |

### 2. 닫기 버튼

| 결정 | 이유 |
|---|---|
| 닫기 간격 규칙을 메뉴가 끼어도 걸리는 형제 규칙(`.link-dot ~ .dock-tab-close`)으로 바꾼다. 탭 묶음 구조와 `Menu`의 그리는 자리는 바꾸지 않는다. | 원인이 이 규칙이고 샌드박스에서 바꿔 넣어 확인했다. 가장 작은 변경이다. |
| 메뉴가 열린 동안에도 닫기는 지금처럼 보인다. | 사용자는 움직이지 않게 해 달라고 했다. 보임 규칙은 지난 플랜의 결정이다. |
| 메뉴를 열기 전·연 동안·Esc로 닫은 뒤, 탭의 점과 닫기의 위치가 같은지 E2E로 단언한다. 끔 탭과 색이 있는 탭을 하나씩 본다. | 사용자가 겪은 것을 그대로 막는다. 지금 시험은 닫힌 상태만 본다. |

## 작업과 순서

| 작업 ID | 내용 | 방식 | 방식의 이유 | 시작 조건 |
|---|---|---|---|---|
| `link-menu-polish` | 연동 색 메뉴에 색 점을 살려 안 A로 다시 그리고, 메뉴가 열려도 탭의 닫기 버튼이 제자리에 있게 한다 | `basic` (`minor-fix`) | 화면 조정과 CSS 한 규칙의 작은 버그 수정, 저장 동작은 그대로 | 바로 시작 |

작업은 하나다. 두 문제가 같은 부품(`LinkDot.tsx`)과 같은 CSS 구역(`ui.css`의 `.link-dot`·`.dock-tab-close`), 같은 시험 파일을 고친다. 나누면 같은 화면 영역을 두 PR이 차례로 고쳐야 한다.

## 범위 밖

- 연동 색의 뜻, 색 수(A·B·C), 색 토큰, 같은 색 따르기·저장·알림.
- 공용 `Menu`의 고른 줄 강조색, 다른 메뉴의 머리.
- 닫기 버튼의 보임 규칙(포인터·초점일 때만 보임).
- 대괄호 임의값 클래스를 런타임에 조립하지 못하게 막는 기계 검사. 지금 이 꼴은 한 곳뿐이고 이 작업에서 없어진다.

## 사용자가 정해야 하는 결정

미리보기에 권장안과 다른 선택지를 함께 보였다. 정하지 않으면 권장안으로 진행하고, 다르게 정하면 지시서만 고친다. 검증을 약하게 하는 작업은 없다. 메뉴 항목의 색과 닫기 위치를 보는 E2E를 더한다.

| # | 물음 | 권장(지시서에 적용) | 다른 선택지 | 맡는 작업 |
|---|---|---|---|---|
| 1 | 연동 색 메뉴의 모양 | A: 색 점을 살린 세로 메뉴, 머리 두 줄 | B: 가로 색 견본(새 부품, ←→ 키보드, 메뉴 시험을 다시 씀. 고르면 작업의 `profile`을 `implementer`로 바꾼다) / C: 같은 색 창 이름을 힌트로 보이는 세로 메뉴 | `link-menu-polish` |
| 2 | 메뉴가 열린 동안 닫기(x) | 제자리에 보임 | 열린 동안 숨김 | `link-menu-polish` |

# 연동 색 열 개, 가로 색 견본 메뉴, 닫기 버튼 고정 플랜

작성일 2026-11-18. 승인 시점의 기록이며 구현 중 바뀐 것은 반영하지 않는다.

기준: `origin/main` dbde15b1. 대상 메뉴는 직전 플랜 `docs/plans/ui-polish.md`의 3번 작업(`link-color-menu`, PR #479, cbd1fdaa)이 만들었다.

## 사용자가 풀려는 문제

사용자의 말(그대로):

> [첨부 이미지: 연동 색 메뉴 캡처] 이거 ui다시 제안
>
> 그리고 A를 클릭하면 팝오버가 나오고, 이때 x 닫힘 버튼이 움직여 , 안움직이게

캡처의 메뉴는 머리 "연동 색 · 같은 색 창끼리 종목을 맞춥니다", 줄 "끔"(빈 고리), "✓ A  창 2개"(강조색 글자), "B  없음", "C  없음"이다.

미리보기를 본 뒤 사용자가 메뉴 모양으로 B(가로 색 견본)를 골랐고, 이어서 말했다:

> 그리고 추가로 10가지 그룹으로 확대해줘

"그룹"은 이 저장소의 **연동 색**이다(`GLOSSARY.md`). 세 가지를 한다. 연동 색을 A·B·C 셋에서 열 개로 늘리고, 연동 색을 고르는 메뉴를 가로 색 견본으로 바꾸고, 탭의 점을 눌러 메뉴가 열릴 때 그 탭의 닫기(x) 버튼이 움직이지 않게 한다.

## 미리보기

구현 전에 미리보기를 만들어 사용자에게 보였다. "지금"은 기준 커밋을 격리된 샌드박스(verify-vally, 오프라인·루프백, 가짜 키움)로 띄워 1440×860 창에서 찍은 캡처에 번호를 단 것이다. 견본 메뉴(두 줄·한 줄, 데스크톱·휴대폰 360px), 열 색의 탭 점과 대비·색차 표, 닫기 버튼의 지금·고친 뒤는 제품의 색 토큰과 치수로 그린 목업이고 눌러 볼 수 있다. 미리보기 파일은 저장소에 넣지 않는다. 아래 그림은 권장안을 글자로 옮긴 것이다.

```
견본 메뉴(두 줄)            연동 색
                            ○ │ (A) (B) (C) (D) (E)
                              │ (F) (G) (H) (I) (J)
                            A · 창 1개와 종목을 맞춥니다
                            ○ 끔(빈 고리)  (A) 색 + 글자, 지금 값은 강조색 고리
폭                          데스크톱 약 230px(견본 28px), 휴대폰 약 290px(견본 36px)
닫기 버튼                   지금: 메뉴가 열린 동안 x가 점 쪽으로 11px 붙음   →   열려도 닫혀도 제자리
```

## 확인한 사실

### 1. 지금 메뉴의 색 점이 빠진 결함

- `LinkDot.tsx`의 `Swatch`는 끔이면 `shadow-[inset_0_0_0_2px_var(--line-strong)]`, 색이면 `` `bg-[var(--link-${link})]` ``를 클래스로 쓴다. 뒤쪽은 런타임에 조립한 이름이라 Tailwind가 소스에서 찾지 못해 규칙을 만들지 않는다.
- 이 저장소의 UI를 빌드한 CSS에 `bg-[var(--link-` 규칙은 0건이다. `--link-*`를 쓰는 규칙은 탭 점의 `.link-dot[data-link=…]` 셋뿐이다.
- 샌드박스에서 메뉴 줄마다 점 요소의 계산된 스타일을 읽었다. 끔은 `--line-strong` 고리, A·B·C는 배경이 `rgba(0, 0, 0, 0)`이다. 시험은 메뉴 항목의 이름과 값만 보고 색은 보지 않아 이 결함을 잡지 못했다.
- 같은 꼴(대괄호 임의값 안에 `${…}`)의 클래스는 `web/src` 안에서 이곳 하나다.

### 2. 닫기 버튼이 움직이는 버그

- 도킹 탭 한 칸은 `.dock-tab-group` 안에 탭 버튼, `LinkDot`, 닫기 버튼(`.dock-tab-close`)이 형제로 놓인다(`DockGroup.tsx`). 닫기와 점 사이 간격은 `ui.css`의 `.link-dot + .dock-tab-close { margin-left: calc(var(--size-29) - var(--size-18)) }`(11px)이 준다.
- `LinkDot`은 열린 동안 메뉴를 점 바로 뒤에 그린다. `Popover`는 `popover="manual"`로 최상위 층에 띄워 자리를 차지하지 않지만 DOM에서는 점과 닫기 사이의 형제다. 그래서 열린 동안 `+`(바로 다음 형제) 규칙이 풀려 margin-left가 0이 된다.
- 샌드박스(칸 1 탭)에서 점은 x=75로 그대로이고, 닫기는 포인터를 올린 때 x=105, 메뉴를 연 때 x=94(앞 형제 `ui-popover`), 닫은 뒤 x=105였다. 끔·A 두 상태에서 같았다.
- 같은 화면에서 규칙만 `.link-dot ~ .dock-tab-close`로 바꿔 넣자 관심종목 탭의 닫기가 열기 전·연 동안·닫은 뒤 모두 같은 자리였다.
- 메뉴의 초점은 같은 탭 묶음 안의 팝오버에 있어 열린 동안에도 닫기가 보인다(`--close-shown`). 캔버스·떠 있는 창 머리(`WindowHeader.tsx`의 `.window-actions`)에는 점 뒤 형제에 기대는 규칙이 없다.

### 3. 연동 색 값이 사는 곳

- 서버: `crates/server/src/api.rs`의 `enum LinkColor { A, B, C }`(`serde` 소문자, `ts-rs`로 `web/src/api/generated/LinkColor.ts` 생성)와 `LayoutWindow.link: Option<LinkColor>`. 생성 파일은 `crates/server/tests/contract.rs`가 커밋된 파일과 같은지 본다.
- DB: `crates/server/migrations/0011_layout_windows.sql`의 `layout_windows.link TEXT CHECK (link IN ('a','b','c'))`이고 표는 `STRICT`다. SQLite는 CHECK를 바꾸는 `ALTER`가 없어 표를 다시 만들어야 한다. `drawings`가 `(layout_id, window_id)`로 `layout_windows`를 가리키는 외래 키(`DEFERRABLE INITIALLY DEFERRED`)가 있고, 연결은 `foreign_keys(true)`로 연다(`db.rs`). 부모 표를 지우고 새 표로 바꾸는 마이그레이션은 이 저장소에 아직 없다. 저장은 `userdata.rs`의 `wire_name`·`from_wire_name`으로 enum 이름을 그대로 쓴다.
- 기기 동기화: 레이아웃은 계정 서버에 JSON 문서로 오가고(`setup_bundle.rs`), 받는 쪽이 `Layout`으로 읽는다. 계정 서버는 내용을 보지 않는다. 옛 버전 앱은 `d`~`j`가 든 레이아웃을 읽지 못한다.
- 웹: `web/src/persist/restore.ts`의 `LINK_COLORS = [null, "a", "b", "c"]`(브라우저 미저장본 검사), `LinkDot.tsx`의 `CHOICES`, `web/src/styles/tokens.css`의 `--link-a`·`--link-b`·`--link-c`, `ui.css`의 `.link-dot[data-link=a|b|c]` 셋. `stores/layout.ts`의 `linkLabel`, `alignLinks`, `sendSymbol`, 알림 문구는 색 수와 상관없다.
- 문서: ADR 0019(`link`는 `a`·`b`·`c`·없음), `GLOSSARY.md`의 연동 색("A·B·C와 끔"), `docs/design-system.md`의 "종목 연동과 연동 색" 문단.
- 시험: `api.rs`·`userdata.rs`의 단위 시험, `contract.rs`, `web/src/stores/layout.test.ts`, E2E `win-link`·`win-journey`·`win-float`·`win-manage`(메뉴를 열어 `menuitemradio`로 고름, `win-link`는 메뉴 항목 네 개의 글자를 단언). 지난 PR #476에서 놓친 spec이 머지 뒤 검사를 깨뜨린 일이 있다.

### 4. 열 색의 기준

미리보기에서 후보 색을 계산해 골랐다. 대비는 WCAG 대비율, 색차는 CIEDE2000(ΔE00)이다. 기준은 바탕 `--bg`(#080B09) 대비 7 이상, 점 위 글자(`--bg` 색) 대비 7 이상, 상승·위험(#FF6B78)·하락(#5B9BFF)·강조(#C7F36B)·성공(#7FD69A)·경고(#EBC074)와 ΔE00 14 이상이다. A·B·C는 지금 색을 두고, 나머지는 이미 고른 색과의 가장 작은 ΔE00이 가장 큰 후보를 차례로 골랐다(앞 글자일수록 서로 멀다).

| 이름 | 값 | 바탕 대비 | 가장 가까운 기존 색(ΔE00) | 가장 가까운 연동 색 ΔE00 |
|---|---|---|---|---|
| A | `#B9A6FF` | 9.4 | 하락 18.0 | 14.8 |
| B | `#5ED4E8` | 11.4 | 하락 25.4 | 14.3 |
| C | `#E88AE0` | 8.6 | 상승 23.5 | 15.0 |
| D | `#F59047` | 8.4 | 경고 17.2 | 22.8 |
| E | `#B5C07C` | 10.2 | 강조 14.3 | 15.3 |
| F | `#DEBDBA` | 11.4 | 상승 21.7 | 14.2 |
| G | `#64F7DE` | 15.0 | 성공 14.0 | 17.1 |
| H | `#DED2BA` | 13.2 | 경고 14.1 | 15.3 |
| I | `#BAD2DE` | 12.6 | 하락 20.4 | 14.3 |
| J | `#CA91A4` | 7.6 | 상승 15.7 | 14.2 |

연동 색끼리 가장 가까운 쌍은 F·J(14.2), B·I(14.3)다. 뒤쪽 F~J는 옅은 색이라 색만으로는 덜 구분된다. 점과 견본 안의 글자가 늘 이름을 보인다.

사용자가 미리보기를 보고 정했다.

| 결정 | 근거 |
|---|---|
| 연동 색 메뉴는 B, 가로 색 견본이다. | 사용자의 선택 |
| 메뉴가 열린 동안에도 닫기(x)는 제자리에 보인다. | 권장안 확정 |
| 연동 색을 열 개로 늘린다. | 사용자의 말 |

## 스스로 정한 결정

### 1. 열 개의 이름과 색, 저장

| 결정 | 이유 |
|---|---|
| 이름은 A~J, 저장 값은 `a`~`j`다. 저장된 `a`·`b`·`c`는 그대로 읽힌다. | 기존 값과 문구("연동 A")를 바꾸지 않는다. 숫자 이름은 저장된 값을 옮기는 마이그레이션이 더 든다. |
| 색은 위 표의 열 개다. 토큰 `--link-a`~`--link-j`. | 위 기준을 모두 넘는다. A·B·C는 지금 색이다. |
| 열 개의 목록은 웹에서 한 곳(생성된 `LinkColor`에서 만든 상수 하나)에 두고 `restore.ts`·`LinkDot`·견본 메뉴가 그것을 쓴다. 탭 점과 견본의 색 규칙은 `data-link` 속성으로 칠한다. | 지금 셋이 세 곳에 따로 적혀 있다. 런타임에 클래스 이름을 조립하면 지금 결함이 다시 난다. |
| 서버 `LinkColor`에 `D`~`J`를 더하고, 마이그레이션 0014가 `layout_windows`를 CHECK `a`~`j`로 다시 만든다. 행과 이 창을 가리키는 드로잉은 그대로 남고 외래 키 검사(`PRAGMA foreign_key_check`)가 비어 있어야 한다. | SQLite는 CHECK를 바꿀 수 없다. 부모 표를 바꾸면 `drawings`의 외래 키가 걸린다. 0011처럼 새 표를 만들어 옮긴다. |
| 마이그레이션은 0013까지 올린 DB에 `a`·`b`·`c`·없음 창과 "이 칸" 드로잉을 넣고 0014를 돌리는 Rust 시험으로 증명한다. | 사용자 자료를 바꾸는 단계다. |
| ADR 0019의 `link` 문장을 `a`~`j`로 고치고 "기존 자료"에 0014를 한 줄 더한다. `GLOSSARY.md`와 `design-system.md`의 "A·B·C"도 고친다. | 결정 기록을 지금 모양에 맞춘다. 새 결정이 아니라 값 범위가 넓어진 것이다. |

### 2. 가로 색 견본 메뉴

| 결정 | 이유 |
|---|---|
| 견본은 끔 + A~J 열한 개를 두 줄로 놓는다. 첫 칸에 끔(빈 고리)을 두고 세로선으로 나눈 뒤, 위 줄 A~E, 아래 줄 F~J다. | 한 줄은 데스크톱 약 400px, 휴대폰 약 510px로 360px 화면을 넘는다. 두 줄은 약 230px·290px다. |
| 견본은 탭의 점과 같은 모양(색 + `--bg` 색 글자)이고 데스크톱 28px, 767px 이하 36px다. 끔은 칠하지 않은 `--line-strong` 고리다. | 탭의 점과 바로 맞춰 본다. 휴대폰에서 누르기 쉽다. |
| 머리는 "연동 색" 한 줄이다. 견본 아래 한 줄이 가리키거나 초점이 간 견본을 설명한다: "끔 · 이 창만 따로 봅니다", "A · 창 1개와 종목을 맞춥니다", 없으면 "A · 아직 이 색을 쓰는 창이 없습니다". 기본은 지금 값이다. 팝오버 폭은 설명이 바뀌어도 변하지 않는다. | 미리보기의 B 모양이다. 창 수를 잃지 않는다. |
| 지금 값은 강조색 바깥 고리, 키보드 초점은 그와 다른 고리로 보인다. | 둘이 겹쳐도 구분된다. |
| 역할은 `role="menu"`(이름 "연동 색", `aria-orientation="horizontal"`)와 견본마다 `menuitemradio`다. 접근성 이름은 "A · 창 1개", "B · 없음", "끔"이고 지금 값은 `aria-checked`다. | 화면 읽기 프로그램이 수까지 읽는다. 기존 시험의 선택자(`menuitemradio` 이름 "A…")와 맞는다. |
| 키보드: 열면 지금 값 견본에 초점. ←→ 차례(끔, A…J), ↑↓ 위아래 줄(A↔F, 끔은 그대로), Home·End, A~J 글자 키는 그 견본으로 초점만 옮긴다. Enter·Space로 고르고 닫는다. Esc·바깥 누르기는 바꾸지 않고 닫는다. 닫으면 초점은 점으로 돌아간다. Tab은 닫는다. | 공용 메뉴의 첫 글자 이동과 같은 규칙이다. 글자 키로 바로 바꾸면 잘못 누른 키가 저장된다. |
| 공용 `Popover`로 새 견본 부품을 만든다. 공용 `Menu`는 고치지 않는다. 고르면 지금과 같은 `setLink`를 부르고 같은 값이면 아무것도 바꾸지 않는다. | `Menu`는 세로 목록과 ↑↓ 키보드를 전제로 한다. 저장 동작은 그대로다. |
| 도킹 탭과 캔버스·떠 있는 창 머리의 점이 모두 같은 견본을 연다. 점의 접근성 이름 "연동 색: A", `aria-haspopup="menu"`, `aria-expanded`는 그대로다. | 점은 한 부품이다. |

### 3. 닫기 버튼

| 결정 | 이유 |
|---|---|
| 닫기 간격 규칙을 메뉴가 끼어도 걸리는 형제 규칙(`.link-dot ~ .dock-tab-close`)으로 바꾼다. 탭 묶음 구조는 바꾸지 않는다. | 원인이 이 규칙이고 샌드박스에서 바꿔 넣어 확인했다. 새 견본 팝오버도 같은 자리에 그려진다. |
| 메뉴를 열기 전·연 동안·Esc로 닫은 뒤 탭의 점과 닫기의 위치가 같은지 E2E로 단언한다. | 지금 시험은 닫힌 상태만 본다. |

## 작업과 순서

| 작업 ID | 내용 | 방식 | 방식의 이유 | 시작 조건 |
|---|---|---|---|---|
| `link-colors-ten` | 연동 색을 A~J 열 개로 늘린다. 서버 enum, 마이그레이션 0014, 생성 타입, 웹 목록·토큰·점 규칙, 문서, 모든 시험 | `poteto` | 저장된 사용자 자료의 표를 다시 만드는 마이그레이션과 외래 키 | 바로 시작 |
| `link-swatch-menu` | 연동 색 메뉴를 가로 색 견본으로 바꾸고, 메뉴가 열려도 탭의 닫기 버튼이 제자리에 있게 한다 | `basic` | 화면 부품과 CSS 한 규칙, 저장 동작은 그대로 | `link-colors-ten` 병합 뒤 |

```
link-colors-ten ── link-swatch-menu
```

순차로 둔 이유: `link-swatch-menu`는 `link-colors-ten`이 만드는 열 색의 목록과 토큰·`data-link` 규칙을 쓰고, 둘 다 `LinkDot.tsx`, `ui.css`의 `.link-dot` 구역, `win-link.spec.ts`를 고친다.

`link-colors-ten`이 끝난 사이에는 지금 세로 메뉴가 열한 줄로 보인다. 색 점은 `link-swatch-menu`가 견본으로 바꾸며 돌아온다.

## 범위 밖

- 연동 색의 뜻과 종목 맞춤 규칙(`setLink`·`alignLinks`·`sendSymbol`), 알림 문구.
- 공용 `Menu`의 모양과 동작.
- 닫기 버튼의 보임 규칙(포인터·초점일 때만 보임).
- 옛 버전 앱과의 동기화 호환. 옛 버전 앱은 `d`~`j`가 든 레이아웃을 읽지 못하므로 동기화하는 기기를 모두 새 버전으로 올린다.
- 대괄호 임의값 클래스를 런타임에 조립하지 못하게 막는 기계 검사. 지금 이 꼴은 한 곳뿐이고 `link-swatch-menu`에서 없어진다.

## 사용자가 정해야 하는 결정

미리보기에 권장안과 다른 선택지를 함께 보였다. 정하지 않으면 권장안으로 진행하고, 다르게 정하면 맡는 작업의 지시서만 고친다. 검증을 약하게 하는 작업은 없다. `win-link`의 메뉴 항목 글자 단언은 열한 개 견본에 맞춰 바뀌고, 메뉴 색·키보드·닫기 위치를 보는 시험이 더해진다.

| # | 물음 | 권장(지시서에 적용) | 다른 선택지 | 맡는 작업 |
|---|---|---|---|---|
| 1 | 열 개의 이름 | A~J, 저장 값 `a`~`j` | 1~9·0(숫자 키로 고르기, 저장된 `a`·`b`·`c`를 옮기는 마이그레이션이 더 듦) | `link-colors-ten`, `link-swatch-menu` |
| 2 | 색 열 개 | 위 표의 조합(A·B·C는 지금 색) | 바꿀 색을 알려 주면 같은 기준으로 다시 잼 | `link-colors-ten` |
| 3 | 견본 배치 | 두 줄: 끔 │ A~E / F~J | 한 줄(데스크톱 약 400px, 휴대폰은 넘침) | `link-swatch-menu` |

```sh
python3 scripts/dev.py cargo test -p server --test contract
python3 scripts/dev.py cargo test -p server --lib -- userdata api::tests
python3 scripts/web.py check src/stores/layout.test.ts src/persist/restore.test.ts
python3 scripts/web.py e2e e2e/win-link.spec.ts e2e/win-manage.spec.ts e2e/win-journey.spec.ts e2e/win-float.spec.ts
```

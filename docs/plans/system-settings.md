## 사용자가 풀려는 문제

키움이 지정단말기 인증 실패(`[8050]`)로 거절했고, 화면은 "고친 뒤 서버를 다시 켜야 합니다"만 보였다. 사용자는 서버를 켤 때 키움 연결을 바로 확인하는 동작을 원하지 않는다. 사용자 요청은 다음과 같다.

- 차트 설정과 별도인 **시스템 설정**을 만든다. 거기서 키움 키를 넣는다.
- 키를 넣고 사용자가 연결할 때 키움 서버로 접속한다.
- 시스템 설정은 왼쪽 메뉴 목록, 오른쪽 내용의 두 칸 레이아웃이다.

사용자는 읽기 전용 작업자가 만든 제안서와 시안을 보고 승인했다("ui 미리보기 마음에 들어"). 사용자가 정할 일은 권장안으로 진행하라고 위임했다("정해야하는거 니가 알아서 진행해줘").

- 제안서: `/home/dev/.claude/orch/briefs/kiwoom-connect-ux/proposal.md` (저장소 밖, 읽기 전용 참고)
- 시안: `/home/dev/.claude/orch/briefs/kiwoom-connect-ux/preview.html` (저장소 밖, 읽기 전용 참고)

이 문서는 제안서를 다시 설계하지 않는다. 실행 범위, 작업 순서, 구현 전에 정한 세부를 적는다.

## 지금 코드의 사실 (기준 커밋 `10a5fa2`)

- 서버를 켜면 키움 요청이 바로 나간다. `crates/server/src/app.rs:194`의 `initialize_rest`가 첫 토큰을 발급하고, `:196`의 `KiwoomStream::spawn`이 WebSocket에 접속하며 토큰이 없으면 발급도 부른다. `:198`의 `initialize_market`은 종목 목록(ka10099)을 받고 실패하면 10초마다 다시 받는다. 기본값이 `on`인 스크리너 시작 갱신(`config.rs:193`)도 여기서 돈다. `:199`의 20:05 토큰 재발급과 07:45 종목 목록 갱신은 멈춘 상태가 아니면 언제나 돈다.
- 앱키·시크릿이 없으면 서버가 켜지지 않는다(`config.rs:176-177`). `VALLY_KIWOOM_BASE_URL`·`VALLY_KIWOOM_WS_URL`도 필수다(`config.rs:157-161`).
- `KiwoomAuth`는 만들 때 앱키·시크릿을 고정해 쥔다(`kiwoom/auth.rs:57-64`, `:91-102`). 키를 실행 중에 바꾸는 길이 없다.
- 서버 시험은 `crates/server/tests/common/mod.rs`의 `Server`가 `serve`와 같은 순서로 앱을 조립한다(`initialize_rest`, `initialize_market`). `tests/token.rs`와 `tests/e2e.rs`는 "서버를 켜면 발급이 한 번 나간다"를 확인한다. 시작 동작을 바꾸면 이 시험의 뜻도 바뀐다.
- 병합 검사는 `scripts/web.py check`, clippy, `cargo test -p server`, `scripts/web.py e2e`를 돌린다. 서버 DTO를 바꾸면 생성 타입(`web/src/api/generated`)과 웹 타입 검사도 함께 통과해야 한다.

## 확정된 결정

사용자가 직접 정했다.

1. 서버는 켜질 때 키움을 부르지 않는다. 연결은 시스템 설정의 "키움에 연결" 단추로만 한다. 한 번 누르면 토큰 발급은 최대 1회다.
2. 시스템 설정은 가운데 큰 창이다. 위 막대 "시스템" 단추(연결 상태 점), 상태 줄의 연결 문장, `Alt+,`로 연다. 왼쪽 세로 메뉴와 오른쪽 내용의 두 칸이다. 좁은 화면(48rem 미만)에서는 목록 화면과 내용 화면을 오간다.
3. 제안서와 시안이 화면 구현의 기준이다.

사용자가 위임해 권장안으로 정했다. 바꾸라고 하면 바꾼다.

4. 8050 뒤에는 확인 체크 두 칸("포털에 지금 공인 IP를 등록했습니다", "반복 발급 잠금이 풀렸는지 확인했습니다")을 하고 발급 간격(10분)이 지나면 화면에서 다시 연결한다. 서버를 다시 켤 필요가 없다.
5. 키는 저장소 밖 별도 파일에 둔다. 디렉터리 700, 파일 600이다.
6. `.env`(또는 프로세스 환경)에 `VALLY_KIWOOM_APP_KEY`·`VALLY_KIWOOM_APP_SECRET`이 있으면 화면 저장값보다 앞선다. 화면은 출처 배지와 가린 값만 보이고 편집을 막는다.
7. 첫 구현의 메뉴는 키움 연결, 그리고 읽기 전용의 일반·데이터·정보다. 알림·텔레그램과 재무자료·DART는 "준비 중"으로 비활성이다.
8. 서버 시작 때 자동 연결하는 스위치는 넣지 않는다. 연결은 수동뿐이다.

## 작업과 순서

| 작업 | 내용 | 뒤에 |
|---|---|---|
| `adr-connect` | ADR 0021 새로 쓰기, ADR 0004·0009·0001 고치기, 용어집 최소 추가 | 없음 |
| `srv-idle-start` | 키 없이 켜기, 시작 때 키움 호출 0회, 연결 상태와 `connect`·`disconnect`(Rust 수준), 8050 확인 뒤 풀기, 시험 조립 갱신 | 없음 |
| `srv-system-api` | 키 파일, 키 교체·삭제, `/api/system/*` 라우트, 상태 밀어 주기, Host·Origin 검사, 비밀값 비출력 시험 | `srv-idle-start` |
| `srv-ip-check` | 공인 IP 확인과 등록 IP 기억 | `srv-system-api` |
| `ui-settings-shell` | 시스템 설정 창, 왼쪽 메뉴·오른쪽 내용, 좁은 화면 전환, 여는 곳, 읽기 전용 메뉴, 연결 상태 저장소 | `srv-system-api` |
| `ui-kiwoom-panel` | 키움 연결 내용: 상태 카드, 키 폼, 연결·끊기, 확인 체크, 대기 카운트다운, IP 도움 | `ui-settings-shell`, `srv-ip-check` |
| `ui-before-connect` | 연결 전 화면(차트·검색·관심종목·스크리너·알림), 상태 줄 문장·색 | `ui-settings-shell` |

병렬: `adr-connect`와 `srv-idle-start`가 처음에 함께 돈다. `srv-system-api` 뒤에 `srv-ip-check`와 `ui-settings-shell`이 함께 돈다. `ui-settings-shell` 뒤에 `ui-kiwoom-panel`(`srv-ip-check`도 기다림)과 `ui-before-connect`가 함께 돈다.

순차로 둔 이유:

- `srv-system-api`는 `srv-idle-start`가 만든 연결 상태와 키 교체 API를 쓰고, 같은 `app.rs`·`kiwoom/auth.rs`를 다시 짠다.
- `srv-ip-check`는 `srv-system-api`의 라우트 모듈과 검사 계층에 길을 더한다.
- 화면 작업은 `srv-system-api`가 내보낸 생성 타입을 쓴다.
- `ui-kiwoom-panel`과 `ui-before-connect`는 `ui-settings-shell`이 만든 창 틀과 연결 상태 저장소를 쓴다. 둘은 서로 다른 화면 영역을 고치므로 병렬이다. 둘 다 `web/e2e/fixtures/scenario.ts`에 기본 응답을 더할 수 있으니 그 파일은 최소 변경으로 한다.
- `ui-kiwoom-panel`은 IP 확인 DTO가 필요해 `srv-ip-check`를 기다린다.

## 다른 플랜과 겹치는 곳

- `server-test-speed`(실행 중)가 `crates/server/tests/`와 시험 보조 코드를 고친다. `srv-idle-start`도 `tests/common/mod.rs`, `tests/token.rs`, `tests/e2e.rs`를 고쳐야 한다. 오케스트레이터는 가능하면 `server-test-speed`가 병합된 뒤에 `srv-idle-start`를 시작한다. 먼저 시작하면 작업자는 `tests/` 변경을 최소로 하고 PR 전에 최신 `main`으로 충돌을 푼다.
- `verify-vally`(실행 중)가 `tests/common/mod.rs`의 조립 방식을 재사용할 수 있다. 시작 동작이 바뀌면 그 스킬의 "서버를 켜면 종목 목록이 온다" 가정도 바뀐다. `srv-idle-start`의 PR 본문에 이 변화를 적는다.
- `hoga-*` 작업이 `GLOSSARY.md`를 고친다. `adr-connect`는 용어집에 줄을 더하고 고치기만 하며 다른 항목을 옮기지 않는다.

## 범위 밖

- 알림·텔레그램 설정, OpenDART 키 편집(메뉴는 "준비 중")
- 서버 시작 자동 연결 스위치, 대기 끝 자동 연결, 연속 8050 상한
- 접속 대상 주소를 화면에서 바꾸기, 증권사 선택
- `.env` 키를 화면 저장으로 옮기는 단추(제안서 4절 안 C)
- 기존 쓰기 라우트(`/api/user/*` 등)에 Host·Origin 검사 넓히기
- 밝은 테마, 도킹 창이나 전용 쪽 방식
- 실제 키움·실제 공인 IP 서비스에 접속하는 시험

## 사용자가 정해야 하는 결정

막는 결정은 없다. 아래는 구현 뒤 사용자가 확인하면 좋은 것이다.

1. 키움 포털의 실제 메뉴 이름, 허용 IP가 IPv4만인지, 포털 주소가 `https://openapi.kiwoom.com`이 맞는지. 다르면 `ui-kiwoom-panel`의 안내 문구만 고친다.
2. 공인 IP 확인 서비스로 `api.ipify.org`를 써도 되는지(서버의 공인 IP가 그 서비스에 알려진다).
3. 배포 뒤 처음 서버를 켜면 사용자가 "키움에 연결"을 눌러야 시세가 나온다. 지금 계정은 8050 상태이므로, 포털에서 IP와 잠금을 확인한 뒤 체크 두 칸을 하고 누른다.

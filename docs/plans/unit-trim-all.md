# 남은 화면의 수량 단위 "주" 빼기

작성일: 2026-11-19. 승인 시점의 기록이며 구현 중 바뀐 것은 반영하지 않는다.

## 사용자가 풀려는 문제

사용자 요청(원문):

> 주 모두 제거

직전 플랜 [`ui-trim.md`](ui-trim.md)의 `qty-unit-trim`(PR #673, 병합됨)이 10호가창·호가주문창에서 화면에 보이는 수량 "주"를 모두 뺐다. 그 플랜은 두 창 밖의 "주"를 범위 밖으로 남겼다. 이 요청은 그 나머지 화면에서도 수량 단위 "주"를 모두 없애는 것으로 해석한다(오케스트레이터 해석). 같은 규칙을 따른다. 천 단위 쉼표는 남기고, 화면에 보이지 않는 접근성 이름은 그대로 둔다.

미리보기(비공개): <https://claude.ai/artifact/B1941cyvyoquMj9jPo9F9M>. main 5b653574를 e2e 합성 자료로 띄워 다섯 화면을 찍은 지금 캡처와, 같은 화면에서 글자만 바꿔 찍은 바뀐 뒤 캡처를 나란히 두었다.

### 앱 전체를 다시 찾은 결과

`web/src`에서 "주"가 숫자 뒤나 괄호 안에 붙는 곳과 `formatShares`·`signedShares`·`VALUE_UNIT` 사용처를 모두 확인했다. 서버(`crates/`)는 화면에 보일 수량 글자를 만들지 않는다. 수량 단위로 "주"가 보이는 곳은 다음 다섯 화면이고, 오케스트레이터가 짚은 목록에 두 곳이 더 있다(아래 굵게).

1. 체결 창 띠의 누적 수량: `web/src/features/trades/TradesWindow.tsx`, `formatShares`로 "누적 744주".
2. 프로그램 체결 창: `web/src/features/program/ProgramWindow.tsx`. 머리의 순매수("+2,000주")와 매수·매도("매수 5,000주 · 매도 3,000주")가 `formatShares`를 쓰고, **표의 열 제목 "순매수 증감(주)"**도 있다.
3. 거래원 입체분석 창의 행 끝 누적 순매수: `web/src/features/brokers/BrokersWindow.tsx`의 `signed`가 `formatShares`로 "+400주"(`broker-cumulative`).
4. 순위 창: `web/src/features/ranking/rankingFormat.ts`의 `signedShares`가 "+13만주"를 만든다. 쓰는 열은 외국인 연속의 D-1~D-3·합계, **투자자별 순매수(수량 단위)의 순매수, 호가잔량의 순매수잔량**이다. 외국인 연속의 열 제목 "D-1(주)"·"D-2(주)"·"D-3(주)"·"합계(주)"는 `rankingColumns.ts`에 있다. 부호 없는 수량 열(`sharesCell`, "3만")은 이미 "주"가 없다.
5. 스크리너의 거래량 값 범위 조건: `web/src/lib/screener.ts`의 `VALUE_UNIT.volume = "주"`가 조건 편집 칸 뒤에(`screen-dialog/ConditionFields.tsx`의 `RangeBoxes`) "[100000] 주 ~ [5000000] 주"로, `VALUE_TEXT.volume`이 조건 문장에 "거래량이 10,000주 이하"로 보인다.

수량이 아닌 "주"는 해당하지 않는다. 아래 "범위 밖"에 적었다.

## 확정된 결정

- 사용자 지시: 위 다섯 화면에서 수량 단위 "주"를 모두 뺀다.
- 오케스트레이터가 정한 규칙(직전 플랜과 같다): 천 단위 쉼표는 남긴다. 화면에 보이지 않는 접근성 이름은 "주"를 남긴다.

## 스스로 정한 결정과 이유

1. **글자 모양.** 숫자와 부호, 쉼표, 만·억 줄임은 그대로 두고 "주"만 뺀다.
   - 체결 "누적 744", 프로그램 "+2,000"·"매수 5,000 · 매도 3,000", 거래원 "+400"·"−120", 순위 "+13만"·"−3,000".
   - 열 제목은 괄호째 뺀다: "순매수 증감", "D-1"·"D-2"·"D-3"·"합계". 같은 표의 다른 열("현재가", "한도소진율")도 단위를 적지 않는다.
2. **형식 함수.** 세 창은 `market-window/format.ts`의 `formatQuantity`(PR #673이 더한 숫자만의 수량 형식)를 쓴다. `formatShares`는 남은 쓰임이 호가주문창의 접근성 이름(`OrderLadder.tsx`의 주문 칩, `OrderTotals.tsx`의 접수 합계)뿐이므로 그 용도로 남긴다. 순위 창의 `signedShares`는 "주"만 빼고 이름과 쓰임은 그대로 둔다. 값의 뜻이 주 수라서 이름이 맞다.
3. **스크리너.** 거래량의 단위 글자를 없앤다. 편집 칸 뒤에는 단위 자리를 그리지 않아 "[100000] ~ [5000000]"이 된다(빈 칸이 여백으로 남지 않게 한다). 한쪽만 적는 모양은 "[100000] 이상"이다. 조건 문장은 "거래량이 100,000 이상 5,000,000 이하인 봉이 있다"가 된다. 원·억 원 단위의 다른 값 범위는 그대로다.
4. **접근성 이름.** 다섯 화면에는 "주"가 든 접근성 이름이 없다. 순위 표의 열 제목은 화면에 보이는 글자이므로 뺀다.
5. **문서.** `docs/design-system.md`의 "숫자 형식" 줄(`formatShares`를 "그 밖의 창"이 쓴다는 설명)과 순위 창 "표" 줄("외국인 연속의 D-1~D-3은 키움이 주는 주 단위로 보인다")을 바뀐 동작에 맞춘다.
6. **작업은 하나다.** 화면 다섯 곳의 표시 글자와 그 시험만 바꾸는 작은 수정이고 서로 의존하지 않는다. 오케스트레이터가 PR 하나를 권했다.

   | 작업 | 내용 | 방식과 이유 | 순서 |
   |---|---|---|---|
   | `unit-trim-all` | 체결·프로그램 체결·거래원·순위·스크리너의 수량 "주" 빼기, `design-system.md` 두 줄 | `basic`: 표시 글자만 바꾼다. 값 계산, 저장 모양, 서버는 건드리지 않는다 | 바로 |

   이 탭 계획에서 진행 중인 다른 작업이 없어 겹치는 파일이 없다.

## 범위 밖

- week 뜻의 "주": 봉 주기 단추 "주"(주봉), 스크리너 기간 단위("최근 8주 이내", `UNIT.W`), "52주 신고가" 같은 이름, 결과의 맞은 날짜 "11-02 주"(`matchedDateText`), 이평 기간 오류 문구("긴 이평 20주보다").
- 종목 종류 이름: "우선주", "보통주".
- 화면에 보이지 않는 접근성 이름: 호가주문창 주문 칩·접수 합계의 `aria-label`("매수 접수 12주 2건").
- 재무 지표 DPS의 단위 "원/주"(`chart/axisFormat.ts`, `chart/financials.ts`). 한 주당 금액이라 수량 단위가 아니다. 아래 "사용자가 정해야 하는 결정"에 적었다.
- 생성된 API 타입의 주석(`api/generated/*.ts`, "잔량은 주")과 API 설명 문서(`docs/kiwoom-rankings-api.md`의 "(주)"). 화면에 보이지 않는다.
- 값 계산, 줄임 규칙(만·억), 열 순서와 폭.

## 사용자가 정해야 하는 결정

- DPS의 "원/주"는 남긴다. 한 주당 배당금이라는 뜻이 단위에 들어 있어서다. 이것도 빼려면(축과 범례를 "원"으로) 말해 주면 지시서에 한 줄 더한다.

검증을 약하게 하는 변경(검증 단계 삭제, 시간 제한 증가, `paths` 축소)은 없다. "주"를 기대하던 단위 시험과 e2e는 새 글자를 기대하도록 바꾸고, 체결 창 누적 수량에는 "주"가 없다는 기대를 새로 더한다.

# 차트 연동 플랜: 십자선 연동 범위 고르기와 짧은 주기 차트로 봉 바로가기

작성일 2026-11-18, 사용자 답을 반영해 2026-11-19에 두 번 고침. 승인 시점의 기록이며 구현 중 바뀐 것은 반영하지 않는다.

기준: `origin/main` 128aa99f(처음), ce2e3c27(두 번째 고침).

## 사용자가 풀려는 문제

캔버스에 일봉 차트와 분봉 차트를 나란히 띄우고 본다. 두 가지가 필요하다.

1. 십자선 연동이 어느 차트끼리 묶일지 고르고 싶다. 사용자의 말로는 "같은 창번호만, 같은 번호만, 아니면 둘 다"다.
2. 일봉에서 바로가기를 누르면 그 날짜가 분봉 차트의 가장 오른쪽에 오고, 기본 봉 수만큼 보이게 하고 싶다. 그 뒤 왼쪽으로 스크롤하면 과거 봉을 더 받는다. 먼 날짜도 기다림 없이 가야 한다("그날짜까지 가도록 자동으로 받도록 해야지", "기준날짜 우측에 캔들데이터는 필요없으니까 뱃지같은걸로 지금은 바로가기 모드다 라고 표현해주고 하면 더 빨리 받을 수도 있어?" → "2번으로 해줘").

## 지금 있는 것 (조사 결과)

- **십자선 연동**: 레이아웃 메뉴의 체크 항목 하나(`LayoutSync.crosshair`)다. 켜면 같은 레이아웃의 보이는 모든 차트가 한 묶음이다(`web/src/chart/crosshairSync.ts`의 `CrosshairSync.connect(key, …)`, 열쇠는 `${session}:${layoutId}`, `web/src/features/grid/ChartCell.tsx`). 주기가 다르면 긴 주기는 그 시각을 포함하는 봉, 짧은 주기는 그 구간의 첫 봉에 맞춘다(`matchingBarTime`).
- **저장 형식**: `LayoutSync`(`crates/server/src/api.rs`)는 레이아웃 행의 `sync` 열에 JSON으로 들어간다. 필드마다 `#[serde(default = "yes")]`가 있고 `deny_unknown_fields`가 없다. 그래서 필드를 하나 더해도 DB 마이그레이션이 필요 없고, 옛 앱은 모르는 필드를 무시한다.
- **과거 봉 받기**: 이미 있다. `BarFeed.needOlder()`가 왼쪽 끝이 가까워지면(`LOAD_OLDER_WITHIN`) `before` 커서로 500봉 페이지를 하나씩 받고, 받은 봉을 이어진 열의 앞에 붙인다(`prependOlder`). `BarFeed`는 socket 없이도 만들 수 있다. 서버 봉 캐시(`crates/server/src/bars.rs`)는 (종목, 거래소, 주기)마다 빠짐없는 구간 하나를 두고, `before` 앞에 `limit`봉이 모일 때까지 키움 연속조회를 거꾸로 이어 받는다. 07:45에 모두 비우고(`clear_all`) 10분 쓰지 않은 시리즈를 내린다(`evict_idle`).
- **오늘 기준으로 내려가는 길의 비용**: 주식 분봉은 오늘부터 연속조회로 내려가야 한다. 통합 1분봉 1년은 191페이지, 57초였다(키움 실측 기록 §2, 삭제된 `docs/kiwoom.md`, 커밋 4f4b1503의 부모에 있다). 페이지는 900봉이고 요청 사이 간격은 260ms(`SEND_SPACING`)다. 오늘 기준 연속조회의 끝은 마지막 관측일로부터 1년이다.
- **과거 기준일 분봉(ka10080 `base_dt`)**: `base_dt`에 과거 날짜를 넣으면 그날 마지막 봉(예: 19:59)부터 거꾸로 온다(같은 기록 §1). 주식은 그날 뒤의 권리발생이 빠진 가격이 온다(§4.1). 알테오젠 `196170_AL` 60분봉 실측에서 두 조회의 가격 비율은 봉마다 같았고(약 1.2995), 거래량은 같았다. 고정 입력이 이미 있다: `crates/server/tests/fixtures/kiwoom/ka10080_196170_AL_60_base_20260716.json`, `…_today_p1.json`, `…_today_p2.json`. 이것을 쓰는 시험이 `crates/server/tests/adjustment_basis.rs`다. 명세는 `upd_stkpc_tp=1`이 "`base_dt`보다 앞선 권리발생만 반영"한다고 적고(ka10081), 실측은 분봉도 같음을 보였다. 키움이 주는 수정 가격은 호가 단위로 반올림되지 않은 정수다(예: 214,306). 과거 `base_dt`의 연속조회가 어디서 끝나는지(오늘부터 1년인지, 그 날짜부터 1년인지)는 **근거가 없다**.
- **서버 코드**: `BarService::fetch_direct(key, base, cont, prio)`가 이미 기준일(`base: KstDate`)을 받아 `MinuteChart::new(…, base)`·`DailyChart::new(…, base)`에 넘긴다. 그래서 `crates/server/src/kiwoom/api.rs`를 고치지 않고 과거 기준일 조회를 보낼 수 있다. 지금 이 기준일은 시리즈의 오늘(`Series.today`)뿐이다.
- **브라우저 시험**: e2e는 서버 없이 `web/e2e/fixtures/scenario.ts`가 생성 DTO 모양의 응답을 주고, 모르는 API는 거절한다(ADR 0016).
- **우클릭 메뉴와 컨트롤러**: 차트 빈 곳 우클릭 메뉴는 `drawingMenu`(`web/src/features/drawings/menus.ts`)다. 컨트롤러는 셀 id로 찾는다(`controllerFor`, `web/src/features/grid/controllers.ts`). 이미지 저장(`features/snapshot/saveSnapshot.ts`)이 같은 길을 쓴다.
- **단축키**: `Alt+G`는 비어 있다. `G`는 자석(드로잉), `Shift+G`는 자석 세기다.

## 확정된 결정 (사용자 답)

- **범위의 뜻**: 창번호는 연동 색, 번호는 종목이다. 범위는 끔·모든 차트·같은 종목·같은 연동 색이고 기본은 모든 차트다("너가 말한대로하면돼"). 아래 결정 1~4.
- **바로가기의 기준 봉**: 기준 차트 화면에 보이는 가장 오른쪽 봉이다. 우클릭 메뉴와 `Alt+G` 모두 같고, 포인터나 누른 자리와 상관없다("현재 일봉의 가장 우측 봉 날짜", 우클릭 메뉴도 그렇게 하느냐는 물음에 "응 그렇게해줘"). 아래 결정 5.
- **바로가기 모드**: 오늘부터 이어 받지 않고, 그 날짜를 기준일로 분봉을 바로 받아 보인다. 그 날짜 뒤의 봉은 받지 않고, 대상 차트에 뱃지로 바로가기 모드임을 보인다. 과거 기준일 가격은 오늘 기준 수정주가로 보정한다("2번으로 해줘"). 그래서 처음 고침의 30,000봉 한도와 오늘부터 `needOlder`로 이어 받는 바로가기는 빠진다. 아래 결정 7~12.
- **바로가기 대상**: 사용자가 답하지 않아 플랜의 기본값(같은 종목의 더 짧은 주기 차트 모두)으로 진행한다. 아래 결정 6.

## 결정

### 십자선 연동 범위

1. **"창번호"는 연동 색(A~J), "번호"는 종목(종목코드)으로 읽는다.** 이 앱의 연동 색은 HTS의 연동 그룹 번호를 색으로 바꾼 것이다. 같은 연동 색의 차트는 언제나 같은 종목이므로(`alignLinks`) "둘 다 맞을 때"는 "같은 연동 색"과 같다. "둘 중 하나가 맞을 때"는 "같은 종목"과 같다. 그래서 고를 수 있는 범위는 셋이다: **모든 차트**(지금 동작), **같은 종목**, **같은 연동 색**. 사용자가 이 해석을 확정했다.
2. **레이아웃 메뉴의 체크 항목 하나를 라디오 네 개로 바꾼다.** 머리 "십자선 연동" 아래 끔 / 모든 차트 / 같은 종목 / 같은 연동 색. 범위 하나만 고르는 일이라 라디오가 맞고, 끔을 같은 줄에 두어 메뉴에서 한 번에 고른다. 연동을 끈 동안에도 고른 범위는 남는다.

   ```
   ┌ 레이아웃 ───────────────┐
   │ ✓ 기본                  │
   │   분석                  │
   │ ─────────────────────── │
   │ 새 이름으로 저장…       │
   │ 이름 바꾸기…            │
   │ 지우기                  │
   │ ─────────────────────── │
   │ 십자선 연동             │  ← 머리
   │   끔                    │
   │ ✓ 모든 차트             │
   │   같은 종목             │
   │   같은 연동 색          │
   │ ─────────────────────── │
   │ 기본 배치로             │
   │ …                       │
   └─────────────────────────┘
   ```
3. **레이아웃마다 저장한다.** 지금 십자선 연동 켜짐이 레이아웃마다이므로 범위도 같은 자리(`LayoutSync`)에 둔다. 저장 이름은 `crosshairScope`, 값은 `"all" | "symbol" | "link"`이고, 키가 없으면 `"all"`로 읽는다. 기존 레이아웃과 새 레이아웃의 기본값은 `"all"`이라 업데이트 뒤에도 동작이 그대로다.
4. **묶음은 `CrosshairSync`의 열쇠로 나눈다.** `CrosshairSync` 클래스는 바꾸지 않는다. 열쇠를 레이아웃 열쇠 + 범위별 꼬리(같은 종목이면 종목코드, 같은 연동 색이면 색)로 만들고, 종목이나 색이 바뀌면 다시 연결한다. 같은 연동 색 범위에서 연동 색이 꺼진 차트는 어느 묶음에도 들지 않는다. 같은 종목은 종목코드만 비교하고 거래소는 보지 않는다(거래소는 앱 전체 설정, ADR 0020). 비교 종목은 보지 않는다.

### 봉 바로가기

5. **이름은 "바로가기"(사용자의 말)이고, 우클릭 메뉴와 `Alt+G` 두 곳에서 부른다. 기준은 언제나 기준 차트 화면에 보이는 가장 오른쪽 봉이다.** 화면 오른쪽 끝 시각 이하인 마지막 봉이고, 오른쪽 여백 때문에 화면 끝이 마지막 봉보다 오른쪽이면 마지막 봉(진행 중 봉 포함)이다. 포인터 위치와 누른 자리는 보지 않는다. 우클릭 메뉴 항목은 기준 차트에 봉이 있으면 누른 자리와 상관없이 보이고, 이름에 기준 날짜를 적는다: "바로가기 · 2026-11-09"(분봉이 기준이면 "바로가기 · 2026-11-09 10:30"). 날짜 뒤 조사("로/으로")가 숫자마다 달라지지 않게 가운뎃점으로 잇는다. hint는 `Alt+G`다. `Alt+G`는 활성 칸이 기준 차트다.
6. **대상은 같은 레이아웃에서 같은 종목을 보는, 기준 차트보다 짧은 주기의 다른 차트 창 모두다.** 일봉 → 분봉이 주 사용처이고, 같은 규칙으로 주봉 → 일봉, 60분 → 1분도 된다. 기준 구간은 기존 `barInterval(봉 시각, 기준 주기)`이고, 기준 날짜는 그 구간 마지막 순간이 속한 한국 날짜다. 연동 색과 십자선 연동 범위는 보지 않는다(같은 연동 색은 이미 같은 종목이다). 고르지 않은 탭에 숨은 차트도 대상이다. 대상이 없으면 아무것도 바꾸지 않고 "같은 종목의 더 짧은 주기 차트가 없습니다"를 알린다.
7. **대상마다 길을 셋으로 나눈다.**
   - 대상이 이미 그 구간 시작까지 봉을 가지고 있거나 기준 날짜가 오늘이다: 지금 봉 열에서 화면만 옮긴다. 오늘인데 첫 페이지가 오늘 첫 봉에 못 미치면(통합 1분봉은 하루 최대 약 720봉) `needOlder`로 한두 페이지 이어 받는다. 모드에 들지 않으므로 실시간 봉이 계속 붙는다.
   - 대상이 분봉이고 그 구간을 아직 가지지 않았으며 기준 날짜가 오늘보다 이르다: **바로가기 모드**에 든다(결정 8~12).
   - 대상이 일·주·월봉이다(주봉 → 일봉 등): 지금처럼 `needOlder`로 그 구간까지 이어 받는다. 일봉 전체도 1985년부터 약 11,000봉이라(키움 600봉 페이지) 몇 초 안에 끝나고, 과거 기준일 보정이 필요 없다. 한도는 두지 않는다.

   어느 길이든 화면은 그 구간의 마지막 봉(`t < 구간 끝`인 마지막 봉)을 가장 오른쪽에 두고 보이는 봉 수 설정만큼 보인다. 자동이면 첫 화면과 같은 수(`fitInitialRange`: 데스크톱 130, 767px 이하 90)이고 오른쪽 여백도 첫 화면과 같다. 활성 칸은 바꾸지 않는다. 결과는 알림 하나로 묶어 보인다(예: "1분·5분 차트를 2026-11-09로 옮겼습니다").
8. **바로가기 모드는 그 날짜를 기준일로 한 별도 봉 열이다.** 서버에 새 조회 `GET /api/bars/jump?symbol&venue&period&date=YYYY-MM-DD[&before&limit]`를 둔다. 첫 페이지는 그 날짜의 마지막 분봉에서 끝나는 `limit`봉이고, `before`로 더 과거를 받는다. 대상 차트는 평소 봉 받기(구독 포함)를 닫고 이 조회로 만든 `BarFeed`(socket 없음)를 연다. 그래서 왼쪽 스크롤의 과거 받기는 같은 기준일 계열로 지금처럼 이어진다. 오른쪽(그 날짜 뒤)의 봉은 받지 않고 그리지 않는다. 키움 조회는 첫 페이지에 분봉 1번과 일봉 1~2번이면 되고, 1분봉으로 1년 전에 가도 1초 안팎이다.
9. **서버의 바로가기 봉 열은 기존 캐시와 따로 둔다.** `BarService` 안에 (종목, 거래소, 주기, 기준일)을 열쇠로 하는 두 번째 표를 두고, 기존 시리즈(`Series`, 오늘 기준)에는 한 봉도 넣지 않는다. 기존 07:45 비우기와 10분 미사용 내리기를 같이 따른다. 실시간 집계기는 이 표를 보지 않는다. 같은 열쇠의 동시 요청은 기존처럼 열쇠별 잠금에서 줄을 선다. 주기는 분봉만, 날짜는 오늘보다 이른 날만 받고 나머지는 `bad_request`다.
10. **가격은 날마다 일봉 비율로 오늘 기준 수정주가로 바꾼다.** 날짜 d의 비율은 "오늘 기준 일봉의 d 종가 ÷ 기준일 D로 받은 일봉의 d 종가"다. 두 값은 같은 일봉 TR(ka10081, `upd_stkpc_tp=1`, 같은 거래소 코드)이라 종가의 뜻이 같다. 기준일 D로 받은 분봉과 일봉은 같은 규칙("D보다 앞선 권리발생만 반영")을 따르므로, 이 비율은 D 뒤(그리고 D 당일)의 권리발생만 담는다. 분봉의 마지막 종가와 일봉 종가를 견주지 않는 이유는 일봉 종가·거래량이 분봉과 어긋나는 날이 실측에 있기 때문이다(같은 기록 §3). 오늘 기준 일봉은 기존 캐시의 일봉 시리즈에서 읽고, 기준일 일봉은 그 바로가기 봉 열에 붙여 한 번(600일, 모자라면 연속조회) 받는다.
    - 시가·고가·저가·종가에 그날 비율을 곱해 정수 원으로 반올림한다. 키움의 수정 가격도 호가 단위로 반올림되지 않은 정수라 차이는 1원 안팎이다. 거래량은 바꾸지 않는다(실측에서 수정 전후 거래량이 같았다).
    - 지수는 수정주가가 없어 비율이 1이고 일봉을 받지 않는다.
    - 그날 비율을 구할 수 없으면(어느 한쪽 일봉에 그날이 없음, 종가가 0) 그날 분봉은 받은 가격 그대로 두고, 응답의 `unadjustedDays`에 그 날짜를 적는다.
    - 한 페이지 안의 비율은 대개 하나다. 비율이 날마다 다른 것은 그 사이에 권리발생이 있었다는 뜻이므로 오류로 보지 않는다.
11. **뱃지와 모드 중의 화면.** 대상 차트 칸 왼쪽 아래(시간축 바로 위, 가격축 방식 콤보박스와 반대쪽)에 뱃지 "바로가기 · 2026-11-09"와 닫기 버튼(접근성 이름 "바로가기 끝내기")을 둔다. 받는 동안은 "· 받는 중"을 붙인다. `unadjustedDays`가 하나라도 있으면 경고색으로 "· 일부 날짜 수정주가 미반영"을 붙이고, 그 날짜 목록은 `title`에 둔다. 모드 중에는 다음과 같다.
    - 실시간 봉을 붙이지 않는다. 범례는 그 계열의 마지막 봉 값이다.
    - 지표는 이 봉 열로 계산한다.
    - 드로잉은 그대로 보이고 고칠 수 있다. 가격을 오늘 기준으로 바꿨으므로 같은 자리에 놓인다.
    - 십자선 연동에도 평소처럼 참여한다.
    - 비교 종목 선은 숨긴다. 비교 종목은 오늘 기준 계열이라 이 봉 열과 맞지 않는다. 비교 종목이 있으면 뱃지에 "· 비교 숨김"을 붙인다.
    - 모드는 레이아웃에 저장하지 않는다. 새로고침하면 평소 화면이다.
12. **모드 끝내기와 실패.**
    - 뱃지의 닫기, 대상의 종목·주기·거래소 바꾸기, 오늘 날짜로의 바로가기는 모드를 끝낸다. 평소 봉 받기를 다시 열고 첫 화면(최신)으로 돌아온다.
    - 모드 중에 다른 날짜로 바로가기가 오면 새 기준일 계열로 바꾼다.
    - 받는 도중 모드가 끝나거나 새 바로가기가 오면 앞 응답은 버린다(기존 `BarFeed` 세대 규칙).
    - 첫 페이지가 비었다(키움이 그 날짜 분봉을 주지 않음): 모드에 들지 않고 "2026-01-05 분봉을 키움이 주지 않습니다 · 분봉은 대개 최근 1년까지입니다"를 알린다. 과거 기준일의 끝이 어디인지 근거가 없어(조사 결과) 날짜로 미리 막지 않는다.
    - 그 날짜 분봉은 없고 그 전 봉만 있다(거래정지 등): 첫 페이지의 마지막 봉을 오른쪽에 두고 "그 날 분봉이 없어 직전 봉까지 보입니다"를 알린다.
    - 받기 실패: 모드에 들지 않고 평소 화면을 그대로 두며 "분봉을 받지 못했습니다"를 알린다. 모드 중 과거 페이지 실패는 기존 과거 받기 실패 안내(다시 시도)를 쓴다.

### 작업 나누기

| 작업 | 내용 | 방식과 이유 | 순서 |
|---|---|---|---|
| `xhair-scope` | `LayoutSync.crosshairScope`(서버·생성 타입·웹 기본값), 레이아웃 메뉴 라디오, `ChartCell`의 묶음 열쇠, GLOSSARY·design-system의 십자선 연동 | `poteto`: 레이아웃 저장 형식을 바꾼다(상태 저장) | 병렬 |
| `jump-server` | `GET /api/bars/jump`, `BarService`의 기준일별 봉 열 표, 날마다 일봉 비율 보정, DTO·생성 타입, 합성 transport 시험 | `poteto`: 시세 캐시와 수정주가 보정(데이터), 열쇠별 잠금(동시성) | 병렬 |
| `bar-jump` | 바로가기 순수 함수(대상·기준 봉·오른쪽 끝 봉·길 고르기), 컨트롤러의 화면 옮기기와 바로가기 모드(`BarFeed` 바꾸기, 뱃지, 비교 숨김), 우클릭 메뉴·`Alt+G`, 알림, e2e 시나리오의 `/api/bars/jump`, GLOSSARY·design-system의 바로가기 | `poteto`: 컨트롤러·봉 받기·메뉴·단축키에 걸친 새 설계이고 비동기 받기의 취소를 다룬다 | `jump-server` 뒤 |

`bar-jump`는 `jump-server`가 만든 생성 TS 타입(`JumpBarsPage`)과 조회 모양을 쓰므로 뒤에 둔다. `xhair-scope`와 `jump-server`는 다른 타입과 다른 서버 모듈을 고친다. 겹치는 파일은 `crates/server/src/api.rs`(각자 자기 타입만 더함)와 `crates/server/tests/contract.rs`(생성 타입 목록에 한 줄씩)이고 최소 변경으로 병렬이다. `xhair-scope`와 `bar-jump`가 같이 고치는 파일은 `GLOSSARY.md`, `docs/design-system.md`, `web/src/chart/crosshairSync.ts`(`PERIOD_ORDER` 내보내기), `web/e2e/fixtures/scenario.ts`이고 각자 몇 줄씩이다. `web/src/features/grid/ChartCell.tsx`는 `xhair-scope`만 고친다. `bar-jump`는 뱃지를 컨트롤러가 칸 위에 얹는 DOM으로 그린다(화면 내 최고·최저 꼬리표 `.chart-extreme`와 같은 방식).

같은 탭의 순위 창 플랜(`docs/plans/ranking-window.md`)과 겹치는 파일:

- `crates/server/src/api.rs`: `xhair-scope`는 `LayoutSync`에, `jump-server`는 새 DTO를 더한다. 순위 작업의 `WindowContent`·순위 DTO·`SymbolKind`·`ExcludeKind`와 다른 타입이라 최소 변경으로 병렬이다.
- `crates/server/src/http.rs`, `crates/server/src/lib.rs`: `jump-server`는 경로 하나와 모듈 하나를 더한다. `rank-service`도 순위 경로와 모듈을 더한다. 각자 한두 줄이다.
- `crates/server/src/kiwoom/api.rs`: `rank-tr`가 고친다. `jump-server`는 고치지 않는다(`fetch_direct`가 이미 기준일을 받는다).
- `GLOSSARY.md`, `docs/design-system.md`: 순위 창 작업은 새 절을 더하고 이 플랜은 십자선 연동·우클릭 메뉴·바로가기 문단을 고치거나 더한다. 최소 변경으로 병렬이다.
- `web/src/api/generated/`: 각자 자기 타입 파일만 다시 만든다.

## 범위 밖

- 스크롤 연동(`LayoutSync.scroll`): 저장 필드만 있고 동작은 없다. 이번에도 넣지 않는다.
- 차트 창마다 다른 십자선 연동 범위: 레이아웃 하나에 범위 하나다.
- 바로가기 대상이 없을 때 새 분봉 차트를 만들거나 기준 차트의 주기를 바꾸기.
- 긴 주기 차트로 바로가기(분봉 → 일봉). 긴 주기 차트는 십자선 연동으로 이미 그 봉을 가리킨다.
- 바로가기 모드에서 그 날짜 뒤(오른쪽)를 이어 받기, 모드 중 실시간 봉, 모드 중 비교 종목.
- 과거 기준일 분봉의 끝을 실제 키움으로 재기. 시험은 실제 키움을 부르지 않는다. 재려면 사용자가 따로 정한다.
- 휴대폰 화면의 바로가기: 차트가 하나라 대상이 없다. 우클릭 메뉴가 있는 곳에서는 같은 알림이 나온다.

## 사용자가 정해야 하는 결정

1. **수정주가를 반영하지 못한 날의 처리.** 그날 비율을 구할 수 없으면 받은 가격 그대로 보이고 뱃지에 "일부 날짜 수정주가 미반영"을 경고색으로 붙인다(결정 10·11). 그날 뒤 권리발생이 있었다면 그날 가격이 일봉·드로잉과 어긋나 보인다. 이런 날을 아예 그리지 않기를 원하면 알려 달라. 기본값으로 진행해도 된다.
2. **1년보다 먼 날짜.** 과거 기준일 분봉이 오늘부터 1년에서 끝나는지 근거가 없다. 플랜은 날짜로 미리 막지 않고 키움이 비운 응답을 주면 알린다. 실제 키움으로 한 번 재 볼지는 사용자가 정한다(이 플랜에는 넣지 않았다).

바로가기 대상은 기본값(같은 종목의 더 짧은 주기 차트 모두)으로 진행한다.

검증 단계 삭제, 시간 제한 증가, `paths` 축소처럼 검증을 약하게 하는 작업은 없다.

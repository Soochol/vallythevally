# 10호가·호가주문 창의 거래소 연동

작성일: 2026-11-19. 승인 시점의 기록이며 구현 중 바뀐 것은 반영하지 않는다.

미리보기(점검표, 지금/바뀐 뒤 비교, 정할 것): https://claude.ai/artifact/YQ7dnRusLko2Jg4ALh7ArU

## 사용자가 풀려는 문제

사용자 요청(원문):

> 호가주문에서  거래서(krx, nxt, 통합) 이걸 변경해도 전환이 안돼 연동이 안되어있나봐 다른 창들도 연동이 되어야하는지 조사하고 체크해줘, 별도 플랜으로 진ㅇ

거래소(통합·KRX·NXT)를 바꾸면 호가주문창의 사다리 호가·체결·잔량도 그 거래소로 바뀌기를 기대했다. 다른 창도 거래소를 따라야 하는지 점검해 달라고 했다.

## 원인

- **호가 사다리는 통합 하나로만 받게 설계돼 있다.** 서버는 종목마다 키움 통합 코드 `_AL` 하나만 등록한다(`crates/server/src/kiwoom/wire.rs` `real_item_code`). 통합 0D에는 거래소 필드가 없어 나눌 수 없다. 그래서 ADR 0028 "거래소"가 호가·프로그램·거래원 창은 통합 값만 보이고 앱 전체 거래소가 KRX·NXT이면 "통합" 표시를 붙이기로 정했다. 서버는 `subscribe_feed`의 거래소를 체결에만 쓰고 호가는 늘 통합으로 받는다(`crates/server/src/ws.rs`). 호가 첫 화면 ka10004도 통합으로만 묻는다(`kiwoom/api.rs` `StockOrderBook`).
- **웹도 호가를 통합으로 고정한다.** `web/src/features/book/useBookFeed.ts`는 호가·체결 구독, 호가 첫 화면, 현재가를 모두 `combined`로 받는다. 10호가창의 사다리 안 체결·거래량도 `combined`다(`BookWindow.tsx`).
- **호가주문창 한 창 안에 기준이 셋이다.** 사다리·잔량·현재가는 통합, 사다리 안 체결 7건과 거래량은 ⚙의 주문 경로(SOR·KRX·NXT, 모의는 KRX)를 따른다(`OrderWindow.tsx` `venue`). 위 막대 거래소는 탭의 "통합" 표시만 바꾼다. 사용자가 위 막대 거래소를 바꿨든 ⚙ 주문 경로를 바꿨든 사다리는 바뀌지 않는다.
- **KRX만, NXT만의 호가는 받을 수 있다.** 키움 코드 접미사는 REST·실시간 모두 KRX가 접미사 없음, NXT가 `_NX`, 통합이 `_AL`이다(`docs/kiwoom-intraday-snapshot-api.md`). 통합 호가가 KRX·NXT 호가를 합친 것이라는 판정은 hoga-ops가 거래소별 호가와 견주어 낸 것이다(`docs/research/2026-11-15-kiwoom-al-realtime-types.md`). 실시간 등록 자리는 코드마다 하나라서 `_NX`를 더하면 자리가 늘어난다(같은 조사 문서 "필요한 키").

## 확정된 결정

1. 별도 플랜으로 진행한다(요청).
2. 따라야 하는데 따르지 않는 창은 고친다(요청·오케스트레이터 메모).
3. 실제 키움은 부르지 않는다. 확인은 합성 transport와 e2e 장면으로 한다.
4. 미리보기의 정할 것은 모두 추천안으로 한다(2026-11-19 사용자: "이것 모 추천으로 진행").
   - 호가 사다리를 거래소마다 바꾼다. 10호가·호가주문 창이 KRX·NXT 호가를 따로 받는다.
   - 호가주문창 시세는 위 막대 거래소를 따른다. ⚙ 주문 경로는 주문이 나가는 곳만 정한다.
   - 프로그램 체결·거래원 창은 지금처럼 통합 값과 "통합" 표시를 둔다.
   - 이 플랜의 작업은 같은 파일을 고치는 `ladder-trades`·`order-account`·`book-flicker`·`drag-cancel`과 `account-number-api` 뒤에 돈다.

## 스스로 정한 결정

1. **10호가창·호가주문창은 거래소별 호가를 받는다.** ADR 0020이 "거래소를 한 번 바꾸면 모든 화면이 그 거래소로 바뀌어야 한다"고 정했고 사용자 기대도 같다. 통합 호가를 나눌 수는 없으니 서버가 KRX면 접미사 없는 코드, NXT면 `_NX` 코드로 0D와 ka10004를 따로 받는다.
2. **다른 실시간 종류는 지금처럼 `_AL`이다.** 0B 체결은 `_AL` 한 흐름에서 `9081`로 이미 거래소를 가른다. 0E(장후 시간외 총잔량)·0w·0F도 `_AL` 그대로다. 거래소별로 따로 받는 것은 0D뿐이다.
3. **같은 값을 주는 코드는 다시 쓴다.** NXT에 없는 종목은 KRX 호가가 통합 호가와 같으므로 `_AL` 0D를 쓴다. NXT에 없는 종목을 NXT로 보면 차트와 같은 규칙(ADR 0020)으로 통합 호가를 보이고 "통합" 표시를 붙인다. 자리가 더 드는 경우는 NXT에서도 거래되는 종목을 KRX나 NXT로 볼 때뿐이다. 그때 그 종목은 `_AL`과 거래소 코드 두 자리를 쓴다.
4. **거래소별 0D도 지금의 자리 규칙을 그대로 따른다.** 새 창 보유자 순위, 30초 유예, 200개가 찬 상태에서 해지 먼저, 다시 이어질 때 모두 다시 REG가 거래소 코드에도 같다. 자리가 모자라면 지금처럼 `realtime_limit` 거절이 그 창에 보인다.
5. **호가주문창의 시세는 위 막대 거래소를 따른다.** 사다리·잔량·현재가·사다리 안 체결·거래량이 모두 같은 거래소다. ⚙의 주문 경로는 주문이 나가는 곳만 정한다. GLOSSARY "주문 경로"가 이미 "시세가 체결된 곳인 거래소와 다른 말이다"라고 적었다. `order-book-ui` 플랜 스스로 정한 결정 12의 "호가주문창은 주문 경로 거래소의 체결을 쓴다"를 바꾼다.
6. **모의 프로세스도 같은 규칙이다.** 지금 모의는 사다리 안 체결을 KRX로 고정하지만, 시세가 따르는 값이 주문 경로에서 위 막대 거래소로 바뀌므로 그 고정도 없앤다. 모의 서버가 거래소 코드를 받지 못하면 지금 있는 거절·멈춤 표시로 보인다(ADR 0030 결정 10).
7. **"통합" 표시는 프로그램 체결·거래원 창과 NXT 대체 때만 남긴다.** 10호가·호가주문 창은 통합 값이 아니게 되므로 탭·머리의 "통합" 표시를 떼고, NXT에 없는 종목을 NXT로 볼 때만 붙인다.
8. **ADR은 새로 쓴다.** ADR 0028의 "거래소" 항목 가운데 호가 부분을 바꾸는 ADR 0032를 서버 작업이 쓰고, 0028에서 그 항목에 0032를 가리키는 한 줄을 더한다.
9. **화면에 새 거래소 표시는 더하지 않는다.** 위 막대가 이미 거래소를 보인다.

## 나눈 방식

| 작업 | 맡는 것 | 순서 |
|---|---|---|
| `book-venue-server` | 호가 구독·ka10004에 거래소를 받고, 거래소 코드 0D를 등록·해지·배달한다. ADR 0032 | 먼저 |
| `book-venue-web` | 10호가·호가주문 창이 위 막대 거래소로 호가·체결·현재가를 받고, "통합" 표시를 고친다. GLOSSARY·ADR 0020 | `book-venue-server` 뒤. 서버가 거래소별 호가를 줘야 화면을 시험할 수 있다 |

같은 탭 계획의 다른 플랜 작업과 같은 파일을 고친다. 그래서 `after`로 그 뒤에 둔다(확정된 결정 4).

- `order-polish2`의 `book-flicker`: `kiwoom/wire.rs`·`kiwoom/stream.rs`·`market/hub.rs`·`useBookFeed.ts`와 `OrderWindow.tsx`를 고친다.
- `order-polish2`의 `ladder-trades`: `useLadderSlots.ts`·`BookWindow.tsx`·`intraday_feed.rs`와 `OrderWindow.tsx`를 고친다.
- `order-polish2`의 `order-account`: `OrderSettingsPopover.tsx`와 `OrderWindow.tsx`를 고친다.
- `drag-cancel`: `OrderWindow.tsx`·`win-order.spec.ts`·`e2e/order-window.ts`를 고친다.

`book-venue-server`는 `book-flicker`·`ladder-trades`와 서버 API 타입·생성 타입을 고치는 `account-number-api` 뒤, `book-venue-web`은 `book-venue-server`·`order-account`·`drag-cancel` 뒤다. `drag-cancel`이 앞의 넷을 모두 기다리므로 `book-venue-web`은 결국 넷 모두의 뒤가 된다.

## 범위 밖

- 프로그램 체결창·거래원 입체분석창의 거래소별 값(확정된 결정 4).
- 주문 경로 고르기와 주문 전송.
- 순위 창, 스크리너, 지수.
- 실제 키움에서 거래소 코드 0D가 오는지와 자리 계산을 실측하는 일. 실제 키움 호출이 금지돼 있다. 병합 뒤 실사용에서 확인한다.
- 호가 복기 수집기의 등록 방식.

# 새 창 후속 두 가지: 흔들리는 계정 삭제 시험, 도킹 탭의 "통합" 배지

작성일 2026-11-18. 승인 시점의 기록이며 구현 중 바뀐 것은 반영하지 않는다.

기준: `origin/main` 1d8ca36f. 앞 플랜은 [`new-windows.md`](new-windows.md)다.

## 사용자가 풀려는 문제

> 흔들리는시험 작업에 올려 / 후속 작업 올려

새 창 작업을 하다 남은 두 가지를 끝낸다.

1. **서버 시험 하나가 가끔 실패해 chute 반송을 일으킨다.** `crates/server/tests/account_login.rs`의 `when_the_state_file_cannot_be_removed_after_deletion_memory_and_file_still_agree`가 main에서 10번에 1번꼴로 실패한다. win-kit PR #504가 base e8b2160e에서 이 실패로 반송됐다(`/home/dev/.local/state/chute/repos/Soochol__vallythevally/reports/pr-504/1.md`). 실패 문구는 `파일이 남았으니 메모리도 로그인 상태다`이고, `left: "signed_out"`, `right: "signed_in"`이다.
2. **도킹된 탭 묶음에서는 "통합" 배지가 보이지 않는다.** 10호가·프로그램 체결·거래원 입체분석·호가주문 창은 앱 전체 거래소가 KRX나 NXT일 때 통합(`_AL`) 값임을 알리는 "통합" 배지를 붙인다(앞 플랜의 스스로 정한 결정 2). 배지는 창 머리(`WindowHeader`)에 있다. 그런데 도킹된 탭 묶음에는 창 머리가 없다. 그래서 창마다 본문에 배지를 따로 넣어 우회했다. 프로그램 체결창은 본문 배지에 CSS(`.window-head:has(.mw-integrated) ~ .window-panel .pg-badge`)를 더해 캔버스에서 두 번 보이지 않게 했고, 10호가·거래원 창은 본문에 배지를 넣었다. 호가주문창은 도킹되면 배지가 아예 없다.

## 확정된 결정

1. 시험을 지우거나 단언을 약하게 하지 않는다(요청).
2. "통합" 배지는 탭 막대에 단다. 그 뒤 창별 우회 배지와 CSS를 지운다(요청).
3. 두 작업은 따로 PR로 간다. 겹치는 파일이 없어 병렬로 간다(요청).

## 흔들리는 시험의 원인

코드를 읽어 찾은 원인이다. 작업자가 먼저 재현으로 확인한다.

시험 순서는 다음과 같다.

1. 로그인한 뒤 상태 파일 디렉터리를 `0o500`으로 바꾼다.
2. `POST /api/account/delete`를 보낸다. 계정 서버는 계정을 지운다. 커넥터는 상태 파일을 지우지 못해 500을 돌려주고 메모리를 로그인 상태로 둔다(`AccountState::delete_account`, `crates/server/src/account/mod.rs`).
3. 디렉터리를 `0o700`으로 되돌린다.
4. `GET /api/account`가 `signed_in`인지 본다.

`delete_account`는 실패한 경로에서도 `session_changed()`를 부른다. 이것이 셋업 동기화 루프(`account::sync::run`, `crates/server/src/account/sync.rs`)를 깨워 바로 `Phase::Full` 동기화를 돌린다. 계정 서버는 지워진 계정의 토큰에 401을 준다. `guard` → `expire`가 상태 파일을 지우고 메모리를 로그아웃으로 바꾼다.

- `expire`가 3번 전에 돌면 디렉터리가 아직 `0o500`이라 지우기가 실패하고 메모리는 로그인 상태로 남는다. 시험이 통과한다.
- `expire`가 3번과 4번 사이에 돌면 지우기가 성공하고 메모리가 `signed_out`이 된다. 시험이 실패한다.

이때도 메모리와 파일은 서로 맞는다. 둘 다 로그아웃이다. 서버 동작은 시험 이름이 말하는 성질을 지킨다. 틀린 것은 시험이 권한을 되돌린 뒤에 "아직 로그인 상태"를 보는 순서다.

## 스스로 정한 결정과 이유

1. **흔들리는 시험은 시험 순서를 고친다. 서버 코드는 고치지 않는다.** 상태 확인을 디렉터리가 `0o500`인 동안 하고, 그 자리에서 상태 파일이 남아 있는지도 본다. 그 뒤 권한을 되돌린다. 권한이 막혀 있는 동안에는 어느 경로도 파일을 지울 수 없으니 결과가 시각에 매이지 않는다. 단언은 그대로 두고 파일 확인을 하나 더하니 약해지지 않는다. `delete_account`가 실패 경로에서 `session_changed()`를 부르지 않게 바꾸는 안은 고르지 않았다. 로그인 직후의 동기화가 이미 돌고 있으면 그 동기화의 401도 같은 경합을 만든다. 그리고 지우기에 실패한 뒤 곧바로 다시 동기화해 정리를 시도하는 지금 동작은 맞다.
2. **재현을 먼저 남긴다.** 작업자는 고치기 전에, 권한을 되돌린 뒤 상태를 보기 전에 잠깐 기다리는 줄을 임시로 넣어 실패가 매번 나는지 확인한다. 그 줄은 커밋하지 않는다. 원인이 위와 다르면 서버 코드를 고치지 않고 멈춰 보고한다. 서버 동작을 바꾸는 일은 이 플랜이 정하지 않았기 때문이다.
3. **"통합" 배지는 탭 이름 옆에 둔다.** 스크리너 탭의 `ScreenerBadge`와 같은 자리다. 선택되지 않은 탭에도 보인다. 캔버스 창과 도킹 바깥에 띄운 창(`DockFloats`)은 지금처럼 `WindowHeader`의 배지를 쓴다. 결과적으로 어느 배치에서도 배지는 창마다 정확히 하나, 창 틀(탭이나 머리)에만 있다.
4. **본문의 우회 배지를 모두 지운다.** 10호가 띠, 거래원 띠, 프로그램 체결 "순매수 누적" 제목의 배지와 `.pg-badge` CSS 두 줄이다. 체결창의 "통합 기준"(`trade-integrated-only`)은 뜻이 다르다. 선택한 거래소로 조회되지 않은 종목을 알리는 표시라서 그대로 둔다.

## 범위 밖

- 계정 동기화 루프와 `delete_account`의 동작 변경.
- 같은 파일의 다른 시험이나 다른 흔들리는 시험 찾기. 이번에 반송을 일으킨 시험 하나만 고친다.

- 배지의 문구·색 바꾸기. 지금 `.mw-integrated` 모양을 그대로 쓴다.

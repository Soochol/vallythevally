## 스스로 정한 결정과 이유

### 방향: 조용한 표면, 또렷한 숫자

- 화면 틀은 뒤로 물리고 숫자에 대비를 준다. 강조색(`--accent`)은 고른 것·주요 행동·초점·"지금" 표시에만 쓰고 자료(막대·선·넓은 면)에는 쓰지 않는다.
- 누를 수 있는 것은 쉬고 있을 때도 경계(면 또는 테두리)가 보인다. 예외는 도구 막대의 아이콘 버튼이다.
- 빈·오류·불러오는 중은 모든 창이 같은 상태 판으로 말한다.
- `--up`·`--down`은 값의 방향에만, 상태는 `--danger`·`--warning`·`--success`에만 쓴다.

### 틀의 치수는 지킨다

- 위 막대 48px, 바깥 간격 12px, 탭 줄 34px, 상태 줄 28px, 목록 줄 34px(기본)은 바꾸지 않는다.
- 이유: 2~4px의 이득에 비해 창 배치 계산(`WINDOW_HEAD_HEIGHT`)과 치수를 단언하는 시험을 넓게 흔든다. 이득은 틀의 높이가 아니라 틀 안의 줄 수를 줄이는 데서 낸다(순위 고르기 188→76px, 스크리너 255→150px, 페이지 본문 y=134→72).

### 규칙을 시험으로 지킨다 (`ui2-tokens`)

- CSS와 TSX가 쓰는 모든 `var(--이름)`이 `tokens.css`에 정의돼 있는지 확인하는 단위 시험.
- 글자·바탕 쌍의 대비가 4.5:1 이상인지 확인하는 단위 시험(쌍 목록은 시험 파일에).
- 표식 파일 `.ui2`가 있는 폴더는 굵기 넷·글자 크기 일곱 단계·11px 하한·색 직접 값 금지를 지켜야 한다. 화면별 작업이 자기 폴더에 표식을 둔다. 한 파일의 허용 목록을 여러 작업이 함께 고치지 않게 하려는 방식이다.

### 성능 규칙

1. 흐림(`backdrop-filter`)은 작고 잠깐 뜨는 메뉴·팝오버에만 쓴다. 틀, 차트·시세 위에 오래 떠 있는 창, 포인터를 따라 움직이는 것은 불투명이다.
2. 실시간 구역(호가·체결·시세 줄·차트)에는 배치를 바꾸는 전환을 넣지 않는다. 움직임은 `opacity`와 `transform`만 쓴다.
3. 줄은 자기 값이 바뀔 때만 다시 그린다. 새 구독이나 목록 전체 리렌더를 더하지 않는다.
4. 숫자 열은 고정 폭과 tabular 숫자다. 폭이 모자라면 열을 우선순위대로 빼고 가로 스크롤을 쓰지 않는다.
5. 창 틀은 `contain: layout paint`, 긴 목록과 화면 밖 카드는 `content-visibility: auto`.
6. 그림자는 팝오버와 대화상자 두 단계만. 창과 카드는 1px 선.
7. 뼈대는 움직이지 않는다.
8. 성능을 고치는 작업(`ui2-mw-perf`, `ui2-list-rows`, `ui2-heatmap`)은 고치기 전과 뒤의 그리기 횟수를 시험으로 남긴다. 재현은 지연 주입·가짜 시계와 `VALLY_E2E_CPU_THROTTLE`로만 한다.

### 표기 규칙

- 방향: 등락률 배지는 ▲▼와 절댓값, 대비(원)는 부호. 현재가는 `--text`이고 등락률 열이 빠질 때만 방향 색(갈림길 10).
- 날짜·시각: `YYYY-MM-DD HH:MM`, 오늘이면 `HH:MM`. 초는 실시간 기준 시각에만.
- 다시 하기 문구는 "다시 시도" 하나. 불러오는 중은 "…을 받는 중".
- 종목 한 줄에는 이름만 적고 코드는 풍선말에 둔다(지금 규칙). 표(페이지)에서는 "이름 + 코드 11px".

### 약속 작업

`ui2-tokens`(토큰의 이름과 값, 규칙 시험)와 `ui2-primitives`(공통 부품의 이름·props·클래스)가 약속 작업이다. 화면 작업 24개가 모두 이 둘이 정한 모양을 쓰고, 둘이 끝나면 병렬로 간다. `ui2-primitives`는 모양만이 아니라 구현도 담는다. 빈 부품으로는 화면 작업이 자기 e2e를 통과시킬 수 없어서다. `ui2-css-split`은 그 앞에 두는 일괄 이관이다.

### 핵심 경로

핵심 경로: `ui2-css-split` → `ui2-tokens` → `ui2-primitives` → `ui2-mw-perf` → `ui2-order` → `ui2-order-safety`. 여섯 가운데 poteto가 다섯이고, `ui2-mw-perf`는 다른 플랜의 order-ledger 병합도 기다린다. 작업 수로는 `ui2-primitives` 뒤의 `ui2-topbar` → `ui2-page-frame` → `ui2-heatmap` → `ui2-market-page` 쪽이 일곱으로 더 길지만 poteto가 둘뿐이라 먼저 끝난다. 핵심 경로의 작업은 묶지 않았고 더 쪼개지도 않았다. 지금은 앞 작업의 병합을 기다려야 다음이 시작하므로, 같은 파일을 고치는 일을 더 쪼개면 병합 대기가 한 번씩 늘어난다.

### 묶음

묶음 규칙(같은 영역, 같은 방식, 항목 5개 이하, 합친 diff 약 600줄 이하, 서로 순서 없음, 위험한 일과 쉬운 일을 섞지 않음)으로 basic 작업 20개를 다시 보았다.

- `ui2-shell-states`(항목 2, 추정 약 650줄): 복원·오류 화면과 재무자료 버튼·상태 창. 둘 다 작고 폴더가 달라 순서가 없다.
- `ui2-screener`(항목 2, 추정 약 800줄): 스크리너 창과 조건 편집 창. 같은 화면이고, 같은 폴더라서 두었던 순서 한 단계가 없어진다.
- 나머지 basic 16개는 묶지 않았다. 하나가 이미 고칠 곳 7~13군데와 새 e2e 경우 6~10개로 추정 400~900줄이어서, 둘만 합쳐도 600줄 기준을 넘는다. 추정 근거: 최근 `web/` 위주 PR 40개의 diff 중앙값이 361줄, 상위 25%가 685줄이고, 히트맵·ETF·시장 종합 페이지를 처음 넣은 PR이 755·848·1,188줄이었다.
- 순서가 필요한 쌍(`ui2-topbar` → `ui2-page-frame`, `ui2-heatmap` → `ui2-market-page`, `ui2-chart-axis` → `ui2-chart-legend`)은 규칙대로 묶지 않았다.
- poteto 작업 9개는 주문 창, 실시간 렌더 구조, 창 배치 저장, 키 입력처럼 위험한 일이라 서로도 묶지 않았다.

### 순차로 둔 이유

- `ui2-css-split` → `ui2-tokens` → `ui2-primitives`: 토큰 작업은 나눈 파일 구조 위에서 `index.css`를 고치고, 부품 작업은 그 토큰으로 부품을 만든다. 나머지 모두가 부품을 쓴다.
- `ui2-page-frame` 뒤 `ui2-topbar`: 페이지 위 막대가 작업 영역 위 막대의 검색·상태 부품을 다시 쓴다.
- `ui2-dock-fit` 뒤 `ui2-dock-tabs`: 같은 창 틀 코드(`features/workspace`)를 고친다.
- `ui2-chart-legend` 뒤 `ui2-chart-axis`: 둘 다 `ChartController.ts`를 고친다. 대비 수정이 작고 급해 먼저다.
- `ui2-ranking`·`ui2-screener` 뒤 `ui2-list-rows`: 공통 줄과 열 머리를 쓴다.
- `ui2-mw-perf` → `ui2-order` → `ui2-order-safety`·`ui2-market-windows`: 같은 사다리·주문 창 코드다. 성능을 먼저 두어 줄 단위로 나눈 구조 위에서 모양을 고친다. 뒤의 둘은 겹치는 파일이 없어 병렬이다.
- `ui2-market-page` 뒤 `ui2-heatmap`: 히트맵 작업이 색 함수를 공용 자리로 옮기고 시장 종합의 업종 지도가 그것을 쓴다. 둘 다 `ui2-page-frame`의 페이지 틀을 쓴다. `ui2-etf`도 같다.
- `ui2-onboarding` 뒤 `ui2-settings`: 마법사가 설정 창이 정리한 키 입력 폼과 IP 안내를 가져다 쓴다.
- `ui2-density` 뒤 `ui2-list-rows`·`ui2-settings`: 줄 높이 토큰을 쓰는 목록과 설정 화면의 메뉴가 먼저 있어야 한다.
- 다른 플랜의 작업 뒤: `ui2-statusbar`·`ui2-screener`는 screener-kis-summary(`features/status`, `features/screener`), `ui2-mw-perf`와 그 뒤의 셋은 order-ledger(`features/order`), `ui2-page-frame`·`ui2-market-page`는 kis-rest-edges(`features/market-page`, `market-page.spec.ts`).

### 병렬

`ui2-primitives`가 끝나면 `ui2-topbar`·`ui2-shell-states`·`ui2-dock-tabs`·`ui2-search`·`ui2-chart-axis`·`ui2-chart-tools`·`ui2-drawings`·`ui2-list-rows`·`ui2-settings`가 함께 간다. `docs/design-system.md`는 모든 작업이 자기 절만 고치는 공유 파일이다. 여러 영역을 함께 확인하는 e2e(`float-content`·`float-surfaces`·`float-menus`·`win-shell`·`lime-ui`·`lime-layout`)와 `App.tsx`·`PageRail.tsx`도 공유 파일로 두고 최소 변경으로 고친다.

## 작업별 결정

### ui2-css-split
- `styles/ui.css`(한 줄에 선언 하나, 298줄)를 공통(`ui.css`) · `shell.css` · `workspace.css` · `chart-cell.css` · `screener.css` · `financial.css`로 나눈다. `drawings.css`의 범례 밀도 규칙은 `chart-cell.css`로, `ui.css`의 드로잉 규칙은 `drawings.css`로 옮긴다.
- 선언은 글자 하나 바꾸지 않는다. 불러오는 순서로 생기는 우선순위 차이가 없게 한다.

### ui2-tokens
- 위 "토큰" 표와 "규칙을 시험으로 지킨다".

### ui2-primitives
- 위 "공통 부품" 표. 기존 클래스(`tb-btn`·`seg-btn`·`icon-btn`·`btn-primary`·`ui-field`·`ui-state`)는 남기고 새 규칙으로 다시 칠한다. 화면별 작업이 직접 값을 부품으로 바꾼다.

### ui2-topbar
- 세 구역(앱 전체 | 고른 칸 | 작업 공간), 조작부 30px 하나, 줄임 경계 1280·1024·832 셋.
- 레이아웃 메뉴는 레이아웃(목록·저장·이름·지우기)과 배치(창 배치 방식·기본 배치·크기 고르게·되돌리기·다시 하기)로 가른다. 십자선 연동은 레이아웃 메뉴에 남긴다.
- 분봉 버튼의 동작(첫 누름은 마지막 분봉, 분봉일 때 다시 누르면 메뉴)은 바꾸지 않는다.

### ui2-shell-states
묶음이다. 항목 1 복원·오류 화면:
- 복원 중에는 위 막대·창 자리·레일·상태 줄의 틀 뼈대. 렌더 오류에는 "다시 불러오기"와 "기본 화면으로 열기"가 있는 화면.

항목 2 재무자료 버튼과 상태 창:
- 버튼 상태 다섯(쉼·수집 중·멈춤·확인 필요·완료), 점은 진행 중·실패에만. 진행률은 전체 기준 하나. 직접 그린 진행 막대.

### ui2-statusbar
- 상태 줄은 연결 · 장 상태와 시각(분 단위) · 저장 · 동기화 · 재무 · 오른쪽 끝 출처. 점은 연결에만.
- 저장 실패·서버 미연결·키움 조회 멈춤·실시간 멈춤은 위 막대 아래 한 줄 띠(32px)로 올린다. 띠는 작업 영역 위에 겹쳐 띄워 배치를 바꾸지 않는다.
- 연결 전 카드는 시작 안내(세 걸음)와 원인별 실패 제목.

### ui2-page-frame
- 페이지에서는 위 막대 한 줄에 로고·페이지 이름·신선도·그 페이지의 조작·보낼 연동 색·찾기·시스템. 페이지 머리 섬을 없앤다. 주소 조각을 지운다.
- 데스크톱에서 "‹" 링크를 숨긴다. 신선도 줄은 한 모양.

### ui2-dock-tabs
- 탭 줄 34px 유지. 고른 탭 `--raised`, 올린 탭 `--hover`. 탭 위 강조선은 두지 않는다.
- 넘치면 ＋ 고정, "탭 N개" 목록, 가장자리 흐림. 닫기는 탭 모양 안, 누르는 자리 24px.
- 끈 연동 점은 포인터·초점일 때만 보인다(갈림길 8).

### ui2-dock-fit
- 저장된 비율은 두고 그릴 때 최소 크기로 누른다. 다 못 담으면 낮은 우선순위 묶음을 탭으로 접고 알린다.
- 기본 배치는 종류의 최소 높이를 본다. 호가주문의 `home`은 세로 자리.
- 캔버스로 처음 바꿀 때 겹침이 셋을 넘으면 가지런히 배치.

### ui2-search
- 결과 줄 격자(별 · 이름과 코드 · 시장 · 현재가 · 등락률), 찾은 글자는 굵기로 강조, 상태 판, 바닥 줄 안내는 모드별 한 곳.
- 명령마다 다른 아이콘. `?` 키와 레일로 여는 단축키 판.

### ui2-chart-axis
- 현재가·드로잉 꼬리표 글자는 `--on-data`. 7자리 가격에서 글자를 줄이지 않고 축 폭 72·80·88px.
- 패널마다 주 값 하나만 축 꼬리표. 현재가 선 실선 55%, 십자선 파선, 날짜 구분선 점선.
- 칸 오류·불러오는 중·봉 없음·연결 전은 상태 판. 수동 조치 오류에는 "시스템 설정 열기".

### ui2-chart-legend
- 전체·압축(칸 폭 480px 미만 또는 가격 패널 300px 미만)·최소(폭 320px 미만) 세 단계. 가격 패널 위 여백은 범례 높이.
- 지표가 셋을 넘으면 접는다. 최고·최저 꼬리표는 범례를 피한다.
- "조회 값"·"멈춤"·한도 초과는 한 벌의 알약(경고는 `--warning`). 바로가기 뱃지는 범례 머리줄 끝.
- 휴대폰은 최소 단계.

### ui2-chart-tools
- 차트 설정은 버튼 아래 340px 팝오버(갈림길 14). 지표 창은 1280px 이상에서 "차트 옆"이 기본이고 가운데 창은 720px로 오른쪽 위.
- 지표 팝오버는 두 단(설정값 먼저, 색 더 보기). 색 고르기 문구 하나.

### ui2-drawings
- 세부 설정은 높이 560px 안, 탭 넷, 드로잉 반대쪽. 피보나치 수준 한 줄 다섯 칸.
- 드로잉 기본색 `--draw`는 강조색과 다른 색. 드로잉 글자에 차트 바탕 상자.

### ui2-list-rows
- `listRow.tsx`에 공통 열 머리와 줄. 등락률 배지 64px, 열 사이 8px. 보는 종목 줄은 지금처럼 바탕색.
- 좁으면 열을 우선순위로 빼고, 빠진 열은 메뉴에 "창이 좁아 숨김". 등락률 열이 빠지면 현재가에 방향 색.
- 줄을 틀과 값으로 나누고 `memo`. 구독을 좁힌다. 창 폭은 열 수가 바뀔 때만 상태로.

### ui2-ranking
- 고정 열 폭과 열 우선순위(그 순위의 값 → 등락률 → 현재가). 한 줄 34px. 고르기 두 줄(분류와 상태 / 순위 칩과 "조건").
- 줄 우클릭 메뉴. 발 줄 한 줄.

### ui2-screener
묶음이다. 항목 1 스크리너 창:
- 머리 한 줄, "…" 메뉴 하나, 요약 한 줄(큰 숫자 없음), 단축키 안내 줄 삭제.
- 자료 없음은 호박색 점, 멈춤만 빨강. 조건 요약 한 줄은 갈림길 15.

항목 2 조건 편집 창:
- 편집 창은 불투명. 숫자에 이름("볼린저 밴드(기간 20, 배수 2)"), 조사 붙여 쓰기, 자리에서 숫자 고치기.
- 휴대폰 대화상자의 조건은 같은 문장 편집.

### ui2-mw-perf
- 사다리 줄과 주문 칸을 값 비교로 건너뛰는 컴포넌트로. 소켓 메시지는 프레임당 한 번 반영. `OrderBody`를 호가 부분과 계좌 부분으로.
- 막대는 `transform: scaleX`. 체결·프로그램 목록은 줄 24px 고정에 보이는 줄만.
- 화면 모양은 바꾸지 않는다.

### ui2-order
- 종목 머리 줄(`SymbolHead`): 이름·코드·현재가·등락률·장 상태.
- 계좌 버튼과 실전·모의 배지. 모의는 머리 줄 바탕에 표시.
- 열 머리 고정. 주문 열은 옅은 매도·매수 면, 포인터를 올린 칸에만 테두리와 미리보기.
- 처음 열 때·종목 바꿀 때·"현재가" 버튼에 현재가 줄을 가운데로. 높이가 모자라면 단수를 줄인다.
- 끊김·연결 전은 띠와 흐림. 좁으면 카드·체결 열을 숨긴다. 10px 글자를 11px로. `user-select: none`.

### ui2-order-safety
- 둘 이상의 주문을 한 번에 취소하는 동작은 두 번 누르기(갈림길 12). 주문 한 건의 신규·정정·취소는 그대로.
- 합계 목록 줄에 "취소" 글자를 따로. 고액 확인 상자에 종목·방향·계좌·경로.
- 결과 막대는 색 띠·아이콘·12px, 사다리 아래 고정 줄.

### ui2-market-windows
- 다섯 창의 뼈대(종목 머리 · 요약 띠 · 표 머리 24px · 줄 24px · 바닥 띠)와 숫자 규칙.
- 체결량은 방향 색. 프로그램 표 머리 정렬. 잘릴 숫자는 그리지 않는다. 모든 조회 실패에 "다시 시도".

### ui2-market-page
- 12칸 격자. 지수 28px와 포인트. 수급 범례에 색과 선 끝 값, 주체는 범주색. 거래대금 막대는 중립 면에 오늘만 강조, 평균선과 날짜.
- 업종 지도는 히트맵의 색 함수와 범례. 표 머리 정렬, 거래대금 부호 없음, 줄 전체 누르기.

### ui2-heatmap
- 보드 오류·불러오는 중 화면. `HeatmapGroup`·`Tile`을 `memo`, 신선도 시각을 따로.
- 도구 막대 한 줄. 타일 글자는 px 기준. 등락률순은 상승·보합·하락 묶음 안에서 넓이순.
- 색 함수·글자 규칙을 공용 자리로. 테마 편집 서랍은 불투명.

### ui2-etf
- 트리맵 농도 12~34%, 겹침 행렬 0~38%, 대각선 "—". 이평선 점에 범례. 공용 `Select`. 누적 곡선 글자 11px.

### ui2-settings
- 대화상자 기본 글자 14px. 버튼 단계. 칸 오류. 키 없음 빈 상태. 8050 화면은 한 카드에 차례로.
- 주문 사용은 위험 설정(스위치·경고 띠·"실전 주문 켜기"). 계좌 확인 두 단계는 지킨다.
- 휴대폰 입력 칸 높이 버그. 메뉴 묶음. 호출 한도 카드 접기. 큰 대화상자 불투명.

### ui2-onboarding
- 마법사 세 단계(키 준비 → 붙여넣기와 연결 → 끝), 가운데 560px 카드, 주요 버튼 하나, Esc.
- 덮어쓰기 확인은 위험색. 공개 모드의 사용 불가 화면은 하나로, 한도 안내에 남은 시간.

### ui2-density
- 줄 높이 기본 34px·촘촘 28px. 이 브라우저에만 저장한다. 이유: 알맞은 밀도는 화면 크기에 달려 기기마다 다르다.

## 범위 밖

제안은 artifact에 있고, 하기로 정하면 작업으로 만든다(갈림길 16에서 이번 범위는 P1·P2로 확정됐다).

- 휴대폰 화면 다시 짜기(차트 머리, 휴대폰용 호가·주문·순위).
- 랜딩과 로그인 뒤 시작 화면.
- 수집 현황판을 페이지 틀에 넣기.
- 밝은 테마(갈림길 2).
- 체결 알림, 키보드만으로 주문하기, 더블클릭 즉시 주문의 기본값 바꾸기, 끊긴 동안 주문 막기(갈림길 13).
- 스크리너 결과 없음에서 조건별로 남은 종목 수 보이기(서버 응답이 필요).
- 서버의 오류 문구 자체를 고치기. 이 플랜은 화면이 오류 코드에 맞는 제목을 붙이고 서버 문구를 "자세히"로 내린다.

# NXT 미거래 종목의 장 마감 뒤 호가주문창 빈 사다리

작성일: 2026-11-18. 승인 시점의 기록이며 구현 중 바뀐 것은 반영하지 않는다.

## 사용자가 풀려는 문제

GS건설(006360)을 호가주문창에 띄우면 2026-11-18 19:50경(KST) 사다리 대신 "호가 사다리 없음 / 이 종목은 15:30 뒤 호가가 멈춥니다"만 보인다. 주문 경로를 SOR(통합)·KRX·NXT 중 어느 것으로 바꿔도 같다. 사용자는 NXT에서 거래되지 않는 종목에서만 이렇게 된다고 봤다.

## 조사 결과

증상은 화면이 받은 호가를 버려서 생긴다. 서버는 정상이다.

1. **GS건설은 NXT 미거래 종목이다.** 8080 서버의 `GET /api/symbols/006360`이 `nxtEnabled: false`를 돌려줬다.
2. **서버는 장 마감 뒤에도 호가를 준다.** 19:59에 `GET /api/symbols/006360/order-book`(키움 `ka10004`)이 매도·매수 10호가씩과 총잔량 2,053/7,714, `bookTime` 19:59:39를 돌려줬다. 서버 로그(`target/vally-server.log`)에도 `ka10004`가 HTTP 200으로 계속 기록된다.
3. **화면이 시각만 보고 사다리를 지운다.** `web/src/features/order/holdingSummary.ts`의 `ladderClosed`는 `nxtEnabled === false`이고 KST 15:30 이후이면 `true`를 돌려준다. `OrderWindow.tsx`는 `closed`이면 받은 호가(`view`)가 있어도 사다리 대신 위 빈 상태를 그린다.
4. **주문 경로 선택은 이 판단에 들어가지 않는다.** `ladderClosed`는 경로를 받지 않는다. `useBookFeed`는 경로와 상관없이 호가를 언제나 `combined`로 구독하고 `/order-book`을 조회한다. 그래서 SOR·KRX·NXT 어느 것을 골라도 같은 빈 상태가 보인다. NXT 거래 종목은 `ladderClosed`가 `false`라 사다리가 보인다. 사용자가 본 "NXT 미지원 종목만"과 맞는다.
5. **의도된 설계였다.** order-panels 지시서가 "시간외는 '호가 사다리 없음' 빈 상태다. 호가 0D가 15:30 뒤 멈추는 KRX 전용 종목도 같다"고 정했다(커밋 3211b338). 결과적으로 마감 호가를 볼 수 없게 됐고, 사용자는 이것을 이상하다고 봤다. 10호가창(`features/book/`)에는 이 판단이 없어 같은 시각에 호가가 보인다. 두 창이 서로 다르게 동작한다.
6. **ladder-grid(PR #568) 때문이 아니다.** 실행 중인 서버는 19:12 빌드이고 웹 `dist`는 19:15 빌드다. 둘 다 main 1a540488(19:08)에서 나왔다. ladder-grid는 19:49에 병합됐으니 이 빌드에 없다. 서빙 중인 번들 `index-BqRb32Uu.js`에 "15:30 뒤" 문구가 있다.

조사하다 본 다른 현상: 같은 로그에서 18:09(KST)부터 `kt00010`(주문가능금액)이 `return_code 20`으로 실패한다. 서버는 그 뒤 이 조회를 막아 두었다. 화면의 "매수 가능 -"은 이 때문이다. 이 플랜 범위 밖이다.

## 확정된 결정

- NXT 미거래 종목도 15:30 뒤 호가주문창에 받은 호가로 사다리를 그린다.

## 스스로 정한 결정과 이유

1. **사다리는 그대로 그리고, 사다리 바로 위에 한 줄 안내를 둔다.** 문구는 "15:30 장 마감 뒤 멈춘 호가입니다 · NXT에서 거래되지 않는 종목"이다. 뒷부분은 `web/src/lib/venue.ts`의 `NXT_UNAVAILABLE` 문구를 쓴다. 마감 뒤 KRX 정규장 호가는 실제로 마감 시점에 멈춰 있다. 값을 보여 주면서 움직이지 않는 이유를 알리는 편이 빈 상태보다 정보가 많다. 10호가창과도 맞는다.
   호가가 없어 사다리를 못 그리면(조회 실패나 대기 중) 지금 빈 상태를 그대로 보이고 안내는 보이지 않는다.
2. **"멈춤" 조건은 지금과 같다**: `nxtEnabled === false`이고 KST 15:30 이후. 이 조건은 이제 사다리를 지우지 않고 안내만 켠다. `ladderClosed`는 세션 토글(`"after"`)만 본다. 안내 조건은 새 함수 `bookFrozen(kstSecondOfDay, nxtEnabled)`로 나눈다.
3. **시간외 토글의 빈 상태는 그대로 둔다.** 사용자가 고른 보기이고 이번 문제와 관계없다.
4. **주문 칸 동작은 바꾸지 않는다.** 마감 뒤 사다리에서 주문하면 키움이 받거나 거절하고, 창은 그 결과를 지금처럼 보인다. NXT 거래 종목의 20:00 뒤와 주말에도 지금 이렇게 동작한다. 장 시간으로 주문 칸을 막는 일은 별도 결정이다(아래 결정 1).
5. **미리보기는 만들지 않았다.** 사다리 모양은 바뀌지 않고 안내 한 줄만 더한다.
6. **작업 하나**(`book-frozen`, `minor-fix`, 방식 `basic`): 화면 조건과 문구, 단위·e2e 시험만 바꾼다. 주문 동작·상태 저장·서버는 건드리지 않는다.

## 다른 작업과의 순서

`book-frozen`은 `OrderWindow.tsx`에서 사다리 영역의 분기(`closed ? … : view ? …`)를 고친다. 다른 플랜의 작업도 같은 파일을 고친다.

- `order-explorer`(대기): 같은 사다리 영역과 `OrderLadder`, `order-window.css`의 사다리 부분, `win-order-panels.spec.ts`를 다시 짠다. 같은 화면 영역을 다시 짜므로 **`order-explorer` 병합 뒤에 시작한다.**
- `order-settings`(진행 중): `OrderWindow.tsx`에 몇 줄을 더하고 `order-window.css`와 `win-order-panels.spec.ts`도 고친다. 둘 다 몇 줄씩만 더하니 겹쳐도 병렬로 둘 수 있다. 다만 `order-explorer`가 이미 `order-settings`보다 늦게 병합되므로, 위 순서만 지키면 이 작업도 그보다 늦게 시작한다.
- `live-signal`(진행 중): `useBookFeed.ts`와 `hub.rs`를 고친다. 이 작업은 두 파일을 건드리지 않는다. 병렬이다.
- `mw-allow`, `mw-pin`(대기): 각자 `QuantityRow.tsx`와 창 고정을 고친다. 이 작업은 `QuantityRow.tsx`를 건드리지 않는다.

`tasks.json`의 `after`는 같은 플랜 안의 작업만 가리킨다. 그래서 위 순서는 오케스트레이터가 지킨다.

## 범위 밖

- `kt00010` 실패와 "매수 가능 -"(위 조사 결과 참고).
- 장 운영 시간표(장전, 20:00 뒤, 주말·휴장일)에 따른 사다리·주문 칸 처리.
- 시간외 단일가 호가(0E)를 그리는 일.
- 10호가창(`features/book/`)과 서버.

## 사용자가 정해야 하는 결정

1. **마감 뒤 주문 칸.** 추천: 지금처럼 둔다. 키움이 받거나 거절하고 창이 결과를 보인다. 다른 안: 안내가 켜진 동안 사다리 주문 칸을 막는다. 이 경우 NXT 종목의 20:00 뒤와 휴장일에도 같은 규칙이 필요해서 장 시간표를 따로 설계해야 한다.
2. **NXT 미거래 종목의 NXT 주문 경로.** 지금은 경로 버튼에서 NXT를 고를 수 있고, 주문을 보내면 서버가 `NxtUnavailable`로 거절한다. 추천: 이번에는 두고 따로 다룬다. 다른 안: 이런 종목에서 NXT 버튼을 막는다. 이 경우 창에 NXT가 저장돼 있을 때 어떤 경로로 보낼지(SOR로 바꿀지, 막고 고르게 할지)도 정해야 한다. 주문 경로를 바꾸는 결정이다.

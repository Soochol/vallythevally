# 모의투자 플랜: 키움 모의투자 서버로 주문·정정·취소·계좌 조회를 먼저 확인한다

작성일 2026-11-18. 승인 시점의 기록이며 구현 중 바뀐 것은 반영하지 않는다.

기준: `origin/main` 84ba6fdb.

## 사용자가 풀려는 문제

[새 창 다섯 개 플랜](new-windows.md)으로 호가주문창의 실제 주문([ADR 0029](../adr/0029-order-window-sends-cash-limit-orders.md))이 main에 들어갔다. 그 플랜의 사용자가 정해야 하는 결정 7은 "모의투자: 쓰지 않음"이었다. 그래서 서버는 실전 키 하나만 쓴다. 사용자는 실계좌로 소량 주문을 확인하기 전에 키움 모의투자로 주문·정정·취소·계좌 조회를 먼저 확인하려 한다.

> 모의투자 해줘 .env나 hogaops .env에 모의투자 계정있어.

이 요청은 결정 7을 바꾼다. 지금 막히는 곳은 다음과 같다.

- **설정에 모의 키 자리가 없다.** `crates/server/src/config.rs`는 `VALLY_KIWOOM_APP_KEY`·`VALLY_KIWOOM_APP_SECRET`만 읽는다. 모의 키는 메인 체크아웃 `.env`에 `KIWOOM_MOCK_APP_KEY`·`KIWOOM_MOCK_APP_SECRET`라는 이름으로 있다(오케스트레이터와 플래너가 이름과 값 유무만 확인했다). 접두사가 없어 서버가 읽지 않는다. `/home/dev/code/hoga-ops/.env`에는 모의 전용 이름이 없다.
- **주소 판정이 실전과 모의를 가르지 않는다.** `config.rs`의 `Endpoint::of`는 `kiwoom.com`과 `*.kiwoom.com`을 모두 "실제 키움"으로 받는다. 그래서 지금도 `mockapi.kiwoom.com`을 적으면 서버가 뜬다. 하지만 그때 서버는 실전 키·실전 토큰 파일·실전 스위치 파일·실전 저널을 그대로 쓴다. 실전 키로 모의 주소에 발급을 요청하면 키움은 `8030`(투자구분이 달라 앱키를 쓸 수 없음)으로 답한다. 이 코드는 인증 차단으로 분류된다([ADR 0009](../adr/0009-kiwoom-errors-closed-categories.md)). 그리고 [ADR 0027](../adr/0027-kiwoom-connects-by-itself-when-a-key-is-present.md)에 따라 차단이 토큰 파일에 남는다. 지금 구조로는 모의를 안전하게 켤 수 없다.
- **모의투자의 제약을 서버가 모른다.** 모의투자는 같은 TR을 초당 1회만 받는다([docs/kiwoom-intraday-snapshot-api.md](../kiwoom-intraday-snapshot-api.md) 67줄, 키움 공식 유량 안내). 지금 대기열은 TR을 가리지 않고 260ms 간격(`SEND_SPACING`)으로 보낸다. 주문 경로도 KRX·NXT·SOR을 모두 받는다.

## 확정된 결정

1. **모의투자를 쓴다.** new-windows 플랜의 사용자가 정해야 하는 결정 7("쓰지 않음")을 바꾼다. 결정은 새 ADR 0030에 적는다. ADR 0004의 "모의투자 키는 쓰지 않는다"와 ADR 0029 "키와 토큰"의 같은 문장에는 개정 줄을 단다.
2. **키움 시험 규칙은 그대로다.** 자동 시험은 합성 transport·세션과 루프백 가짜 키움만 쓴다(AGENTS.md). 실제 모의 서버로 하는 확인은 자동 시험이 아니다. 병합 뒤 사람이(또는 허락을 받은 오케스트레이터가) 아래 "수동 검증 체크리스트"대로 돌린다.

## 스스로 정한 결정과 이유

1. **투자구분은 서버 프로세스 하나에 하나다.** 새 설정 `VALLY_KIWOOM_ENV`는 `real`(기본)이나 `mock`이다. 모의 프로세스는 시세·계좌·주문을 모두 모의 서버에서 받는다. 시세는 실전, 주문만 모의로 받는 섞은 구성은 만들지 않는다. 섞으면 키 둘, 토큰 둘, WebSocket 세션 둘을 한 프로세스가 가져야 한다. 그러면 ADR 0029의 "키 하나·토큰 하나·세션 하나에 00·04를 함께 등록" 구조를 다시 짜야 하고, 주문이 어느 쪽으로 나가는지가 요청마다 갈린다. 요청서는 "모의 모드에서 실서버 주소·키를 쓰지 않음"을 바란다. 프로세스 단위로 가르면 그 조건이 구조로 선다.
2. **모의 키는 새 이름 `VALLY_KIWOOM_MOCK_APP_KEY`·`VALLY_KIWOOM_MOCK_APP_SECRET`로만 받는다.** 서버의 다른 설정과 같이 `VALLY_` 접두사를 붙인다. 프로세스 환경에서는 `VALLY_`로 시작하는 키만 읽는 지금 규칙을 따른 것이다.
   - 모의 프로세스는 실전 키 변수(`VALLY_KIWOOM_APP_KEY`·`_SECRET`)가 있으면 뜨지 않는다. 키 파일(`kiwoom-key.json`)도 읽지 않는다.
   - 화면의 키 저장·삭제는 모의 프로세스에서 거절한다. 모의 키는 환경 키만 받는다. 환경 키는 원래 화면에서 저장할 수 없다(ADR 0027).
   - 실전 프로세스는 모의 키 변수를 읽지 않는다. 있어도 무시한다.
   - 메인 `.env`의 `KIWOOM_MOCK_APP_KEY`는 서버가 읽지 않는다. 값을 옮기는 일은 체크리스트 1단계가 한다.
3. **주소는 투자구분마다 정확한 호스트만 받는다.** 실전은 `api.kiwoom.com`이나 루프백, 모의는 `mockapi.kiwoom.com`이나 루프백이다. 주소를 비우면 투자구분의 공식 주소를 쓴다. 지금의 `*.kiwoom.com` 판정은 정확한 호스트 비교로 바꾼다. 그러면 실전 키로 모의 주소에 붙어 8030 차단이 남는 길이 설정 단계에서 막힌다. 시험 시계(`VALLY_CLOCK_START`)가 루프백 주소와만 뜨는 규칙은 그대로다.
4. **모의 프로세스의 상태는 따로 둔다.** 기본 경로가 투자구분을 따른다.

   | 설정 | 실전 기본(지금) | 모의 기본 |
   |---|---|---|
   | `VALLY_LOCK_PATH` | `$XDG_RUNTIME_DIR/vallythevally/server.lock` | `$XDG_RUNTIME_DIR/vallythevally/mock/server.lock` |
   | `VALLY_TOKEN_PATH` | `$XDG_STATE_HOME/vallythevally/token.json` | `$XDG_STATE_HOME/vallythevally/mock/token.json` |
   | `VALLY_KIWOOM_KEY_PATH`(스위치·IP 기록 파일이 같은 폴더) | `$XDG_STATE_HOME/vallythevally/kiwoom-key.json` | `$XDG_STATE_HOME/vallythevally/mock/kiwoom-key.json` |
   | `VALLY_DB_PATH` | `data/vally.db` | `data/mock/vally.db` |
   | `VALLY_SCREENER_DB_PATH` | `data/screener.duckdb` | `data/mock/screener.duckdb` |
   | `VALLY_FINANCIAL_DB_PATH` | DB 옆 `financials.db` | DB 옆 `financials.db`(규칙 그대로라 `data/mock/financials.db`) |
   | `VALLY_BIND` | `127.0.0.1:8080` | `127.0.0.1:8081` |
   | `VALLY_SCREENER_UPDATE_ON_START` | `on` | `off` |

   - 이렇게 하면 모의의 계좌 참조 소금·주문 사용 스위치·명령 저널·토큰이 실전 파일과 섞이지 않는다. 포트가 달라 브라우저 저장소(origin)도 갈린다.
   - 잠금이 달라 실전 서버와 모의 서버를 같은 PC에서 함께 띄울 수 있다. 키가 다르므로 ADR 0004의 "토큰을 가진 프로세스는 키마다 하나"는 그대로 선다.
   - 스크리너 시작 갱신은 모의에서 기본 꺼짐이다. 전 종목 일봉을 같은 TR로 초당 1회씩 받으면 몇 시간이 걸리고, 그동안 주문 확인용 조회와 대기열을 나눠 쓰게 된다.
5. **경로를 잘못 겹쳐도 섞이지 않게 파일에 투자구분을 적는다.** 위 기본 경로는 덮어쓸 수 있다. 그래서 다음 세 곳에 투자구분 표시를 둔다.
   - 토큰 파일과 주문 사용 스위치 파일: 레코드에 `environment`를 둔다. 표시가 없는 기존 파일은 `real`로 본다. 지금 프로세스와 다르면 읽지도 쓰지도 않는다. 파일 권한이 열려 있을 때와 같이 다룬다. 토큰 파일이면 차단(조회·발급 멈춤)이고, 스위치 파일이면 꺼짐이다.
   - 사용자 자료 SQLite(`vally.db`, 명령 저널이 있다): 새 마이그레이션이 투자구분 한 줄을 남긴다. 새로 만든 DB에는 지금 투자구분을 적는다. 이미 자료가 있는데 표시가 없는 DB는 `real`로 본다. 다르면 서버가 뜨지 않는다.
6. **계정 서버 동기화는 모의에서 쓰지 않는다.** `VALLY_ACCOUNT_SERVER_URL`을 모의와 함께 주면 뜨지 않는다. 셋업 동기화([ADR 0024](../adr/0024-setup-storage-and-sync.md))가 실전과 모의의 레이아웃·설정을 한 문서로 합치기 때문이다. 기본 계정 상태 파일 경로는 모의에서 쓰지 않는다(로컬 전용 모드).
7. **모의 유량: 같은 TR은 1초에 한 번만 보낸다.** 모의 프로세스의 REST 대기열은 지금의 전체 간격(260ms)에 더해 TR마다 마지막 전송 뒤 1초를 기다린다. 기다리는 TR이 줄 앞에 있어도 다른 TR은 먼저 나간다. 우선순위(주문 → 화면 → 복구 → 배경)는 그대로다. 실전 프로세스의 동작은 바뀌지 않는다. 한도를 넘으면 받는 `1700`은 지금처럼 ADR 0009 정책 표가 처리한다.
8. **모의 주문 경로는 KRX만이다.** 모의 프로세스는 NXT와 SOR(화면 값 `combined`) 경로의 신규 주문을 보내기 전에 거절한다. 거절 사유는 닫힌 값 `mockKrxOnly`다. 정정·취소는 원주문의 경로를 따르므로 KRX다. 공식 명세에는 모의의 거래소 제약이 없다. 그래도 hoga-ops가 모의를 KRX로 제한했고, 확인되지 않은 경로로 모의 주문을 보낼 까닭이 없다. 실전의 경로 선택은 바뀌지 않는다.
9. **화면은 모의를 늘 보인다.**
   - 서버는 투자구분(`real`/`mock`)을 키움 연결 상태(`KiwoomLinkStatus`, `/api/system/kiwoom`과 WebSocket `kiwoom_link`)와 시스템 설정(`SystemSettings`)에 싣는다.
   - 모의 프로세스의 화면에는 상단 막대에 늘 보이는 "모의투자" 표시가 있다. 브라우저 탭 제목 앞에도 "[모의]"를 붙인다.
   - 호가주문창의 계좌 띠에 "모의" 표시를 둔다. 주문 경로 고르기(`QuantityRow`의 SOR·KRX·NXT)에서는 SOR·NXT를 끄고 "모의투자는 KRX 주문만 됩니다"를 보인다.
   - 시스템 설정 키움 탭은 키 저장 칸 대신 "모의투자 키는 환경 설정에서만 받습니다"를 보인다.
   - 실전 화면은 지금과 같다.
10. **모의에서 지원하지 않는 기능은 그 기능의 자리에서 알린다.**
    - 알려진 것(주문 경로 NXT·SOR)은 결정 8·9대로 화면이 먼저 막고, 서버도 거절한다.
    - 알려지지 않은 것(키움이 `8104`로 답하는 TR)은 지금처럼 `Unsupported` 범주로 그 API 경로만 멈춘다. 브라우저는 지금과 같은 사유 `unsupported`를 받는다. 모의 프로세스의 화면은 이 사유의 문구를 "모의투자에서 지원하지 않는 기능입니다"로 보인다. 프런트는 키움 숫자 코드를 다시 판정하지 않는다(ADR 0009).
    - 실시간 등록 거절은 지금의 실시간 멈춤 상태로 보인다. 새 처리를 더하지 않는다.
11. **ADR은 새로 쓴다(0030).** ADR 0029의 결정 대부분(허용 목록, 주문 사용 스위치, 서버 검사, 명령 저널)은 모의에서도 그대로다. 바뀌는 것은 키·토큰·주소·상태 경로와 모의 제약이다. 0029를 고쳐 쓰면 실전 규칙과 모의 규칙이 한 문서에 섞인다. 그래서 0030에 모의 규칙을 모으고, 0004와 0029에는 "(2026-11-18 개정) 모의투자는 ADR 0030" 한 줄만 단다.

## ADR 0030에 적을 것 (작업 `mock-config`가 쓴다)

제목: 키움 모의투자는 별도 서버 프로세스로 띄우고, 모의 키·모의 주소·모의 상태만 쓴다.

- 맥락: 사용자 요청, new-windows 결정 7의 변경, 위 "확인한 사실" 표.
- 결정: 스스로 정한 결정 1~10을 그대로 옮긴다(결정 7·8·10의 구현은 작업 `mock-limits`·`mock-web`이 하지만 결정은 이 ADR에 함께 적는다).
- 시험: AGENTS.md의 합성 transport 규칙 그대로. 실제 모의 서버 확인은 사람의 수동 절차이고, 절차는 `docs/kiwoom-mock-trading.md`에 있다.
- Considered Options
  - 시세는 실전, 주문만 모의(결정 1의 이유)
  - 같은 DB에 투자구분 열을 더해 저널을 나누기: 화면의 최근 명령·`unknown` 막음·계좌 참조가 모든 조회에서 열을 걸러야 한다. 하나를 빠뜨리면 섞인다. 파일을 가르면 빠뜨릴 곳이 없다.
  - 주소만 보고 투자구분을 정하기: 주소 한 줄을 잘못 적으면 키·상태가 엇갈린다. 투자구분을 먼저 정하고 주소와 키를 거기에 맞춘다.
  - 메인 `.env`의 `KIWOOM_MOCK_APP_KEY`를 그대로 읽기: 서버 설정은 모두 `VALLY_` 접두사이고, 프로세스 환경은 접두사로 거른다. 이름 하나만 예외가 된다.

GLOSSARY `## 화면`의 **주문 사용** 옆에 **투자구분**(실전/모의. 서버 프로세스 하나가 붙는 키움 환경)을 더하고, _Avoid_에 "모의 모드", "페이퍼"를 적는다. 기존 **주문 사용**의 _Avoid_ "실거래 모드"는 그대로 둔다.

## 작업

| ID | 내용 | 방식 | 순서 |
|---|---|---|---|
| `mock-config` | `VALLY_KIWOOM_ENV`, 모의 키 변수, 정확한 호스트 판정, 투자구분별 기본 경로, 계정 서버 거절, 키 저장 거절, 토큰·스위치 파일과 DB의 투자구분 표시, 연결 상태·시스템 설정에 투자구분, ADR 0030과 0004·0029 개정 줄, GLOSSARY, `docs/kiwoom-mock-trading.md` | `poteto`: 인증·비밀값·상태 저장(토큰·스위치·DB 표시), 여러 모듈에 걸친 새 설계 | 먼저 |
| `mock-limits` | 모의 REST 대기열의 TR별 1초 간격, 모의 주문 경로 KRX 제한(`mockKrxOnly`) | `poteto`: 키움 대기열의 동시성·순서, 주문 서버 검사 | `mock-config` 뒤 |
| `mock-web` | 상단 "모의투자" 표시와 탭 제목, 계좌 띠 "모의", 주문 경로 고르기 제한, 시스템 설정 키 칸 안내, 모의의 `unsupported` 문구, e2e | `basic`: 화면과 문구. 서버가 정한 값을 보이기만 하고 주문은 지금 경로를 쓴다 | `mock-limits` 뒤 |

순서는 `mock-config` → `mock-limits` → `mock-web`이고 셋 다 순차다.

순차로 둔 이유:

- `mock-limits` → `mock-config`: 대기열과 주문 검사가 투자구분 값(설정·`AppState`)을 읽는다. 한쪽이 다른 쪽의 결과를 쓴다.
- `mock-web` → `mock-limits`: 화면이 새 거절 사유 `mockKrxOnly`의 생성 TS 타입과 `mock-config`의 투자구분 필드를 쓴다. 한쪽이 다른 쪽의 결과를 쓴다.

## 수동 검증 체크리스트 (병합 뒤, 자동 시험 아님)

세 작업이 모두 병합된 뒤 돌린다. 키움 모의 서버에 실제로 붙는다. 비밀값은 화면·로그·보고서에 내보내지 않는다. 결과 보고에는 통과/실패와 화면 문구만 적고, 계좌번호·주문번호·키는 적지 않는다(끝 2자리 표시는 된다).

준비

1. 모의 설정 파일을 저장소 밖에 만든다. 예: `~/.config/vallythevally/mock.env`, 권한 600. 값은 메인 `.env`의 `KIWOOM_MOCK_APP_KEY`·`KIWOOM_MOCK_APP_SECRET`를 화면에 찍지 않는 명령으로 옮긴다. 파일에는 `VALLY_KIWOOM_ENV=mock`, `VALLY_KIWOOM_MOCK_APP_KEY=…`, `VALLY_KIWOOM_MOCK_APP_SECRET=…`만 둔다. 실전 키 변수와 키움 주소 변수는 넣지 않는다.
2. 키움 포털에서 모의 앱키에 지금 공인 IP가 등록돼 있는지 확인한다. 미등록이면 8050으로 멈춘다(ADR 0004).
3. 거래일 09:05~15:15 KST에 한다.
4. release나 개발 빌드의 `vally-server`를 `VALLY_ENV_FILE=<모의 설정 파일 절대 경로>`로 켠다. 작업 디렉터리는 메인 체크아웃 루트다(`web/dist`, `data/mock/`).

확인

5. 시작 로그에 투자구분 `mock`과 `mockapi.kiwoom.com`이 보이고, `api.kiwoom.com`이 보이지 않는다. `~/.local/state/vallythevally/mock/`에 `token.json`이 생기고, 실전 `token.json`의 수정 시각은 그대로다.
6. `http://127.0.0.1:8081`의 상단 막대에 "모의투자" 표시가 있고, 탭 제목이 "[모의]"로 시작한다. 시스템 설정 키움 탭이 연결됨이고, 키 저장 칸 대신 안내 문구가 있다.
7. 시스템 설정에서 주문 사용을 켠다. 보이는 계좌 끝 2자리가 모의 계좌의 것과 맞는지 확인하고 켠다. `mock/kiwoom-orders.json`이 생기고, 실전 `kiwoom-orders.json`은 바뀌지 않는다.
8. 호가주문창을 연다(유동성이 큰 KRX 종목 하나. 예: 005930). 계좌 띠에 "모의"가 있다. 경로 고르기에서 SOR·NXT가 꺼져 있다. 잔고·미체결·주문 가능 금액·당일 체결이 오류 없이 보인다.
9. 신규 매수 1주를 현재가보다 몇 호가 낮게 낸다. 미체결에 나타나고 실시간 00으로 화면이 다시 조회한다.
10. 그 주문의 가격을 한 호가 옮긴다(정정). 미체결의 가격이 바뀐다.
11. 그 주문을 취소한다. 미체결에서 사라지고, 당일 체결내역에는 체결이 없다.
12. 매수 1주를 매도 1호가에 내서 체결시킨다. 잔고에 1주가 생기고 매도 가능 수량이 1이 된다. 같은 1주를 매수 1호가에 매도해 체결시키고 잔고가 0으로 돌아오는지 본다.
13. 1초 안에 정정을 두 번 이어서 낸다. 두 번째가 1초 간격을 지켜 나가고 `1700` 한도 오류가 화면에 뜨지 않는다.
14. 차트·10호가·체결 창을 같은 종목으로 열어 본다. 키움이 `8104`로 답하는 창이 있으면 그 창에 "모의투자에서 지원하지 않는 기능입니다"가 보이는지 적는다. 어느 TR이었는지 서버 로그의 API ID로 적는다.
15. 서버를 끄고, 실전 서버(기본 설정)를 켜서 실전 화면에 "모의투자" 표시가 없고 실전 주문 사용·저널·토큰이 그대로인지 본다.

결과는 `docs/kiwoom-mock-trading.md` 끝의 "확인 기록" 절에 날짜와 통과/실패만 더하는 별도 PR로 남긴다(선택).

## 범위 밖

- 실전 시세와 모의 주문을 한 프로세스에서 함께 쓰는 구성(스스로 정한 결정 1).
- 모의 시세의 품질(지연·누락) 비교. hoga-ops TODOS에 별도 과제로 있다.
- 모의에서 NXT·SOR 주문을 시험해 보는 일(스스로 정한 결정 8).
- 모의의 시간외·장전 주문. 실전에도 아직 없다(new-windows 스스로 정한 결정 12).
- 수집기(`crates/collector`)와 수집 키. 이 플랜은 앱 서버만 다룬다.
- 메인 `.env`나 hoga-ops `.env`를 고치는 일. 체크리스트 1단계는 저장소 밖의 새 파일만 만든다.

## 사용자가 정해야 하는 결정

1. **수동 검증을 오케스트레이터가 대신 돌려도 되는가.** 추천: 허용한다. 범위는 "수동 검증 체크리스트" 1~15단계와 모의 설정 파일 하나로 한정한다. 모의 키와 `mockapi.kiwoom.com`만 쓰고 실전 서버·실전 키에는 손대지 않는다. 주문은 1주 단위로 몇 번만 낸다. 결과는 통과/실패와 화면 문구로만 보고한다. AGENTS.md의 "실제 키움은 호출하지 않는다"는 자동 시험의 규칙이다. 이 확인은 자동 시험이 아니지만 실제 키움(모의 서버)을 부른다. 그래서 사용자가 정한다. 다른 안: 사용자가 직접 돌리고 오케스트레이터는 절차만 안내한다.
2. **모의 키를 옮기는 방식.** 추천: 체크리스트 1단계처럼 저장소 밖에 새 모의 설정 파일을 만들고, 값은 메인 `.env`에서 화면에 찍지 않고 옮긴다. 메인 `.env`는 고치지 않는다. 다른 안: 메인 `.env`의 두 줄 이름을 `VALLY_KIWOOM_MOCK_APP_KEY`·`VALLY_KIWOOM_MOCK_APP_SECRET`로 바꾼다. 이 경우 실전 서버는 모의 키 변수를 무시하므로 영향이 없다. 다만 모의로 켤 때 `VALLY_KIWOOM_ENV=mock`을 프로세스 환경으로 주고 `.env`의 `VALLY_KIWOOM_BASE_URL`·`VALLY_KIWOOM_WS_URL`(실전 주소)을 비워야 한다. 모의 프로세스는 실전 주소를 거절하기 때문이다.

검증을 약하게 하는 변경은 없다. `crates/server/tests/allowlist.rs`와 기존 시험은 그대로 두고, 주소 판정은 지금보다 좁아진다.

# 같은 종류 창 여러 개 플랜

작성일 2026-11-18. 승인 시점의 기록이며 구현 중 바뀐 것은 반영하지 않는다.

기준: `origin/main` eb68c370. 앞 플랜은 [`layout-free.md`](layout-free.md), [`new-windows.md`](new-windows.md)다.

## 사용자가 풀려는 문제

> 그리고 이것도 별도 플래닝해줘, 기본 컨셉은 창은 중복해서 여러개 띄울 수 있다.

지금은 차트 창만 여러 개(최대 8개) 열 수 있다. 관심종목, 스크리너, 개체 목록, 지표, 체결, 10호가, 프로그램 체결, 거래원 입체분석, 호가주문은 한 레이아웃에 종류마다 하나뿐이다. 사용자는 같은 종류의 창을 여러 개 띄우고 싶어 한다. 예를 들어 10호가 창 둘에 서로 다른 종목을 띄우거나, 관심종목 창 둘에 서로 다른 목록을 띄우는 것이다.

첫 플랜을 본 뒤 사용자가 답했다.

> 개체목록 창 제거
> 관심종목도 여러개
> 3. 창 수 상한 50개
> 나머진 추천으로 하면 되는데

### 하나만 열리게 막는 곳

| 곳 | 내용 |
|---|---|
| ADR 0019 | "차트가 아닌 종류는 종류마다 하나 이하" |
| 서버 `check_layout` (`crates/server/src/user_routes.rs`) | 차트가 아닌 창의 종류가 겹치면 400 "`<종류>` 창은 하나만 둘 수 있습니다". 셋업 묶음(`setup_bundle.rs`)도 같은 검사를 쓴다. `userdata.rs`의 시험이 두 번째 창을 거절하는지 본다 |
| 웹 `WINDOW_KINDS` (`web/src/layout/kinds.ts`) | 차트만 `maxCount: 8`, 나머지는 `1` |
| 웹 `restore.ts` | 종류별 수가 `maxCount`를 넘는 레이아웃은 읽지 않는다 |
| 웹 레이아웃 저장소 `showWindow` (`web/src/stores/layout.ts`) | 같은 종류가 있으면 새로 만들지 않고 그 창을 앞으로 가져온다 |
| 창 더하기 메뉴 (`AddWindowMenu.tsx`), 캔버스 빈 화면 단추 (`CanvasWorkspace.tsx`) | 열린 종류에 "열려 있음"을 붙이고, 고르면 `showWindow`로 그 창에 간다 |
| e2e `win-kinds.spec.ts` | "… 두 번째는 만들어지지 않는다"를 시험한다 |

창 id는 이미 `kind`, `kind-2`, `kind-3` 순으로 만든다(`freeWindowId`). DB `layout_windows`에는 종류가 겹치지 않게 하는 제약이 없다(마이그레이션 0016). 저장 모양을 바꾸지 않아도 검사만 풀면 여러 개를 저장할 수 있다.

### 창 상태는 창 단위인가 종류 단위인가

| 종류 | 종목 | 연동 색 | 창마다 다른 설정 | 앱 전체 하나인 설정 |
|---|---|---|---|---|
| 차트 | 창이 가진다 | 창 단위 | 봉 주기, 차트 설정 | - |
| 관심종목 | 보내는 창 | 창 단위 | 없음 | 고른 목록(`UiPrefs.activeWatchlistId`), 열(`watchColumns`), 접힌 그룹 |
| 스크리너 | 보내는 창 | 창 단위 | 없음 | 고른 조건식(`screenEditingFor(queryClient)`의 `chosen`), 정렬(`useScreenerStore.sort`) |
| 개체 목록, 지표 | 활성 칸을 따른다 | 없음 | 없음 | - |
| 체결, 10호가, 프로그램 체결, 거래원 입체분석 | 따르는 창. 끔이면 활성 칸, 색이면 그 색의 첫 차트(`watchedSymbol`) | 창 단위 | 체결 최소 금액·거래원 선택은 컴포넌트 상태(저장 안 함) | - |
| 호가주문 | 위와 같다 | 창 단위 | 주문 경로(`venue`, 레이아웃에 저장) | 수량 프리셋·표시(`UiPrefs.orderSettings`) |

- 레이아웃 저장·복원은 창 목록 단위다. 창마다 `id`, `link`, 종류별 내용이 저장된다(ADR 0019). 종류 단위로 묶인 저장은 없다.
- 시세 구독은 창 단위다. 창마다 `marketSocket.subscribeFeed`로 따로 구독(`sub`)하고, 서버 허브는 구독마다 `FeedSub`을 두고(`crates/server/src/market/hub.rs`의 `Conn.feeds`) 종목별 실시간 종류를 모든 구독의 합집합으로 등록한다. 같은 종류 창 둘이 같은 종목을 봐도 서버 쪽은 바꿀 것이 없다.
- 관심종목 현재가 구독도 창 단위다. 관심종목 창마다 `quoteBook`에 lease를 잡고 `quoteBook`이 lease의 합집합으로 `setWatch`를 보낸다(`web/src/stores/quoteBook.ts`). 관심종목 창 둘이 다른 목록을 보여도 두 목록의 종목이 모두 구독된다.
- 그래서 검사만 풀면 체결·10호가·프로그램 체결·거래원 입체분석·호가주문은 연동 색을 달리해 바로 여러 개를 쓸 수 있다. 관심종목·스크리너는 두 창이 같은 목록·같은 조건식을 보인다. 개체 목록·지표는 언제나 같은 내용이다.
- 관심종목 창의 "＋"로 여는 종목 검색은 넣을 곳(`putTarget.listId`)이 앱 전체 목록과 같을 때만 그 목록에 넣는다(`SearchDialog.tsx`의 `putGroup`). 창마다 목록이 달라지면 다른 목록에 들어갈 수 있다. `mw-watch`가 고친다.
- 화면 안 고정 DOM id가 겹친다: `order-quantity`(`QuantityRow.tsx`), `order-confirm-title`(`HighValueConfirm.tsx`), `br-time`(`BrokersWindow.tsx`), `watch-name-problem`·`watch-group-<그룹 id>`(`Watchlist.tsx`).
- 창 이름은 종류 이름뿐이다(`WINDOW_KINDS[kind].name`). 같은 종류 둘이면 탭, 머리, 닫기 단추의 접근성 이름, 닫기 알림이 똑같아진다.

### 개체 목록 창이 맡는 일

`web/src/features/drawings/ObjectList.tsx`(83줄)는 활성 칸 종목의 드로잉을 범위(종목 전체·이 레이아웃·이 칸)별로 나열한다. 기본 레이아웃(`DEFAULT_LAYOUT`)과 마이그레이션 0011이 만든 레이아웃에 들어 있고, 드로잉 도구 막대의 "개체 목록 열기" 단추가 연다. 이 창이 하는 일과 창을 없앤 뒤 남는 길은 다음과 같다.

| 일 | 다른 곳에 있는가 |
|---|---|
| 모든 드로잉 숨기기·잠그기, 이 종목 드로잉 모두 지우기 | 있다. 차트 빈 곳 우클릭 메뉴, `Ctrl+Alt+H` |
| 드로잉 하나 잠그기·숨기기·지우기 | 있다. 고른 드로잉의 우클릭 메뉴, 떠 있는 스타일 막대 |
| 순서 옮기기 | 있다. 고른 드로잉 우클릭 메뉴의 맨 앞으로·앞으로·뒤로·맨 뒤로 |
| **숨긴 드로잉 하나를 다시 보이기** | **없다.** 숨긴 드로잉은 차트에서 고를 수 없다(`DrawingSurface`가 `hidden`이면 고르지 않는다). 창을 없애면 숨긴 드로잉이 다시 보일 길이 사라진다 |
| **드로잉 이름 바꾸기**(F2, 두 번 누르기) | **없다.** 이름은 이 목록에서만 보이고 바꾼다 |
| **목록에서 드로잉 고르기**(화면 밖·가려진 드로잉, Ctrl로 여러 개) | **없다** |
| **범위별 드로잉 수 보기** | 일부. 차트 빈 곳 메뉴 머리에 "드로잉 n개"만 있다 |
| 드로잉이 없을 때 "추세선 그리기" 안내 | 없다 |

e2e 27개 spec(과 `fixtures/scenario.ts`)이 개체 목록을 약 100곳에서 쓴다. 대부분 드로잉이 생겼는지, 숨김·잠김·순서가 바뀌었는지 보는 관찰 창구로 쓴다(`win-manage`, `drawing-tools-all`, `win-shell`, `win-dock`, `drawing-past`, `drawing-engine` 순으로 많다).

### 창 50개일 때

| 항목 | 영향 |
|---|---|
| 도킹 렌더링·구독 | 차트가 아닌 창은 보이는 탭(또는 떠 있는 창)일 때만 내용을 그린다(`WindowHost.tsx`: `window.kind === "chart" \|\| active`). 고르지 않은 탭의 시세 창은 구독하지 않는다. 50개를 열어도 그리고 구독하는 것은 묶음 수만큼이다 |
| 캔버스 렌더링·구독 | 캔버스는 모든 창을 그린다. 시세 창 40개면 구독 40개, 10호가는 구독마다 100ms에 한 번(초당 10번) 사다리를 다시 그린다. 10호가 40개면 브라우저가 초당 약 400번 사다리를 그린다 |
| 차트 | 차트 창은 탭에 숨어도 늘 그려 둔다(봉 구독 유지). 그래서 차트 상한은 8개로 둔다 |
| 키움 실시간 자리 | 종목 단위 200자리(`REALTIME_LIMIT`)를 관심종목과 함께 쓴다. 새 창의 보유자는 차트 칸과 같은 순위다(ADR 0028). 시세 창 50개가 다른 종목 50개를 보면 그만큼 관심종목이 쓸 자리가 준다 |
| 키움 REST | 시세 창이 처음 열릴 때 그 종목의 첫 화면 TR(ka10004·ka10003·ka90008·ka10001)을 부른다. 서버 대기열은 초당 4회다(ADR 0003). 캔버스에서 서로 다른 종목의 시세 창 30개가 든 레이아웃을 열면 첫 화면이 모두 차는 데 10~20초가 걸릴 수 있다. 도킹에서는 보이는 창만 부른다 |
| 저장 크기 | 배치(`placement`)는 64KB 상한이다. 창 50개가 모두 따로 묶음이어도 도킹 트리와 떠 있는 창이 약 15KB, 캔버스 사각형이 약 5KB다. 레이아웃 본문 상한(`LAYOUT_LIMIT`)은 차트 수로 정해지고 차트가 아닌 창은 수십 바이트다 |
| 도킹 화면 | 새 창은 종류별 기본 묶음의 탭으로 들어간다. 탭 줄은 가로로 넘치면 스크롤바 없이 가로 스크롤된다(`.dock-tabs`). 한 묶음에 탭이 수십 개면 보이지 않는 탭에 닿기 어렵다 |
| 캔버스 화면 | 창마다 최소 크기가 있다(호가주문 420×520). 1440×860에 50개면 겹쳐 쌓인다. 자리를 맞추는 기능은 없다 |

## 확정된 결정

1. 같은 종류의 창을 여러 개 띄울 수 있다(요청).
2. **개체 목록 창을 없앤다**(사용자 답 "개체목록 창 제거"). 창 종류에서 빼고, 창 더하기 메뉴·도구 막대 단추·레이아웃 검사·복원·저장된 레이아웃·시험·문서·ADR을 정리한다.
3. **관심종목 창도 여러 개**이고 창마다 다른 목록을 본다(사용자 답 "관심종목도 여러개").
4. **창 수 상한은 50개**다(사용자 답). 차트 창 상한은 8개 그대로다(스스로 정한 결정 2).
5. **지표 창은 하나로 둔다.** 언제나 활성 칸을 보이므로 둘이면 같은 내용이다(첫 플랜 정할 것 1의 추천, "나머진 추천으로").
6. **시세 창(체결·10호가·프로그램 체결·거래원 입체분석·호가주문)은 자기 종목을 고정할 수 있다.** 연동 끔인 창에서 종목을 고르면 그 창에 고정하고 ✕로 푼다. 연동 색 창에서 고르면 그 색의 차트로 보낸다(첫 플랜 정할 것 2의 추천).
7. **창 더하기 메뉴에서 이미 열린 종류를 고르면 언제나 새 창을 더한다.** 힌트는 "N개 열림"이다(첫 플랜 정할 것 4의 추천).
8. **호가주문 창도 여러 개, 같은 종목도 허용한다.** 서버가 계좌 쓰기를 하나씩 처리하고 결과 불명이면 그 계좌를 막으므로(ADR 0029) 안전장치는 그대로다(첫 플랜 정할 것 5의 추천).
9. **order-book-ui 플랜의 호가주문·10호가 작업이 먼저 병합된다.** 이 플랜의 `mw-allow`·`mw-pin`은 그 뒤에 뜬다. 오케스트레이터가 순서를 잡는다(첫 플랜 정할 것 6의 추천).

## 스스로 정한 결정과 이유

1. **규칙 변경은 ADR 0031로 적는다.** ADR 0019의 "차트가 아닌 종류는 종류마다 하나 이하"와 창 종류 목록(개체 목록)을 바꾼다. 서버가 검사하는 저장 규칙이라 되돌리기 어렵다. ADR 0019 해당 줄에 "(2026-11-18 개정) ADR 0031"을 단다. 다른 플랜이 먼저 0031을 쓰면 다음 빈 번호를 쓴다.
2. **차트 창 상한은 8개로 둔다.** 차트는 탭에 숨어도 늘 그려 두고 봉을 구독한다(`WindowHost.tsx`). 창이 가장 무겁고, 50개 상한과 함께 늘리면 숨은 차트만으로 브라우저가 무거워진다. 50개 상한은 가벼운 창(보일 때만 그림)을 위한 것이다.
3. **같은 종류가 둘 이상일 때만 이름에 번호를 붙인다.** 창 목록 순서로 같은 종류 안에서 1부터 센다. "체결 1", "체결 2"처럼 탭, 머리, 닫기·크게 보기 단추의 접근성 이름, 닫기 알림에 쓴다. 하나뿐이면 지금 이름 그대로다. 차트의 "칸 n"과 같은 방식이고, 기존 e2e의 정확한 이름(`"체결 닫기"` 등 76곳)이 깨지지 않는다.
4. **단축키·명령·도구 단추는 그 종류의 첫 창을 앞으로 가져온다.** 관심종목 단축키, 스크리너 명령, 지표 "차트 옆"은 지금 `showWindow`를 쓴다. 여러 개일 때는 창 목록 순서의 첫 창으로 간다. 없으면 지금처럼 새로 만든다. "마지막으로 고른 창"을 기억하려면 새 상태가 필요하고, 이 기능들은 어느 창이든 뜻이 같다.
5. **새 창의 처음 상태는 지금과 같다.** 메뉴로 더한 창은 연동 끔, 고정 종목 없음, 목록·조건식은 앱 전체 마지막 값이다. 지금 창을 그대로 하나 더 두려면 도킹 탭 메뉴의 **복제**를 쓴다. 복제는 연동 색, 주문 경로, 고른 목록·조건식, 고정 종목을 옮기고 같은 묶음의 바로 오른쪽 탭에 놓는다. 캔버스에는 탭 메뉴가 없으므로 복제를 두지 않는다(범위 밖).
6. **창별 상태는 레이아웃의 창 목록에 둔다.** `UiPrefs`가 아니라 창 내용(`WindowContent`)에 필드를 더한다. 레이아웃이 창 목록이고(ADR 0019) 셋업 동기화도 레이아웃 단위다(ADR 0024). 차트 창의 `chartSettings`, 호가주문의 `venue`와 같은 방식이다. 저장 모양은 한 번의 마이그레이션으로 바꾼다(작업 `mw-state`).
   - 관심종목 `list: string | null`: 그 창이 보이는 목록. `null`이면 앱 전체 마지막 목록(`activeWatchlistId`)이다. 창에서 목록을 고르면 창의 `list`와 앱 전체 마지막 목록을 함께 바꾼다. 차트 메뉴의 "관심종목에 넣기"는 지금처럼 앱 전체 마지막 목록을 쓴다. 관심종목 창의 "＋" 검색은 그 창의 목록에 넣는다.
   - 스크리너 `screen: string | null`: 그 창이 고른 조건식. `null`이면 첫 조건식이다(지금 동작). 편집 중인 초안(`edits`)은 조건식 id 단위라 두 창이 같은 조건식을 고르면 같은 초안을 본다.
   - 체결·10호가·프로그램 체결·거래원 입체분석·호가주문 `symbol: StockCode | null`: 고정 종목(확정된 결정 6).
   - 서버는 목록·조건식 id가 실제로 있는지 보지 않는다. 형식만 본다. 없는 id면 화면이 `null`처럼 다룬다. `placement`를 읽을 때 맞추는 것과 같은 이유다(지워진 목록 때문에 레이아웃 저장이 실패하면 안 된다).
7. **관심종목 열과 접힌 그룹, 스크리너 정렬, 호가주문 설정은 앱 전체 하나로 둔다.** 열 구성과 수량 프리셋은 사람의 습관이라 창마다 다르게 둘 이유가 약하다. 접힌 그룹은 그룹 id 단위라 목록이 다르면 이미 따로 논다.
8. **서버의 시세 구독은 바꾸지 않는다.** 구독이 이미 창 단위다. 같은 종목·같은 종류를 두 창이 구독하다 하나를 닫아도 다른 창의 구독이 남는지는 작업 `mw-allow`의 성공 조건으로 확인한다.
9. **고정 DOM id는 `useId`로 바꾼다.** 같은 창이 둘이면 `label`의 `htmlFor`와 `aria-describedby`가 엉뚱한 창을 가리킨다.
10. **저장된 개체 목록 창은 지운다. 들어오는 옛 레이아웃에서는 빼고 받는다.** 마이그레이션이 `layout_windows`의 `objects` 행을 지운다. 배치에 남은 그 창 자리는 화면이 읽을 때 지운다(지금 규칙). 셋업 묶음(ADR 0024)과 브라우저 미저장본에 `objects` 창이 든 옛 레이아웃이 오면 그 창만 빼고 받아들인다. 계정 서버에 올려 둔 옛 레이아웃을 내려받을 때 거절하면 동기화가 막히기 때문이다. ADR 0019의 "옛 모양을 받아 주는 호환 코드는 두지 않는다"와 다르므로 ADR 0031에 이유를 적는다. 빼는 것은 `objects` 한 종류뿐이다.
11. **개체 목록을 관찰 창구로 쓰던 e2e는 같은 사실을 다른 곳에서 확인하게 바꾼다.** 저장된 드로잉(`scenario.documents`), 차트 빈 곳 메뉴 머리의 "드로잉 n개", 고른 드로잉의 우클릭 메뉴, 화면의 드로잉으로 확인한다. 단언을 지우지 않고 옮긴다. 이름 바꾸기·목록에서 고르기처럼 기능이 없어지는 단언만 그 기능과 함께 지운다.
12. **창 50개에서 탭 줄의 보이지 않는 탭에 닿는 길을 확인한다.** 탭을 고르면(새 창, 복제, 단축키) 그 탭이 탭 줄 안으로 스크롤되어야 한다. 지금도 되는지 `mw-allow`가 확인하고 안 되면 고친다. 탭 넘침 메뉴 같은 새 부품은 만들지 않는다.

## 작업

| ID | 내용 | 방식 | 순서 |
|---|---|---|---|
| `mw-objects` | 개체 목록 창 없애기: 서버 `WindowContent::Objects`와 마이그레이션(행 지우기), 옛 레이아웃에서 빼고 받기, 웹 종류·기본 레이아웃·도구 막대 단추·`ObjectList`, 숨긴 드로잉 다시 보이기(정할 것 1), e2e 옮기기, GLOSSARY·디자인 문서·ADR 0031 | `poteto`: 저장된 자료를 지우는 마이그레이션과 동기화 호환 | 먼저 |
| `mw-allow` | 검사 풀기, `WINDOW_KINDS`·`restore.ts`, 창 상한 50, 창 더하기 메뉴·캔버스 단추, 번호 붙은 이름, 탭 메뉴 복제, 고정 DOM id, 탭 스크롤, ADR 0031 갱신, GLOSSARY | `poteto`: 서버가 검사하는 레이아웃 저장 규칙을 바꾸고 웹·서버·ADR에 걸친다 | `mw-objects` 뒤 |
| `mw-state` | 창별 상태 필드 셋(`list`, `screen`, `symbol`)의 서버 타입·마이그레이션·검사, 웹 타입·복원·저장소 setter, 복제가 새 필드를 옮김. 화면은 바꾸지 않는다 | `poteto`: 저장 모양과 마이그레이션(상태 저장) | `mw-allow` 뒤 |
| `mw-watch` | 관심종목 창이 자기 `list`를 보이고 목록 고르기·"＋" 검색·지우기가 그 창의 목록에 적용된다 | `basic`: 저장소 setter를 쓰는 화면 조정이다 | `mw-state` 뒤 |
| `mw-screener` | 스크리너 창이 자기 `screen`을 고르고 실행·편집이 그 창의 조건식에 적용된다 | `poteto`: 앱 전체 하나인 편집 상태(`screenEditingFor`)를 창마다 고른 조건식으로 나누는 설계 | `mw-state` 뒤 |
| `mw-pin` | 시세 창 다섯의 고정 종목: 머리·탭의 종목 표시와 고르기, `useLinkedSymbol`, 연동 색 메뉴 | `poteto`: 다섯 창과 구독이 함께 쓰는 종목 결정 규칙을 바꾼다 | `mw-state` 뒤 |

```
1단: mw-objects
2단: mw-allow
3단: mw-state
4단: mw-watch · mw-screener · mw-pin   (셋 병렬)
```

순차로 둔 이유:

- `mw-allow` → `mw-objects`: 둘 다 `WINDOW_KINDS`, `restore.ts`, `check_layout`, `userdata.rs` 시험, 기본 레이아웃, 창 더하기 메뉴, `win-manage`·`win-kinds`·`win-dock` e2e를 고친다. 개체 목록이 먼저 빠지면 `mw-allow`는 "하나로 남는 종류"를 지표 하나로만 다루면 된다.
- `mw-state` → `mw-allow`: 둘 다 `check_layout`, `restore.ts`, `stores/layout.ts`의 같은 함수(창 검사·복원·복제)를 다시 짠다. 복제가 새 필드를 옮기려면 복제가 먼저 있어야 한다. `mw-objects`와 `mw-state`는 마이그레이션이 둘이라 같은 표를 다시 만드는 순서도 이렇게 정해진다.
- 4단 셋 → `mw-state`: 새 필드와 setter를 쓴다.

4단의 같은 파일:

- `web/src/stores/selection.ts`: `mw-watch`(넣을 곳 `putTarget` 판정), `mw-screener`(`openScreenEditor`에 창 id). 두 지시서에 최소 변경을 적었다.
- `web/src/features/workspace/WindowHeader.tsx`, `DockGroup.tsx`: `mw-pin`만 고친다. `mw-watch`·`mw-screener`는 창 본문 안에서 목록·조건식을 고른다.

### order-book-ui 플랜과 겹치는 곳

플랜 `order-book-ui`(호가주문·10호가 화면 고치기)는 `web/src/features/order/`(`OrderWindow.tsx`, `OrderLadder.tsx`, `QuantityRow.tsx`, 설정), `web/src/features/book/BookWindow.tsx`, `web/src/features/market-window/`(`PriceLadder.tsx`, `ladder.ts`)를 고칠 것으로 보인다.

| 이 플랜의 작업 | 겹칠 수 있는 파일 | 변경 크기 |
|---|---|---|
| `mw-allow` | `order/QuantityRow.tsx`, `order/HighValueConfirm.tsx`(고정 id 한 줄씩) | 최소 |
| `mw-pin` | `market-window/MarketWindowGate.tsx`(`useLinkedSymbol`), 호가주문·10호가 창이 종목을 읽는 곳 | 작음 |

확정된 결정 9대로 order-book-ui가 먼저 병합된다. `tasks.json`의 `after`는 플랜 안의 작업만 가리킬 수 있으므로 오케스트레이터가 `mw-allow`·`mw-pin`을 order-book-ui의 호가주문·10호가 작업 뒤에 띄운다. `mw-objects`는 겹치지 않는다.

## 범위 밖

- 휴대폰 화면(`features/phone`).
- 차트 창 상한(8개) 바꾸기(스스로 정한 결정 2).
- 캔버스 창의 복제(캔버스 머리에 메뉴가 없다). 캔버스에서는 창 더하기로 연다.
- 창 50개를 위한 새 배치 기능(캔버스 자동 정렬, 탭 넘침 메뉴, 창 목록 찾기).
- 시세 창 첫 화면 TR의 순서나 속도 바꾸기(캔버스에서 많이 열 때의 지연은 위 표대로 둔다).
- 창별 관심종목 열·스크리너 정렬·호가주문 설정(스스로 정한 결정 7).
- 체결 최소 금액·거래원 선택을 저장하기.
- 시세 창에서 고른 종목을 연동 색 차트로 보내는 것 말고 다른 창으로 보내기(관심종목처럼 "보내는 창"이 되는 것).
- 서버 시세 구독의 변경(스스로 정한 결정 8).
- 드로잉의 `name` 자료 지우기. 이름을 바꾸는 화면만 없어지고 저장된 이름은 그대로 둔다.

## 사용자가 정해야 하는 결정

**추천**으로 지시서를 썼다. 승인하면 추천대로 간다. 다르게 정하면 알려 주면 지시서를 고친다.

1. **개체 목록 창을 없애면 사라지는 기능.** 위 "개체 목록 창이 맡는 일" 표에서 다른 곳에 없는 것은 넷이다. 숨긴 드로잉 하나를 다시 보이기, 드로잉 이름 바꾸기, 목록에서 드로잉 고르기, 범위별 드로잉 수 보기.
   - 추천: 숨긴 드로잉을 다시 보이는 길 하나만 옮긴다. 차트 빈 곳 우클릭 메뉴에 "숨긴 드로잉 n개 다시 보이기"를 더한다. 이 종목의 숨긴 드로잉을 모두 보이고 되돌리기 알림을 띄운다. 숨긴 드로잉이 없으면 메뉴에 없다. 이것이 없으면 숨긴 드로잉이 다시는 보이지 않는다. 나머지 셋은 기능과 함께 없앤다.
   - 다른 안: 이름 바꾸기도 옮긴다(고른 드로잉의 "세부 설정…" 창에 이름 칸). 이름은 목록에서만 보였으므로 목록이 없으면 이름을 볼 곳도 없다.
   - 다른 안 2: 네 가지 모두 없앤다. 숨긴 드로잉은 다시 보이지 않는다.

검증을 바꾸는 점:

- 하나만 열리는지 보던 시험 둘의 단언을 새 규칙으로 바꾼다. `crates/server/src/userdata.rs`의 "종류가 겹치면 거절" 시험은 지표에만 남기고 나머지 종류는 둘을 받아들이는지 보게 한다. `web/e2e/win-kinds.spec.ts`의 "두 번째는 만들어지지 않는다"는 "두 번째가 만들어지고 따로 연동된다"로 바꾼다.
- 개체 목록을 관찰 창구로 쓰던 e2e 27개 spec의 단언을 다른 관찰로 옮긴다(스스로 정한 결정 11). 개체 목록의 이름 바꾸기·목록에서 고르기·범위별 수처럼 기능이 없어지는 것의 시험은 기능과 함께 지운다. 사용자가 개체 목록 창 제거를 정했으므로 그에 딸린 시험 삭제로 본다.
- 시간 제한을 늘리거나 `paths`를 줄이는 일은 없다.

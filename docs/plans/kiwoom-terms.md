# ADR에서 약관·이용 조건·처리방침, 공개 조건, 개인용 결정 제거 플랜

작성일: 2026-11-17. 승인 시점의 기록이며 구현 중 바뀐 것은 반영하지 않는다.

## 풀려는 문제

PR #435(ADR 0025)에서 사용자는 "개인용 범위는 그대로다(제3자 제공 금지 등)"와 키움 약관 제5조③ 문장을 넣지 않게 했다. 이번에는 같은 취지를 나머지 문서 전체로 넓힌다. 사용자는 네 번에 걸쳐 범위를 정했다.

1. "키움 약관 관련 모두 제거"
2. "키움이 아닌 원천의 약관(공공데이터포털, KRX OPEN API)과 개인정보 처리방침 언급도 … 이것도 제거"
3. "공개하려면 시세 원천을 정식 계약 원천으로 바꾼다" 규칙, ADR 0001의 "운영자 한 명만 쓴다", ADR 0001의 코스콤 정보이용계약 안에 대해 "이것도 다 제거"
4. "개인용"·"한 명" 표현(ADR 0022 "개인용이고 루프백이다", `GLOSSARY.md` "무료 개인용 도구", ADR 0006 "사용자는 한 명이다")과 ADR 0001에 남기려던 내용(로그인 없는 서버, 외부 비공개, 셀프 호스팅)에 대해 "이것도 제거"

main(33c47b50)의 `docs/plans/` 밖 전체(코드, `web/`, `GLOSSARY.md`, `AGENTS.md`, `docs/`, `research/`)에서 `약관`·`제5조`·`제3자`·`AG001`·`처리방침`·`개인정보`·`비상업`·`재배포`·`공공데이터`·`KRX OPEN`·`가족`·`정식 계약`·`코스콤`·`공개 서비스`·`개인`·`한 명`·`혼자`·`셀프 호스팅`·`personal`·`ADR 0001`을 다시 찾았다. 대상은 아래 "작업이 고치는 곳"에 모두 적었다.

## 확정된 결정 (사용자와 정함)

- 키움 오픈 API 이용약관 언급을 모두 뺀다. 제5조②·③, 원문 인용, 원문 PDF 링크, 그 조항에 기댄 "제3자" 문장, ADR 0008의 계좌 해지 위험 문장이 대상이다.
- 키움이 아닌 원천의 약관·이용 조건(공공데이터포털, KRX OPEN API)을 뺀다.
- 개인정보 처리방침과 "약관 해석" 언급을 뺀다(ADR 0023 Consequences 항목).
- "공개하려면 시세 원천을 정식 계약 원천으로 바꾼다" 규칙을 뺀다(ADR 0001·0022·0023).
- ADR 0001의 결정 전부를 뺀다. "운영자 한 명만 쓴다", 코스콤 안, 로그인 없는 서버, 외부 비공개(루프백·사설망), 셀프 호스팅이 모두 대상이다. 사용자는 이것이 결정을 바꾸는 일임을 알고 정했다.
- "개인용"·"한 명" 표현을 뺀다(ADR 0022 제목과 결정, `GLOSSARY.md` 3행, ADR 0006 9행, 같은 뜻의 다른 문장).
- chute로 병합한다.

## 빼서 바뀌는 범위

- ADR 0001이 정했던 결정이 문서에서 모두 없어진다. 사설망(VPN)으로 클라우드에 올리는 길, 셀프 호스팅, 유사투자자문업 문장, 버린 안 (b)·(c)·(d)의 ADR 0001판이 함께 빠진다. (b)·(c)안은 ADR 0023의 Considered Options에 이미 옮겨져 있고, (d)안은 ADR 0023 결정 자체다.
- 공개 서비스의 전제 조건이 ADR에서 없어진다. 그렇다고 공개 서비스를 허락하는 결정이 생기지는 않는다. 이 플랜은 새 결정을 더하지 않는다.
- 코드 동작은 바뀌지 않는다. 코드가 지키는 규칙은 ADR 0001이 빠져도 다른 ADR에 남는다.
  - 앱 서버·커넥터의 루프백 거절(`crates/server/src/config.rs` `BindAddr`)과 쓰기 라우트 보호, 공인 IP 확인은 ADR 0023 "커넥터의 규칙"에 있다.
  - `collector serve`의 루프백 거절(`crates/collector/src/serve.rs`)은 ADR 0022 "루프백이다"에 있다.
  - 계정 서버 주소가 없을 때 로그인 화면 없이 도는 것은 ADR 0023 "로컬 전용 모드"에 있다.
  - 사설망 주소를 받는 코드는 없다(`BindAddr`는 루프백만 받는다). 그래서 VPN 문장이 빠져도 코드와 어긋나지 않는다.
- MIT 라이선스는 이유 없이 사실만 남는다.
- 지운 문장과 규칙은 git 이력에 남는다.

## 스스로 정한 결정과 이유

1. **ADR 0001은 파일을 지우지 않고 대체 기록만 남긴다.** 이 저장소는 바뀐 ADR을 지우지 않고 "ADR N이 이 결정을 바꿨다"를 적어 둔다(ADR 0001·0006·0022 머리줄). 번호를 남기면 `docs/plans/`처럼 "ADR 0001"을 번호로 적은 기록에서 찾아갈 곳이 있다. 남기는 문장은 대체한 ADR과 날짜, "이전 내용은 git 이력에 있다"뿐이다. 지운 내용은 다시 적지 않는다. 파일명 `personal-use-only`는 지우는 결정 그 자체라 `0001-superseded-by-0023.md`로 바꾼다. 파일명 링크는 ADR 0023 3행 하나였고 그 문장째 지운다.
2. **ADR 0001을 가리키던 문장은 같은 사실을 적은 ADR로 돌리거나 가리킴을 뺀다.** 루프백·쓰기 보호·공인 IP는 ADR 0023, `collector serve` 루프백은 ADR 0022가 적고 있다(ADR 0021 18행, `docs/hoga-collector.md`, `config.rs`). 같은 사실이 다른 곳에 없는 가리킴(ADR 0021 27행 클라우드, ADR 0006 9행 한 명, ADR 0008 22행 셀프 호스팅, ADR 0022 34행)은 가리킴이나 문장을 뺀다. 새 근거를 지어 넣지 않는다.
3. **ADR 0022 파일명을 바꾼다.** `for-personal-replay`는 지우는 "개인용"이다. 링크는 `GLOSSARY.md`, ADR 0001·0003·0004(두 곳)·0025에만 있고 `docs/plans/`에는 없어 끊기는 링크가 생기지 않는다. 새 이름은 제목의 남는 앞부분 "시세를 디스크에 모은다"를 따른다.
4. **ADR 0022의 "루프백이다"와 ADR 0023 "커넥터의 규칙"은 남긴다.** 사용자가 지우라고 한 것은 ADR 0001의 결정과 "개인용"·"한 명" 표현이다. 이 두 ADR의 루프백 규칙은 각자의 결정이고 코드가 지킨다. 지우면 코드가 지키는 규칙이 문서에서 사라진다(사용자 결정 1).
5. **ADR 0023 19행 절 제목을 "커넥터의 규칙"으로 바꾼다.** 남는 네 항목(각자 PC와 키, 커넥터 루프백, 쓰기 라우트 보호, 공인 IP 확인)이 모두 커넥터 규칙이다. ADR 0001 출처 표시를 빼면 남는 이름이다.
6. **근거가 지울 내용뿐이던 문장과 버린 안은 통째로 지운다.** 근거와 결정이 함께 빠진 반쪽 문장을 남기지 않는다. ADR 0022의 "수집 자료를 공개 저장소에 올려 화면을 공개하기" 안이 그렇다. 원격 저장소·CDN에 올리지 않는다는 규칙은 같은 ADR "루프백이다"에 남는다.
7. **"개인 도구에서", "로컬에서 혼자 쓰는 동안에는"(ADR 0003·0004)도 지운다.** 같은 뜻의 "개인용"·"한 명" 표현이다. 남는 문장은 조건 없이 그대로 성립한다.
8. **ADR 0024 3행은 ADR 0006 머리줄과 같은 말로 바꾼다.** 인용하던 "사용자는 한 명이다"가 없어지므로 "ADR 0006의 결정을 바꾼다"로 줄인다. ADR 0006 머리줄이 이미 "ADR 0024가 이 결정을 바꿨다"고 적는다.
9. **`config.rs` 문서 주석은 가리킴만 고친다.** 코드는 바꾸지 않는다. 주석이 가리키던 ADR 0001이 비므로 같은 규칙을 적은 ADR 0023을 가리킨다.
10. **남기는 비슷한 말.** ADR 0023 34행 "받는 개인정보는 식별자 하나다"는 받는 자료를 줄인 설계 사실이다. ADR 0024 40행 "한 사람 계정"은 계정 하나의 충돌 상황을 말한다. ADR 0006 23행 "여러 사람이 쓰거나 서버를 여러 대 띄우게 되면 다시 검토한다"는 SQLite 선택의 재검토 조건이다. 셋 다 개인용 결정이 아니라 둔다(사용자 결정 2).
11. **바꿀 문장을 스크립트로 준다.** 고칠 곳이 열세 파일이라 손으로 옮기면 빠뜨리기 쉽다. 플래너가 쓴 스크립트는 바꿀 원문이 정확히 한 번(ADR 0004 링크는 두 번) 있는지 확인한 뒤 바꾼다. 작업자는 스크립트를 돌리고 결과 diff를 이 표와 대조한다.
12. **작업 하나, `basic`, 기본 프로필(`implementer`).** 문서와 문서 주석 한 줄만 고치고 코드 동작, 상태 저장, 동시성, 머지 판정 코드는 건드리지 않아 `basic`이다. 결정 변경이 들어가고 열세 파일에 걸치므로 `minor-fix` 대신 기본 프로필로 둔다. 파일들이 ADR 번호와 링크로 서로 이어져 있어 한 PR로 검토한다.

## 범위 밖

- `docs/plans/`의 플랜 문서. 승인 시점의 기록이라 고치지 않는다. 같은 언급이 `docs/plans/hoga-replay-prototype.md` 171행, `docs/plans/multi-user-oauth.md` 155행, `docs/plans/collector-adr.md` 28행 등에 남는다(사용자 결정 3).
- git 이력. 저장소는 이력 그대로 공개돼 있고(ADR 0008), 이 작업은 이력을 다시 쓰지 않는다.
- 공개 서비스를 허락하거나 새 전제 조건을 두는 결정. 필요하면 새 ADR로 한다.
- 코드 동작. 루프백 거절과 쓰기 라우트 보호는 그대로다.

## 사용자가 정해야 하는 결정

플랜은 아래 기본값으로 진행한다. 다르게 하려면 승인 전에 알려 준다.

1. **다른 ADR의 루프백·비공개 규칙.** ADR 0022 "루프백이다"(`collector serve` 루프백, 원격 저장소·CDN에 올리지 않음), ADR 0023 "커넥터의 규칙"(커넥터 루프백, 쓰기 라우트 보호), ADR 0008 3행 "코드를 공개하는 것이지 서비스를 공개하는 것이 아니다". 기본값: 남긴다. 루프백 규칙은 코드가 지키는 동작이라, 지우면 그 동작을 적은 문서가 없어진다.
2. **남기는 비슷한 말**(위 결정 10): ADR 0023 34행, ADR 0024 40행, ADR 0006 23행. 기본값: 남긴다.
3. **`docs/plans/`에 남는 언급.** 기본값: 승인 시점의 기록이라 둔다. 지우려면 별도 작업으로 한다.
4. **ADR 0001 파일 처리.** 기본값: 대체 기록 두 줄만 남긴다. 파일을 아예 지우는 쪽을 고르면 번호가 비고, `docs/plans/`의 "ADR 0001" 언급이 찾아갈 곳이 없어진다.

검증을 약하게 하는 변경(검증 단계 삭제, 시간 제한 증가, `paths` 축소)은 없다.

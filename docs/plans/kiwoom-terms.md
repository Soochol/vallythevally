# ADR에서 약관·이용 조건·처리방침 언급 제거 플랜

작성일: 2026-11-17. 승인 시점의 기록이며 구현 중 바뀐 것은 반영하지 않는다.

## 풀려는 문제

PR #435(ADR 0025)에서 사용자는 "개인용 범위는 그대로다(제3자 제공 금지 등)"와 키움 약관 제5조③ 문장을 넣지 않게 했다. 이번에는 같은 취지를 나머지 ADR 전체로 넓힌다. 사용자 요청은 "키움 약관 관련 모두 제거"였고, 이어서 "키움이 아닌 원천의 약관(공공데이터포털, KRX OPEN API)과 개인정보 처리방침 언급도 … 이것도 제거"라고 범위를 넓혔다.

main(33c47b50)에서 `약관`·`제5조`·`제3자`·`AG001`·`처리방침`·`개인정보`·`비상업`·`재배포`·`공공데이터`·`KRX OPEN`·`가족`을 `docs/plans/` 밖 전체(코드, `web/`, `GLOSSARY.md`, `AGENTS.md`, `docs/`, `research/`)에서 다시 찾았다. 해당하는 언급은 ADR 0001·0008·0022·0023 네 문서에만 있다. `docs/kiwoom-*.md`의 `openapi.kiwoom.com` 링크는 API 명세 링크라 대상이 아니다.

## 확정된 결정 (사용자와 정함)

- 네 ADR에서 키움 오픈 API 이용약관 언급을 모두 뺀다. 제5조②·③, 원문 인용, 원문 PDF 링크, 그 조항에 기댄 "제3자" 문장("가족과 지인도 제3자다", "그것이 곧 제3자 제공이다", "시세의 제3자 제공이 아니다")이 대상이다.
- ADR 0008의 "키움 약관 제5조③에 비춰 보면 최악의 경우 계좌 API가 해지될 수 있다. 이 위험은 알고 받아들였다" 문장을 뺀다. 커밋해도 된다는 규칙과 2026-11-09 사용자 결정 날짜는 남긴다.
- 키움이 아닌 원천의 약관·이용 조건도 뺀다. ADR 0001의 공공데이터포털(제3자 제공·재배포 금지)과 KRX OPEN API(비상업 목적, 제3자 제공 금지)가 대상이다.
- 개인정보 처리방침과 "약관 해석" 언급도 뺀다. ADR 0023 Consequences의 "로그인 서비스를 운영하면 계정 식별자를 받는 개인정보 처리자가 된다. 처리방침 게시와 약관 해석은 사용자가 확인한다." 항목 전체가 대상이다.
- 문서만 고치고 chute로 병합한다.

## 스스로 정한 결정과 이유

1. **결정은 그대로 두고 근거 문장만 뺀다.** 운영자 한 명 사용(ADR 0001, ADR 0023이 이미 바꾼 기록), 루프백, 키와 시세는 각자 PC의 커넥터, 공개 서비스에는 정식 계약 원천이 먼저라는 규칙은 남긴다. 이 저장소에서 결정을 바꾸려면 새 ADR을 쓴다. 근거를 빼는 PR이 결정까지 바꾸면 검토 범위가 달라진다.
2. **새 근거를 지어내지 않는다.** 근거가 약관뿐이던 결정 문장(ADR 0001 7행)은 결정만 남긴다. 그때 정하지 않은 이유를 새로 적으면 기록이 아니게 된다.
3. **근거가 약관뿐이던 버린 안은 항목째 지운다.** ADR 0001의 "공개 서비스 + 공공데이터포털 주식시세 또는 KRX OPEN API 일봉"과 "사용자가 자기 키움 키를 연결하는 방식"이 그렇다. 이유 없는 버린 안은 읽는 사람에게 쓸모가 없다. 뒤의 안은 같은 절의 (b)안이 보안 이유로 다시 다룬다.
4. **다른 근거가 함께 있는 버린 안은 약관 부분만 뺀다.** ADR 0001·0023의 (b)안은 보안과 백엔드 이유가 남는다. ADR 0001 (d)안은 "약관과 보안 위험"에서 "보안 위험"만 남긴다. ADR 0022의 "수집 자료를 공개 저장소에 올려 화면을 공개하기"는 같은 ADR의 "공개 서비스는 범위 밖이다" 결정을 가리키게 한다.
5. **ADR 0001의 코스콤 정보이용계약 안은 둔다.** 무엇을 금지하는 조항이 아니라 공개 서비스로 가는 계약 경로의 설명이고, "정식 계약 원천"이 가리키는 실체다. 사용자가 빼라고 하면 지운다(아래 결정 2).
6. **ADR 0008 7행 "제3자 원자료"는 "외부 원자료"로 바꾼다.** 약관 뜻이 아니라 외부 원천이라는 뜻이다. 같은 낱말이 남으면 성공 조건의 검색이 나뉘고, 바꿔도 뜻은 같다.
7. **남기는 비슷한 말.** ADR 0023 34행 "받는 개인정보는 식별자 하나다"는 처리방침이 아니라 받는 자료를 줄인 설계 사실이라 둔다. ADR 0008 22행 MIT 라이선스는 원천의 약관이 아니라 이 저장소 코드의 라이선스라 둔다.
8. **작업 하나.** 고칠 파일은 ADR 넷이고 모두 같은 취지의 문장 삭제다. 서로 링크로 이어져 있어(0022·0023이 0001을 가리킨다) 한 PR로 검토하는 편이 낫다.

## 범위 밖

- `docs/plans/`의 플랜 문서. 승인 시점의 기록이라 고치지 않는다. 같은 언급이 `docs/plans/hoga-replay-prototype.md` 171행, `docs/plans/multi-user-oauth.md` 155행, `docs/plans/collector-adr.md` 28행에 남는다(아래 결정 3).
- git 이력. 저장소는 이력 그대로 공개돼 있고(ADR 0008), 이 작업은 이력을 다시 쓰지 않는다. 지운 문장은 이전 커밋에 남는다.
- 결정 자체의 변경(개인 한 명 사용, 공개 서비스 규칙 등). 필요하면 새 ADR로 한다.

## 사용자가 정해야 하는 결정

플랜은 아래 기본값으로 진행한다. 다르게 하려면 승인 전에 알려 준다.

1. **"공개하려면 시세 원천을 정식 계약 원천으로 바꾼다" 규칙.** ADR 0001 38행, ADR 0022 36행, ADR 0023 26행에 있다. 약관을 언급하지 않아 남기지만, 그 근거였던 약관 설명이 빠지므로 근거 없이 결정만 남는다. ADR 0001 7행 "이 도구는 운영자 한 명만 쓴다"도 같다. 기본값: 남긴다. 빼면 공개 서비스를 허락하는 범위가 바뀌므로 새 ADR이 필요하다.
2. **ADR 0001의 코스콤 정보이용계약 안(24행).** 이용료와 KRX 승인 조건을 적은 계약 경로 설명이다. 기본값: 남긴다.
3. **`docs/plans/`에 남는 세 줄.** 기본값: 승인 시점의 기록이라 두고, 지우려면 별도 작업으로 한다.

검증을 약하게 하는 변경(검증 단계 삭제, 시간 제한 증가, `paths` 축소)은 없다.

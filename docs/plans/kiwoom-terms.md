# ADR에서 약관·이용 조건·처리방침 언급과 공개 조건 제거 플랜

작성일: 2026-11-17. 승인 시점의 기록이며 구현 중 바뀐 것은 반영하지 않는다.

## 풀려는 문제

PR #435(ADR 0025)에서 사용자는 "개인용 범위는 그대로다(제3자 제공 금지 등)"와 키움 약관 제5조③ 문장을 넣지 않게 했다. 이번에는 같은 취지를 나머지 ADR 전체로 넓힌다. 사용자는 세 번에 걸쳐 범위를 정했다.

1. "키움 약관 관련 모두 제거"
2. "키움이 아닌 원천의 약관(공공데이터포털, KRX OPEN API)과 개인정보 처리방침 언급도 … 이것도 제거"
3. 플랜 초안이 남기려던 "공개하려면 시세 원천을 정식 계약 원천으로 바꾼다" 규칙, ADR 0001의 "운영자 한 명만 쓴다", ADR 0001의 코스콤 정보이용계약 안에 대해 "이것도 다 제거"

main(33c47b50)에서 `약관`·`제5조`·`제3자`·`AG001`·`처리방침`·`개인정보`·`비상업`·`재배포`·`공공데이터`·`KRX OPEN`·`가족`·`정식 계약`·`코스콤`·`공개 서비스`·`한 명`·`ADR 0001`을 `docs/plans/` 밖 전체(코드, `web/`, `GLOSSARY.md`, `AGENTS.md`, `docs/`, `research/`)에서 다시 찾았다. 지울 언급은 ADR 0001·0008·0022·0023에 있다. ADR 0006 9행 "사용자는 한 명이다(ADR 0001)"는 ADR 0001의 지울 결정을 가리킨다. `docs/kiwoom-*.md`의 `openapi.kiwoom.com` 링크는 API 명세 링크라 대상이 아니다.

## 확정된 결정 (사용자와 정함)

- 키움 오픈 API 이용약관 언급을 모두 뺀다. 제5조②·③, 원문 인용, 원문 PDF 링크, 그 조항에 기댄 "제3자" 문장("가족과 지인도 제3자다", "그것이 곧 제3자 제공이다", "시세의 제3자 제공이 아니다")이 대상이다.
- ADR 0008의 "키움 약관 제5조③에 비춰 보면 최악의 경우 계좌 API가 해지될 수 있다. 이 위험은 알고 받아들였다" 문장을 뺀다. 커밋해도 된다는 규칙과 2026-11-09 사용자 결정 날짜는 남긴다.
- 키움이 아닌 원천의 약관·이용 조건을 뺀다. ADR 0001의 공공데이터포털·KRX OPEN API 안이 대상이다.
- 개인정보 처리방침과 "약관 해석" 언급을 뺀다. ADR 0023 Consequences의 "개인정보 처리자가 된다. 처리방침 게시와 약관 해석은 사용자가 확인한다." 항목 전체가 대상이다.
- "공개하려면 시세 원천을 정식 계약 원천으로 바꾼다" 규칙을 뺀다. ADR 0001 Consequences, ADR 0022 "공개 서비스는 범위 밖이다", ADR 0023 "ADR 0001에서 여전히 유효한 규칙"의 해당 항목이 대상이다. 사용자는 이것이 결정을 바꾸는 일임을 알고 정했다.
- ADR 0001의 "운영자 한 명만 쓴다" 결정을 뺀다.
- ADR 0001의 코스콤 정보이용계약 안을 뺀다.
- 문서만 고치고 chute로 병합한다.

## 빼서 바뀌는 범위

- ADR 어디에도 시세를 여러 사람에게 보여 주는 공개 서비스의 전제 조건이 없어진다. 그렇다고 공개 서비스를 허락하는 결정이 생기지는 않는다. 이 플랜은 새 결정을 더하지 않는다.
- ADR 0001은 "한 명만 쓴다"가 빠지고 로그인 없는 서버, 외부 비공개(루프백·사설망), 로컬 쓰기 API 보호, 공인 IP 확인, 셀프 호스팅 방식과 (b)·(c)·(d)안만 남는다. 그래서 제목과 파일명을 남는 내용에 맞게 바꾼다.
- 코드는 바뀌지 않는다. 코드가 지키는 루프백 거절(앱 서버, 커넥터, 수집기 `collector serve`)과 쓰기 라우트 보호는 ADR에 그대로 남는다.
- 지운 문장과 규칙은 git 이력에 남는다.

## 스스로 정한 결정과 이유

1. **새 ADR 없이 기존 ADR을 고친다. 머리줄도 더하지 않는다.** 새 ADR이나 "…을 뺐다" 머리줄은 무엇을 뺐는지 적어야 해서 지우려는 내용을 다시 불러온다. "한 명만 쓴다"는 이미 ADR 0023이 여러 사용자 구조로 바꿨고, ADR 0001 머리줄이 그 사실을 적고 있다. 정식 계약 원천 규칙을 지키는 코드는 없다. 이 저장소의 ADR은 제자리에서 고친 선례가 있다(ADR 0008 3행이 ADR 0023을 가리키게 고쳐졌다). 바뀐 범위는 이 플랜과 PR 본문에 남는다.
2. **새 근거나 새 결정을 지어내지 않는다.** 근거가 빠진 결정은 결정만 남긴다(ADR 0001 "로그인은 없다"). 근거와 결정이 모두 지울 대상인 문장은 통째로 지운다.
3. **근거가 지울 내용뿐이던 버린 안은 항목째 지운다.** ADR 0001의 Considered Options 세 안(코스콤, 공공데이터포털·KRX OPEN API, 자기 키움 키 연결)이 모두 그렇다. 그래서 그 절을 제목째 지운다. 자기 키 연결 안은 "여러 사람이 쓰는 방법"의 (b)안이 보안 이유로 다시 다룬다. ADR 0022의 "수집 자료를 공개 저장소에 올려 화면을 공개하기"도 근거가 약관과 지우는 "공개 서비스는 범위 밖이다"뿐이라 지운다. 원격 저장소에 올리지 않는다는 규칙은 같은 ADR의 "개인용이고 루프백이다"에 남는다.
4. **다른 근거가 함께 있는 버린 안은 지울 부분만 뺀다.** ADR 0001·0023의 (b)안은 보안과 백엔드 이유가 남는다. ADR 0001 (d)안은 "약관과 보안 위험"에서 "보안 위험"만 남긴다.
5. **ADR 0001의 제목과 파일명을 바꾼다.** 제목 "운영자 한 명만 쓰는 도구로 운영한다"와 파일명 `0001-personal-use-only.md`는 지우는 결정 그 자체다. 남는 내용을 그대로 줄인 제목 "서버는 로그인 없이 돌고 외부에 공개하지 않는다"와 파일명 `0001-loopback-server-without-login.md`로 바꾼다. 번호는 그대로라 "ADR 0001"로 가리키는 문장(ADR 0008·0021·0022·0023, `docs/hoga-collector.md`)은 고치지 않는다. 파일명 링크는 ADR 0023 3행 하나뿐이고 함께 고친다.
6. **ADR 0001의 남는 문장은 지운 결정에 기대지 않게 다듬는다.** "호가 복기 수집기가 모은 시세도 같은 범위다"는 "호가 복기 수집기도 루프백에서만 열고 공개하지 않는다"로, "로그인은 없다. 사용자가 한 명뿐이라 …"는 "로그인은 없다."로 줄인다. 그 밖의 남는 문장은 그대로 둔다.
7. **ADR 0023 3행의 "ADR 0001의 Considered Options (d)안"은 "ADR 0001의 "여러 사람이 쓰는 방법" (d)안"으로 고친다.** (d)안은 원래도 Considered Options가 아니라 "여러 사람이 쓰는 방법" 절에 있고, Considered Options 절은 이번에 없어진다.
8. **ADR 0006 9행은 가리킴만 뺀다.** "사용자는 한 명이다(ADR 0001)"는 SQLite 자료의 성격을 적은 ADR 0006 자신의 기록이고, ADR 0024가 이 문장을 인용해 대체했다고 적는다. 문장은 두고 지워지는 결정을 가리키는 "(ADR 0001)"만 뺀다.
9. **ADR 0008 7행 "제3자 원자료"는 "외부 원자료"로 바꾼다.** 약관 뜻이 아니라 외부 원천이라는 뜻이다. 같은 낱말이 남으면 성공 조건의 검색이 나뉘고, 바꿔도 뜻은 같다.
10. **남기는 비슷한 말.** ADR 0023 34행 "받는 개인정보는 식별자 하나다"는 처리방침이 아니라 받는 자료를 줄인 설계 사실이라 둔다. ADR 0008 22행 MIT 라이선스는 이 저장소 코드의 라이선스라 둔다.
11. **작업 하나, `basic`·`minor-fix`.** 결정 변경이 들어가지만 바꿀 문장을 지시서에 그대로 적었고 코드는 건드리지 않는다. 고칠 파일 다섯이 서로 ADR 번호와 링크로 이어져 있어 한 PR로 검토한다.

## 범위 밖

- `docs/plans/`의 플랜 문서. 승인 시점의 기록이라 고치지 않는다. 같은 언급이 `docs/plans/hoga-replay-prototype.md` 171행, `docs/plans/multi-user-oauth.md` 155행, `docs/plans/collector-adr.md` 28행에 남는다(사용자 결정 3).
- git 이력. 저장소는 이력 그대로 공개돼 있고(ADR 0008), 이 작업은 이력을 다시 쓰지 않는다.
- 공개 서비스를 허락하거나 새 전제 조건을 두는 결정. 필요하면 새 ADR로 한다.

## 사용자가 정해야 하는 결정

플랜은 아래 기본값으로 진행한다. 다르게 하려면 승인 전에 알려 준다.

1. **ADR 0001 Consequences의 "판정을 불특정 다수에게 보여 주지 않으므로 유사투자자문업 문제는 생기지 않는다."** 약관이 아니라 법령 이야기라 이번 범위에 넣지 않았다. 남는 "서버를 외부에 공개하지 않는다"에서 나오는 결과라 문장도 성립한다. 기본값: 남긴다.
2. **"개인용"·"한 명" 표현.** ADR 0022 제목과 "개인용이고 루프백이다" 결정, `GLOSSARY.md` 3행 "무료 개인용 도구", ADR 0006 9행 "사용자는 한 명이다"는 ADR 0001의 "운영자 한 명만 쓴다"와 별개인 각 문서의 결정·설명이라 둔다. 기본값: 남긴다.
3. **`docs/plans/`에 남는 세 줄.** 기본값: 승인 시점의 기록이라 둔다. 지우려면 별도 작업으로 한다.

검증을 약하게 하는 변경(검증 단계 삭제, 시간 제한 증가, `paths` 축소)은 없다.

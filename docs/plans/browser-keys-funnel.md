# Funnel 공개와 브라우저 키움 이전 첫 단계 플랜

작성일 2026-11-22. 승인 시점의 기록이며 구현 중 바뀐 것은 반영하지 않는다.

## 사용자가 풀려는 문제

사용자는 이 도구를 여러 사람이 웹 화면만 열어 쓰는 서비스로 열려 한다. 사용자 키움 키는 각자 브라우저에만 두고 브라우저가 키움을 직접 부른다. 수집은 지금 서버 PC처럼 운영 서버 한 곳에서 한다. 이 구조는 ADR 0038(PR #754, 아직 병합되지 않음)에 적었다. 공개 방법은 Tailscale Funnel이다. 지금 서버 PC의 `tailscale serve`(ADR 0036)를 바탕으로 무료 요금제로 시작한다.

사용자의 말: "좋아. funnel 하는걸로 하고 /orch 으로 플래닝해줘."

지금 코드로는 다음이 막는다.

- 로그인은 루프백 흐름뿐이다. 계정 서버(`crates/account-server`)가 일회용 코드를 `http://127.0.0.1:<포트>/auth/complete`로 보내고(`app.rs`의 `connector_url`), 커넥터가 그것을 커넥터 토큰으로 바꾼다. 원격 브라우저에서는 끝나지 않는다. 계정 서버에는 브라우저 세션이 없다.
- `vally-server`에는 사람을 가리는 계층이 없다. 루프백이나 설정한 tailnet 이름으로 오면 모든 라우트에 닿는다. 쓰기 가드(`write_guard.rs`)는 Host·Origin·Content-Type 형식만 보고, 사용자 자료 `PUT`, 스크리너·재무 갱신 `POST`, `/api/ws`, 모든 읽기에는 걸려 있지 않다. 이 서버 프로세스에는 운영자의 실전 키와 주문 라우트가 있다. 그대로 Funnel로 열면 인터넷의 누구나 운영자 계좌에 닿는다.
- 응답에 CSP 같은 보안 헤더가 없다(`http.rs`).
- 사용자 키로 하는 일(키 저장, 토큰, 시세 REST, 실시간, 시세 허브와 봉 만들기, 계좌·주문)은 모두 Rust 서버에 있다. `crates/server/src/kiwoom/` 약 13,800줄, `market/` 약 5,200줄, `trading/` 약 4,100줄, 그리고 `bars.rs`, `quotes.rs`, `intraday_feed.rs`, `investors.rs`, `rankings/`, `market_overview/`, `heatmap_flow/`, `ws.rs`다.

## 확정된 결정

사용자가 정했다(2026-11-22). ADR 0038과 요청서에 있다.

1. 여러 사람이 쓰는 서비스로 연다. 사용자가 프로그램을 설치하는 방식(ADR 0023의 커넥터 설치)은 아니다.
2. 사용자 키움 키는 각자 브라우저에서 입력해 브라우저에만 저장하고 서버로 보내지 않는다. 토큰, 시세, 실시간, 계좌·주문은 브라우저가 키움에 직접 한다.
3. 수집기는 운영 서버 한 곳에서만 돌린다.
4. 공개 방법은 Tailscale Funnel이다. 지금 `tailscale serve` 구성을 바탕으로 하고, 무료 요금제로 시작하며, 나중에 자기 도메인으로 옮길 수 있다.
5. Google·Naver 로그인, `(provider, subject)` 계정 식별, 셋업 범위는 ADR 0023 그대로다.
6. 실제 Funnel 켜기, IdP 앱 등록, 배포는 사용자 승인 일이다(ask #8을 이어받는다).

## 이번 플랜의 범위

공개 서버의 뼈대와 브라우저 키움 엔진의 바닥까지를 첫 단계로 한다. 시세 REST, 실시간, 주문을 브라우저로 옮기는 일은 다음 플랜이다(아래 "다음 단계"). 첫 단계가 끝나면 다음이 된다.

- 운영 서버가 운영자용 주소와 별도인 **공개 리스너**에서 로그인한 사용자에게 수집 자료와 계정별 셋업을 준다. 운영자 라우트는 공개 리스너에 없다.
- 브라우저가 공개 주소에서 Google·Naver로 직접 로그인한다.
- 브라우저가 키움 키를 잠금 비밀번호로 암호화해 저장하고, 엄격한 CSP 아래에서 돈다.
- 브라우저 키움 엔진이 탭들이 나눠 쓰는 연결 하나로 키마다 토큰을 규칙대로 받고, 요청 대기열을 거쳐 키움 REST를 부른다.
- 지금 서버 PC의 로컬 전용 운영과 수집은 그대로 돈다.

## 스스로 정한 결정과 이유

사용자가 바꾸라고 하면 바꾼다.

### 공개 서버 구조

| # | 결정 | 이유 |
|---|---|---|
| D1 | 공개 모드는 지금 `vally-server` 프로세스에 **두 번째 리스너**(공개 리스너)를 더해 받는다. 설정 `VALLY_PUBLIC_BIND`(루프백만)와 `VALLY_PUBLIC_ORIGIN`이 둘 다 있을 때만 뜬다. 없으면 지금과 똑같다. | 운영자용 리스너(8080)와 같은 프로세스라 스크리너 DuckDB, 재무 DB, 종목 목록을 그대로 나눠 쓴다. 공개 인스턴스를 따로 띄우면 DuckDB 파일을 두 프로세스가 열 수 없어 자료를 복사해야 한다. 운영자 리스너는 바뀌지 않으므로 지금 운영이 끊기지 않는다. |
| D2 | 공개 리스너의 라우터는 **허용 목록**으로 만든다. 운영자 라우터를 걸러서 만들지 않는다. 넣는 것: 화면 파일, 로그인·세션(`/v1/…`), 서버 모드 조회, 수집 자료 읽기(스크리너 실행·상태, ETF, 재무 읽기, 종목 목록), 수집 현황(운영자 계정만), 계정별 셋업(D9). 넣지 않는 것: 키움을 부르는 모든 라우트(봉, 호가, `/api/ws`, 순위, 시장 개요, 히트맵 흐름, 투자자, 체결·호가 조회, 기본 정보), `/api/system/*`, `/api/trading/*`, 커넥터 계정 라우트, 셋업 내보내기·가져오기, 스크리너·재무 갱신 `POST`. | 운영자 키로 받은 시세를 공개 사용자에게 주지 않는다(ADR 0038 "운영 서버는 사용자 키로 키움을 부르지 않는다", 시세는 각자 키로). 새 라우트가 운영자 라우터에 생겨도 공개 리스너에는 저절로 열리지 않는다. 시험이 운영자 라우트 목록을 공개 리스너에 보내 모두 404인지 확인한다. |
| D3 | Funnel은 **8443 포트**로 공개 리스너만 연다. `tailscale funnel --bg --https=8443 http://127.0.0.1:<공개 포트>`. 지금 443의 `tailscale serve`(tailnet 전용, 운영자 리스너)는 그대로다. | Funnel은 포트 단위로 켠다. 운영자 리스너는 망 수준에서 인터넷에 닿지 않는다. 지금 운영자 주소가 바뀌지 않는다. 사용자에게 보이는 주소는 `https://<서버>.<tailnet>.ts.net:8443`이다. 443으로 바꿀지는 사용자 결정 5. |
| D4 | 계정 기능은 `account-server` 크레이트를 라이브러리로 써서 공개 리스너 프로세스 안에 붙인다. `server`가 `account-server`에 의존하고 그 반대는 없다. 별도 `vally-account` 프로세스와 커넥터 루프백 흐름은 지우지 않는다. | 세션 확인이 함수 호출이 된다. 프로세스 사이 세션 조회와 경로 나누기가 필요 없다. ADR 0023의 "계정 서버는 `server`·`collector`·`domain`에 의존하지 않는다"는 그대로 선다. 커넥터 계정 모드는 거둘 때까지 산다(D20). |
| D5 | 공개 리스너는 **모든 요청**의 Host를 확인한다. Host는 `VALLY_PUBLIC_ORIGIN`의 호스트(포트 포함)와 정확히 같아야 한다. Origin이 있으면 그 출처와 정확히 같아야 하고, `GET`·`HEAD`·`OPTIONS`가 아닌 요청은 Origin이 반드시 있고 본문이 `application/json`이어야 한다. | 인터넷에 열리면 읽기도 보호 대상이다. 지금 가드는 쓰기에만 걸려 있다. 브라우저는 `fetch`의 `POST`·`PUT`·`DELETE`에 늘 Origin을 붙인다. Funnel이 Host를 어떤 모양(포트 포함 여부)으로 넘기는지는 운영 단계 P4에서 확인하고, 다르면 규칙을 고친다. |
| D6 | 공개 리스너의 `/api/*`는 서버 모드 조회를 빼고 모두 세션이 있어야 한다. 없으면 `401`과 `{"error":"signed_out"}`이다. 화면 파일과 로그인 시작은 세션 없이 받는다. | 로그인하지 않은 요청이 닿는 범위를 화면 파일, 로그인, 모드 조회로 줄인다. |
| D7 | 요청 제한은 프로세스 안에서 한다. 세션마다 토큰 버킷(초기값 초당 20, 묶음 100), 세션 없는 로그인 시작에 전체 버킷(초기값 분당 30), 기존 대기 로그인 한도. 넘으면 `429`와 `Retry-After`. 시계는 주입하고 시험은 가짜 시계로 한다. IP별 제한은 이번에 하지 않는다. | Funnel 뒤에서 클라이언트 IP가 어떤 헤더로 오는지 확인하지 않았다. 확인되지 않은 헤더를 믿으면 위조된다. 세션과 전체 한도는 IP 없이 된다. 확인되면 다음에 더한다(P4). |
| D8 | 수집 현황(`/api/collector/*`)은 공개 리스너에서 **요청한 세션의 계정**이 `VALLY_COLLECTOR_ADMINS`에 있어야 보인다. 운영자 리스너의 판정(서버에 저장된 커넥터 계정)은 그대로다. | 지금 판정은 서버 주인 계정으로 하므로 공개하면 누구나 같은 판정을 받는다. 운영자 전용 화면은 이것 하나다. 나머지 운영 기능(키, 주문, 스크리너·재무 갱신, 시스템 설정)은 공개 리스너에 아예 없다(D2). |

### 로그인과 세션

| # | 결정 | 이유 |
|---|---|---|
| D9 | 공개 리스너의 사용자 자료 라우트(관심종목, 조건식, 히트맵 테마, 화면 상태, 레이아웃, 드로잉)는 지금과 **같은 경로와 같은 JSON**으로 받고, 저장은 계정 서버 저장소의 그 계정 셋업 문서에 한다. revision 규칙(`stale_revision`), 삭제 표시, 크기 한도는 ADR 0024와 `crates/setup` 그대로다. | 셋업 문서 본문이 지금 HTTP 본문 JSON 그대로다(ADR 0024). 웹의 저장 계층(`web/src/persist/`)을 바꾸지 않아도 된다. 공개 모드에는 커넥터가 없으므로 동기화 고리도 필요 없다. |
| D10 | 브라우저 로그인: 화면이 `/v1/…` 로그인 시작으로 최상위 이동 → 계정 서버 코드가 `state`·`nonce`와 기존 로그인 흐름 쿠키를 두고 IdP로 보냄 → 같은 callback 주소로 돌아옴 → 계정을 찾거나 만들고 세션을 만들어 쿠키를 두고 공개 출처의 `/`로 302. 돌아갈 곳은 늘 `/`이고 질의로 받지 않는다. 실패는 `/?login=error&reason=<cancelled|idp_failed|…>`. | 로그인 흐름 쿠키로 로그인 CSRF를 막는 지금 장치를 그대로 쓴다. 돌아갈 곳을 받지 않아 열린 리다이렉트가 구조로 없다. IdP에 등록하는 callback이 커넥터 흐름과 같아 하나만 등록한다. |
| D11 | 세션 쿠키는 `__Host-vally_session`, `HttpOnly; Secure; SameSite=Lax; Path=/`. 값은 32바이트 난수이고 DB에는 SHA-256만 둔다. 30일 동안 쓰지 않으면 만료하고, 로그아웃과 계정 삭제가 폐기한다. | 커넥터 토큰과 같은 수준(ADR 0023)이다. 스크립트가 쿠키를 읽지 못한다. 세션은 셋업과 수집 자료에만 닿고 키움 키에는 닿지 않는다. |
| D12 | 로그아웃(`POST`)과 계정 삭제(`DELETE /v1/account`)는 세션과 D5의 Origin·JSON 검사를 받는다. 계정 삭제는 identity, 세션, 커넥터 토큰, 셋업을 모두 지운다. 브라우저의 키움 키는 서버가 모르므로 화면이 따로 지우기를 권한다. | 남의 페이지가 로그아웃·삭제를 일으키지 못한다. |
| D13 | 새 계정 수 상한을 둔다(설정, 기본 100). 차면 새 가입을 거절하고 기존 계정 로그인은 받는다. | 아무나 Google·Naver로 계정을 만들어 계정당 32MB 저장소를 쓸 수 있다. 기본값은 사용자 결정 2. |

### 브라우저 키 보호

| # | 결정 | 이유 |
|---|---|---|
| D14 | 키는 IndexedDB에 **잠금 비밀번호로 암호화**해 둔다. WebCrypto PBKDF2-SHA256(600,000회, 16바이트 솔트)로 AES-GCM-256 키를 만들고 쓸 때마다 새 12바이트 IV를 쓴다. 잠금 비밀번호는 저장하지 않고 서버로 보내지 않는다. 풀린 키는 메모리에만 있고, 잠그거나 엔진이 내려가면 사라진다. 잊으면 키를 모두 지우고 다시 넣는다. 키움 토큰도 같은 키로 암호화한다. | 디스크나 백업, 저장소를 읽는 다른 경로로 키가 새지 않는다. 토큰도 24시간 주문이 되는 값이다. |
| D15 | 키 목록 규칙은 ADR 0037 그대로다. 최대 5개, 별칭 1~20자, 같은 앱키 한 번, 키 ID `k1`… 다시 쓰지 않음, 시세 키 하나(기본 첫 줄). 환경 키는 브라우저에 없다. | 키마다 따로인 규칙(토큰, 발급 간격, 8050)이 키 목록을 전제로 한다. |
| D16 | 공개 리스너는 엄격한 CSP를 낸다: `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self' https://api.kiwoom.com wss://api.kiwoom.com:10000; worker-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'`. 그리고 `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Cross-Origin-Opener-Policy: same-origin`. 정책 문장은 저장소의 파일 하나에 두고 서버와 e2e가 같은 파일을 읽는다. 빌드한 화면이 이 정책에서 위반 없이 도는지 e2e로 확인한다. `style-src`가 빌드 결과와 맞지 않으면 `'unsafe-inline'`을 `style-src`에만 더하고 보고한다. `script-src`는 넓히지 않는다. | 풀린 키를 읽을 수 있는 길은 화면에 끼어든 스크립트다. 외부 스크립트와 인라인 스크립트를 막는 것이 첫 방어다. 정책이 두 곳에 있으면 어긋난다. |

|---|---|---|---|---|

| `public-user-data` | 공개 리스너의 사용자 자료 라우트를 계정 셋업 문서로 | `poteto` | 계정별 자료 저장과 삭제 | `public-listener` |
| `web-public-mode` | 웹의 모드 판단, 브라우저 로그인 화면, 계정 메뉴, 공개 모드에서 없는 기능 숨기기 | `poteto` | 인증 흐름과 계정 삭제 화면 | `public-listener` |
| `browser-key-vault` | 잠금 비밀번호 암호화 키 보관, 키 목록 화면(공개 모드), CSP 아래 e2e | `poteto` | 비밀값 저장·보안 | `web-public-mode`, `public-user-data` |
| `browser-engine` | `kiwoom-wasm`, SharedWorker 엔진, 키별 Web Locks, 발급 기록, 요청 대기열, 키움 REST 한 줄, 연결 상태 화면 | `poteto` | 토큰 규칙, 동시성(탭·잠금), 여러 모듈에 걸친 새 설계 | `browser-key-vault`, `kiwoom-core` |

병렬: 처음에 `adr-public`, `acct-browser-session`, `kiwoom-core`가 함께 돈다. `acct-browser-session` 뒤에 `public-listener`가 돈다(`kiwoom-core`와 병렬). 그 뒤 `public-user-data`와 `web-public-mode`가 함께 돈다. 둘 뒤에 `browser-key-vault`, 그것과 `kiwoom-core` 뒤에 `browser-engine`이 돈다.

순차로 둔 이유:

- `public-listener`는 `acct-browser-session`이 내놓은 라이브러리 진입점(라우터, 세션 확인)을 붙인다.
- `public-user-data`는 `public-listener`의 공개 라우터와 세션 문에 라우트를 더하고, `acct-browser-session`의 셋업 저장소를 함수로 부른다.
- `web-public-mode`는 `public-listener`가 만든 서버 모드 생성 타입과 로그인 경로를 쓴다.
- `browser-key-vault`는 `web-public-mode`가 공개 모드에서 비운 시스템 설정 자리에 키 화면을 넣는다. CSP 파일을 고칠 수 있어서 같은 `crates/server/src/public/` 아래를 고치는 `public-user-data` 뒤에 둔다.
- `browser-engine`은 `browser-key-vault`의 보관소를 SharedWorker로 옮기고, `kiwoom-core`를 WASM으로 감싼다.

같은 파일에 몇 줄씩 더하는 곳(병렬, 각 지시서에 최소 변경으로 적었다):

- `Cargo.lock`: `acct-browser-session`·`public-user-data`(의존성이 늘 때만), `kiwoom-core`, `public-listener`.
- `crates/server/Cargo.toml`: `kiwoom-core`(새 크레이트 의존)와 `public-listener`(`account-server`를 dev-dependency에서 dependency로).

## 다음 단계 (이 플랜의 작업이 아니다)

첫 단계가 병합된 뒤 각각 플랜으로 한다. 순서는 권장이다.

1. **브라우저 시세 REST**: 봉(모든 주기, 건너뛰기), 호가·당일 요약, 기본 정보, 투자자, 체결·호가·프로그램 조회, 순위, 시장 개요, 히트맵 흐름을 엔진이 사용자 키로 부른다. 웹의 `web/src/api/*`가 모드에 따라 서버나 엔진으로 간다. 개인 캐시는 IndexedDB에 작게 둔다.
2. **브라우저 실시간**: 키마다 WebSocket 세션, 구독 관리(200개 한도, 30초 유예), 시세 허브와 봉 만들기(`domain` 집계를 WASM으로), 실시간 알림(ADR 0005). 엔진이 탭에 지금 `/api/ws`와 같은 `ServerMessage`를 보내 화면 코드를 바꾸지 않는다. 숨긴 탭에서 시험한다.
3. **브라우저 계좌·주문**: 계좌·주문 TR, 주문 사용 스위치, 주문 명령 기록, 계좌 실시간(`00`, `04`). ADR 0029 규칙 그대로.
4. **공개 시작**: 아래 운영 단계 P1~P5.
5. **거두기**: 커넥터 계정 모드(루프백 로그인, 커넥터 토큰, 동기화)와 `vally-account` 별도 실행을 지운다. 운영자도 공개 모드로 쓰게 되면 서버의 사용자 키움 코드와 로컬 전용 모드를 언제 지울지 그때 정한다.

## 운영 단계 (병합 뒤, ★는 사용자 승인)

`tasks.json`의 작업이 아니다. 첫 단계의 `public-listener`·`public-user-data`·`web-public-mode`가 병합된 뒤 로그인부터 tailnet 안에서 확인할 수 있다.

| 단계 | 누가 | 내용 |
|---|---|---|
| P1 ★ | 사용자 | Google Cloud OAuth 클라이언트와 Naver 앱 등록. callback은 `https://<서버>.<tailnet>.ts.net:8443/v1/auth/google/callback`과 `…/naver/callback`. client id·secret은 서버 PC의 env 파일(600)에만 둔다 |
| P2 ★ | 오케스트레이터 | 서버 PC 배포에 공개 리스너 설정을 더한다(`docs/public-operations.md`). 지금 배포 hold를 푸는 일과 함께 사용자가 승인한다 |
| P3 | 오케스트레이터 | Funnel 없이 tailnet 전용으로 8443을 연다(`tailscale serve --bg --https=8443 http://127.0.0.1:<공개 포트>`). 개발 PC 브라우저로 로그인, 셋업 저장, 운영자 라우트 404를 확인한다 |
| P4 ★ | 사용자·오케스트레이터 | tailnet 정책에 서버 PC의 `funnel` 노드 속성을 더한다(사용자, 관리 콘솔). 오케스트레이터가 `tailscale funnel --bg --https=8443 http://127.0.0.1:<공개 포트>`로 켠다. 확인: 인터넷 쪽에서 Host 모양(포트 포함 여부), 클라이언트 IP 헤더가 오는지, 443은 여전히 tailnet 전용인지, 운영자 리스너 라우트가 404인지 |
| P5 | 오케스트레이터 | 되돌리기 확인: `tailscale funnel --https=8443 off`. 공개 리스너 설정을 지우고 재시작하면 지금과 같다 |

## 범위 밖

- 시세 REST, 실시간, 계좌·주문의 브라우저 이전(다음 단계 1~3).
- 커넥터 계정 모드와 루프백 로그인 지우기(다음 단계 5).
- IP별 요청 제한. Funnel이 클라이언트 IP를 넘기는지 P4에서 확인한 뒤 정한다.
- 브라우저에서 자기 공인 IP 확인. 서버의 공인 IP 확인(`public_ip.rs`)은 서버 PC의 IP라 공개 사용자에게 맞지 않는다. 화면은 포털 등록 안내만 보인다.
- 같은 키를 여러 기기에서 함께 쓰기(D21), 휴대폰 지원.
- 다른 기기 세션 모두 끊기(ask #4).
- 자기 도메인으로 옮기기, 별도 호스팅.
- `verify-vally` 스킬의 공개 모드. 첫 단계 뒤 필요해지면 따로 한다.

## 사용자가 정해야 하는 결정

구현을 막는 결정은 없다. 모든 작업은 권장안으로 시작한다.

1. **PR #754 처리** (권장: 플랜 승인과 함께 그대로 먼저 병합). 병합이 늦어도 `adr-public`이 그 커밋을 가져와 진행한다. 그 경우 #754는 오케스트레이터가 닫는다.

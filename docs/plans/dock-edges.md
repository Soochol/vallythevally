# 도킹 묶음 단계 가장자리와 배치 Ctrl+Z 플랜 (2026-11-19)

작성일 2026-11-19. 승인 시점의 기록이며 구현 중 바뀐 것은 반영하지 않는다.

## 사용자가 풀려는 문제

사용자의 말(그대로):

> 그리기 창 배치 방식에서 도킹 고도화 하자.
>
> 예를 들어 창이 왼쪽에 위아래로 1개씩 배열, 오른쪽에 1개로 배열. 왼쪽은 2개로 화면, 오른쪽은 1개로 화면이야.
> 이때 내가 오른쪽1개에 탭을 만들고, 그 새로운 탭을 도킹하려는데 현재는 드래그해서 가져다 놓을 때 왼쪽 각 창의 옆에만 붙일 수 있어.
> 내가 하고싶은것은 오른쪽 1개 긴 창처럼도 드래그 드랍으로 만들고 싶단 말이지.

오케스트레이터가 그림으로 정리했고 사용자가 "응 맞아"라고 했다.

```
지금 배치                 지금 가능한 것              원하는 것
┌────────┬────────┐      ┌───┬───┬────────┐        ┌────┬────┬────────┐
│   A    │        │      │ A │C2 │        │        │ A  │    │        │
├────────┤   C    │      ├───┴───┤   C    │        ├────┤ C2 │   C    │
│   B    │ (탭 C2)│      │   B   │        │        │ B  │    │        │
└────────┴────────┘      └───────┴────────┘        └────┴────┴────────┘
                           (A 한 칸만 쪼개짐)          (왼쪽 묶음 전체 높이)
```

이어서 사용자가 더 요청했다:

> 응 맞아 그걸 둘다 지원되도록 인터렉션을 강화시켰으면 좋겠고, 그리고 ctrl+z로 잘못된경우 이전 배치로 돌아가게 하고 싶어.

정리하면 두 가지다.

1. 묶음 한 칸 옆에 붙이기(지금 동작)와, 여러 묶음을 담은 나눔(위 그림의 왼쪽 A·B)이나 화면 전체의 가장자리에 길게 붙이기를 모두 끌어 놓기로 한다. 끄는 동안 어느 단계에 어떤 크기로 생기는지 보여야 한다.
2. 배치를 잘못 바꿨으면 Ctrl+Z로 앞 배치로 돌아간다. 차트 드로잉의 Ctrl+Z와 입력 칸의 되돌리기와 부딪치지 않아야 한다.

"그리기 창 배치 방식"의 "그리기"는 코드와 문서에 없는 방식 이름이다. 창 배치 방식은 도킹과 캔버스 둘뿐이다(`docs/adr/0019-layout-is-windows-and-placement.md`, 레이아웃 메뉴의 `layout-mode-control`). 이 플랜은 "그리고"로 읽고 도킹을 다룬다. Ctrl+Z는 배치 기록이 두 방식에 하나이므로 두 방식 모두에 둔다.

사용자의 예에서 C2를 C 자신의 왼쪽 띠에 놓으면 지금도 `A·B | C2 | C` 모양이 된다. 다만 C2의 폭을 C에서 가져와 C가 반으로 준다. 사용자가 그린 "원하는 것"은 폭을 왼쪽 묶음에서 가져오고 C는 그대로다. 그 자리는 "왼쪽 나눔 전체의 오른쪽"이고 지금은 고를 수 없다. 그리고 문구가 같아 화면 전체 나누기와 묶음 나누기를 끄는 동안 구별하기 어렵다.

## 확정된 결정

1. 묶음 한 칸 옆 붙이기(지금 동작)는 그대로 두고, 나눔 전체와 화면 전체의 가장자리에도 끌어 놓기로 붙일 수 있게 한다.
2. 끄는 동안 어느 단계에 어떤 크기로 생기는지 미리보기로 보인다.
3. Ctrl+Z로 배치를 앞으로 되돌린다. 차트 드로잉의 Ctrl+Z와 입력 칸의 되돌리기와 부딪치지 않게 범위를 정한다.

## 스스로 정한 결정과 그 이유

1. **단계는 "가장자리가 같은 줄에 있는 바깥 나눔"이다.** 포인터 아래 묶음 G의 한 변(예: 오른쪽)을 두고, G에서 뿌리 쪽으로 올라가며 그 변이 같은 선에 놓인 나눔을 모은다. 오른쪽 변이면 가로 나눔에서는 G가 뒤쪽(`second`)에 있을 때만 이어지고, 세로 나눔은 언제나 이어진다. 한 번 끊기면 더 올라가지 않는다. 이 목록이 그 변의 **단계**다. 안쪽부터 묶음 G, 나눔들, 마지막이 화면 전체(뿌리)다. 나눔을 고르면 그 나눔 전체를 한 덩어리로 나눠 새 묶음을 그 변 바깥에 둔다. 사용자의 예에서 A의 오른쪽 단계는 A, 왼쪽 세로 나눔(A·B) 둘이다.
2. **같은 길이의 단계는 하나만 둔다.** 길이(오른쪽 변이면 높이)가 바로 안쪽 단계와 같은 나눔은 빼고, 길이가 늘어나는 나눔 가운데 가장 안쪽 것만 남긴다. 미리보기가 똑같이 보이는 단계를 사용자가 구별할 수 없기 때문이다. 화면 전체는 지금 있는 동작이므로 길이가 같아도 남긴다.
3. **단계는 가장자리 선에 가까울수록 바깥이다.** 묶음 가장자리 띠(지금처럼 묶음 크기의 24%) 안에서, 선에서 가까운 쪽부터 바깥 단계에 띠를 하나씩 준다. 띠 폭은 24px이고, 바깥 단계가 k개면 묶음 띠 깊이의 1/(k+1)보다 넓지 않게 줄여 묶음 G 단계가 언제나 남게 한다. 화면 전체 단계는 지금의 "작업 영역 가장자리 24px"과 같은 자리에 온다. 포인터를 선 쪽으로 밀면 미리보기가 길어지는 것을 보며 고를 수 있다. 다른 방식(안내 단추, 휠로 단계 바꾸기)은 "사용자가 정해야 하는 결정"에 둔다.
4. **묶음 사이 6px 틈도 놓을 곳이다.** 틈에서는 가까운 쪽 묶음의 그 변 가장 바깥 단계로 본다. 위 예에서 A·B와 C 사이 틈은 "왼쪽 나눔 전체의 오른쪽"이 된다. 지금은 틈이 판정 밖이라 놓아도 아무 일이 없다.
5. **새 묶음의 몫은 지금 규칙(고른 단계의 절반)을 따른다.** 사용자의 예에서 C2는 왼쪽 나눔 폭의 절반을 받아 A·B와 C2가 같은 폭이 된다. 그림과 같고, `split.test.ts`의 화면 전체 나누기 기대값도 그대로다. 단계와 상관없이 두께를 같게 두는 다른 방식은 "사용자가 정해야 하는 결정"에 둔다.
6. **미리보기에 세 가지를 보인다.** 결과 묶음 자리의 면(지금 그대로), 나누는 단계 전체를 두르는 점선 테두리, 그 변에서 고를 수 있는 단계를 늘어놓은 작은 단계 표시(지금 단계를 강조)다. 문구는 묶음 단계는 지금 문구("오른쪽에 나눠 놓기"), 나눔 단계는 "묶음 2개 전체 오른쪽에 나눠 놓기", 화면 전체는 "화면 전체 오른쪽에 나눠 놓기"다. 기존 시험의 `toContainText("위에 나눠 놓기")`와 탭 메뉴 항목 이름은 그대로 맞는다. 상태 영역 알림도 같은 문구다.
7. **끄는 창이 묶음의 마지막 탭이면 그 묶음이 빠진 트리에서 단계를 구한다.** 나누기는 지금도 원래 창이 빠진 트리(`withoutWindow`)에서 계산하고, 미리보기는 "원래 창이 빠진 뒤의 실제 배치"를 보인다(`docs/design-system.md` 도킹 조작). 단계도 같은 트리에서 구해야 미리보기와 결과가 같다. 띠의 자리는 화면에 보이는 묶음 사각형으로 잰다.
8. **탭 메뉴는 바꾸지 않는다.** 탭 메뉴의 네 방향 나누기는 지금처럼 그 묶음 단계다. 키보드로 바깥 단계에 놓는 길은 "사용자가 정해야 하는 결정"에 둔다.
9. **Ctrl+Z는 초점 자리로 나눈다.** 입력 칸(`isTypingTarget`)은 브라우저 되돌리기, 차트 칸 안은 드로잉 되돌리기(지금 그대로), 그 밖(탭, 경계, 창 머리, 관심종목 목록, 빈 곳)은 배치 되돌리기다. 끌어 놓은 뒤에는 초점이 옮긴 탭에 있으므로(`focusTab`) 곧바로 Ctrl+Z를 누르면 배치가 돌아온다. 대화상자, 열린 메뉴·팝오버(`ownsChartKeyboard`), 설정 마법사, 휴대폰 폭에서는 쓰지 않는다. 끄는 중에는 기존 끌기 처리가 키를 막으므로 배치를 바꾸지 않는다. 드로잉과 배치를 시간 차례로 섞는 하나의 되돌리기는 "사용자가 정해야 하는 결정"에 둔다.
10. **다시 하기를 넣는다.** 드로잉이 이미 Ctrl+Shift+Z·Ctrl+Y로 다시 하고, 단축키 설정도 그 키를 되돌리기·다시 하기 몫으로 막아 두었다(`hotkeysView.ts`). 배치에도 같은 키를 둔다. 되돌린 단계는 다시 하기 기록으로 옮기고, 새 배치 변경이나 레이아웃 열기(`load`)가 다시 하기 기록을 비운다. 레이아웃 메뉴의 "배치 되돌리기" 아래에 "배치 다시 하기"를 둔다.
11. **Ctrl+Z는 "배치 되돌리기"와 같은 기록을 쓴다.** 무엇이 한 단계인지(경계 놓기, 화살표 한 번, 떠 있는 창·캔버스 창을 앞으로 올리기 등)는 바꾸지 않는다. 기록 규칙을 바꾸면 기존 메뉴와 닫기 알림의 되돌리기 동작이 함께 바뀐다. 앞으로 올리기를 기록에서 뺄지는 "사용자가 정해야 하는 결정"에 둔다.
12. **키로 되돌리거나 다시 하면 짧은 알림을 보인다.** 배치 변화가 작으면 눌렀는지 알기 어렵다. "배치를 되돌렸습니다", "배치를 다시 했습니다", 기록이 없으면 "되돌릴 배치 변경이 없습니다"·"다시 할 배치 변경이 없습니다"다. 메뉴로 할 때는 지금처럼 알리지 않는다.
13. **저장 모양(`placement`)은 바꾸지 않는다.** 단계 나누기는 나눔 트리의 한 마디를 새 나눔으로 감쌀 뿐이고, 다시 하기 기록은 저장하지 않는다(배치 기록도 저장하지 않는다). 서버, 마이그레이션, ADR 0019와 무관하다.
14. **순수 계산을 먼저 만든다.** 단계 목록, 단계 나누기, 띠 판정은 `web/src/layout/dock/` 안 새 파일의 순수 함수로 두고 단위 시험으로 고정한다. 화면 작업은 그 함수를 부른다. 앞선 도킹 플랜(`layout-free.md`, `dock-tuning.md`)과 같은 방식이다.

## 작업 나눔과 순서

PR 하나로 검토하고 병합할 수 있는 단위 3개로 나눈다.

| 순서 | 작업 ID | 내용 | 기다리는 작업 | 방식 | 방식의 이유 |
|---|---|---|---|---|---|
| 1 | `dock-levels-math` | 단계 목록, 단계 나누기, 띠 판정의 순수 함수와 단위 시험 | 없음 | `basic` | 한 폴더의 새 순수 함수와 단위 시험 |
| 1 | `arrangement-undo-keys` | 배치 다시 하기 기록, Ctrl+Z·Ctrl+Shift+Z·Ctrl+Y, 레이아웃 메뉴 "배치 다시 하기" | 없음 | `poteto` | 배치 기록(저장되는 레이아웃을 바꾸는 상태)과 여러 모듈에 걸친 키 처리 순서를 다룬다 |
| 2 | `dock-levels-drop` | 끌어 놓기 판정에 단계와 틈을 더하고 미리보기(점선 테두리, 단계 표시, 문구)를 강화 | `dock-levels-math` | `basic` | 놓을 곳 판정과 화면 조정이고 저장·데이터를 건드리지 않는다 |

병렬로 도는 작업과 겹치는 파일:

- `dock-levels-math` ∥ `arrangement-undo-keys`: 겹치는 파일이 없다. 앞은 `web/src/layout/dock/`만 쓴다.
- `dock-levels-drop` ∥ `arrangement-undo-keys`(늦게 끝날 때): `docs/design-system.md`에 각자 몇 줄을 더한다(앞은 "도킹 조작" 문단, 뒤는 배치 기록 문단). 두 지시서에 최소 변경으로 하라고 적었다. 키 처리 훅은 `web/src/App.tsx`에 걸고 `Workspace.tsx`는 고치지 않는다.

순차로 둔 이유:

- `dock-levels-drop` → `dock-levels-math`: 단계 목록, 단계 나누기, 띠 판정 함수를 쓴다.

이 탭 계획의 다른 플랜은 모두 끝나 겹치는 진행 중 작업이 없다.

## 범위 밖

- 탭 메뉴에서 바깥 단계에 나눠 놓기(결정 8).
- 새 묶음의 몫을 놓는 자리로 정하기(지금은 언제나 고른 단계의 절반).
- 배치 기록에 무엇을 한 단계로 넣는지 바꾸기(결정 11).
- 드로잉 되돌리기와 배치 되돌리기를 하나로 합치기(결정 9).
- 캔버스 창과 떠 있는 창끼리의 끌어 놓기 규칙. 떠 있는 창 머리를 묶음에 놓는 것은 같은 판정을 쓰므로 단계도 함께 쓴다.
- 시스템 설정 단축키 화면에 Ctrl+Z 배치 되돌리기를 보이기.
- 저장 모양과 휴대폰 화면.

## 미리보기 제안

고르는 방식을 사용자가 손으로 느껴 보고 정하도록, 승인 전에 끌어 볼 수 있는 목업을 보이기를 제안한다. 저장소 밖 artifact로 만들고 플랜 작업에는 넣지 않는다.

- 화면: 위 그림의 "지금 배치"(왼쪽 A·B 세로 나눔, 오른쪽 C와 탭 C2)를 실제 비율(작업 영역 1416×748, 6px 틈)로 그린다.
- 안 1(권장): C2를 끌어 A의 오른쪽으로 가져가면 띠에 따라 "A 오른쪽"과 "묶음 2개 전체 오른쪽"이 바뀌고, 점선 테두리와 단계 표시가 따라 바뀐다. 틈 위와 화면 가장자리도 보인다.
- 안 2: 묶음 위에 다섯 방향 안내 단추, 나눔 가장자리와 화면 가장자리에 바깥 단추를 띄우고 단추 위에 놓는다.
- 안 3: 안 1의 띠에 휠(또는 Ctrl)로 단계를 한 칸씩 바꾸는 것을 더한다.
- 놓은 뒤 Ctrl+Z·Ctrl+Shift+Z로 배치가 오가는 것.

## 사용자가 정해야 하는 결정

아래는 사용자가 말하지 않아 권장안으로 정하고 작업을 나눈 것이다. 다른 선택지를 고르면 해당 작업의 지시서를 고친다. 이 플랜에는 검증을 약하게 하는 작업(검증 단계 삭제, 시간 제한 증가, `paths` 축소)이 없다.

1. **단계를 고르는 방식**
   - 권장(적용): 가장자리 띠. 선에 가까울수록 바깥 단계이고 미리보기 길이·점선 테두리·단계 표시로 알린다. 새 조작부가 없고 지금 끄는 감각을 그대로 쓴다.
   - 다른 선택지: 안내 단추(Visual Studio식). 고르는 자리가 분명하지만 끄는 동안 화면에 단추가 많이 뜨고 `dock-levels-drop`이 커진다. 또는 띠에 휠·Ctrl로 단계 바꾸기를 더한다.
2. **새 묶음의 두께**
   - 권장(적용): 고른 단계의 절반(지금 규칙). 사용자의 그림과 맞다.
   - 다른 선택지: 단계와 상관없이 포인터 아래 묶음을 나눌 때와 같은 두께로 두고 길이만 늘린다. 화면 전체 나누기의 지금 크기와 `split.test.ts` 기대값이 바뀐다.
3. **Ctrl+Z의 범위**
   - 권장(적용): 초점 자리로 나눈다. 입력 칸은 브라우저, 차트 칸 안은 드로잉, 그 밖은 배치다. 차트를 누른 뒤에 누르면 드로잉이 되돌아간다.
   - 다른 선택지: 드로잉과 배치 변경을 시간 차례로 섞어 가장 최근 것을 되돌린다. 드로잉 기록(`web/src/chart/drawings/history.ts`, 칸마다 따로)과 배치 기록을 묶는 새 설계가 필요해 작업이 하나 늘고 `poteto`가 된다.
4. **다시 하기**
   - 권장(적용): 넣는다. Ctrl+Shift+Z·Ctrl+Y와 레이아웃 메뉴 "배치 다시 하기".
   - 다른 선택지: 되돌리기만 둔다.
5. **앞으로 올리기를 기록에 남길지**
   - 권장(적용): 지금처럼 남긴다. 떠 있는 창이나 캔버스 창을 눌러 앞으로 올린 것도 Ctrl+Z 한 번으로 되돌아간다.
   - 다른 선택지: 차례만 바뀐 변경은 기록하지 않는다. 캔버스에서 창을 여러 번 누른 뒤 Ctrl+Z를 누르면 곧바로 앞선 이동·크기 변경이 돌아온다. `web/src/stores/layout.ts`의 기록 규칙과 그 단위 시험이 바뀐다.
6. **탭 메뉴에서 바깥 단계에 놓기**
   - 권장(적용): 이번에는 넣지 않는다.
   - 다른 선택지: 탭 메뉴에 "묶음 전체·화면 전체" 하위 항목을 더해 키보드로도 바깥 단계에 놓는다. `dock-levels-drop` 뒤의 작업 하나가 늘어난다.

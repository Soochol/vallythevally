# 히트맵 테마 플랜

작성일 2026-11-22. 기준: `origin/main` d33253bd.

미리보기(합성 자료, 읽기 전용 참고): https://claude.ai/artifact/7VzGzdbJ1doDM6Pp6v9deW. 사용자는 그 가운데 안 A(테마 카드 격자)를 골랐다.

## 사용자가 풀려는 문제

히트맵은 지금 관심종목 그룹을 그대로 쓴다([페이지 플랜](pages-etf.md) 결정 14). 그룹은 웹이 만들어 종목 목록으로 서버에 보내고, 서버는 그룹을 모른다. 사용자는 히트맵의 묶음을 관심종목과 따로, 자기 방식으로 정하고 싶어 한다.

> 히트맵을 나만의 방식으로 테마를 정하고 종목을 구성하겠다고 한건데

사용자가 고른 것:

- 히트맵 전용 테마를 둔다. 관심종목 그룹은 히트맵에서 빠진다.
- 테마 안의 종목은 사용자가 직접 골라 넣는다. 규칙으로 자동으로 채우지 않는다.
- 키움·한국투자의 테마 API는 쓰지 않는다.

## 결정

1. **테마는 서버가 저장하는 사용자 자료다.** 사용자 자료 SQLite(ADR 0006)에 관심종목과 다른 표로 둔다. 테마는 이름과 순서가 있는 종목 목록이고, 테마끼리 순서가 있다. 한 종목이 여러 테마에 들 수 있다. 같은 테마 안에서는 중복될 수 없다.
2. **편집은 문서 전체를 바꾸는 방식이다.** 관심종목처럼 `GET`으로 문서와 `revision`을 받고, `PUT`은 `revision + 1`일 때만 받는다. 거절한 PUT은 아무것도 바꾸지 않는다.
3. **히트맵 보드는 서버가 구성한다.** 서버가 테마마다 종목 시세를 모으고 테마 요약(아래)을 계산해 한 응답으로 준다. 테마 순서도 서버가 정한다. 웹은 받은 순서대로 그린다.
4. **화면 배치는 웹에 남긴다.** 타일 크기·자리(treemap), 색, 테마 안의 타일 정렬, 실시간 색 갱신은 지금 코드를 그대로 쓴다. 화면 크기에 따라 달라지는 일이기 때문이다.
5. **평균은 거래대금 가중 평균이다.** 보드 요약과 흐름 비교가 같은 정의를 쓴다. 단순 평균에서는 작은 종목 하나가 급등하면 테마 전체가 오른 것처럼 보이기 때문이다. 정의는 Σ(등락률 × 거래대금) / Σ거래대금이다.
   - 보드: 거래대금은 `ka10095`의 당일 누적 거래대금(`tradedMillionWon`)이다.
   - 흐름 비교: 1분봉에는 거래대금이 없다. 그래서 칸마다 그 칸 끝까지의 당일 1분봉 `종가 × 거래량` 합을 근사 거래대금으로 쓴다. 그 칸까지 거래가 없는 종목은 가중치가 0이다. 지수는 거래대금을 알 수 없어 가중치가 0이다. 칸의 가중치 합이 0이면(첫 거래 전, 지수만 있는 그룹) 단순 평균을 쓴다.
   - 흐름 비교의 `/api/heatmap/flow?symbols=…`는 경로와 응답 모양을 그대로 두고, `rate`의 뜻만 가중 평균으로 바꾼다. `docs/heatmap-flow-api.md`의 계산 절과 화면 문구("그룹 평균 등락률")를 함께 고친다.
   - 테마당 종목 상한은 흐름 비교의 상한 60(`MAX_SYMBOLS`)에 맞춰서 `overLimit`이 생기지 않게 한다.
6. **처음 자료는 관심종목에서 가져온다.** 편집 화면에 "관심종목 그룹에서 가져오기"를 둔다. 목록 하나를 고르면 그 목록의 그룹들이 같은 이름·순서의 테마로 추가된다.
   - 이름이 같은 테마가 이미 있으면 그 그룹은 건너뛰고, 건너뛴 이름을 알려 준다.
   - 그룹의 종목이 60개를 넘으면 앞의 60개만 넣고 알려 준다.
   - 가져오기 단추는 관심종목을 바꾸지 않는다.
7. **관심종목의 "히트맵" 목록은 옮긴 뒤 지운다.** hoga-ops 히트맵은 이미 관심종목의 "히트맵" 목록으로 옮겨져 있다([가져오기 문서](../import-hoga-watchlists.md)). 실서버에 `themes-edit`까지 배포되면 다음 순서로 옮긴다. 사용자가 지우기로 정했다. 이 일은 코드가 아니라 한 번 하는 운영 단계다.
   1. 그 목록을 가져와 테마로 만든다.
   2. 테마 문서와 목록의 그룹·종목 순서가 같은지 GET으로 비교한다.
   3. 같으면 관심종목에서 "히트맵" 목록을 지운다.
8. **레이아웃은 안 A(테마 카드 격자)다.** 테마마다 카드 하나에 요약 머리와 타일 지도를 둔다. 미리보기에서 함께 정한 화면 변경은 다음과 같다.
   - 툴바: "테마 순서"와 "테마 편집"을 더한다. 기존 "정렬"은 "칸 정렬"로 이름을 바꾼다.
   - 범례: "칸 색 = 등락률" 라벨과 "시세 없음" 칸을 더한다.
   - 칸 색: 칸 전용 색 토큰을 따로 둬서 진한 칸에서도 글자가 읽히게 한다.
   - 칸 풍선: 코드, 거래대금, 테마 안 비중을 보인다.
   - 카드 아래: 시세를 받지 못한 종목을 적는다.
   - 흐름 비교: 칩에 현재 값을 붙이고, 포인터를 올린 시각의 테마별 값을 보인다.
   - 편집: 오른쪽 서랍에서 하고, 저장을 눌러야 반영한다.

## 용어와 ADR

- `GLOSSARY.md`에 **테마**를 넣는다: "사용자가 히트맵에 보려고 직접 고른 종목 묶음. 이름과 순서가 있고, 한 종목이 여러 테마에 들 수 있다." 피할 말은 히트맵 그룹, 섹션이다.
- **섹터**의 `_Avoid_`에서 "테마"를 빼고, 섹터와 테마의 차이를 한 줄 적는다. 섹터는 한 종목이 하나에만 들고, 테마는 여러 곳에 들 수 있다.
- 새 ADR: "히트맵 테마는 관심종목과 따로 서버에 저장한다". 페이지 플랜 결정 14를 바꾸는 이유(관심종목은 매매·감시용이고 히트맵 묶음은 시장 보기용이라 수명과 편집 방식이 다르다)와, 고려했던 대안 두 개(관심종목 그룹 유지, 둘 다 고르기)를 적는다.

## 서버 경로

### `GET /api/heatmap/themes`, `PUT /api/heatmap/themes`

```jsonc
{
  "revision": 7,
  "themes": [
    { "id": "t-…", "name": "반도체 소부장", "symbols": ["042700", "403870", "…"] }
  ]
}
```

| 검사 | 값 |
|---|---|
| 테마 수 | 100 이하 |
| 테마당 종목 | 60 이하(흐름 비교 상한과 같은 상수를 쓴다) |
| 이름 | 1~40자, 앞뒤 공백 없음, 테마끼리 중복 없음 |
| 종목 코드 | 서버 종목 목록에 있는 주식·ETF. 지수는 받지 않는다 |
| `id` | 웹이 만들고, 문서 안에서 고유 |

틀리면 400과 이유를 주고 저장하지 않는다. `revision`이 맞지 않으면 409다.

### `GET /api/heatmap/board?venue=combined&order=rate`

| 인수 | 뜻 |
|---|---|
| `venue` | `/api/quotes`와 같다 |
| `order` | 테마 순서. `rate`(가중 평균 등락률 높은 순, 기본), `custom`(사용자 순서), `traded`(거래대금 합 큰 순). 값이 같거나 요약이 `null`이면 사용자 순서를 따르고, `null`은 맨 뒤에 둔다 |

```jsonc
{
  "revision": 7,
  "asOf": 1795000000,
  "themes": [
    {
      "id": "t-…",
      "name": "반도체 소부장",
      "summary": {
        "weightedRate": 2.41,
        "tradedEok": 5120,
        "rising": 9, "flat": 1, "falling": 2,
        "leader": "042700"
      },
      "members": [
        { "symbol": "042700", "name": "한미반도체", "changeRate": 6.12, "tradedMillionWon": 210000 }
      ],
      "missing": ["…"]
    }
  ]
}
```

- 요약 값:
  - `weightedRate`: 받은 종목 등락률의 거래대금 가중 평균이다(결정 5). 거래대금 합이 0이면 `null`이다.
  - `tradedEok`: 거래대금 합이고 단위는 억원이다.
  - `rising`, `flat`, `falling`: 상승·보합·하락 종목 수다.
  - `leader`: 테마 안에서 등락률이 가장 높은 종목이다.
- 시세는 기존 `QuoteService`(`ka10095`, 100종목씩)에서 받는다. 테마 전체의 종목을 중복 없이 모아 한 번에 묻는다. 테마 30개 × 20종목이 겹침 없이 600종목이면 1분에 6건이다.
- 보드 응답은 서버 메모리에 45초 둔다(흐름 비교의 `FRESH_SECS`와 같다). 웹은 지금처럼 60초마다 다시 부른다. 테마 문서가 바뀌면 캐시를 버린다.
- 시세를 못 받은 종목은 `missing`에 적고 요약에서 뺀다. 모든 종목을 못 받은 테마는 요약이 `null`이다.

## 웹

- `HeatmapPage`의 섹션을 `heatmapSections(lists)` 대신 `/api/heatmap/board`의 `themes`에서 만든다. 색 범위, 크기 기준, 테마 안 정렬, 보드·흐름 보기 설정은 그대로 둔다. 주소의 query에 `order`를 더한다.
- 테마 머리에 요약 한 줄을 보인다: 가중 평균 등락률, 거래대금 합, 상승·하락 수, 대장주.
- 실시간 색은 지금처럼 `quoteBook.lease`로 테마 종목을 구독해 바꾼다.
- 편집: 히트맵 툴바에 "테마 편집" 단추를 둔다. 편집 패널에서 할 수 있는 일은 다음과 같다.
  - 테마 추가·이름 바꾸기·지우기·순서 끌기
  - 종목 검색으로 넣기, 빼기, 순서 끌기
  - 관심종목 그룹에서 가져오기
  - 타일을 우클릭해 "다른 테마에 추가", "이 테마에서 빼기"
- 테마가 하나도 없으면 빈 상태 안내와 "관심종목 그룹에서 가져오기" 단추를 보인다.

## AI용 CLI

AI가 테마를 쉽고 안전하게 바꿀 수 있게 `scripts/themes.py`를 둔다. `PUT`은 문서 전체를 갈아 끼우므로, curl로 직접 바꾸면 테마를 빠뜨리거나 `revision`·`id`를 틀리기 쉽다. CLI는 바꿀 부분만 명령으로 받는다.

```sh
python3 scripts/themes.py --url http://127.0.0.1:8080 list
python3 scripts/themes.py add "반도체 소부장" 한미반도체 HPSP 403870
python3 scripts/themes.py remove "2차전지" 엘앤에프
python3 scripts/themes.py create "로봇" --after "조선·방산"
python3 scripts/themes.py rename "로봇" "로봇·자동화"
python3 scripts/themes.py move "로봇·자동화" --before "금융"
python3 scripts/themes.py delete "로봇·자동화"
python3 scripts/themes.py add "AI 반도체" 삼성 --dry-run
```

- **명령마다 최신 문서에 적용한다.** 매번 GET으로 최신 문서를 읽고, 명령만 적용해 `revision + 1`로 PUT한다. 409면 다시 읽어 같은 명령을 다시 적용한다. 최대 3번이다. 명령은 "넣어라·빼라" 같은 뜻이라 다시 적용해도 결과가 같다. 이미 있는 종목을 넣거나 없는 종목을 빼면 바꾸지 않고 그렇다고 알린다.
- **종목은 이름이나 코드로 받는다.** 서버 종목 목록에서 찾는다. 이름이 정확히 하나에 맞지 않으면 고르지 않고 후보를 보여 주며 실패한다. 이때 아무것도 보내지 않는다.
- **테마는 이름으로 가리킨다.** 이름은 문서 안에서 고유하다(결정 1의 검사). 새 테마의 `id`는 CLI가 만든다.
- **`--dry-run`은 바뀔 내용만 보여 준다.** 테마별로 넣을 종목과 뺄 종목, 순서 변화를 보여 주고 PUT하지 않는다.
- **검사는 서버가 한다.** 상한, 이름 중복 같은 거절은 서버 응답의 이유를 그대로 보여 준다.
- **출력은 사람이 읽는 글이 기본이다.** `--json`을 주면 기계가 읽는 결과를 낸다.
- **서버 주소는 `--url`로 받는다.** 기본은 `http://127.0.0.1:8080`이다. 앱 서버 API에는 로그인 미들웨어가 보이지 않는다(`http.rs`). 다만 실서버(tailnet https)에 인증이 붙어 있는지는 이 작업이 확인한다.
- **사용법 문서를 둔다.** 문서 이름은 `docs/heatmap-themes-cli.md`다. `AGENTS.md` 개발 문서 목록에 "히트맵 테마를 바꾸기 전 읽는다"를 한 줄 넣는다.
- **위치는 `scripts/`다.** 기존 `import-hoga-watchlists.py`처럼 Python 도구로 둔다. ADR 0002가 막는 것은 Python 백엔드다.

## 작업 순서

| 작업 | 범위 | 확인 |
|---|---|---|
| `flow-weighted` | 흐름 비교를 거래대금 가중 평균으로 바꾸기, API 문서와 화면 문구 | `heatmap_flow` 서버 시험의 손 계산 값을 가중 평균으로 고침, 가중치 0 칸, e2e `heatmap-flow.spec.ts` |
| `themes-store` | ADR, GLOSSARY, 마이그레이션, `GET/PUT /api/heatmap/themes`, ts-rs 타입 | 서버 시험: 왕복, 검사별 거절, revision 충돌, 거절 뒤 불변 |
| `themes-cli` | `scripts/themes.py`(아래 "AI용 CLI"), 사용법 문서, `AGENTS.md` 개발 문서 목록에 한 줄 | `scripts/test-themes.py`가 루프백 합성 서버에 붙어 명령별 결과, 409 뒤 다시 적용, 애매한 이름 거절, `--dry-run`이 PUT을 보내지 않음을 확인 |
| `themes-board` | `/api/heatmap/board`, 요약 계산, 45초 캐시, 문서 변경 시 캐시 버림 | 합성 transport로 손 계산한 요약, `order` 세 가지, `missing`, 호출 건수 |
| `themes-web` | 페이지가 board를 쓰게 바꾸기, 요약 줄, `order` 설정 | e2e `heatmap-page.spec.ts`, `heatmap-flow.spec.ts` 고침 |
| `themes-edit` | 편집 패널, 관심종목 그룹에서 가져오기, 타일 우클릭 메뉴 | e2e 새 spec: 만들기·가져오기·편집이 새로 고침 뒤에도 남는다 |

`flow-weighted`는 테마와 상관없이 먼저 머지할 수 있다. `themes-store`와 `themes-board`는 서버만, 뒤의 두 작업은 웹만 고친다. 각 작업이 따로 머지돼도 화면이 깨지지 않는다. `themes-web`이 머지되기 전까지 페이지는 관심종목 그룹을 그대로 쓴다.

## 확인하지 못한 것

- 실서버의 "히트맵" 목록 그룹 중에 종목이 60개를 넘는 것이 있는지는 보지 않았다. 있으면 결정 6대로 앞의 60개만 넣는다.

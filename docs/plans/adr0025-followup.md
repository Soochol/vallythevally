# ADR 0025의 정리·구간 파일 값을 실험 결과에 맞추는 플랜

작성일: 2026-11-17. 승인 시점의 기록이며 구현 중 바뀐 것은 반영하지 않는다.

## 풀려는 문제

PR #435로 머지된 [ADR 0025](../adr/0025-collector-stores-closed-days-for-the-app.md)의 "수집 저장소" 항목은 store-bench 마지막 측정 이전의 값을 적고 있다. 마지막 측정은 PR #467의 [수집 저장소 처리 방식 실험](../diagnostics/collector-store-experiment.md)에 있고, PR #467은 main에 머지됐다(dd7ced3c). 사용자는 ADR의 정리·구간 파일 항목을 그 값으로 고치고, 근거로 실험 문서를 링크하라고 했다.

## 확정된 결정 (사용자 요청)

- 정리의 묶음(row group)은 3만 행이 아니라 122,880행이다. 실험 문서의 "5분 구간 하나를 만들 때 묶음 크기" 표에서 구간 조회 13ms(3만 행은 16ms), 전체 크기 1,533MB로 가장 작았다.
- 구간 파일 전송은 brotli q5가 아니라 zstd다. 서버 압축 0.5ms에 312KB가 37KB가 된다. brotli q5는 서버 압축이 3.4ms이고, 브라우저에서 응답 헤더가 3~5ms 늦다. 브라우저 쪽 압축 풀기와 해독은 구간 하나에 1~2ms다.
- 병합 스레드 4개(최대 메모리 약 4.1GB)와 정리 시간을 근거로 적는다.
- ADR이 실험 문서를 근거로 링크한다.

## 스스로 정한 결정과 이유

1. **정리 시간은 49초로 적는다.** 요청서는 "164초→40초"라고 했다. 실험 문서에서 40초는 병합 스레드 8개(8.2GB)일 때고, ADR이 고르는 4개(4.1GB)는 49초다. 164초는 실제 수집기에 없는 표본 단계 때문에 늦었던 값이다. 그래서 ADR에는 "병합 스레드 4개, 2시간 15분 치 49초, 최대 메모리 4.1GB"를 적고 164초는 적지 않는다. 같은 수치를 두 곳에 두지 않도록 자세한 경위는 실험 문서에 맡긴다.
2. **부호 열을 정리 항목에 더한다.** 실험 문서는 "모든 FID와 부호 열을 남긴다"를 골랐고, 49초·4.1GB·1,533MB는 모두 부호 열을 넣고 잰 값이다. ADR이 "모든 FID"만 적으면 근거로 드는 값과 결정이 어긋난다. 키움이 가격에 붙이는 `+`가 숫자로만 저장하면 사라진다는 것이 이유다.
3. **"아직 정하지 않은 것"의 "정리에 걸리는 시간"도 고친다.** 지금은 "재지 않았다"고 적혀 있다. 2시간 15분 치는 쟀고 하루치는 5배 어림(약 4분)이며 실제 하루치는 아직 재지 않았다는 것으로 바꾼다. 정리 완료 표시를 나눌지는 그대로 남긴다.
4. **지금 `build`의 brotli q11 설명은 그대로 둔다.** ADR 61행의 "지금 `build`는…"과 `docs/hoga-collector.md` 194행은 지금 코드의 동작을 적는다. 코드가 바뀔 때 함께 고친다.
5. **원문 zstd 9 항목은 고치지 않는다.** 실험 문서가 고른 것과 같다.
6. **작업 하나, `basic`, `minor-fix`.** ADR 파일 하나의 몇 줄을 고치는 문서 수정이다. 코드, 상태 저장, 동시성, 머지 판정 코드를 건드리지 않는다.

## 범위 밖

- 수집기 코드(`build`, 앞으로의 Parquet 정리, 구간 서버). 이 플랜은 문서만 고친다.
- `docs/hoga-collector.md`, `docs/hoga-format.md`의 brotli q11 설명. 지금 코드의 동작이다.
- 실험 문서(`docs/diagnostics/collector-store-experiment.md`)의 내용.
- ADR 0025의 다른 결정과 "아직 정하지 않은 것"의 다른 항목.

## 사용자가 정해야 하는 결정

1. **부호 열을 ADR 결정에 넣을지.** 기본값: 넣는다(위 결정 2). 빼면 정리 항목은 "모든 FID"만 남고, 근거 값은 부호 열을 넣은 측정이라고 실험 문서가 따로 밝힌다.
2. **정리 시간을 49초(4스레드)로 적을지, 요청서의 40초로 적을지.** 기본값: 49초(위 결정 1). 40초는 8스레드·8.2GB일 때라 ADR이 고르는 4스레드와 맞지 않는다.

검증을 약하게 하는 변경(검증 단계 삭제, 시간 제한 증가, `paths` 축소)은 없다.

### 실시간 반영

호가가 웹에 오는 길은 막혀 있지 않다. 원인 후보 셋을 가렸다.

- **서버 허브·outbox: 배제.** 0D는 `parse_book`(`crates/server/src/kiwoom/wire.rs`)을 거쳐 허브 `on_book`이 구독자에게 묶음마다 가장 새 값을 보낸다(`crates/server/src/market/hub.rs`, `market/outbox.rs`). 합성 transport 시험 `book_sends_only_the_latest_per_flush`, `book_program_and_broker_frames_become_events_with_the_receive_time`, `reg_adds_only_the_new_type_for_a_symbol`이 통과한다.
- **웹 호가 갱신: 배제.** `feed_book`이 오면 `acceptLive`가 바꾸고 스냅샷은 무시한다(`web/src/features/book/bookModel.ts`). 합성 캡처에서 두 번째 `feed_book` 뒤 값이 바뀌었다.
- **웹·허브의 결함 둘: 확인.**
  1. **현재가가 얼어붙는다.** `useBookFeed`의 `lastPrice`는 `lastTrade ?? quote.price`인데 시세 조회는 한 번만 한다. 체결(0B)이 오지 않으면 현재가 행과 등락률이 첫 조회 값에 머문다.
  2. **이미 끊긴 뒤 연 창은 끊김을 보이지 않는다.** 허브의 `publish_feed_link`는 연결 상태가 바뀔 때만 `feed_link`를 보내고, `attach_feed`는 새 구독에 지금 상태를 알리지 않는다. 키움 실시간이 내려간 뒤 창을 열면 웹은 `linkLive = true`로 남아 스냅샷을 살아 있는 호가처럼 보인다.
- **외부 조건: 확인하지 못함.** 캡처 시각 18:10은 KRX 장 마감 뒤 NXT 애프터마켓이다. 계좌 띠에 "모의" 표시가 없어 실계좌다. 사다리가 보였으니 NXT 거래 종목이다(`ladderClosed`). 이 시간에 그 종목의 `_AL` 0D가 실제로 왔는지는 자동 시험으로 알 수 없다. 결함 2를 고치면 키움 실시간이 끊긴 경우 창이 "끊김"을 보인다. 장중에 다시 확인해 달라는 요청을 사용자가 정해야 하는 결정 5에 적었다.

캡처 아래의 "거절 · 키움이 응답하지 않습니다"는 호가가 아니라 주문 명령이 `kiwoom_unavailable`로 거절된 상태 줄이다(`web/src/features/order/statusText.ts`). 이 플랜 범위가 아니다.

### 설정 ⚙

| 항목 | 지금 동작 | 판정 |
|---|---|---|
| 등락률 표시 | 등락률은 현재가 행 하나에만 그려진다. 끄면 그 한 칸만 사라진다(합성 캡처에서 `.mw-px small` 1개 → 0개) | 실제로 안 되는 것처럼 보인다. 고친다 |
| 평단가 점 | 보유 종목일 때만 점이 생긴다. 보유가 없으면 켜고 꺼도 아무 변화가 없고 이유도 안 보인다 | 안내가 없다. 고친다 |
| 구분선 | 매도·매수 경계선이 켜고 꺼진다 | 된다 |
| 수량 프리셋(주) | 입력 칸을 벗어날 때(blur)만 저장된다. Enter로는 저장되지 않는다. 주/금액 중 **금액**을 고르면 프리셋 단추가 고정값(100만·500만·1000만·5000만)이라 설정이 반영되지 않는다 | 고친다 |
| 설정 창 닫기 | Esc와 바깥 클릭으로 닫히지 않는다. ⚙를 다시 눌러야 닫힌다 | 고친다 |

기존 e2e `설정 ⚙의 값이 창 설정으로 저장되고 새로고침해도 유지된다`는 속성(`data-divider`)과 저장 문서만 본다. 화면에 보이는 효과는 보지 않아서 위 문제를 잡지 못했다.

## 확정된 결정

1. 주문 입력(수량, 주/금액, 프리셋, 주문 경로, 예상 주문금액)은 사다리 위로 올린다(요청).
2. 오른쪽 위 정보란과 왼쪽 아래 체결은 사다리 행과 같은 줄에 맞춘다(요청).
3. 잔량 변화 효과는 잔량 칸 안에서 보인다. 따로 뜬 뱃지를 없앤다(요청).
4. 전체 호가는 상한가부터 하한가까지 모든 호가를 스크롤로 보고 그 자리에서 주문한다. 다시 누르면 현재가 기준 10호가로 돌아온다(요청).
5. 10호가창의 총잔량 띠와 비율 막대는 아래로 내리고, 오른쪽 위에 상세정보를 둔다(요청).
6. 설정 ⚙의 항목이 실제 화면에 반영되게 고친다(요청).

## 스스로 정한 결정과 이유

1. **10호가는 현재가 중심의 가격 격자 20행이다.** 위 10행은 현재가보다 1~10틱 높은 가격, 아래 10행은 현재가와 그보다 1~9틱 낮은 가격이다. 틱은 KRX 호가 단위표(`web/src/features/order/priceRange.ts` `tickSize`)를 쓴다. 각 행의 매도 잔량과 매수 잔량은 받은 호가에서 그 가격으로 찾아 넣는다. 교차 호가는 같은 행에 매도·매수 잔량이 함께 보인다. 같은 가격이 두 줄로 나오지 않는다. 기준 가격은 현재가, 없으면 매수 1호가, 없으면 기준가다. 상·하한 밖의 행은 빈 행이다. 전체 호가와 같은 행 모델이라 두 모드를 오갈 때 가격 줄이 바뀌지 않는다. 앞 플랜의 "사다리가 교차 상태를 그대로 그린다"는 바뀌지 않는다. 교차는 한 행 안의 두 잔량으로 보인다. 대신 받은 10단 가운데 10틱 밖에 떨어진 단은 이 화면에서 빠진다. 이 결정은 사용자가 정해야 하는 결정 1로 확인받는다.
2. **현재가가 바뀌면 격자를 다시 가운데로 맞춘다.** 칩을 끄는 동안에는 격자를 멈춘다. 끌기 중에 가격 줄이 움직이면 놓는 자리가 바뀌기 때문이다.
3. **모든 행은 같은 열과 같은 높이를 쓴다.** 열 폭은 사다리 하나에 한 번 정하고 모든 행이 그 값을 쓴다(`minmax(0, 1fr)`). 행 높이는 24px로 고정한다. 현재가 행은 테두리로만 강조하고 높이를 바꾸지 않는다. 등락률은 가격 칸 안 같은 줄 오른쪽에 작게 둔다.
4. **정보란과 체결은 사다리의 빈 잔량 칸에 행 단위로 넣는다.** 위 7행(1~7행)의 매수 잔량 칸에 정보 7항목(현재가, 전일대비, 등락률, 거래량, 기준가, 상한가, 하한가), 아래 8행(13~20행)의 매도 잔량 칸에 체결강도 한 줄과 최근 체결 7건을 둔다. 가운데 8~12행은 비워 두어 교차 잔량이 들어갈 자리로 남긴다. 그 칸에 잔량이 있으면 잔량이 이긴다. hoga-ops `OrderWindow.tsx`의 `order-trades-slot`·`order-summary-slot`과 같은 방식이다.
5. **잔량 변화는 숫자 옆 작은 증감과 막대 끝의 짧은 반짝임으로 보인다.** 증감 글자는 잔량 숫자 바로 안쪽에 붙고 1.4초 뒤 사라진다. 막대는 늘어난 만큼 길어지며 0.6초 밝아진다. `prefers-reduced-motion`이면 반짝임 없이 증감 글자만 보인다. 다른 안은 사용자가 정해야 하는 결정 2다.
6. **호가주문창 배치는 위에서부터 계좌 띠 → 보유 요약 → 주문 입력·도구(전체 호가, 현재가, ⚙) → 상태 줄 → 사다리 → 총잔량 띠 → 접수 합계다.** 상태 줄은 주문 입력 바로 아래에 둔다. 주문 결과를 입력한 자리 근처에서 본다. 접수 합계와 그 목록은 사다리 아래에 남긴다.
7. **10호가창은 위에서부터 (알림이 있을 때만) 알림 줄 → 사다리 → 총잔량 띠다.** 아래 상한·기준·하한 띠는 오른쪽 위 정보란으로 옮기고 지운다. 정보란은 호가주문창과 같은 7항목이다.
8. **전체 호가는 상한가부터 하한가까지의 모든 틱을 한 목록으로 그리고 브라우저 스크롤로 움직인다.** 휠은 일반 스크롤이다. 켤 때와 "현재가"를 누를 때 현재가 행을 가운데로 스크롤한다. 행 높이가 고정이니 보이는 구간과 앞뒤 몇십 행만 그린다(가격이 1,000원대인 종목은 900행이 넘는다). 상·하한가를 아직 받지 못했으면 단추를 끄고 이유를 툴팁으로 보인다. 전체 호가 안에서도 잔량은 실시간으로 바뀐다.
9. **설정은 이렇게 고친다.** 등락률 표시는 가격이 있는 모든 행에 등락률을 그린다. 평단가 점은 보유가 없으면 체크 옆에 "보유 종목일 때 보입니다"를 보인다. 수량 프리셋은 올바른 값이 입력되는 즉시 저장하고 Enter로도 저장하며, 틀린 값은 칸을 벗어날 때 저장된 값으로 되돌린다. 금액 프리셋 4칸(만원 단위)을 더해 금액 모드의 프리셋 단추도 설정을 따른다. 설정 창은 Esc와 바깥 클릭으로 닫히고, 머리에 "모든 호가주문창에 적용"을 적는다(설정은 창별이 아니라 앱 설정 `orderSettings`다).
10. **현재가는 체결과 시세 조회 가운데 늦은 시각의 값이다.** `useBookFeed`가 시세를 5초마다 다시 읽고, 마지막 체결의 `t`와 시세의 `t`를 비교해 늦은 쪽을 현재가로 쓴다.
11. **허브는 새 호가·체결 구독에 지금의 실시간 상태를 알린다.** `attach_feed`가 세션이 내려가 있으면 그 구독에 `feed_link { live: false }`를 한 번 보낸다. 웹은 이미 이 메시지로 "끊김"과 흐린 사다리를 보인다.
12. **10호가창 왼쪽 아래에는 체결을 넣지 않는다.** 사용자는 정보란만 말했고 체결창이 따로 있다. 다른 안은 사용자가 정해야 하는 결정 3이다.

| `order-layout` | 호가주문창 배치: 주문 입력·도구·상태 줄을 위로, 정보란·체결을 사다리 행 자리로, 총잔량·접수 합계를 아래로 | `basic`: 화면 배치. 주문 동작은 그대로다 | `ladder-grid` 뒤 |
| `order-settings` | 설정 ⚙: 등락률·평단가 점 안내·프리셋 저장·금액 프리셋·닫기 | `basic`: 설정 화면과 앱 설정 값의 작은 수정 | `ladder-grid` 뒤(`order-layout`과 병렬) |
| `order-explorer` | 전체 호가: 상한~하한 전체 스크롤, 보이는 구간만 그리기, 현재가로 스크롤, 끄면 10호가 | `basic`: 화면과 스크롤. 주문은 행의 가격으로 기존 경로를 탄다 | `order-layout` 뒤 |

```
1단: ladder-grid ─┬─ live-signal          (병렬)
2단: order-layout · order-settings        (둘 다 ladder-grid 뒤, 서로 병렬)
3단: order-explorer                       (order-layout 뒤)
```

순차로 둔 이유:

- `order-layout` → `ladder-grid`: 정보란과 체결을 사다리 행 자리에 넣는 공개 모양을 `ladder-grid`가 만든다. 한쪽이 다른 쪽의 결과를 쓴다.
- `order-settings` → `ladder-grid`: 등락률이 모든 행에 그려지는 것은 `ladder-grid`의 행 렌더링이다. 설정 작업은 그것을 켜고 끄는 길과 시험을 맡는다.
- `order-explorer` → `order-layout`: 둘 다 `OrderWindow.tsx`의 사다리 영역과 `OrderLadder.tsx`를 다시 짠다.

같은 파일에 몇 줄씩 더하는 병렬 작업:

- `web/e2e/win-book.spec.ts`: `ladder-grid`(배치 시험 고침)와 `live-signal`(현재가 시험 추가). 두 지시서에 최소 변경을 적었다.
- `web/src/features/order/OrderWindow.tsx`, `web/src/features/order/QuantityRow.tsx`, `web/src/styles/order-window.css`, `web/e2e/win-order-panels.spec.ts`: `order-layout`(배치)과 `order-settings`(설정 값 전달 몇 줄, 프리셋 줄, 설정 창 CSS). 두 지시서에 최소 변경을 적었다.

## 사용자가 정해야 하는 결정

검증을 약하게 하는 변경(검증 단계 삭제, 시간 제한 증가, `paths` 축소)은 없다. 기존 e2e 둘은 동작이 바뀌어 다시 쓴다. `교차 호가를 그대로 그리고 현재가 행은 하나다`는 교차를 한 행의 두 잔량으로 보는 시험이 되고, `휠로 상·하한 사이를 훑고 현재가 단추로 돌아온다`는 스크롤 시험이 된다. 각 항목의 **추천**으로 지시서를 썼다. 승인하면 추천대로 간다.

1. **10호가의 행.** 추천: 현재가 중심 가격 격자 20행(스스로 정한 결정 1). 다른 안: 받은 매도 10단·매수 10단을 그대로 쓰되 같은 가격 두 줄만 한 줄로 합친다. 다른 안은 호가가 띄엄띄엄한 종목에서 10단을 모두 보이지만, 전체 호가와 행 모델이 달라 두 모드를 오갈 때 줄이 바뀐다.
2. **잔량 변화 효과.** 추천: 숫자 안쪽의 작은 증감 글자와 막대의 짧은 반짝임(스스로 정한 결정 5). 다른 안: 증감 글자 없이 막대의 늘거나 준 부분만 잠깐 색으로 보인다.
3. **10호가창 왼쪽 아래 체결.** 추천: 넣지 않는다. 다른 안: 호가주문창처럼 체결강도와 최근 체결 7건을 넣는다.
4. **끊긴 문장 "우측 상단에"의 해석.** "10호가창에도 우측 상단에 상세정보가 없다"로 읽었다. 다른 뜻이었다면 알려 주면 된다.
5. **실시간 확인 부탁.** 이 플랜으로 끊김 표시와 현재가 갱신은 고친다. 장중(09:00~15:30)에 같은 종목으로 호가가 움직이지 않으면, 그때 창에 "끊김"이 보이는지 알려 주면 된다. 보이지 않는데도 멈춰 있으면 키움 쪽 0D 수신을 따로 조사한다.

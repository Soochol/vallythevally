# 거래소별 시세 모드(UN·KRX·NXT) 검토와 제안

- **상태**: 제안. 사용자 결정 전이다. 앱 코드, PR #13, 용어집, ADR은 바꾸지 않았다.
- **작성**: 2026-11-09. 근거 실측은 `docs/kiwoom.md` 12절에 적었다.
- **요청**: 차트에서 UN(통합, `_AL`)·KRX(접미사 없음)·NXT(`_NX`) 중 하나를 골라, 봉 종가가 그 거래소 기준으로 그려지게 한다.
- **계기**: PR #13 화면에서 삼성전자 2026-11-06 일봉 종가가 193,400원(`_AL`)이었다. 예전 미리보기(Yahoo)는 188,700원이었다.
- **다시 여는 결정**: "차트는 언제나 통합 시세"(`GLOSSARY.md:31-32`, `decisions-r1.md:137` D16).

## 0. 한 줄 결론

188,700원은 **KRX 종가가 아니라 정규장 종가**(15:30 종가 단일가)다. 키움의 KRX 코드 일봉 종가는 193,500원이다. 2026-09-14부터 KRX 일봉이 애프터마켓(16:00~20:00)까지 포함하기 때문이다. 그래서 거래소 모드로는 원래 목표를 이루지 못한다. 필요한 것은 **장 구분 축(정규장 종가)**이다. 정규장 종가는 이미 받는 일봉에서 거꾸로 구할 수 있다. **거래소 모드는 보류하고, "정규장 종가" 표시를 #2 병합 뒤 새 이슈로 추가하기를 추천한다.**

2026-11-06 삼성전자 하나로 본 값이다.

| 무엇 | 값 | 몇 시 체결까지 |
|---|---|---|
| `005930_AL` 일봉 종가(지금 차트) | 193,400 | 19:59~20:00:0x, KRX+NXT 중 마지막 체결 |
| `005930` KRX 일봉 종가 | 193,500 | 19:59~20:00:0x, KRX 애프터마켓 마지막 체결 |

| KRX 1분봉 15:30 봉 종가 = 정규장 종가 | **188,700** | 15:30 종가 단일가 |
| Yahoo(예전 미리보기) | 188,700 | 정규장 종가 |

## 2. 사용자 목표 다시 쓰기

요청은 "거래소를 고르면 종가가 그 거래소 기준"이다. 그러나 계기가 된 숫자 188,700원은 거래소가 아니라 **장 구분**의 차이다.

- KRX 모드를 만들어도 2026-11-06 종가는 **193,500원**이다(F3). 2026-09-14 이후 36일 중 30일이 정규장 종가와 다르다.
- NXT 모드는 193,400원이다. NXT에는 종가 단일가가 없다(F18).
- 188,700원을 보이려면 "정규장(09:00~15:30, 종가 단일가 포함)"이라는 장 구분 축이 필요하다.

그래서 목표를 이렇게 다시 쓴다. **"일봉에서 그날의 공식 종가(정규장 종가, 다음 날 등락의 기준)를 볼 수 있다."** 거래소 선택은 이 목표에 필요하지 않다. 증권사 앱과 포털이 보여 주는 "종가"와 "전일 대비"는 이 값을 기준으로 한다(F10, F18).

거래소 모드가 따로 쓸모 있는 경우는 "NXT에서만 거래된 양을 보고 싶다"처럼 거래소 자체가 관심일 때다. 이것은 원래 요청의 계기와 다른 목표다.

## 3. 선택지

### (a) 거래소 모드만 둔다 (UN / KRX / NXT)

- **보이는 것**: 칸마다(또는 전체) 거래소 선택. KRX 모드 종가 193,500, NXT 모드 193,400. **188,700은 어디에도 안 나온다.**
- **설계 변경**
  - `Symbol::Stock`에 거래소를 넣거나 `SeriesKey`에 `venue`를 더한다. 지수는 거래소가 없으니 `Stock`에만 붙는 타입이어야 한다.
  - `kiwoom_stock_code`가 거래소를 받는다. 캐시 시리즈가 종목당 최대 3개가 된다.
  - `BarsPage`, `/api/bars` 쿼리, `CellState`, 주소(URL), 레이아웃 저장 형식에 거래소가 들어간다.
  - 드로잉: 종목에 붙인 채로 두어야 한다(거래소를 바꿔도 같은 가격대다). 지표는 보이는 시리즈로 계산한다. 알림은 거래소별로 판단할지 정해야 한다.
  - 검색과 범례에 거래소 표시. NXT 불가 종목은 NXT 선택을 막는다.
  - 용어집 "통합 시세"를 고치고 ADR을 새로 쓴다.
- **실시간**: `_AL` 하나에서 `9081`로 나누면 구독 수는 그대로다(F19). 단 애프터마켓 시간대 `9081` 값이 확인되지 않았다(F20). 따로 구독하면 종목당 2~3칸(F22).
- **한계**: NXT 이력은 2025-03-24부터(F16). NXT 가능 종목은 주식의 22%(F15)이고, 나머지 78%는 `_AL` = KRX, NXT 모드는 빈 차트다(F17). 분봉은 거래소와 상관없이 1년.
- **구현량**: 크다. 백엔드 타입·캐시·계약·구독, 프런트 상태·계약·UI 전부. 시세 쪽 변경 중 가장 넓다.

### (b) 거래소 모드 + 정규장 종가 표시

- (a)와 (c)를 모두 한다. 구현량은 (a)에 (c)를 더한 것이다.
- 정규장 종가는 거래소와 무관한 값이라(F10, 세 코드에서 같다), 모드를 바꿔도 같은 숫자가 나온다. 둘을 함께 두면 "KRX 모드인데 종가가 두 개"라는 설명 부담이 생긴다.

### (c) 정규장 종가 표시만 둔다 (봉은 지금처럼 통합 시세)

- **보이는 것**: 일봉(그리고 원하면 주·월봉)에서 범례와 십자선 값에 `정규장 종가 188,700`을 함께 보인다. 원하면 가격 패널에 정규장 종가를 잇는 선을 하나 더 그린다. 캔들 자체는 그대로 통합 시세다.
- **값의 출처**
  - 2026-09-11까지의 관측일: KRX 일봉 종가가 곧 정규장 종가다(F3, F10). `_AL`과 다른 날이 있으므로, 이 구간도 아래 역산으로 같은 규칙을 쓰는 편이 단순하다. 1997년 이전 행은 `pred_pre`에 부호가 없어 역산이 안 되지만, 그 구간은 NXT 이전이라 `_AL` 종가 = KRX 종가 = 정규장 종가다(`kiwoom.md` 3절).
  - 2026-09-14부터의 지난 관측일: 다음 행의 `cur_prc − pred_pre`(F10). 이미 받는 일봉 페이지 안에서 계산한다. **조회가 늘지 않고, 분봉 1년 한계도 없다.**
  - 오늘(가장 최근 관측일): 다음 행이 없다. #4 이후에는 `_AL` 0B의 종가 단일가 체결(F12)로, #2·#3에서는 1분봉의 종가 단일가 봉으로 구하거나 비워 둔다. 종가 단일가 봉은 15:30에 고정되지 않으므로(F11) "15:20~15:29 공백 뒤 첫 KRX 봉" 같은 규칙이 필요하다. 이 규칙은 **코드 가정**이다.
  - 2026-09-14 전 날은 KRX 일봉 종가와 같다(F3). 계산해도 같은 값이 나온다.
- **설계 변경**: `Symbol`, `SeriesKey`, `kiwoom_stock_code`는 그대로다. 일봉 응답에 값 하나를 더한다.
  - 예 1: `Bar`에 `rc: number | null`(정규장 종가)을 더한다. 일봉에서만 채우고 나머지 봉 주기는 `null`.
  - 예 2: `BarsPage`에 `regularCloses: { t, c }[]`를 따로 둔다. `Bar`는 그대로다.
  - 파서(`server::kiwoom::wire`)가 다음 행을 보고 계산한다. 페이지 경계의 마지막 행은 다음 페이지 첫 행이 있어야 한다. 경계 처리가 하나 생긴다.
  - 용어집에 "정규장 종가"를 더한다. "통합 시세" 문구는 그대로 두되 "일봉 종가는 그날 마지막 체결가"라고 덧붙인다.
- **실시간 비용**: 없다. 오늘 값만 `_AL` 0B에서 종가 단일가 체결을 알아보면 된다(#4).
- **한계**: 정규장 **종가만** 된다. 정규장 시가·고가·저가·거래량은 일봉에서 구할 수 없다. 2026-09-14 뒤 KRX 일봉 시고저가 애프터마켓까지 포함하기 때문이다. 이것들은 1분봉으로 모아야 하고, 1분봉은 1년만 받을 수 있다(`kiwoom.md` 2절). 2027-09 이후에는 2026-09~ 초기 구간의 정규장 시고저를 영영 다시 만들 수 없다(캐시는 메모리에만 있다, D14). 역산을 적용하는 구간 안에 권리락이 있었던 종목은 수정주가 환산(F13 ②)이 필요하다. 수정주가 일봉에서는 권리락 전 행의 `pred_pre`가 수정되지 않기 때문이다.
- **구현량**: 작다. 파서 계산 하나, 계약 필드 하나, 범례·십자선 표시, 선택적인 선 하나.

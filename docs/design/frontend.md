- **기준 문서**: `GLOSSARY.md`, `docs/adr/0001`~`0007`, 백엔드 설계 `docs/design/backend.md`. 백엔드 쪽 경계는 그 문서의 §8(브라우저 계약)과 §9(지표 크레이트 API)다.
- **1차 수정(2026-11-08)**: 코디네이터 결정 `docs/design/decisions-r1.md`(U1·U2, D1~D11)와 교차 리뷰 `docs/design/review-w4.md`의 프런트 지적(W4-25, 28, 29, 31, 32)을 반영했다. 계약 이름은 decisions-r1.md를 글자 그대로 따른다. 이 문서와 그 문서가 다르면 그 문서가 맞다.
- **2차 수정(2026-11-09)**: #2의 코드(`web/src`)에 맞췄다. #2에서 켜진 절은 코드가 지금의 사실이다. D12~D17과 ADR 0007(칸마다 거래소)도 반영했다.
- **목업**: `docs/design/mockup/index.html`. 빌드 없이 브라우저로 연다. 데이터는 시드로 만든 가짜 값이다.

## 0. 단계별로 켜지는 것

D3의 표를 그대로 옮긴다. 단계 번호는 이슈 번호다. 이 문서의 각 절 제목 끝에 그 절이 켜지는 이슈를 `(#N~)`으로 적었다. 표시가 없는 절은 #2부터 적용된다.

| 이슈 | 단계 | 켜지는 것 | 아직 없는 것 |
|---|---|---|---|
| #2 | 1단계 기반 | 1칸 고정, REST `/api/symbols`·`/api/bars`, 캐시, 키움 조회 대기열, 차트 설정은 브라우저 메모리에 | WebSocket, WASM, 사용자 자료 DB |
| #14 | 1.5단계 거래소 | 칸마다 거래소(통합·KRX·NXT), 분봉(1·3·5·15·30·60분) 과거 조회. 분봉의 진행 중 구간은 조회 스냅숏 | WebSocket, 실시간 현재 봉 |
| #3 | 2단계 저장 | 사용자 자료 스키마, 기본 레이아웃 마이그레이션, 관심종목, `UiState`, 자동 저장. 관심종목 현재가는 REST 조회 | WebSocket |
| #4 | 3단계 실시간 | WebSocket, 구독, 실시간 현재 봉 집계(일·주·월봉과 분봉), `seq` | |
| #5 | 4단계 지표 | WASM 지표, 비교 종목 | |
| #6~#9 | 5~8단계 | 드로잉 → 여러 칸 → 알림 → 클라우드 | |

**#2에서 프런트가 하는 일**(W4-18, D3)
- **화면**: 레이아웃 스토어는 메모리에 기본 1칸(코스피 일봉)만 갖는다. 위 막대에는 종목 버튼, 봉 주기(일·주·월), 봉 모양, 로그 축, 테마만 켠다. 왼쪽 도구, 관심종목, 알림, 칸 배치는 숨긴다.
- **현재 봉**: 실시간이 없다. 진행 중인 구간은 REST 최신 페이지의 `current`로 보여 준다. 이 값은 키움 조회가 준 오늘 봉이다. 종목이나 봉 주기를 바꾸거나 새로고침할 때만 새로 받는다. 범례 시각 옆에 `조회 값`이라고 적어, 체결마다 움직이는 값이 아님을 알린다.
- **거래량**: 지표가 아니라 봉의 `v`를 그대로 막대로 그린다. 계산이 없으므로 WASM이 필요 없다. 이동평균을 곁들인 거래량 지표는 #5에서 바꾼다(#75에서 바꿨다. §5.5).
- **테마**: `UiState`가 없으므로 localStorage에만 둔다. #3부터는 `UiState.theme`이 원본이다.
- **연결 상태**: WebSocket이 없으므로 연결 상태 점을 숨기고 `조회 모드`라고만 적는다.

**#14에서 프런트가 더하는 것**(ADR 0007, D17). #14는 #3보다 먼저 한다. #3의 레이아웃 저장 형식이 처음부터 칸의 거래소를 담게 하려는 것이다.
- **칸 상태**: 칸이 거래소를 갖는다(`CellState.venue`, §5.3). 지수면 `null`이다.
- **위 막대**: 종목 버튼 뒤에 거래소 선택기(통합 / KRX / NXT)를 둔다(§2.1). 지수면 숨기고, NXT 불가 종목이면 NXT를 비활성으로 둔다.
- **봉 주기**: 1·3·5·15·30·60분을 켠다. 위 막대 봉 주기는 9개가 된다(지금 코드의 `PERIODS_ON`은 일·주·월 셋이다). 단축키 `1` `3` `5`, `Shift+1` `Shift+3` `Shift+6`도 켠다(§3.2).
- **분봉의 진행 중 구간**: #2와 같이 `current`(키움 조회 스냅숏)로 그리고 `조회 값`을 붙인다. 실시간 현재 봉은 #4다.
- **1년 끝**: 분봉에서 과거 끝에 닿으면 "분봉은 최근 1년까지"를 안내한다(U1, §5.4).
- **범례**: 머리줄에 거래소를 적는다(§2.3).
- **주소**: `/?symbol=005930&venue=krx&period=5m`(§5.1).
- **휴대폰**: 같은 선택기와 분봉 칩(§4).
- **정규장 종가**: 표시하지 않는다(D17). 범례와 휴대폰 머리의 종가는 그 거래소 봉의 종가다.

**#3에서 프런트가 하는 일과 이 문서와 다른 점**
- **복원**: `UiState` → `lastLayoutId`의 레이아웃(없거나 404면 목록의 첫 레이아웃, 그때는 `lastLayoutId`도 고쳐 저장) → 칸마다 `venueFor`. 복원이 끝나기 전에는 칸을 그리지 않는다. 주소의 `?symbol=`은 복원 뒤에 적용한다(`persist/restore.ts`, `persist/boot.ts`).
- **저장할 거래소와 그리는 거래소**(R1): `CellState.venue`는 사용자가 고른 **저장 원본**이다. 칸이 그리는 거래소는 저장하지 않는 파생값 `shownVenue(cell.venue, 종목 정보)`이고 타입도 `ShownVenue`로 나눈다. 차트(`ChartController.apply`), 칸 이름, 거래소 선택기는 `ShownVenue`만 쓴다.
  - 종목 정보가 없으면(받는 중, 일시 실패) NXT 허용을 모르므로 NXT 칸만 통합으로 그린다. 저장 원본은 `nxt` 그대로다. 그동안 봉 주기 같은 다른 편집을 저장해도 `nxt`로 저장된다.
  - 저장 원본은 두 경우에만 바뀐다. 사용자가 거래소나 종목을 직접 바꿀 때, 그리고 NXT 불가가 **확인된** 때다. 확인은 복원(`restoreCell`)이나, 복원 때 확인하지 못한 칸이 나중에 종목 정보를 받았을 때(`ChartCell`) 한다. 그때만 통합으로 고쳐 저장하고 알린다. 한 칸의 확인이 다른 칸의 미확인 NXT를 바꾸지 않는다.
- **서버에 닿지 못하면**: 기본 칸으로 열고 상태 줄(휴대폰은 아래 띠)에 알린다. 저장된 값을 덮어쓰지 않도록 그동안의 변경은 저장하지 않는다.
- **휴대폰 칸**: `UiState.phone`(§4)은 #3에 두지 않는다. 휴대폰도 데스크톱 레이아웃의 활성 칸을 함께 쓴다.
- **상태를 두는 곳**(§5.2와 다름): 관심종목 목록들(#37)과 `UiState`도 레이아웃처럼 Zustand 편집 사본(`stores/watchlist.ts`, `stores/ui.ts`)에 둔다. 셋 다 `load`로 싣고, 편집마다 늘어나는 `revision`을 자동 저장이 지켜본다(§5.3의 `dirty`·`saveState` 대신. 저장 상태는 `stores/persist.ts`). 관심종목 현재가는 TanStack Query가 아니라 관심종목 전용 저장소(§5.2 표)에 둔다. 종목이 목록에 처음 들어올 때 REST로 한 번 받고, 그 뒤로는 WebSocket `quotes`로만 바뀐다(#66).
- **`chartSettings` 검사**(§5.5와 다름): zod 대신 손으로 쓴 검사(`parseChartSettings`). 지표·패널은 #5 전이라 빈 배열만 받는다. #75에서 지표·패널을 받는 v2로 넓혔다(§5.5). #76에서 `scale`에 `percent`를 더했다(v는 2 그대로).
- **휴대폰 관심종목**(§4와 다름): 길게 눌러 끌기와 밀어 지우기 대신 머리의 `편집`에서 위·아래·지우기 버튼을 쓴다.
- **관심종목의 `+`**: 같은 검색 대화상자를 "관심종목에 넣기" 목적으로 연다. `Enter`가 칸에 열지 않고 관심종목에 넣는다.

## 1. 화면 디자인 방향

### 1.1 인상

이 도구는 운영자 한 사람이 장중에 오래 켜 두고 보는 도구다(ADR 0001). 그래서 화면은 소개용 제품처럼 꾸미지 않는다. 오래 보는 계기판처럼 조용하게 만든다. 고유한 인상은 세 가지 선택에서 나온다.

1. **바탕은 녹색 기운이 도는 먹색이다(다크).**
   - 차트 앱에 흔한 남색 바탕도, 순수한 검정도 쓰지 않는다.
   - 다크 바탕 `#161F1E`는 이끼 낀 돌 같은 색이다. 빨강·파랑 봉 어느 쪽과도 색상이 겹치지 않는다.
   - 라이트는 그 바탕을 밝힌 회녹색 종이(`#FBFCFB`, 막대 `#EDF1EF`)다.
2. **강조색은 호박색 하나만 쓰고, 등락과는 다른 일을 맡긴다.**
   - 빨강(상승)과 파랑(하락)은 가격 방향에만 쓴다.
   - 사용자가 지금 고른 것, 곧 활성 칸 테두리, 고른 봉 주기, 켠 도구, 키보드 초점, 주 버튼에는 호박색(`--accent`)만 쓴다.
   - 그래서 화면 어디서든 "빨강·파랑이면 시장, 호박색이면 나"로 읽힌다. 강조색이 파랑이면 하락과 헷갈리고, 빨강이면 상승과 헷갈린다. 호박색을 고른 이유다.
3. **대담함은 범례의 종가 숫자 한 곳에만 쓴다.**
   - 칸 왼쪽 위에 십자선이 가리키는 봉의 종가를 크게 둔다. 크기는 1칸 22px, 여러 칸 15px이고 등락 색을 입힌다.
   - 그 아래에 시·고·저·종·량을 12px로 놓는다.
   - 나머지 막대, 버튼, 관심종목은 13px 회색조로 조용히 둔다.
   - 따로 가격판을 두지 않는다. 그래서 차트 위 숫자가 화면의 표제가 된다.

**베끼지 않는 것**
- 로고는 두 골짜기를 이은 선 `VV`로 직접 그렸다. 저장소 이름 vallythevally에서 왔다.
- 아이콘은 1.5px 선으로 모두 새로 그렸다(목업 `index.html`의 `<symbol>`).
- 남색 바탕과 파랑 강조, 청록·빨강 봉 조합은 쓰지 않는다.
- 다만 배치는 차트 앱에 흔한 관례를 따른다. 위 막대, 왼쪽 도구, 오른쪽 목록이다. 손에 익은 배치는 바꿀 이유가 없다.

### 1.3 글꼴과 숫자

- **글꼴은 Pretendard Variable 하나다.**
  - 한글과 라틴 글자의 굵기와 높이가 고르다. 가변 글꼴이라 550·650 같은 중간 굵기를 쓸 수 있다. 범례 숫자에 650을 쓴다.
  - 대체 글꼴은 `"Noto Sans CJK KR", "Apple SD Gothic Neo", system-ui` 순이다.
  - 실제 앱은 npm `pretendard` 패키지의 dynamic subset을 Vite로 함께 묶어 같은 서버에서 내보낸다.
    - 목업만 jsDelivr CDN을 쓴다.
    - 사설망(#9) 밖으로 요청을 내보내지 않으려는 것이다. 서버 하나가 정적 파일을 모두 맡는다(ADR 0002).
- **숫자는 언제나 고정폭이다.** `body`에 `font-variant-numeric: tabular-nums`를 걸었다.
  - 그래서 체결마다 종가가 바뀌어도 자릿수 폭이 같아 숫자가 흔들리지 않는다. 관심종목의 가격 열도 오른쪽 정렬로 자리가 맞는다.
  - 모노스페이스 글꼴은 쓰지 않는다. Pretendard의 tabular 숫자로 충분하고, 글꼴이 둘이면 범례가 산만해진다.
  - Lightweight Charts에는 `layout.fontFamily`로 같은 글꼴을 넘긴다. 축 눈금의 숫자 폭은 Pretendard가 기본으로 맞춰 준다.
- **숫자 표기**
  - 가격: 주식은 원 단위 정수에 천 단위 쉼표(`85,400`), 지수는 소수 둘째 자리(`1,963.30`).
  - 등락: 부호를 항상 붙인다(`+1,600 +1.86%`, `−500 −0.58%`). 부호가 있으니 색을 못 봐도 방향을 안다(§7).
  - 거래량: `만`·`억` 단위(`33만`, `25.64억`).
  - 시각: 한국 시각 `2026-11-06 19:55`. 일봉 이상은 날짜만 쓴다.

### 1.4 정보 밀도

- **높은 밀도를 기본으로 한다.** 데스크톱 1440×900에서 4칸이 각각 지표 패널 1~2개와 함께 들어가고, 관심종목 13종목이 스크롤 없이 보인다.
- **줄이는 것과 지키는 것**
  - 줄이는 것: 칸 머리줄을 따로 두지 않는다. 범례가 머리줄을 겸한다. 그래서 차트 면적이 커진다.
  - 지키는 것: 클릭 대상은 데스크톱 26px 이상, 휴대폰 36px 이상으로 둔다. 범례 줄 높이는 18px이다. 휴대폰의 봉 주기 칩과 테마 버튼도 36px이다(목업보다 크다).
- **범례의 반투명 바탕**: 여러 칸 화면에서는 범례가 봉을 가리지 않게 가격 패널의 위 여백을 26%로 잡는다(`scaleMargins.top`). 범례 줄마다 `--chart-bg` 78%의 바탕을 깔아 봉 위에서도 글자가 읽힌다.

**오른쪽 관심종목**
- **여러 목록**(#37): 머리의 목록 이름 버튼(`기본 ⌄`)이 메뉴를 연다.
  - 메뉴: 목록 고르기, `새 목록`, `이름 바꾸기`, `목록 지우기`, 열 고르기.
  - 목록은 20개까지다. 이름은 앞뒤 공백을 지우고 1~20자이고, 다른 목록과 겹치지 않는다.
  - 새 목록의 처음 이름은 `목록 N`(비어 있는 가장 작은 N)이다. 이름은 머리에서 바로 입력하고, 쓸 수 없는 이름이면 그 까닭을 보이고 만들지 않는다.
  - 마지막 목록은 지울 수 없다(`목록 지우기`가 꺼진다). 종목이 든 목록을 지울 때는 확인을 묻는다. 지운 목록 대신 바로 위(없으면 아래) 목록을 본다.
  - 지금 보는 목록은 `UiState.activeWatchlistId`다. 가리키는 목록이 없으면(다른 탭에서 지움) 첫 목록을 본다.
  - `+`와 검색의 `Ctrl+Enter`는 지금 보는 목록에 넣는다. 빈 검색 화면의 `관심종목` 묶음도 지금 보는 목록이다. 현재가는 지금 보는 목록만 받는다. 브라우저는 보이는 목록을 위에서부터 WebSocket `watch`로 서버에 알린다(backend.md §8.3). 다른 목록을 고르거나 패널을 접거나 휴대폰에서 관심종목 탭을 떠나면, 그 종목은 다른 곳에서 쓰지 않을 때 30초 뒤 해지된다. 데스크톱 패널과 휴대폰 시트는 폭에 따라 CSS로만 숨으므로, 데스크톱 패널은 폭이 `md` 이상일 때만, 휴대폰 시트는 `md` 미만일 때만 현재가를 받는다.
- **다른 목록으로**: 행의 `⋯`(데스크톱은 마우스를 올렸을 때, 휴대폰은 `편집`에서) 메뉴로 다른 목록에 옮기거나 복사한다. 대상 목록의 끝에 붙는다. 이미 있으면 복사는 알림만 띄우고, 옮기기는 원래 목록에서 빼기만 한다.
- **열**: 종목(이름, 코드)은 늘 보인다. 그 밖에 현재가, 등락, 등락률, 거래량 가운데 고른 열을 이 차례로 보인다(기본: 현재가, 등락률). 패널 전체에 하나이고 `UiState.watchColumns`에 둔다. 열을 더하면 데스크톱 패널이 이름 칸 96px를 지키도록 넓어진다(기본 264px, 넷 다 392px). 열을 빼도 기본 열의 폭 264px보다 좁아지지 않는다. 목록 머리와 종목 정보 패널이 이 폭에 맞춰져 있다. 휴대폰 `편집` 중에는 값 열을 숨긴다. 값은 계약의 `Quote` 하나로 채운다. 종목이 목록에 처음 들어올 때 REST `/api/quotes`로 한 번 받고, 그 뒤로는 WebSocket `quotes`가 체결마다 바꾼다. 순서를 바꿔도 다시 받지 않는다. 주기 조회는 없다(#66). 같은 종목을 통합 칸에 열면 칸이 실시간 집계 중일 때 칸의 종가와 이 값이 같다. KRX·NXT 칸은 그 거래소 체결만 쓰므로 다를 수 있다.
- **실시간 아님**(#66): 키움 실시간 등록은 200개까지다. 자리는 열린 칸 → 관심종목(목록의 위부터) 순으로 받는다(backend.md §5.3). 자리를 못 받은 줄(`watch_limited`)은 현재가 칸에 처음 받은 가격을 흐리게 두고 그 아래 작은 글씨로 `실시간 아님`을 적는다. 값이 아직 없으면 `실시간 아님`만 적는다. 다른 열은 처음 값을 그대로 둔다. 다시 조회하지 않는다. 행의 접근성 이름 끝에도 `실시간 아님`을 붙인다. 현재가 열을 끈 경우는 접근성 이름에만 남는다.
- 스파크라인은 v1에 넣지 않는다(W4-31). `Quote`로는 만들 수 없고, 그리려면 관심종목마다 봉을 따로 받아야 한다. 확장 후보로 남긴다.
- 활성 칸의 종목 행에는 호박색 왼쪽 띠를 붙인다.
- 행을 누르면 활성 칸이 그 종목으로 바뀐다. 종목 연동이 켜진 칸들도 함께 바뀐다.
- 머리의 `›`로 28px 띠까지 접는다. 접힌 상태는 `UiState.watchCollapsed`에 둔다.
- 순서는 끌어서 바꾼다. 키보드로는 Alt+↑/↓로 바꾼다.

**종목 정보**(#35): 관심종목 목록 아래에 활성 칸 종목의 기본 정보를 둔다. 값은 계약의 `Fundamentals` 하나다(backend.md §8.2).
- 2열 격자로 열 줄을 놓는다. 시가총액, 상장주식, PER, PBR, EPS, BPS, ROE, 외국인 소진율, 52주 최고, 52주 최저 순서다. 머리에 `종목 정보`와 종목 이름을 적는다.
- 키움이 주지 않은 값과 받는 중인 값은 `—`이다. 시가총액은 `1,130.67조`·`2,345억`, 상장주식은 거래량처럼 `58.46억주`로 적는다.
- 지수면 자리째 숨긴다. 키움 ka10001은 지수를 받지 않는다.
- 받지 못하면 패널 안에 `종목 정보를 받지 못했습니다. <서버 문장>`을 적는다. `unknown_symbol`이나 `manualActionRequired`가 아니면 `다시 시도` 버튼을 둔다. 차트 칸은 이 오류와 상관없이 그린다.
- 관심종목을 접으면 함께 접힌다. 따로 접는 상태를 저장하지 않는다.
- 휴대폰에는 v1에 두지 않는다. 관심종목 탭은 목록만 보인다. 폭이 Tailwind `md`(48rem) 미만이면 패널을 마운트하지 않아 ka10001도 묻지 않는다. 폭이 커지면 그때 마운트해 묻는다.

칸 사이 경계를 끌어 비율을 바꾸는 기능은 v1에 넣지 않는다. 고정 비율로 충분하다.

**상태 줄**: 연결 상태, 자동 저장 표시, 라이브러리 표기, 단축키 도움말 버튼이 있다. 구독 수는 계약에 없는 값이라 보이지 않는다(W4-31).

**키움 조회 멈춤**(#19, #21): 어느 요청이든 `manualActionRequired: true`를 받으면 `api/http.ts`가 그 문장을 `useKiwoomStore.stopped`에 둔다. 데스크톱 상태 줄은 `조회 모드` 자리에 `키움 조회 멈춤: <문장>`을 강조색으로 적는다. 휴대폰은 따로 띠를 두지 않고 칸 오류 문장(§3.7a)이 같은 문장을 보인다. 문장은 서버가 정한다. 8050이면 공인 IP를 키움 포털에 등록하라는 조치가 들어 있다(backend.md §4.3). 서버를 다시 켜야 풀리므로 페이지를 새로 열 때까지 지우지 않는다. `reason: "kiwoom_timeout"`이면 같은 자리에 서버 문장("키움 응답이 15초 안에 오지 않았습니다(…, 응답 대기 단계)")을 두고, 다음 성공 응답에서 지운다(#23).

### 2.2 연결 상태 표시 (#4~)

백엔드 계약의 `ConnectionStatus`(§8.3)를 그대로 보여 준다. 점 하나와 짧은 문장이다.

| 상태 | 점 | 문장 | 추가 |
|---|---|---|---|
| WebSocket 연결 중 / 끊김(브라우저↔서버) | 회색 | `서버에 다시 연결하는 중` | 칸 범례 옆에 `멈춤` 꼬리표. 다시 연결되면 칸을 비우고 다시 만든다(§5.4, D2) |
| `realtime: "live"` | 민트, 2.4초 맥박(움직임 줄이기 설정이면 멈춤) | `실시간 연결됨` | |
| `"live"`, 장 닫힘(20:00~08:00, 주말) | 민트, 맥박 없음 | `장 닫힘: 체결 없음` | 브라우저가 시각으로 판단 |
| `"reconnecting"` | 호박 | `키움에 다시 연결하는 중 (14:02부터)` | `since` 표시 |
| `backfilling: true` | 호박 | `끊긴 구간 메우는 중` | |
| `"halted"` | 빨강 | `실시간 멈춤: 서버를 다시 켜야 합니다` (인증 실패, 또는 다시 구성한 세션에서도 제어 실패. 조회 차트는 그대로 쓴다) | 상태 줄 전체를 띠로 강조 |

- **멈춘 시세 구분**(W4-32)
  - 실시간이 멈춘 동안(브라우저↔서버 끊김, `reconnecting`, `halted`)에는 마지막 가격이 최신 가격처럼 보이면 안 된다.
  - 칸마다 범례 가격줄 끝에 `멈춤 14:02` 꼬리표(호박색 테두리)를 붙인다. 시각은 마지막으로 `bar`를 받은 때다.
  - 종가 숫자는 등락색을 그대로 두되 70% 불투명도로 낮춘다.
  - 관심종목 현재가 열도 같은 방식으로 흐리게 한다.
  - 다시 `live`가 되고 첫 `bar`를 받으면 꼬리표를 걷는다.
- **휴대폰**: 상태 줄이 없으므로 휴대폰 머리의 셋째 줄에 같은 점과 문장, 라이브러리 표기를 둔다(§4).
- **장 닫힘 판단**: 장이 닫혀 있는지는 서버가 알려 주지 않는다. 브라우저가 한국 시각으로 판단한다. 공휴일은 모르므로 공휴일에는 "실시간 연결됨"으로 보일 수 있다. 사소해서 그대로 둔다.
- **구독 오류**: 칸의 구독에 `sub_error`가 오면 그 칸 범례 첫 줄 끝에 이유를 붙인다.
  - `realtime_limit` → `실시간 한도 초과: 조회 값만 보입니다`
  - `kiwoom_unavailable` → `키움 조회 실패: 잠시 뒤 다시 시도합니다`

### 2.3 범례(십자선이 가리키는 봉)

범례는 칸 왼쪽 위에 겹쳐 놓는다(목업 `.legend`). 줄 순서는 다음과 같다.

1. **머리줄**: 종목 연동 꼬리표, 종목 이름(650), 코드(지수는 목업처럼 `지수`. 코드의 `symbolSub`), 거래소(#14. `통합`·`KRX`·`NXT`, 지수는 없음), 봉 주기
2. **가격줄**: 종가(크게, 등락색), 전 봉 대비 변화량과 %, 봉 시각. 분봉의 봉 시각은 날짜까지 쓴다(`2026-11-06 19:55`). 1년치를 스크롤할 때 시각만 있으면 어느 날인지 알 수 없다. 시간축 눈금만 하루 안을 `HH:mm`, 날짜가 바뀌는 눈금을 `11-06`으로 쓴다(#14).
3. **OHLCV 줄**: `시 고 저 종 량`. 이름표 글자는 `--text-3`, 값은 `--text`
4. **가격 패널 지표**: 줄마다 색 견본 10×2px, 이름과 설정값(`이동평균 20`, `볼린저 밴드 20 2`), 값
5. **비교 종목**(#76): 색 견본, 이름, % 변화(등락색). 기준은 화면 왼쪽 끝 봉이고, 십자선이 가리키는 시각에 비교 종목 점이 없으면 직전 점을 쓴다. 보이는 범위가 바뀔 때마다 다시 계산한다. 꼬리표는 `% 기준: 첫 받은 봉`, `실시간 아님`, `받지 못함`, `찾을 수 없음`(§3.4). 마우스를 올리면 지우기 버튼이 보인다

- **지표 패널의 범례**: 각 지표 패널의 왼쪽 위에 한 줄로 따로 둔다. 예: `RSI 14 42.57`, `거래량 33만 — 이동평균 20 57만`.
- **어느 봉을 보여 주나**: 십자선이 차트 밖이면 마지막 봉(현재 봉)이다. 십자선 동기화가 켜져 있으면 다른 칸의 십자선이 움직일 때도 그 칸 범례가 그 시각의 봉을 보여 준다.
- **지표 줄 조작**: 지표 줄에 마우스를 올리거나 키보드 초점이 오면 숨기기·설정 편집·지우기 버튼 셋이 나타난다(목업에서는 1칸 화면의 `이동평균 20` 줄에 켜 두었다).
- **갱신 방식**: 범례는 React 컴포넌트가 아니다. 컨트롤러가 DOM 글자를 직접 바꾼다(§5.4). 십자선 이동과 체결 갱신이 초당 수십 번 일어나기 때문이다.

### 3.1 종목 검색

- **열기**: `/` 또는 `Ctrl+K`, 위 막대의 종목 버튼, 휴대폰 아래 탭의 검색.
- **입력**
  - 이름, 코드 6자리, 초성을 받는다.
  - 결과는 입력할 때마다(100ms 디바운스) 서버에 묻는다. 서버는 최대 20개를 준다(D5). 목록은 8줄 높이로 보이고 나머지는 스크롤한다.
  - 맞은 글자는 호박색 굵은 글씨로 표시한다.
  - 정규화는 서버와 같다(D5): 앞뒤 공백을 자르고, 안쪽 공백을 지우고, 영문은 대문자로 바꾼다. 브라우저는 강조 표시를 위해서만 같은 정규화를 한다.
- **빈 입력**(D5, `desktop-search-empty-dark.png`)
  - 정규화한 입력이 비면 서버를 부르지 않는다.
  - 대신 두 묶음을 보인다. `관심종목`(목록 순서대로)과 `최근 본 종목`(최근 것 먼저, 최대 10개).
  - 최근 본 종목은 칸에 종목을 열 때마다 앞에 넣는다. #2에서는 메모리에만, #3부터는 `UiState.recentSymbols: SymbolCode[]`에 둔다.
  - #2에는 관심종목이 없으므로 최근 본 종목만 보인다. 둘 다 비면 `종목 이름, 코드, 초성을 입력하세요`라고 적는다.
- **결과 없음**: `맞는 종목이 없습니다. 코드 6자리로도 찾을 수 있습니다`.
- **키**

| 키 | 동작 |
|---|---|
| `↑` `↓` | 고르기 |
| `Enter` | 활성 칸에 열기 |
| `Shift+Enter` | 활성 칸의 비교 종목으로 넣기(후속. #76은 지표 대화상자의 탭만 켰다) |
| `Ctrl+Enter` | 관심종목에 넣기 |
| `Esc` | 닫기 |

- **초성 검색**(D5)
  - 한국 종목명은 길고(`삼성바이오로직스`) 한글 입력기 전환이 번거롭다. 초성만 치는 습관이 국내 증권 앱에 널리 퍼져 있다.
  - 입력이 모두 한글 자음(ㄱ~ㅎ)일 때만 쓴다. 종목명의 초성열과 비교한다.
  - 검색은 서버의 `GET /api/symbols?q=`가 한다. 종목 목록은 서버 메모리에 있다. 브라우저가 수천 종목을 받아 둘 필요가 없다.
- **순위**(D5): 코드 완전 일치 > 이름 완전 일치 > 코드 접두 > 이름 접두 > 초성 접두 > 이름 포함 > 초성 포함.
  - 같은 순위 안에서는 지수 > 보통주 > 우선주 > ETF > 리츠 순, 그다음 이름 순서다. 이름 순서는 글자 단위로 **한글 음절 < 라틴 문자 < 숫자 < 그 밖**이고, 한글은 가나다순, 라틴은 알파벳순이다(백엔드 §8.2).
  - 예: `ㅅㅅ` → 삼성물산, 삼성바이오로직스, 삼성생명, 삼성전기, 삼성전자, 삼성SDI, 신세계(모두 초성 접두·보통주), 삼성전자우(우선주).
  - 브라우저는 결과를 다시 정렬하지 않는다. `Intl.Collator('ko')`는 숫자를 한글보다 앞에 두므로 서버 규칙과 다르다. 목업의 `V.search`는 이 Collator를 쓰는 근사이고, 숫자가 섞인 이름에서는 서버와 순서가 다를 수 있다.
  - 브라우저는 서버가 준 순서를 그대로 보인다. 목업의 `V.search`는 이 규칙을 흉내 낸 대역이다.
- **종목을 열 때의 거래소**(#14): 활성 칸의 거래소는 §5.3 `setSymbol`의 세 규칙을 따른다. 고른 종목이 지수면 거래소가 사라지고, 주식이면 지금 거래소를 그 종목이 허용할 때 유지한다. 결과의 `SymbolInfo.nxtEnabled`로 판단하므로 따로 조회하지 않는다.
- **봉 주기 단축키와의 충돌**: 아무 글자나 치면 검색이 열리는 방식은 쓰지 않는다. 숫자와 D·W·M을 봉 주기 단축키로 쓰기 때문이다. 검색은 `/`로 연다.

### 3.3 지표 추가 대화상자와 지표 패널 (#5~)

**열기**: 위 막대의 `지표`, `I`, 휴대폰 봉 주기 줄 끝의 지표 버튼.

**구성**(`desktop-indicator-dialog-dark.png`)

**검증**(D6)
- 설정값은 입력할 때마다 WASM 공개 함수 `validateSpec(specJson: string): SpecValidation`으로 검사한다. 엔진을 만들지 않으므로 가볍다. 워커를 거치지 않고 메인 스레드에서 부른다.
  ```ts
  type SpecValidation = { ok: true } | { ok: false; errors: { field: string; message: string }[] }
  ```
- `ok: false`이면 `errors[].field`에 해당하는 입력칸 아래에 `message`를 그대로 적고 주 버튼을 끈다. 예: `빠른 기간은 느린 기간보다 짧아야 합니다`. `field`가 입력칸과 맞지 않으면 설정 묶음 맨 아래에 적는다.
- 서버에서 불러온 `chartSettings`의 지표는 칸을 열 때 워커가 엔진을 만들며 같은 검사를 한다(메인 스레드의 wasm을 칸 열기 전에 기다리지 않는다, §5.5·§5.6). 틀린 지표는 그리지 않고 범례에 흐린 글자와 `설정 오류`를 남긴다.

**같은 지표 종류 여러 개**
- 지표마다 브라우저가 UUID를 붙인다(§5.5 `chartSettings`).
- 이동평균 5와 이동평균 20은 서로 다른 지표다. 같은 설정의 지표를 또 추가하면 색만 다르게 하나 더 생긴다. 막지 않는다.

**설정 편집**
- 범례 지표 줄이나 "이 칸에 띄운 지표" 목록의 설정 버튼을 누르면 같은 대화상자가 그 지표의 편집 상태로 열린다. 선을 더블클릭해 여는 것은 후속이다(#75에서 미룸).
- 이때 주 버튼은 `변경 적용`이다. 적용하면 대화상자는 닫히지 않고 그 종류의 추가 상태로 돌아간다.

**지표 패널 관리**
- **기본**: 지표 패널 쪽 지표는 추가할 때마다 새 패널을 아래에 붙인다. Lightweight Charts의 pane 하나가 패널 하나다.
- **높이**: 패널 경계를 끌어 바꾼다(`layout.panes.enableResize`). 바꾼 비율은 `chartSettings.panels[].stretch`에 저장한다.
- **순서**: 지표 패널 범례 줄에 마우스나 초점이 오면 `위로`, `아래로`, `패널 닫기` 버튼이 보인다(메뉴 대신 줄 안의 버튼, #75). `패널 닫기`는 그 패널의 지표를 지운다.
- **패널 하나에 지표 하나**(D11): v1은 지표 패널 하나에 지표 하나만 둔다. RSI와 스토캐스틱을 한 패널에 겹치는 기능은 넣지 않는다. `IndicatorConfig.panel`이 패널 id를 가리키므로 나중에 저장 모양을 바꾸지 않고 넣을 수 있다.
- **한 칸의 지표 패널 수**: 최대 4개를 권하고 막지는 않는다. 4칸 화면에서는 2개를 넘으면 가격 패널이 너무 낮아진다.
- **숨긴 지표**: 계산을 멈추고 시리즈를 `visible: false`로 둔다. 범례에는 흐린 글자로 남긴다.

### 3.4 비교 종목과 % 축 (#76)

- **넣기**: 지표 대화상자의 `비교 종목` 탭. 왼쪽에서 종목을 찾아 고르고 `<종목 이름> 추가`를 누른다. 추가해도 대화상자를 닫지 않는다. 메뉴를 지표와 같은 곳에 두는 것은 #5의 요구다. 종목 검색의 `Shift+Enter`는 후속이다.
- **최대 3개**: 4번째는 넣을 수 없다. 추가 버튼이 꺼지고 `비교 종목은 3개까지입니다`라고 적는다. 이미 넣은 종목(`이미 넣은 비교 종목입니다`)과 칸의 종목(`이 칸의 종목입니다`)도 막는다. 칸의 종목을 바꿔 비교 종목과 같아지면 그 비교 종목은 구독하지도 그리지도 않는다. 저장 목록에서는 지우지 않는다.
- **% 축**
  - 가격 패널의 오른쪽 축을 `PriceScaleMode.Percentage`로 그린다. 화면 왼쪽 끝 봉의 종가가 0%다. 왼쪽 끝 봉은 라이브러리가 쓰는 `floor(보이는 논리 범위 왼쪽)` 자리의 봉이고, 반쯤 보이는 봉도 든다.
  - 기준은 라이브러리가 그릴 때마다 정한다. 스크롤하면 바로 새 왼쪽 끝 봉으로 바뀐다. 과거 페이지를 붙일 때는 보이는 범위를 같은 봉에 붙들어 두므로(§5.4) 기준이 그대로다. 오른쪽 끝을 보다가 새 봉이 생기면 범위가 한 봉 밀리고 기준도 한 봉 옮긴다. 처음부터 다시 받으면(종목·봉 주기 변경, `reload`, 새 `hello`) 최신 130봉의 왼쪽 끝이 새 기준이다.
  - 켜는 곳은 위 막대 `로그` 옆의 `%`와, 대화상자 `비교 종목` 탭의 `가격축을 % 변화로` 스위치다. 휴대폰에는 축 버튼이 없어서 탭의 스위치가 % 축에 닿는 길이다. 비교 종목이 없어도 켤 수 있고, `chartSettings.scale = "percent"`로 저장한다.
  - 비교 종목이 하나라도 있으면 저장된 축과 상관없이 %로 그린다(`settings.ts`의 `shownScale`). 그동안 `로그`, `%`, 탭의 스위치는 꺼지고 이유를 적는다. 비교 종목을 넣어도 저장된 `scale`은 바꾸지 않는다. 모두 지우면 저장된 축(일반, 로그, %)으로 돌아간다.
  - 지표 패널 축은 % 모드로 바꾸지 않는다(목업 초판에서 모든 패널 축이 %로 바뀌던 실수가 있었다). 라이브러리는 가격 패널 축의 옵션을 바꿀 때 차트 단위 `rightPriceScale`에도 합쳐 넣고, 나중에 생기는 pane은 그 값을 물려받는다(5.2.1). 그래서 % 또는 로그 축인 칸을 열면 지표 패널이 그 축으로 생겼다(#76에서 찾음). 지표 층은 패널 시리즈를 만들 때마다 그 축을 `PriceScaleMode.Normal`로 둔다.
- **시리즈마다의 기준**
  - 라이브러리는 % 모드에서 시리즈마다 **자기** 데이터의 왼쪽 끝 점을 0%로 잡는다(5.2.1 `Series.firstValue()`). 주 시리즈와 비교 종목에는 이것이 맞다. 비교 종목의 0%는 그 종목 자신의 왼쪽 끝 종가다.
  - 가격 패널 지표 선은 그대로 두면 봉에서 떨어진다. 2026-11-10 측정에서 종가 209.13과 20봉 이동평균 187.40이 둘 다 0% 높이에 그려졌다. 볼린저 밴드는 세 선이 왼쪽 끝에서 한 점으로 모인다. 그래서 가격 패널 지표 선은 점마다 같은 시각의 주 시리즈 종가를 든 사용자 정의 시리즈로 그린다(§5.7).
  - 드로잉은 주 시리즈의 `priceToCoordinate`로 그리므로 % 축에서도 봉에 붙어 있다(§3.5, `e2e/compare.spec.ts`).
- **그리기**: 비교 종목 선은 굵기 2, `--cmp-n` 색이다. 색은 저장 목록의 순서로 정한다. 마지막 값 라벨(%)을 축에 보인다.
- **데이터와 구독**: `chart/compare.ts`의 `CompareLayer`가 맡는다. 비교 종목마다 `BarFeed` 하나로 `subscribe`와 `GET /api/bars`를 따로 한다.
  - 서버에서는 칸 구독과 같은 `Holder::Cell`이고 순위도 칸 순위다(backend.md §5.3). 서버 코드는 바뀌지 않았다. 4칸이면 구독은 최대 16개다.
  - 빼면 `unsubscribe`를 보내고, 서버가 지금 규칙대로 30초 뒤 해지한다. 봉 주기를 바꾸면 옛 구독을 풀고 새로 잡는다.
  - 거래소: 지수면 없다. 주식이면 칸이 그리는 거래소가 KRX이거나 주 종목이 지수일 때 `krx`, 그 밖에는 `combined`다. 종목 정보 없이 정해지고, 주 종목과 시간대가 맞는다.
- **시각 맞추기**
  - 비교 종목 점은 주 시리즈에 있는 봉 시각에만 둔다(`alignToMain`). 시간축은 모든 시리즈 시각의 합집합이다. 그런데 컨트롤러는 논리 번호를 주 봉 번호로 쓴다(범례의 `hoverIndex`, 과거 페이지 조건, 범위 밀기). 비교 종목이 다른 시각을 넣으면 이 번호가 어긋난다.
  - 그래서 비교 시리즈에는 주 시리즈에 없는 시각이 잠깐도 들지 않게 한다. 그리는 때는 둘뿐이다. 주 시리즈를 `setData`한 직후(`realign`)와, 같은 프레임에서 주 시리즈의 대기 봉을 그린 뒤(`flush`)다.
  - 주 종목이 거래하지 않은 시각(거래정지일, 체결 없던 분)의 비교 봉은 그리지 않는다. 대신 비교 종목을 넣어도 주 차트의 봉 간격과 드로잉 자리가 바뀌지 않는다.
- **비교 종목의 과거**
  - 보이는 왼쪽 끝 봉보다 비교 종목의 첫 봉이 늦으면 과거 페이지를 하나씩 잇는다. 주 시리즈가 받아 둔 과거 전체가 아니라 보이는 왼쪽 끝을 본다. 그 끝이 % 기준이 틀어지는 자리이기 때문이다.
  - 키움 조회 비용 때문에 덮기 시도 한 번에 최대 20페이지다(`MAX_COVER_PAGES`, #76 코디네이터 결정). 못 덮으면 멈추고 범례 줄에 `% 기준: 첫 받은 봉`을 붙인다. 스크롤로 왼쪽 끝 봉이 바뀌면 다시 시도한다. 더 받을 과거가 없을 때(상장이 늦은 종목)도 같은 꼬리표다.
- **실패**: 최신 페이지를 받지 못하면 그 줄을 흐리게 하고 `받지 못함`을 붙인다. 목록에 없는 종목이면 `찾을 수 없음`이다(§3.7a). 칸 오류로 올리지 않는다. 칸의 `다시 시도`, 새 `hello`, 봉 주기 변경 때 다시 받는다. 구독이 거절되면(`sub_error`) `실시간 아님`을 붙인다.

### 3.5 드로잉 (#6~)

**흐름**

1. **도구 고르기**: 왼쪽 도구나 단축키로 고른다. 커서가 십자로 바뀐다. 도구는 21개이고 도구별 명세는 `drawing-proposal.md` §2에 있다. #6 엔진 PR은 추세선과 수평선을 넣고, 나머지는 도구 묶음 PR이 더한다.
2. **점 찍기**
   - 두 점 도구(추세선, 사각형, 피보나치 되돌림)는 누르고 끌어 놓아도 되고, 두 번 클릭해도 된다.
   - 한 점 도구(수평선, 수직선, 텍스트)는 한 번 누르면 된다.
   - 세 점 도구는 세 번 클릭한다. 경로는 클릭마다 점을 더하고 더블클릭이나 `Esc`로 끝낸다. 붓은 누르는 동안 점을 모으고 놓으면 끝낸다. 이 상태 기계는 엔진이 맡고 도구는 `Placement`만 낸다.
   - 텍스트는 찍은 자리에 입력칸이 뜬다. `Enter`로 확정하고 `Esc`로 취소한다.
3. **끝내기**
   - 다 그리면 선택 도구로 돌아가고, 방금 그린 드로잉이 골라진 상태가 된다.
   - 도구를 더블클릭하면 그 도구가 잠겨 계속 그린다. `Esc`로 푼다.
4. **자석 모드**(기본 켬)
   - 점을 찍을 때 마우스 x에 가장 가까운 봉으로 시각을 붙인다.
   - 가격은 그 봉의 시·고·저·종 중 마우스 y에 가장 가까운 값에 붙는다(#6).
   - 세기는 둘이다. **약**(기본)은 화면 거리 16px 안일 때만 붙고, 그보다 멀면 마우스 위치 그대로 둔다. **강**은 거리와 상관없이 붙는다(`Shift+G`, drawing-proposal §3.4).
   - 붙을 자리에 작은 원을 미리 보인다.

**선택·이동·삭제**
- **고르기**: 선에서 6px 안을 누르면 고른다. 핸들은 지름 8px, 판정 반경 6px다. 핸들, 선, 채운 안쪽 순으로 잡고 같은 종류에서는 `z`가 큰 것이 이긴다. `Ctrl`+클릭으로 여러 개를 고르고 `Ctrl`+빈 곳 끌기로 상자를 그린다.
- **옮기기**: 수평선처럼 가격만 쓰는 점은 저장 시각을 보존하고 가격 축으로 옮긴다. 시간과 가격을 모두 쓰는 도구는 현재 받은 이력보다 오래된 점을 임의로 화면 안으로 옮기지 않는다. 몸통을 끌면 고른 드로잉들이 함께 옮겨지고, 핸들을 끌면 그 점만 옮겨진다. 옮길 때도 자석이 적용된다. `Shift`+몸통 끌기는 처음 8px 방향으로 수평·수직을 정하고, `Shift`+핸들은 화면 45°로 맞춘다.
- **막대**: 공통 스타일 칸과 설정, 잠금, 지우기, 더 보기를 둔다. 선택 영역 위 14px, 위쪽 여백이 부족하면 아래 14px에 놓고 칸 안으로 제한한다. 끌어서 옮긴 자리는 탭 메모리에 둔다. 오른쪽 클릭 메뉴도 같은 행동을 쓴다. 알림과 템플릿은 후속 PR에서 더한다.
- **설정·개체**: 설정 창의 미리보기는 서버에 쓰지 않고 `확인` 때 한 번 저장한다. `취소`는 초안을 버린다. 좌표는 한국 시각·가격으로 편집한다. 가격 전용 점의 숨긴 시각은 날짜로 변환하지 않는다. 달력 입력으로 표시할 수 없는 유효 시각은 원래 정수 Unix 초로 편집하며, 빈 값·잘못된 날짜·안전한 정수 범위 밖 입력은 초안을 바꾸지 않는다. 오른쪽 패널의 개체 탭에서 고르고 숨기고 잠그고 순서를 바꾼다. 글자 입력은 DOM `textarea`이며 한글 조합 중 `Enter`를 확정으로 받지 않는다.
- **지우기**: `Delete`/`Backspace`, 막대의 지우기, 왼쪽 도구의 휴지통 중 하나로 지운다.
- **되돌리기**: `Ctrl+Z`. 기록은 브라우저 메모리에만 둔다(#6, ADR 0003). 새로고침하면 사라진다. 한 번의 동작(여러 개를 함께 옮기기 등)이 기록 한 칸이다. 되돌리기 직전에 지금 값이 기록의 `after`와 내용이 같을 때만 되돌린다. 다르면 다른 탭이 바꾼 것이라 그 칸을 버리고 알린다(drawing-proposal §3.11).

**저장**
- 다 그리거나 옮기기를 끝내는 순간(pointerup) 그 드로잉 하나를 `PUT /api/drawings/:id`로 저장한다.
- 되돌리기도 서버 쪽에서 보면 PUT이나 DELETE다. 지운 것을 되돌리면 같은 id로 다시 PUT한다.

**고정 방식**(W4-29)
- 점은 `DrawingPoint { t, price }`다. 봉 순서가 아니다. `t`는 **진짜 Unix 초**로 저장하고 보낸다. `+32400`은 화면에 넘길 때만 더한다(§5.4).
- **저장값은 찍은 실제 시각이다.**
  - 자석을 쓰면 `t`는 붙은 봉의 시작 시각이다. 일봉이면 그날 00:00 KST, 60분봉이면 그 시간의 정시다.
  - 자석을 끄면 `t`는 마우스 x를 아래 규칙으로 거꾸로 바꾼 시각이다.
  - 다른 봉 주기로 옮겨 가도 `t`를 고치지 않는다.
- **`t` → x 변환**: 지금 봉 주기의 봉 구간 `[시작, 다음 봉 시작)` 목록 위에서 한다. 계산은 모두 진짜 Unix 초로 한다.
  1. **봉 구간 안**(`시작 ≤ t < 시작 + 길이`): 논리 index = `k + (t − 시작) / 길이`. 길이는 그 봉 주기의 실제 길이다. 분봉은 n분, 일봉은 24시간, 주봉은 7일, 월봉은 그달 일수다.
  2. **체결이 없는 틈**(밤, 주말, 휴일, 거래정지): 바로 다음 봉의 시작 자리, 즉 논리 index `k + 1`에 놓는다.
  3. **마지막 봉 뒤**: 고정 초 길이로 외삽하지 않는다. `futureBarStarts`로 실제 봉 경계를 만든 뒤 1·2번을 그대로 적용한다. 월봉이면 다음 달 1일, 주봉이면 다음 월요일이다.
  4. **첫 봉 앞**: 그리지 않는다. 과거 구간의 확정 봉을 더 받으면 나타난다.
  5. 논리 index → x는 엔진이 직접 계산한다. 라이브러리의 `logicalToCoordinate()`는 소수 index에 `0`을 돌려준다(drawing-proposal §6.3). 정수 index `k`의 좌표에 `(logical − k) × barSpacing`을 더한다.
- **보이는 모습**
  - 일봉에서 자석으로 찍은 점(00:00 KST)은 60분봉에서 2번 규칙에 걸린다. 그래서 그날 첫 60분봉(08:00)의 왼쪽 끝에 보인다. 저장값은 여전히 00:00이다.
  - 60분봉에서 14:00에 찍은 점은 일봉에서 그날 봉 안의 `14/24` 자리에 보인다.
  - 이렇게 하면 일봉에서 그은 추세선이 60분봉에서도 같은 날·같은 가격에 놓인다(#6 완료 조건). 두 순간이 8시간 다르다는 사실은 저장값에 그대로 남고, 화면은 체결이 없는 틈을 접어서 보여 줄 뿐이다.

**종목에 붙는다**: 드로잉은 `symbol` 단위로 받는다(`GET /api/drawings?symbol=`). 거래소와 무관하다(ADR 0007). `scope`와 보이는 봉 주기로 칸마다 거른다. 같은 탭의 칸들은 서버 캐시와 안 보낸 쓰기를 공유하며 끄는 동안의 미리보기는 그 칸에만 있다. 다른 칸에는 놓을 때 반영한다. 다른 탭은 현재 창 초점·`visibilitychange`에서 다시 받는다. #4의 `data_changed`로 옮기는 일은 #47이다.

**% 축일 때**(#76): 드로잉은 주 종목의 가격으로 고정한다. 좌표 변환은 주 시리즈의 `priceToCoordinate`가 % 모드를 고려해 해 준다. 일반 축에서 그린 드로잉이 비교 종목을 넣어 % 축이 된 뒤에도 같은 가격의 봉 좌표에 있음을 `e2e/compare.spec.ts`가 본다.

**알려진 한계**: 액면분할 뒤에는 과거 드로잉이 옛 가격에 남는다(#6). 화면에서 따로 알리지 않는다.

### 3.6 칸 동기화 토글 (#7~)

| 동기화 | 위치 | 기본 | 동작 |
|---|---|---|---|
| 십자선 | 위 막대 칩 `십자선` | 켬 | 한 칸에서 십자선을 움직이면 다른 칸은 그 시각의 봉(없으면 직전 봉)의 종가에 십자선을 둔다. 봉 주기가 달라도 맞춘다 |
| 스크롤 | 위 막대 칩 `스크롤` | 켬 | 같은 봉 주기 칸끼리만 보이는 범위를 맞춘다. 봉 주기가 다른 칸은 따라오지 않는다 |
| 종목 연동 | 칸 범례 머리의 꼬리표 | 칸마다 | 꼬리표를 누르면 켜고 끈다. 연동이 켜진 칸끼리는 종목이 같다. 하나를 바꾸면 모두 바뀐다. 봉 주기와 거래소는 따라가지 않는다. 각 칸의 거래소는 §5.3 `setSymbol` 규칙으로 정한다. 그래서 KRX 칸과 NXT 칸을 연동해 두고 종목만 바꿔 볼 수 있다 |

- **연동 그룹**: 백엔드 계약에서 종목 연동은 칸마다 `Cell.symbolLink: boolean`이다. 그래서 그룹은 하나다. 꼬리표는 켜짐이면 호박색 `A`, 꺼짐이면 회색 `·`이다. 여러 그룹은 확장 후보로 남긴다.
- **스크롤 동기화의 기준**
  - 시각 범위(`setVisibleRange`)로 맞춘다. 논리 index로 맞추면 안 된다.
  - 칸마다 받은 과거 구간의 확정 봉 수가 달라 index가 어긋나기 때문이다.
  - 목업은 데이터 길이가 같아 논리 범위로 간단히 했다.
- **저장 위치**(D10): `Layout.sync: { crosshair: boolean; scroll: boolean }`. 둘 다 기본값은 `true`다. 종목 연동은 칸마다 `Cell.symbolLink`에 둔다.

### 3.7 자동 저장 표시 (#3~)

저장 버튼은 없다. 상태 줄의 한 곳에서 저장 상태를 보인다.

| 상태 | 표시 |
|---|---|
| 바뀐 뒤 1초 기다리는 중, 보내는 중 | `저장 중…` (회색) |
| 성공 | `✓ 자동 저장됨 14:32:08` |
| 실패 | `저장하지 못했습니다: 다시 시도` (빨강 아님, 호박색 버튼). 5초·15초·60초 간격으로 다시 시도한다 |

**보내는 단위와 시점**

| 대상 | 요청 | 시점 |
|---|---|---|
| 레이아웃·차트 설정 | `PUT /api/layouts/:id`, 레이아웃 통째 | 마지막 변경 1초 뒤(#3) |
| 드로잉 | 하나씩 `PUT`/`DELETE` | 즉시 |
| 관심종목 | `PUT /api/watchlists`, 모든 목록 통째 | 즉시 |
| 알림 | 하나씩 `PUT` | 만들기 버튼을 누를 때 |

- **저장 순서와 미저장 본문**(R2): 본문마다 `revision`(backend.md §8.2 "저장 순서")을 붙인다. 서버는 저장된 것보다 큰 것만 받으므로 늦게 도착한 옛 요청이 새 요청을 덮지 못한다. 409 `stale_revision`은 더 새 편집이 이미 저장됐다는 뜻이라 저장됨으로 본다.
  - 편집할 때마다, 그리고 보낼 때마다 최신 본문(주소, revision, JSON)을 localStorage `vv.unsaved.<layout|ui|watchlist>`에 동기로 남긴다(`persist/unsaved.ts`). 서버가 그 revision 이상을 가졌다고 확인되면(성공, `stale_revision`, 413) 지운다. 시세가 아닌 화면 설정이라 ADR 0003과 부딪히지 않는다.
  - 다음 시작 때 복원은 자료마다 서버 revision과 미저장 본문의 revision을 비교한다. 미저장 본문이 크면(같은 주소일 때) 그것을 열고 곧바로 다시 저장한다. 작거나 같으면 지운다.
- **탭을 닫을 때**: 보내지 못한 변경이 있으면 `visibilitychange`(hidden)에서 `fetch(..., { keepalive: true })`로 곧바로 보낸다. **앞 요청이 진행 중이어도 보낸다**(순서는 서버의 revision이 지킨다). keepalive는 본문 64KB까지라 큰 레이아웃은 보내지 못할 수 있다. 그래도 미저장 본문이 남아 다음 시작 때 되살린다. 앞 요청이 이미 모든 편집을 담고 있어도 한 번 더 보낸다(탭을 바꿀 때마다 PUT 하나가 겹칠 수 있다). 닫히는 페이지에서는 앞 요청이 끊길 수 있어서다. 어느 요청이든 모든 편집을 담은 것이 성공하면 저장됨이다.
- **다른 탭의 변경**: `data_changed`를 받으면 해당 쿼리를 무효화한다. 지금 편집 중인 레이아웃이 바뀌었으면 덮어쓰지 않는다. 나중에 쓴 쪽이 이긴다는 계약을 따르고, `다른 창에서 이 레이아웃이 바뀌었습니다: 불러오기` 알림만 띄운다.

### 3.7a 오류 표시: `unknown_symbol`과 `payload_too_large`

`ApiError.message`는 사람이 읽는 한국어 문장이다. 화면은 아래 자리에 그 문장을 그대로 쓰고, 앞뒤에 무엇을 할지 붙인다.

**`unknown_symbol`**(#2~): 종목코드가 키움에 없다. 상장 폐지나 코드 변경이 흔한 원인이다.

| 생기는 곳 | 화면 |
|---|---|
| 칸을 열 때(`/api/bars`, 저장된 레이아웃의 칸) | 칸을 비우고 가운데에 `종목 005930을 찾을 수 없습니다. 상장 폐지되었거나 코드가 바뀌었을 수 있습니다.`와 `종목 검색` 버튼을 둔다. 레이아웃의 칸 설정은 지우지 않는다. 다른 종목을 고르면 그때 바뀐다 |
| 구독(`sub_error`, #4~) | 위와 같다 |
| 비교 종목 | 그 비교 종목 선만 그리지 않는다. 범례 줄에 흐린 이름과 `찾을 수 없음`, 지우기 버튼을 남긴다 |
| 관심종목 행 | 이름을 흐리게, 현재가 자리에 `찾을 수 없음`을 적는다. 사용자가 지울 때까지 목록에 남긴다 |
| 주소의 `?symbol=` | 지금 칸은 그대로 두고 화면 아래 알림으로 `주소의 종목 999999를 찾을 수 없습니다`를 6초 띄운다 |
| 주소의 `?venue=`(#14) | 종목이 그 거래소를 허용하지 않으면(지수에 거래소, NXT 불가 종목에 `nxt`, 모르는 값) 통합으로 연다. 지수면 거래소 없이 연다. NXT 불가 종목에 `nxt`를 바랐으면 화면 아래 알림으로 `NXT에서 거래되지 않아 통합으로 엽니다`를 띄운다. 모르는 값은 알림 없이 통합이다. 종목 정보를 받지 못하면(`unknown_symbol` 밖의 실패) NXT 허용을 모르므로 알림 없이 통합으로 연다 |
| 봉 요청의 `bad_request`(#14) | 브라우저가 허용되지 않는 거래소를 보내는 것은 버그다. 칸 오류와 같이 `message`를 칸 가운데에 적고 `다시 시도`를 둔다 |

**`payload_too_large`**(#3~, 413): `chartSettings`·`UiState`·드로잉 `style`이 64KB를 넘었다.
- **미리 막는다**: 자동 저장은 보내기 전에 본문의 바이트 수(`TextEncoder`)를 잰다. 64KB를 넘으면 보내지 않고 바로 아래 실패 상태로 간다. 413은 이 검사가 놓친 경우의 마지막 방어다.
- **자동 저장 표시**(§3.7)를 실패 상태로 바꾸고 문구를 `저장하지 못했습니다: 설정이 64KB를 넘습니다`로 쓴다. 다시 시도 버튼은 두지 않는다. 같은 내용을 다시 보내도 같은 결과이기 때문이다. 자동 재시도도 하지 않는다.
- **무엇을 줄일지 알린다**: 레이아웃이면 `지표나 비교 종목을 줄이세요`, `UiState`면 `최근 본 종목 기록을 지웠습니다`(프런트가 줄일 수 있는 것은 스스로 줄이고 한 번 다시 보낸다), 드로잉이면 그 드로잉의 막대에 `텍스트가 너무 깁니다`를 적는다.
- 화면의 변경은 버리지 않는다. 브라우저 메모리에 남아 있고, 줄여서 64KB 아래가 되면 다음 자동 저장에 함께 간다.

| 가격 알림 | 조건 `위로 넘어설 때`/`아래로 내려설 때` → `{ kind: "price", op: "gte"/"lte", target }`. 지금 가격(현재가)을 옆에 보인다 |
| 지표 알림: 지표 | 이 칸의 지표와 그 선을 목록으로 보이고 하나를 고른다(MACD의 `macd`/`signal`/`histogram`). `LineRef { spec, line }` |
| 지표 알림: 조건 | `상향 돌파`/`하향 돌파`(값) → `crossValue`. `다른 지표와 교차` → 두 번째 지표 선택칸이 나타나고 `crossLine` |
| 지표 알림: 봉 주기 | 칸의 봉 주기. 바꿀 수 있다 |
| 반복 | `한 번 울리면 끄기`(기본, `once`) / `매번 울리기`(`every`) |
| 받을 곳 | `텔레그램`, `화면 안 알림`(둘 다 기본 켬) |

- **가격 알림은 새로 넘어설 때 울린다**(U2, 용어집 "가격 알림")
  - 조건 이름부터 `이상`이 아니라 `위로 넘어설 때`/`아래로 내려설 때`로 쓴다. 지금 그 쪽에 있다는 뜻으로 읽히지 않게 하려는 것이다.
  - 값을 입력할 때마다 현재가와 비교한다. 이미 넘어 있으면 값 입력칸 바로 아래에 호박색 안내를 띄운다. 예(`gte`, 값 85,000, 현재가 85,400): `지금 가격 85,400이 이미 85,000 이상입니다. 85,000 아래로 내려갔다가 다시 넘어설 때 울립니다.`
  - 막지는 않는다. 그대로 만들 수 있다. 주 버튼 문구도 그대로 `알림 만들기`다.
  - 현재가가 없으면(장 닫힘에 실시간 값이 아직 없음) 마지막 확정 봉의 종가와 비교하고, 안내 끝에 `(마지막 종가 기준)`을 붙인다.
  - **기존 가격 알림을 편집할 때의 비교 기준**(`Alert.priceReference`, 읽기 전용)
    - 알림이 켜져 있고 `priceReference`가 `null`이 아니면 현재가 대신 이 값과 비교한다. 서버가 실제로 다음 체결과 견줄 직전 기준 가격이 이것이기 때문이다. 안내 문구도 `서버 기준 가격 85,400이 이미 …`로 바꾼다.
    - `priceReference`가 `null`이면(서버가 그 종목 가격을 아직 모름) 현재가로 비교한다. 이때 안내 끝에 `(서버는 다음 첫 체결을 기준으로 삼습니다)`를 붙인다.
    - 꺼진 알림을 편집하거나 다시 켜는 경우는 현재가로 비교한다. 서버가 다시 켜는 순간의 현재가에서 기준을 새로 시작하기 때문이다(백엔드 §7.2).
    - `priceReference`는 PUT 본문에 넣지 않는다.
- **이동된 선은 고를 수 없다**(D8)
  - 이동량(`shift`)이 0이 아닌 선, 곧 일목균형표의 선행스팬 A·B와 후행스팬은 목록에 비활성으로 보인다.
  - 줄 끝에 이유를 적는다: `앞뒤로 옮겨 그린 선은 알림에 쓸 수 없습니다`. 마우스를 올리거나 초점이 오면 같은 문장을 `aria-describedby`로 읽힌다.
  - 전환선·기준선은 이동량이 0이라 고를 수 있다.
  - 어떤 선이 이동된 선인지는 WASM 엔진의 `shift(index)`로 판단한다. 지표 종류 이름으로 정해 두지 않는다.
- **안내문**: 대화상자 아래에 다음을 늘 보인다. 헛알림이 없다는 것과, 화면 값과 판단 값이 조금 다를 수 있다는 것을 사용자가 미리 알게 하려는 것이다.
  - 지표 알림: `봉이 확정될 때만 판단합니다. 봉 중간에 잠깐 넘었다 내려오면 울리지 않습니다.`
  - 지표 알림(EMA 계열, D7): `RSI·MACD·지수 이동평균은 서버가 최근 확정 봉 500개 이상으로 다시 계산해 판단합니다. 화면 값과 소수점 아래가 조금 다를 수 있습니다.`
  - 가격 알림: `체결이 들어오는 즉시 판단합니다.`
- **서버 거절**: 서버가 `bad_request`를 돌려주면(spec과 선의 조합이 틀림 등, D6) `message`를 대화상자 바닥에 그대로 적는다.
- **화면 안 알림**
  - `alert_fired`를 받으면 오른쪽 아래에 6초 동안 띄운다. 문구는 `AlertEvent.message` 그대로다.
  - 누르면 그 종목을 활성 칸에 연다.
- **알림 목록과 울린 기록**(D9)
  - 위 막대 `알림` 버튼 옆 메뉴의 서랍으로 연다. 위에는 알림 목록(켜기·끄기, 지우기), 아래에는 울린 기록이 있다.
  - 울린 기록 한 줄: 울린 시각, 종목, 문구, 판단한 봉의 시작 시각, **봉 출처**.
  - 판단한 봉의 시작 시각은 `AlertEvent.barT`, 봉 출처는 `AlertEvent.barSource`다(백엔드 §8.2).
  - `barSource`는 `"realtime"`이면 `실시간으로 만든 봉`, `"kiwoom"`이면 `키움에서 조회한 봉`으로 적는다(용어집 "봉 출처"). `"realtime"`인 지표 알림이면 줄 끝에 `나중에 조회 값으로 바뀔 수 있음`을 흐린 글자로 붙인다.
  - 가격 알림의 `barT`는 그 체결이 속한 1분 구간의 시작이고 `barSource`는 언제나 `"realtime"`이다(D13). 가격 알림 줄은 봉 시각 대신 `1분 구간 14:32`로 적고, `나중에 …` 꼬리는 붙이지 않는다. 체결로 판단했으므로 바뀔 봉이 없다.
  - 나중에 봉 출처가 바뀌거나 끊긴 구간이 메워져도 기록은 고치지 않는다. 서버도 정정하거나 다시 울리지 않는다(D9). 화면은 기록 그대로를 보인다.
- **경고**: `warning: "realtime_limit"`인 알림은 목록에서 호박색 경고 아이콘과 이유를 보인다.

**되는 것**
- **1칸**: 칸 배치 선택과 동기화 토글은 없다.
- **차트 이미지**(#38): 머리 첫 줄의 테마 버튼 앞 카메라 버튼으로 PNG를 내려받는다. 클립보드 복사는 두지 않는다.
- **검색**: 아래 탭의 `검색`. 화면 아래에서 올라오는 시트로 같은 검색을 연다. 초성 검색도 된다. 칩 위의 머리줄 종목 이름을 눌러도 열린다.
- **관심종목**
  - 아래 탭의 `관심종목`을 누르면 전체 화면 목록이 된다. 행을 누르면 그 종목으로 차트 탭에 돌아온다.
  - 행 높이는 44px 이상이다.
  - 순서 바꾸기, 추가, 삭제는 할 수 있다. 길게 눌러 끌기, 왼쪽으로 밀어 삭제다.

- **봉 주기 전환**: 칩 여섯 개(5분, 15분, 60분, 일, 주, 월)를 둔다. 1·3·30분은 칩을 길게 누르거나 상황 메뉴 키로 여는 메뉴에 둔다(D11에서 확정). 칩을 늘리지 않는다. 다만 메뉴로 고른 1·3·30분을 보는 동안에는 지금 주기를 알 수 있게 그 칩을 맨 앞에 하나 더 보인다. #2의 칩은 일·주·월 셋이고(`PeriodChips`, 높이 36px), 분봉 칩은 #14에서 켠다.

  - 칩 줄 끝의 지표 버튼으로 시트를 연다. 이 칸 지표들을 켜고 끄며, 지표 종류를 기본값으로 추가하거나 지운다.
  - 설정값 편집은 데스크톱에서 한다. 휴대폰은 "보기 위주"이므로 입력 폼을 줄인다.
- **실시간 갱신**: 데스크톱과 같은 구독과 컨트롤러를 쓴다.

**되지 않는 것**
- **드로잉 편집**
  - 드로잉 primitive를 `editable: false`로 붙인다. 손가락 조작은 모두 차트 이동과 확대에 쓴다.
  - 차트 왼쪽 아래에 `드로잉 보기 전용` 꼬리표를 둔다. 드로잉이 그 종목에 하나 이상 있을 때만 보인다.
- **레이아웃(여러 칸)**: 없다.

**조작**: 끌어 이동, 두 손가락으로 확대, 길게 눌러 십자선, 십자선이 있을 때 탭하면 해제. Lightweight Charts의 기본 터치 처리를 그대로 쓴다.

**휴대폰 차트 상태의 저장 위치**
- 휴대폰에서 종목을 바꿀 때마다 데스크톱 레이아웃의 칸이 바뀌면 안 된다.
- 그래서 휴대폰 칸 하나의 상태 `{ symbol, venue, period, chartSettings }`를 `UiState.phone`에 따로 둔다. `venue`는 `Cell.venue`와 같은 규칙이다(지수면 `null`). 서버는 모르는 키를 버리지 않고 왕복시키며, `UiState` 전체는 64KB 제한을 받는다(D10). 지표 수십 개를 넣어도 넘지 않는다.
- 처음에는 마지막 레이아웃의 첫 칸에서 복사한다.

**머리줄**: 범례의 머리줄과 가격줄은 휴대폰 머리로 올라간다. 칸 안 범례에는 OHLCV 줄과 지표 줄만 남는다.

**종목을 바꿀 때의 거래소**(#14, ADR 0007): `setSymbol`이 정한다. 규칙은 셋이다.

1. 새 종목이 지수면 `venue = null`이다.
2. 새 종목이 주식이고 지금 거래소가 있으면, 그 종목이 허용할 때 유지하고 아니면 `combined`다. 허용되지 않는 것은 `nxtEnabled = false`인 종목의 `nxt` 하나뿐이다.
3. 지수에서 주식으로 오면(`venue`가 `null`이었으면) `combined`다.

```ts
function venueFor(prev: Venue | null, next: SymbolInfo): Venue | null {
  if (next.kind === "index") return null;
  if (prev === null) return "combined";
  return prev === "nxt" && !next.nxtEnabled ? "combined" : prev;
}
```

- 이 함수 하나를 검색(§3.1), 주소(§5.1), 종목 연동(§3.6, #7), 휴대폰(§4)이 함께 쓴다.
- 주소처럼 거래소를 직접 받는 경로는 받은 값을 `venueFor`의 `prev` 자리에 넣는다. 결과가 받은 값과 다르면 알린다(§3.7a).

- **드로잉 자체를 두는 곳**: 서버 확정본은 TanStack Query 캐시(`["drawings", symbol]`)다. `drawings/sync.ts`만 캐시·요청 줄·기록을 쓴다. 읽을 때 확정본 위에 안 보낸 쓰기와 설정 초안을 얹는다. 이 합친 값은 다시 저장하지 않는다.
- **조회와 ACK**: ACK는 진행 중인 종목 목록 조회가 끝나기를 기다리고, 그동안 새 조회가 시작됐으면 그것도 기다린다. ACK가 최초 목록 조회를 취소하지 않는다. PUT 응답은 이미 확인한 더 큰 revision을 덮지 않는다. 최초 조회 실패 뒤 저장이 성공해도 목록 오류와 다시 시도는 남는다.
- **저장 순서와 복구**: id마다 PUT·DELETE 요청 하나만 보낸다. 기다리는 편집은 최신 하나로 모은다. `revision`은 새 편집에서 한 번 정하고 재시도·새로고침 복구에서도 보존한다. 서버의 409는 그 본문을 버리고 다시 받는다. 상태 줄은 다른 사용자 자료의 자동 저장과 드로잉 요청 줄을 함께 보여 준다.
- **복구 의도의 수명**: 낙관적 화면 반영 전에 `journal.ts`가 UUID별 완전한 pending 기록을 `vv.unsaved.drawing-intent.<uuid>`에 동기 저장한다. intent 순서와 PUT revision은 편집에서 한 번 예약하고 재시도·복구에서도 보존한다. 잠금을 기다리다 닫혀도 고유 pending으로 복구하며, 제거된 UUID를 다시 만들지 않는다. 공유 승인 기록의 비교·수정·정리는 `vv.drawing.journal.<id>` Web Lock 안에서만 한다.
- **완료 기록**: 같은 id의 마지막 완료 order·UUID와 별도 revision 최대값 한 기록을 `vv.drawing.completed.<id>`에 단조 갱신한다. 이 쓰기가 성공한 뒤에만 오래된 pending부터 정리하고, 자기 UUID의 공유 기록만 지운다. 삭제한 id도 완료 기록을 만료 없이 남긴다. pending이 모두 사라진 뒤 늦게 처음 게시된 옛 의도도 이 근거로 거절한다. 다른 id의 완료는 해당 편집을 취소하지 않는다.
- **Storage와 실패**: 중단된 동기 작업의 Storage 읽기는 다른 문서가 완료한 최신 값을 못 볼 수 있다. 동기 예약 때 최신값을 읽었다고 가정하지 않고, 잠금의 비동기 승인·복구·최종 전송 확인에서 남아 있는 같은 id의 완료 기록을 확인한다. 더 큰 완료 순서 이하의 의도는 보내지 않으며 예약값을 새 시각으로 바꾸지 않는다. 완료 기록 쓰기·읽기·정리, 잘못된 메타데이터, Web Locks 실패는 저장 실패로 표시한다. 완료 기록 저장 실패 전에 복구할 작업을 지우거나, 용량 압박·TTL을 이유로 완료 근거를 버리거나, 무잠금 쓰기로 우회하지 않는다.
- **전송과 버전 경계**: 마지막 유효성 확인부터 native fetch 시작까지 같은 짧은 per-id 잠금에서 실행하고 callback은 즉시 반환한다. HTTP 응답·목록 조회는 잠금 밖에서 기다린다. 이미 시작한 옛 PUT이 DELETE 뒤 도착하는 서버 묘비 생략의 한계는 그대로다. 새 보장은 구버전 드로잉 문서를 모두 종료하고 새 버전으로 다시 연 뒤부터 적용한다. 실행 중인 구버전은 새 완료 규칙을 모르며 이미 지워진 과거 완료 근거도 복원할 수 없다. v1 이관은 per-id 잠금 안에서 정확한 기존 값과 최신 의도를 다시 확인하고 예약된 PUT revision을 보존한다. 고유 stage가 없는 v2 공유 기록을 복구 과정에서 다시 게시하지 않는다.

- **드로잉 환경**: `UiState.drawing`은 자석 켬·세기, 연속 그리기, 전체 잠금·숨김, 도구별 마지막 스타일, 지표 자석 여부, 새 범위를 담는다. `ui` 스토어의 기존 자동 저장을 쓰며 `watchColumns`와 `activeWatchlistId`를 함께 보존한다.
- **컨트롤러가 스토어를 읽는 법**: 컨트롤러는 `useLayoutStore.subscribe(selector, …)`로 자기 칸의 설정만 지켜본다. React를 거치지 않는다.

- 컨트롤러는 봉 열을 바꿀 때마다 칸의 차트 요소에 `data-bar-count`, `data-first-bar-t`, `data-last-bar-t`를 쓴다. 브라우저 e2e(`web/e2e/`)는 캔버스 픽셀 대신 이 값으로 그린 봉을 확인한다.
- 봉 받기와 세대는 `chart/barFeed.ts`의 `BarFeed`가 맡는다. 컨트롤러는 `BarFeed`가 알려 주는 `reset`, `prepended`, `failed`, `olderFailed`를 받아 그린다.

**React와의 경계**
- `features/grid/ChartCell.tsx`는 `useEffect`로 컨트롤러를 만들고, 칸 설정이 바뀌면 `apply`만 부른다.
- 이 컴포넌트는 봉 데이터를 props로 받지 않는다.
- 범례와 지표 패널 범례의 DOM도 컨트롤러가 만들고 고친다(§2.3).
- `ChartCell`은 컨트롤러를 `features/grid/controllers.ts`에 칸 번호로 등록한다. 위 막대, 휴대폰 머리, 단축키는 이 등록표로 활성 칸의 컨트롤러를 찾아 `snapshot`을 부른다(#38).
- `useDrawingSurface`는 `ChartController.attach`로 드로잉을 붙인다. 주 시리즈가 바뀌면 컨트롤러가 확장에 `reattach`를 알리고, 컨트롤러를 지우기 전에 확장을 정리한다. 확장은 `ChartHost`의 시리즈·봉·현재 칸 getter를 읽는다. `BarFeed`는 드로잉을 모른다.
- `interaction.ts`는 첫 끌기로 정한 두 점을 유지해 3점 도구의 셋째 클릭을 기다린다. 세 번 클릭하는 입력도 같은 점을 만든다.
- freehand의 입력 보관 한도는 4,096점이다. 한도에 닿으면 내부 점을 순서대로 줄이고 이후 입력을 계속 받아 첫 점과 최신 끝점을 보존한다. 도구의 `finalize`는 이 입력을 받고, 저장 한도 1,000점은 그 결과에 적용한다. 저장 한도로 다시 줄여도 양 끝점을 보존한다. 유효한 최소 점 수가 남지 않으면 만들지 않는다.
- `textLayout.ts`는 글꼴·줄바꿈·폭 제한·정렬·여백·회전을 계산하는 순수 함수다. `DrawingLayer`가 실제 canvas 글자 치수로 개체·미리보기·임시 도형의 레이아웃을 준비한다. 그리기·클릭 판정·상자 선택·선택 영역은 같은 레이아웃을 읽고, 글꼴 로드가 끝나면 함께 갱신한다. geometry에는 브라우저 측정을 넣지 않는다.
- `ToolContext.timeAt`과 `priceAt`은 각 축의 독립 역변환이며 `anchor.ts`가 제공한다.
- 도구 묶음은 `drawings/tools/<id>.ts`의 순수 `ToolSpec`과 테스트를 만들고 `tools/index.ts`에 한 줄만 더한다. 그리기·판정·설정 입력칸·배치 상태 기계는 엔진이 맡는다. `Shape`, `StyleField`, `Placement`, `ToolContext`의 새 종류가 필요하면 코디네이터에게 엔진 변경을 청한다.

**차트 이미지**(#38)
- `chart.takeScreenshot(true, false)`로 primitive까지 찍고 십자선은 뺀다. 지표 선과 드로잉 primitive는 따로 손대지 않아도 찍힌다.
- 범례는 DOM이라 찍히지 않는다. 그래서 `chart/snapshot.ts`의 `composeSnapshot`이 그림 위에 머리 띠를 붙여 다시 그린다. 첫 줄은 종목 이름, 코드, 거래소, 봉 주기, 오른쪽 끝에 찍은 한국 시각이다. 둘째 줄은 마지막 봉의 범례(종가, 등락, 봉 시각, 시고저종량)다. 폭이 모자라면 다음 줄로 넘긴다. 종목 이름이 시각 앞에 들어가지 않으면 첫 줄에는 시각만 두고 이름부터 다음 줄에 둔다. 한 줄 폭보다 긴 글자는 끝을 `…`로 줄인다.
- 그림 아래 18px 띠의 오른쪽 끝에 상태 줄과 같은 문구 `Charts by TradingView Lightweight Charts™`를 작게 그린다(§5.7 표기 의무, 문구는 `CHART_CREDIT` 하나를 같이 쓴다). 글자는 `chart/legend.ts`의 `legendParts`를 화면 범례와 같이 쓴다.
- 파일 이름은 `005930_krx_5m_20261109-1432.png`처럼 종목, 거래소, 봉 주기, 한국 시각이다. 지수는 거래소를 빼고 `IDX-001`처럼 콜론을 바꾼다.
- 지표 패널 범례(#5)가 생기면 머리 띠에 그 줄을 더한다.

**시리즈 세대**(D1)
- 봉 받기(`BarFeed`)마다 `generation: number`를 둔다. 주 종목과 비교 종목은 각자의 `BarFeed`를 갖는다(#76). 비교 종목은 봉 주기가 바뀔 때, 그 종목의 거래소가 바뀔 때, 새 `hello` 때 세대를 올린다. 주 종목만 바뀌면 비교 종목은 키가 그대로라 다시 받지 않는다. 칸의 `reload`는 받지 못한 비교 종목만 다시 받는다.
- 세대를 올리는 때: 종목·거래소·봉 주기가 바뀔 때, `reload`를 받을 때, 브라우저↔서버 WebSocket이 다시 연결될 때(새 `hello`).
- REST 요청, 워커 요청은 보낼 때의 세대를 들고 간다. 응답이 왔을 때 세대가 지금과 다르면 버린다. 과거 페이지 요청도, WASM 결과도 같다.

**데이터 흐름**(한 칸. D1의 처리 순서)

```
apply(symbol, venue, period)  또는  reload  또는  새 hello ── generation += 1, 시리즈와 엔진을 비운다
  1. socket.subscribe(sub, symbol, venue, period)           (#4~. #2·#14·#3에는 1·2·4가 없다)
  2. 그 sub의 메시지(subscribed/bar/confirmed/reload)를 버퍼에 쌓는다. 메시지마다 seq가 있다
  3. GET /api/bars?symbol=&venue=&period= (최신 페이지) → page.bars + page.current, page.seq
     (지수면 venue를 빼고 보낸다. BarsQuery.venue)
     → series.setData(page.bars + page.current)             ← 세대마다 한 번만 setData
     → indicators.create(spec들, 확정 봉 열)                 (#5~)
  4. 버퍼에서 seq > page.seq 인 메시지만 seq 순서로 적용, 나머지는 버린다
     (page.seq가 null이면 버퍼를 모두 적용한다)
     이 세대 동안 뒤에 오는 메시지도 seq <= page.seq면 버린다(HTTP와 WS는 다른 연결이라 옛 메시지가 늦게 온다)
  이후 WebSocket, 칸마다 하나의 처리 줄(queue)에서 도착 순서대로:
     bar        → series.update(bar)                        ← React 렌더 없음
                  indicators.preview(bar) → 지표 선 마지막 점 갱신
                  범례가 마지막 봉을 보고 있으면 범례 DOM 갱신
     confirmed  → series.update(bar)
                  tail = indicators.confirm(bar)            (W4-25, D13: pushConfirmed의 반환값)
                  → 엔진은 이미 이 봉을 커밋했다. 지표 선과 범례를 tail로 갱신한다
     reload     → 세대를 올리고 1~4를 처음부터(구독은 유지하므로 1은 건너뛴다)
과거로 스크롤(subscribeVisibleLogicalRangeChange, 왼쪽 끝이 50봉 안으로 들어오면)
  └─ GET /api/bars?before=nextBefore (symbol, venue, period는 최신 페이지와 같다)
     → 과거 구간의 확정 봉만 담긴다. 이미 가진 봉보다 늦은 t는 덮어쓰지 않는다(D1)
     → 앞에 붙여 setData, 보이는 범위 유지
     → indicators.create로 엔진을 다시 만든다(EMA 계열은 앞이 바뀌면 덧붙일 수 없다: 백엔드 §9.2)
  └─ nextBefore가 null이면 더 받지 않는다. 분봉이면 왼쪽 끝에 안내(U1)
```

- **확정 순간의 지표 값**(W4-25)
  - 서버는 확정 직전의 `bar`를 건너뛰고 `confirmed`만 보낼 수 있다. 그래서 확정 봉의 지표 값은 반드시 `confirmed`의 봉으로 다시 계산해 그린다.
  - 워커의 `confirm(key, bar)`는 WASM의 `pushConfirmed(bar)` 하나만 부른다. 이 함수가 상태를 커밋하고 확정 순간의 최종 값(`Tail`, 선 순서대로의 `Float64Array`)을 돌려준다(백엔드 §9.2·§9.4, D13). 워커는 그 값을 그대로 메인 스레드에 보낸다. `preview`는 부르지 않는다. `pushConfirmed`와 `preview`는 마지막 확정 시각 이하의 봉이나 NaN·무한 가격을 받으면 상태를 바꾸지 않고 던진다(백엔드 §9.1).
  - 그다음에 오는 `bar`는 새 현재 봉이다.
- **처리 순서와 그리기 묶기**
  - 계산과 상태 변경(`confirmed`, `reload`, `bar`의 `preview`)은 칸마다 하나의 처리 줄에서 도착 순서대로 한다. 건너뛰거나 합치지 않는다.
  - 그리기만 `requestAnimationFrame` 한 번에 묶는다. 같은 프레임에 같은 시리즈의 `update`가 여럿이면 마지막 값만 그린다. 서버가 구독당 초당 10회로 줄여 보내지만, 4칸에 비교 종목까지 열면 초당 100회가 넘을 수 있다.
  - 예외는 테마 변경 하나다. `setTheme`은 프레임을 기다리지 않고 대기 중인 봉을 `flushPendingDraw`로 먼저 주 시리즈에, 대기 중인 지표 점을 `indicators.flush()`로 지표 시리즈에 그린 뒤 색을 바꾼다(#58, 2026-11-10 확인. 그때는 거래량 시리즈였고 #75에서 거래량이 지표가 되었다). 시리즈만 최신 `bars`로 바꾸면 보류된 프레임이 지나간 봉을 `update`하다 `Cannot update oldest data`를 던지고, 그 뒤 프레임마다 같은 예외가 반복된다. 예약된 프레임은 빈 큐를 보고 범례만 갱신한다.
- **브라우저 재연결**(D2)
  - 브라우저와 서버의 WebSocket이 다시 연결되면(새 `hello`) 칸마다 세대를 올리고 시리즈·지표 엔진을 **모두 비운 뒤 최신 페이지부터 다시 만든다**.
  - 첫 `hello`도 같다(#4). 연결 전에 생긴 칸은 서버가 구독을 알기 전에 최신 페이지를 받았을 수 있어서다. 칸마다 최신 페이지 조회가 한 번 더 늘 수 있다.
  - 새 페이지가 올 때까지는 가진 봉을 그대로 둔다. 데이터는 처음부터 다시 만들되 빈 화면이 깜빡이지 않게 하려는 것이다.
  - 연결 하나는 `api/socket.ts`의 `MarketSocket`이 맡는다(탭에 하나, `stores/realtime.ts`). 끊기면 1·2·5·10초, 그 뒤 10초마다 다시 붙는다.
  - 과거로 스크롤해 받아 둔 구간은 버린다. 보이는 범위는 최신 쪽으로 돌아간다. 드로잉은 따로 저장되므로 영향이 없다.
  - "`confirmed`를 빠짐없이 보낸다"는 보장은 연결이 살아 있는 동안에만 적용되기 때문이다.
- **분봉은 최근 1년까지**(U1, ADR 0003)
  - 분봉에서 과거로 스크롤하다 `nextBefore`가 `null`이 되면 `분봉은 최근 1년까지 볼 수 있습니다. 더 과거는 일봉으로 보세요` 꼬리표를 띄운다(#14). 자리는 칸 왼쪽 가운데다. 왼쪽 위는 범례가 차지하고, 과거 봉 오류 안내와 같은 자리다. 1년의 끝은 서버가 정한다. 브라우저는 날짜를 계산하지 않고 `nextBefore = null`만 본다. 꼬리표의 `일봉으로 보기`를 누르면 활성 칸의 봉 주기가 일봉으로 바뀐다.
  - 일·주·월봉에서 `null`이면 상장 이후 첫 봉이라 따로 알리지 않는다. NXT 일·주·월봉은 2025-03(NXT 시작)에서 끝나는데, 이것도 따로 알리지 않는다.
- **과거 페이지를 받지 못했을 때**
  - 가진 봉은 그대로 둔다. 가격 패널 왼쪽 끝에 `과거 봉을 받지 못했습니다.`와 `ApiError.message`를 꼬리표로 띄운다(`role="alert"`).
  - 실패한 뒤에는 스크롤해도 과거 페이지를 다시 보내지 않는다. `manualActionRequired`이면 운영자가 고쳐야 하므로 버튼을 두지 않는다. 그 밖의 오류는 `다시 시도` 버튼을 둔다(칸 오류의 §3.7a 판정과 같다).
  - 종목·거래소·봉 주기를 바꾸거나 칸을 다시 열면 꼬리표를 걷는다.
- **#2·#14·#3의 흐름**(D3): WebSocket이 없으므로 1·2·4번과 이후 메시지 처리가 없다. 3번만 하고, `page.current`를 현재 봉 자리에 그린다. `page.seq`는 `null`이다. 분봉도 같다.
- **시각 변환**
  - 계약의 `t`는 진짜 Unix 초다. Lightweight Charts는 UTC로 표시한다.
  - 그래서 시리즈에 넘길 때 `t + 32400`(KST)을 쓴다. 이 변환은 `chart/time.ts` 한 곳에만 둔다.
  - 드로잉 점과 알림 시각을 서버에 보낼 때는 반드시 원래 `t`로 되돌린다(백엔드 §13-8, D11에서 확정). 드로잉 좌표 계산(§3.5)도 진짜 Unix 초로 한 뒤 마지막에만 변환한다.
  - 목업은 처음부터 한국 벽시계를 UTC 초로 만들었다. 그래서 이 변환이 없다.
- **일·주·월봉의 time**: 정수 초를 그대로 쓴다. `BusinessDay` 객체를 섞지 않는다. 드로잉 좌표 변환과 칸 사이 시각 비교가 모두 같은 숫자 축 위에서 이뤄진다.

### 5.5 `chartSettings`의 모양(프런트엔드 소유)

계약은 `Cell.chartSettings: unknown`으로 두고 프런트엔드가 모양을 정하게 했다(D10에서 `Pane` → `Cell`). 코드는 `chart/settings.ts`다(#75).

```ts
interface ChartSettings {
  v: 2;                                     // 모양 버전. 바꾸면 불러올 때 이주
  style: "candle" | "bar" | "line" | "area";
  scale: "normal" | "log" | "percent";      // #76에서 percent. 비교 종목이 있으면 화면에서는 %로 그린다(저장 값은 그대로, shownScale)
  indicators: IndicatorConfig[];            // 그리는 순서
  compare: SymbolCode[];                    // 0~3개, 서로 다름. 순서가 색(--cmp-n)이다
  panels: { id: string; stretch: number }[]; // 지표 패널 순서와 높이 비율(가격 패널 1 대비). 가격 패널은 늘 맨 위
}
interface IndicatorConfig {
  id: string;                               // crypto.randomUUID()
  spec: IndicatorSpec;                      // 계약 §8.2 그대로. 알림에 그대로 넘긴다
  panel: "price" | string;                  // "price" 또는 panels[].id
  visible: boolean;
  style: { colors: IndicatorColor[]; width: 1 | 2 | 3 };  // 선 순서(lines(spec))대로 토큰 이름("ind-2"). 테마를 따라간다
}
```

- **놓는 곳**: 이동평균·볼린저 밴드·일목균형표는 `panel: "price"`. 거래량·RSI·MACD·스토캐스틱 슬로우는 추가할 때마다 `panels` 끝에 자기 패널 하나를 붙인다. 패널마다 지표는 하나다(D11). 지표를 지우면 그 패널도 지운다.
- **색**: `colors`가 선 수보다 모자라면(RSI에 시그널을 켜는 등 선이 늘어난 설정) 대표 색에서 견본 순서대로 채운다(`kinds.ts`의 `lineColor`). 대표 색은 막대가 아닌 첫 선의 색이다. 거래량 막대와 MACD 히스토그램은 색을 저장하지 않고 등락·부호로 칠한다.
- **새 차트의 기본값**: 거래량 지표 하나(`{ kind: "volume", maPeriod: null }`)와 그 패널(`stretch: 0.25`). id는 고정 UUID다(칸 안에서만 유일하면 된다). 대화상자로 거래량을 더할 때의 기본은 §9.5대로 `maPeriod: 20`이다.
- **v1 → v2 이주**(#75): v1은 지표·패널이 빈 배열만 될 수 있었고, 그때 거래량은 늘 그려졌다. 그래서 v1을 읽으면 v2에 기본 거래량 지표를 넣는다. 이주는 읽을 때만 한다. 열기만 해서는 서버에 쓰지 않고(`load`는 `revision`을 올리지 않는다), 사용자가 편집할 때 v2로 저장된다. 서버의 기본 레이아웃 시드(`migrations/0001`)는 v1 그대로다.
- **불러올 때의 검사**: 서버에서 받은 `chartSettings`는 경계에서 한 번 검사한다(손으로 쓴 `parseChartSettings`). 키와 타입, `spec`의 `kind`와 필드, "가격 밖 지표의 `panel`이 `panels`에 있고 패널마다 지표가 정확히 하나", "`compare`가 서로 다른 문자열 3개 이하"(#76)를 본다. 모양이 틀리면 기본 설정으로 열고 콘솔에 남긴다. 설정값의 뜻(예: 기간 0)은 여기서 보지 않는다. 워커가 엔진을 만들 때 거절하면 그 지표만 그리지 않고 범례에 흐린 글자와 `설정 오류`를 남긴다(§3.3).
- **크기**: 64KB 제한은 지표 수십 개로도 넘지 않는다.

### 5.6 WASM 지표를 불러오는 방식 (#5~)

- **빌드**: `pnpm wasm`(`web/scripts/build-wasm.sh`). `crates/indicators-wasm`을 wasm-pack으로 빌드해 `web/src/wasm/indicators/`에 `indicators.js`, `indicators.d.ts`, `indicators_bg.wasm`을 쓴다(백엔드 §9.4). wasm32 타깃과 wasm-pack이 있어야 한다.
  - 결과물은 저장소에 커밋하지 않는다(`.gitignore`).
  - 앱 코드가 wasm을 import하므로 `pnpm build`·`typecheck`·`test`는 앞에서 `pnpm wasm`을 돌린다(#75). `scripts/check.sh`도 wasm을 맨 앞에서 빌드하고, CI의 lint·test·build·e2e 작업은 wasm32 타깃과 wasm-pack을 깐다. 한 번 빌드한 뒤에는 네트워크 없이 캐시로 된다(`offline.sh` 안에서 확인).
  - `validateSpec`의 결과 타입 `SpecValidation`은 `indicators.d.ts`에서 가져온다. `IndicatorSpec`·`LineId`·`MaMethod`는 `web/src/api/generated/`에 있다(ts-rs).
  - 실제 wasm을 쓰는 단위 시험은 `*.node.test.ts`로 이름 짓는다. wasm 파일을 `node:fs`로 읽으므로 `tsconfig.node.json`이 검사한다.
- **불러오기**
  - 탭에 Web Worker 하나(`chart/indicators/worker.ts`, Vite `new Worker(new URL(…), { type: "module" })`)가 접착 코드의 `init(wasmUrl)`을 한 번 부른다. 첫 칸의 컨트롤러가 생길 때 워커를 만들어, 최신 페이지를 받는 동안 wasm을 준비한다(`chart/indicators/client.ts`).
  - wasm 파일은 Vite의 `?url` import로 해시 붙은 정적 파일이 된다. `vite-plugin-wasm` 같은 플러그인은 필요 없다.
  - 서버는 `.wasm`을 `application/wasm`으로 내보내야 한다. 그래야 `instantiateStreaming`이 동작한다(백엔드 §8.5).
  - 대화상자의 `validateSpec`은 메인 스레드에서 따로 init한다(`chart/indicators/validate.ts`). 대화상자를 열 때 한 번이다.
- **워커 안의 상태**(`chart/indicators/engines.ts`. 워커 셸 없이 node에서 실제 wasm으로 시험한다)
  - 차트마다 `Map<지표 id, 엔진>`. 메시지의 `chart`는 컨트롤러 인스턴스 번호다. 칸 번호(slot)로 하지 않는 것은, 다시 마운트된 칸이 옛 컨트롤러의 응답을 받지 않게 하려는 것이다.
  - 엔진마다 봉 시각 열(확정 봉 + 현재 봉), 막대 등락, 현재 봉의 미리 보기 값, 미래 시각을 든다.
  - 메인 스레드는 확정 봉 열을 `Float64Array` 여섯 개로 전송(transfer)한다.
- **메시지**(`chart/indicators/protocol.ts`)

| 메인 → 워커 | 하는 일 |
|---|---|
| `create(chart, gen, period, cols, current, engines[{ id, spec }])` | 같은 확정 봉 열로 엔진들을 만든다. 같은 키의 옛 엔진은 `free`. `current`가 있으면 바로 `preview`까지 한다 |
| `bar(chart, kind: preview \| confirm, bar)` | 그 차트의 모든 엔진에 도착 순서대로 `preview` 또는 `pushConfirmed`(§5.4, D13) |
| `drop(chart, ids \| all)` | 엔진 해제 |

| 워커 → 메인 | 내용 |
|---|---|
| `created(chart, results[])` | 엔진마다 `{ id, gen, lines[{ id, shift }], draws }` 또는 `{ id, gen, error: spec \| calc, message }` |
| `tail(chart, results[])` | 엔진마다 선마다 `update`(점 하나), `set`(점 전체) 또는 `none` |
| `fatal(message)` | wasm init 실패. 그 뒤로는 계산하지 않는다 |

- **점의 자리는 워커가 정한다.** 점은 `{ t, v }`(진짜 Unix 초)이고 거래량 막대 점은 등락(`up`)을 싣는다. 차트 시각 변환은 메인 스레드가 `time.ts`로 한다.
- **§5.6 초판과 다른 점**(#75): `futureStarts` 왕복 메시지를 두지 않는다. 새 현재 봉의 첫 `preview`와 경주하기 때문이다. 워커가 `create`의 `period`로 `futureBarStarts`를 직접 부른다. 주·월봉 `t`는 서버가 구간 시작(월요일, 1일)으로 맞추므로(`kiwoom/wire.rs`) `futureBarStarts`가 던지지 않는다.
- **세대**: 메인 스레드는 컨트롤러마다 `gen`을 `create`를 보낼 때마다 올리고 그 묶음의 엔진 기록에 적는다. 응답은 "기록이 있고 `기록.gen === 응답.gen`"일 때만 받는다(D1). `bar`는 세대 없이 보내고, 워커가 엔진마다의 세대를 붙여 돌려준다.
- **칸마다의 처리 줄**: 컨트롤러는 BarFeed 콜백 안에서 동기로 정하고 바로 `postMessage`한다. 메인 스레드에 `await`가 없으므로 순서는 postMessage의 FIFO와 워커의 단일 스레드가 지킨다(`chart/indicators/sync.ts`).

```
committedT = 엔진에 커밋한 마지막 확정 봉 t (create 때 h.bars의 마지막, confirm 때 갱신)
종목·거래소·봉 주기 변경, 최신 페이지 실패 → 지표 선을 바로 비우고 drop all
reset(최신 페이지), prepended(added > 0)    → 지표 선을 바로 비우고 create all
live·confirmed:
  isTailChange(prev, next, bar) && bar.t > committedT → bar{preview | confirm}
  그 밖(같은 t로 확정 봉 바꿔치기, 확정 안 된 현재 봉이 사라짐, 앞이 바뀜) → 지표 선을 바로 비우고 create all
```

  - `isTailChange`만으로는 못 가린다. `BarFeed`가 마지막 확정 봉과 같은 t의 봉을 내놓을 수 있고(`replaceLast`), 그때 엔진은 던진다.
  - 주 시리즈가 `setData`되면 지표 선도 바로 비운다. 시간축은 모든 시리즈 시각의 합집합이라, 옛 시각이 남으면 범례의 `hoverIndex = round(logical)`과 범위 계산이 어긋난다.
  - 숨긴 지표는 엔진을 만들지 않는다. 다시 켜면 그 지표 하나만 만든다. 설정을 바꾸면 그 지표만 drop하고 다시 만든다.
- **그리기 묶기**: 지표 점은 `(선 시리즈, 점 시각)`마다 하나씩 큐에 쌓고(`drawQueue.ts`) 주 시리즈와 같은 `requestAnimationFrame`에서 그린다. 시리즈당 마지막 값만 남기면 한 프레임에 온 확정 봉의 최종 값을 잃기 때문이다. `set`이 온 선은 그 프레임의 `update`를 따로 그리지 않는다. 그 `update`는 점 사본에 이미 들어 있으므로, 프레임에서 점 사본으로 `setData`를 한 번 한다. 큐가 `set` 배열을 따로 들면 그 배열이 점 사본과 같은 배열이라 뒤의 `update`로 늘어난다. 그러면 큐에 남은 앞선 `update`가 늘어난 끝보다 과거가 되어, Lightweight Charts가 `Cannot update oldest data`로 거절한다(#75 리뷰, 체결 없던 분 뒤 선행스팬). 선 하나를 그리다 예외가 나면 그 선만 점 사본으로 다시 그리고 `console.error`를 남긴 뒤 다음 선을 그린다. `setTheme`과 주 시리즈를 바꿔 붙이기 전에 큐를 먼저 비운다(#58). 메인 스레드는 선마다 점 사본을 들고 범례 값(그 시각에 그려진 점)과 테마를 바꿀 때의 막대 색에 쓴다.
- **실패**(#75)
  - 설정값이 틀리면 `spec` 오류, 그 밖의 실패(이어지지 않는 봉, 엔진 panic)는 `calc` 오류다. 엔진마다 따로 잡아 그 엔진만 버린다. 같은 칸의 다른 엔진은 계속 계산한다.
  - wasm init 실패(`fatal`), 워커 `onerror`, 워커를 만들지 못함은 탭의 모든 칸에 알린다. 주 차트(봉)는 그대로 그리고, 지표 범례에 흐린 글자와 `계산 오류`를 남긴다.
- **현재 봉 갱신**: 체결마다 `preview`만 부르고 선마다 한 점만 갱신한다(#5 "그 봉에 걸린 값만 다시 계산"). 어느 시각의 점인지는 선의 `shift`가 정한다. 아래 일목균형표 항목을 본다.
- **일목균형표와 이동된 선**(W4-28)
  - **주 시리즈에는 빈 시각을 붙이지 않는다.** 주 시리즈 끝에 미래 시각을 붙이면 현재 봉이 시리즈의 마지막 시각보다 과거가 된다. 그러면 Lightweight Charts의 `series.update`(마지막 시각 이상만 받음)로 현재 봉을 갱신할 수 없다. 목업 초판이 이 방식이었고 고쳤다.
  - **미래 시각은 선행스팬 시리즈 자신이 갖는다.** 선의 점 `i`는 시각 `T[i + shift]`에 놓인다. `T`는 확정 봉과 현재 봉의 시작 시각 뒤에 `futureBarStarts`로 만든 미래 시각을 이은 배열이다. 시간축은 모든 시리즈 시각의 합집합이므로, 선행스팬 시리즈만으로 미래 구간이 생긴다.
  - **미래 시각의 개수**: 엔진마다 자기 양의 `shift` 최댓값만큼 만든다. 시간축이 합집합이므로 칸 전체로는 띄운 지표의 양의 `shift` 중 최댓값이 된다. 일목균형표를 지우면 그 선행스팬 시리즈와 함께 미래 구간도 사라진다.
  - **미래 시각을 만드는 법**: 늘 `futureBarStarts`로 만든다. 봉 주기마다 경계 규칙이 다르기 때문이다. 분봉은 08:00~20:00 밖과 주말을 건너뛰지만, 월봉은 1일이 주말이어도 그날이 경계이고, 주봉은 월요일이 경계다. 브라우저가 초 단위 덧셈으로 만들지 않는다.
  - **미래 칸이 예측과 다를 때**: 새 봉의 시각이 직전에 만든 미래 시각의 첫 칸과 다르면(체결 없던 분, 공휴일) 양의 `shift` 선은 `set`으로 다시 놓는다. 그 밖에는 한 점 `update`다.
  - **갱신할 점은 언제나 그 선 시리즈의 마지막 점이다.** 선의 마지막 값은 현재 봉(index `n−1`)에서 나오고 시각 `T[n−1+shift]`에 놓인다. 어느 선 시리즈도 끝에 빈 시각(whitespace)을 붙이지 않으므로, 이 점이 그 시리즈의 마지막 점이다. NaN(워밍업)과 `T` 밖(후행스팬 앞부분)은 점을 만들지 않는다.

  | 선 | `shift` | 현재 봉이 바뀔 때 갱신할 점 | 새 현재 봉이 생길 때 |
  |---|---|---|---|
  | 이동 없는 선(이동평균, 전환선, 기준선 등) | 0 | 현재 봉 시각의 점 | 새 시각의 점을 덧붙인다 |
  | 선행스팬 A·B | 양수 | 현재 봉에서 `shift`만큼 앞 미래 시각의 점 | `futureBarStarts`로 미래 시각을 다시 만들고 그 점을 덧붙인다 |
  | 후행스팬 | 음수 | 현재 봉에서 `|shift|`만큼 뒤 과거 시각의 점. 시간축으로는 과거지만 이 시리즈의 마지막 점이다 | 다음 과거 시각의 점을 덧붙인다 |

  - 그래서 모든 선을 보통의 `series.update(point)`로 갱신한다. v5.2의 `update(point, historicalUpdate = true)`는 쓰지 않는다. 쓰게 되는 것은 시리즈 끝에 빈 시각을 붙였을 때뿐인데, 그 방식은 위에서 버렸다.
  - **고정한 시험**: `engines.node.test.ts`가 체결을 흘려 모든 선의 `update`가 그 선의 마지막 점 이상이고, 점진 결과가 처음부터 다시 만든 결과와 같음을 실제 wasm으로 본다. `e2e/indicators.spec.ts`는 일목균형표가 있는 1분봉 칸에 가짜 키움 체결을 흘려, 실제 Lightweight Charts의 선 시리즈마다 `update` 시각이 그 시리즈의 마지막 점 시각이고 page error가 없음을 본다. #76부터 일목 선은 가격 패널의 사용자 정의 시리즈라, 같은 시험과 `layer.test.ts`의 선행스팬 다시 놓기 시험(#75 F1)이 그 시리즈 위에서 돈다.
  - 알림에서 이동된 선을 고르지 못하는 것은 §3.8(D8)이다.
- **타입**: `indicators` 크레이트의 `Spec`과 계약의 `IndicatorSpec`은 같은 정의다(ts-rs). 워커에는 `JSON.stringify(spec)`을 넘긴다. 선 순서는 `kinds.ts`의 `specLines`가 크레이트의 `Spec::lines`를 따라 쓰고, 시험이 wasm 엔진의 `lines()`와 같은지 본다.
- **목업과의 차이**: 목업의 `data.js` 지표 함수는 화면을 그리려고 만든 대역이다. 실제 앱에서는 쓰지 않는다.

### 5.7 Lightweight Charts 활용

| 요구 | v5.2 기능 | 메모 |
|---|---|---|
| 봉 모양 4가지 | `chart.addSeries(CandlestickSeries \| BarSeries \| LineSeries \| AreaSeries, opts)` | 모양을 바꾸면 주 시리즈를 지우고 새로 만든다. 드로잉 primitive도 새 시리즈에 다시 붙인다 |

## 7. 접근성 기본

### 7.1 키보드 조작

- 마우스로 하는 일은 모두 키보드로도 할 수 있다(§3.2 표). 예외는 드로잉의 자유로운 점 찍기다.
  - 대신 키보드 드로잉을 둔다: 십자선을 `←→`로 봉 단위로 옮기고, `↑↓`로 가격을 호가 단위로 옮긴 뒤 `Enter`로 점을 찍는다.
- **초점 이동 순서**: 위 막대 → 왼쪽 도구 → 칸 1…n → 관심종목 → 상태 줄.
  - 칸은 `tabindex=0`인 `section`이고 `aria-label`은 `칸 1: 삼성전자 5분`이다.
  - 왼쪽 도구는 `role="toolbar"`에 `aria-orientation="vertical"`이고, 화살표로 이동한다(roving tabindex).
- **초점 표시**: 모든 초점은 `:focus-visible`에서 호박색 2px 외곽선으로 보인다. 칸은 활성 칸 테두리가 그 역할을 한다.
- **대화상자**
  - `role="dialog"`, `aria-modal="true"`, 제목으로 `aria-labelledby`를 건다.
  - 열면 첫 입력칸에 초점을 두고 초점을 안에 가둔다. 닫으면 연 버튼으로 초점을 돌린다. `Esc`로 닫는다.
- **목록**
  - 검색 결과와 지표 종류 목록은 `role="listbox"`/`option`이고 `aria-selected`를 쓴다.
  - 입력칸에는 `aria-activedescendant`를 둔다.
- **화면 읽기 프로그램**
  - 범례는 십자선을 따라 너무 자주 바뀌므로 `aria-live`를 걸지 않는다. 대신 칸에 초점이 있을 때 `←→`로 봉을 옮기면, 별도의 숨은 `aria-live="polite"` 영역에 `2026-11-06 종가 85,400 하락 0.58%`를 한 번 읽힌다.
  - 화면 안 알림(`alert_fired`)은 `role="status"`다.

### 7.2 두 테마의 대비

WCAG 2.2 대비를 계산했다. 기준은 본문 4.5:1, 큰 글자·그래픽 3:1이다.

| 전경 | 다크(`--chart-bg` / `--bg`) | 라이트(`--chart-bg` / `--bg`) |
|---|---|---|
| `--text` | 13.75 / 14.32 | 16.06 / 14.49 |
| `--text-2` | 6.55 / 6.82 | 7.05 / 6.36 |
| `--text-3` | 4.85 / 5.05 | 5.27 / 4.76 |
| `--up` | 5.02 / 5.23 | 5.51 / 4.98 |
| `--down` | 5.30 / 5.52 | 5.65 / 5.10 |
| `--accent` | 8.47 / 8.82 | 5.25(`--bg`) |
| `--accent-ink` on `--accent` | 9.07 | 5.98 |

- **조정 이력**: 초안의 `--text-3`(다크 3.79, 라이트 4.03), 라이트 `--up`(`--bg` 위 4.49), 라이트 `--accent`(`--bg` 위 4.68)가 4.5에 못 미쳤다. 그래서 값을 고쳤다. 지금 표는 고친 값이다.
- **빨강과 파랑의 구분**
  - 상승 빨강과 하락 파랑은 서로의 밝기 대비가 1.06(다크), 1.14(라이트)뿐이다. 적록·청황 색약에서 밝기로는 구분되지 않는다.
  - 그래서 색에만 기대지 않는다.
    - 모든 등락 수치에 부호(`+`/`−`)를 붙인다(§1.3).
    - 캔들은 몸통 위치(시가·종가)로도 방향이 보인다.
  - 확장 후보: "상승 봉 속 비우기" 설정.
- **지표 선**: 다섯 기본 색은 차트 바탕 위에서 모두 3:1을 넘는다. 이름과 색 견본이 범례에 함께 있어 색만으로 구분하지 않는다.
- **움직임**: `prefers-reduced-motion`이면 연결 상태 점의 맥박을 멈춘다. 그 밖에 저절로 움직이는 장식은 없다.

## 8. 용어·ADR 제안

GLOSSARY.md와 ADR은 고치지 않았다. 아래는 제안이다. 용어집과 ADR에 이미 들어간 것(활성 칸, 종목 연동, 자석 모드, ADR 0002·0003 문구, 이슈 #7 제목)은 지웠다.

### 용어

- **십자선**(새 용어 제안): 차트 위에서 마우스나 손가락이 가리키는 시각과 가격을 보여 주는 가로·세로 선. 동기화의 대상이다. _Avoid_: 크로스헤어, 커서.
- **범례**(새 용어 제안): 칸 왼쪽 위에 십자선이 가리키는 봉의 시·고·저·종·거래량과 지표 값을 적은 글자 영역. _Avoid_: 레전드, 데이터 창.
- **초성 검색**(새 용어 제안): 종목명의 첫 자음만으로 종목을 찾는 것.
- **연결 상태**(새 용어 제안): 키움 실시간 연결과 브라우저↔서버 연결의 상태를 함께 이르는 말. 백엔드 `ConnectionStatus`와 같다.
- **빈 시각**(새 용어 제안, D10): 차트의 시간축에는 있지만 그 시리즈가 그리지 않는 자리(Lightweight Charts의 whitespace). 현재 봉과 구별한다.
- **지표 패널 / 가격 패널**: 이미 **패널** 항목에 쓰였다. 따로 표제어로 두기를 제안한다. 이 문서는 두 말을 그대로 쓴다.
- **라이브러리 표기의 "TradingView"**: 용어집은 화면 이름으로 "트레이딩뷰"를 _Avoid_로 두었다. 상태 줄의 라이브러리 이름 표기는 라이선스가 요구하는 고유명사라 예외로 둔다는 한 줄을 용어집에 더하기를 제안한다.

### ADR

- **휴대폰 차트 상태를 레이아웃과 따로 둔다**(새 ADR 후보)
  - 휴대폰에서 종목을 바꿔도 데스크톱 레이아웃이 바뀌지 않게 한다. 상태는 `UiState.phone`에 둔다(§4).
  - 화면 동작에 관한 결정이고 되돌리기 쉬워서 ADR까지 갈지는 코디네이터 판단에 맡긴다.

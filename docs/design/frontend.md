# 프런트엔드 설계: 차트 화면

차트 화면의 생김새, 조작, 프런트엔드 코드 구조를 정한다. 로드맵 #12의 1~7단계(#2~#8)가 이 문서를 따른다. 8단계(#9) 배포는 화면에 영향이 없다.

- **기준 문서**: `GLOSSARY.md`, `docs/adr/0001`~`0004`, 백엔드 설계 `docs/design/backend.md`. 백엔드 쪽 경계는 그 문서의 §8(브라우저 계약)과 §9(지표 크레이트 API)다.
- **목업**: `docs/design/mockup/index.html`. 빌드 없이 브라우저로 연다. 데이터는 시드로 만든 가짜 값이다.
  - 화면 상태는 주소의 질의 문자열로 고른다.
    - `?layout=4|1`: 4칸 또는 1칸
    - `&theme=dark|light`: 테마
    - `&dialog=indicator|compare|search|alert`: 대화상자
    - `&sheet=watch`: 휴대폰 관심종목
  - 폭이 768px보다 좁으면 휴대폰 화면으로 바뀐다.
  - `file://`로 열어도 된다(2026-11-08 Chrome headless로 확인).
  - 모듈 import를 쓰지 않고 고전 `<script>`만 쓴다. Lightweight Charts는 unpkg의 v5.2.1 standalone 빌드를 받는다.
- **스크린샷**: `docs/design/mockup/screenshots/`. Playwright로 찍었다.

## 1. 화면 디자인 방향

### 1.1 인상

이 도구는 운영자 한 사람이 장중에 오래 켜 두고 보는 도구다(ADR 0001). 그래서 화면은 소개용 제품처럼 꾸미지 않는다. 오래 보는 계기판처럼 조용하게 만든다. 고유한 인상은 세 가지 선택에서 나온다.

1. **바탕은 녹색 기운이 도는 먹색이다(다크).**
   - 차트 앱에 흔한 남색 바탕도, 순수한 검정도 쓰지 않는다.
   - 다크 바탕 `#161F1E`는 이끼 낀 돌 같은 색이다. 빨강·파랑 봉 어느 쪽과도 색상이 겹치지 않는다.
   - 라이트는 그 바탕을 밝힌 회녹색 종이(`#FBFCFB`, 막대 `#EDF1EF`)다.
2. **강조색은 호박색 하나만 쓰고, 등락과는 다른 일을 맡긴다.**
   - 빨강(상승)과 파랑(하락)은 가격 방향에만 쓴다.
   - 사용자가 지금 고른 것, 곧 활성 칸 테두리, 고른 봉 주기, 켠 도구, 키보드 초점, 주 버튼에는 호박색(`--accent`)만 쓴다.
   - 그래서 화면 어디서든 "빨강·파랑이면 시장, 호박색이면 나"로 읽힌다. 강조색이 파랑이면 하락과 헷갈리고, 빨강이면 상승과 헷갈린다. 호박색을 고른 이유다.
3. **대담함은 범례의 종가 숫자 한 곳에만 쓴다.**
   - 칸 왼쪽 위에 십자선이 가리키는 봉의 종가를 크게 둔다. 크기는 1칸 22px, 여러 칸 15px이고 등락 색을 입힌다.
   - 그 아래에 시·고·저·종·량을 12px로 놓는다.
   - 나머지 막대, 버튼, 관심종목은 13px 회색조로 조용히 둔다.
   - 따로 가격판을 두지 않는다. 그래서 차트 위 숫자가 화면의 표제가 된다.

**베끼지 않는 것**
- 로고는 두 골짜기를 이은 선 `VV`로 직접 그렸다. 저장소 이름 vallythevally에서 왔다.
- 아이콘은 1.5px 선으로 모두 새로 그렸다(목업 `index.html`의 `<symbol>`).
- 남색 바탕과 파랑 강조, 청록·빨강 봉 조합은 쓰지 않는다.
- 다만 배치는 차트 앱에 흔한 관례를 따른다. 위 막대, 왼쪽 도구, 오른쪽 목록이다. 손에 익은 배치는 바꿀 이유가 없다.

### 1.3 글꼴과 숫자

- **글꼴은 Pretendard Variable 하나다.**
  - 한글과 라틴 글자의 굵기와 높이가 고르다. 가변 글꼴이라 550·650 같은 중간 굵기를 쓸 수 있다. 범례 숫자에 650을 쓴다.
  - 대체 글꼴은 `"Noto Sans CJK KR", "Apple SD Gothic Neo", system-ui` 순이다.
  - 실제 앱은 npm `pretendard` 패키지의 dynamic subset을 Vite로 함께 묶어 같은 서버에서 내보낸다.
    - 목업만 jsDelivr CDN을 쓴다.
    - 사설망(#9) 밖으로 요청을 내보내지 않으려는 것이다. 서버 하나가 정적 파일을 모두 맡는다(ADR 0002).
- **숫자는 언제나 고정폭이다.** `body`에 `font-variant-numeric: tabular-nums`를 걸었다.
  - 그래서 체결마다 종가가 바뀌어도 자릿수 폭이 같아 숫자가 흔들리지 않는다. 관심종목의 가격 열도 오른쪽 정렬로 자리가 맞는다.
  - 모노스페이스 글꼴은 쓰지 않는다. Pretendard의 tabular 숫자로 충분하고, 글꼴이 둘이면 범례가 산만해진다.
  - Lightweight Charts에는 `layout.fontFamily`로 같은 글꼴을 넘긴다. 축 눈금의 숫자 폭은 Pretendard가 기본으로 맞춰 준다.
- **숫자 표기**
  - 가격: 주식은 원 단위 정수에 천 단위 쉼표(`85,400`), 지수는 소수 둘째 자리(`1,963.30`).
  - 등락: 부호를 항상 붙인다(`+1,600 +1.86%`, `−500 −0.58%`). 부호가 있으니 색을 못 봐도 방향을 안다(§7).
  - 거래량: `만`·`억` 단위(`33만`, `25.64억`).
  - 시각: 한국 시각 `2026-11-06 19:55`. 일봉 이상은 날짜만 쓴다.

### 1.4 정보 밀도

- **높은 밀도를 기본으로 한다.** 데스크톱 1440×900에서 4칸이 각각 지표 패널 1~2개와 함께 들어가고, 관심종목 13종목이 스크롤 없이 보인다.
- **줄이는 것과 지키는 것**
  - 줄이는 것: 칸 머리줄을 따로 두지 않는다. 범례가 머리줄을 겸한다. 그래서 차트 면적이 커진다.
  - 지키는 것: 클릭 대상은 데스크톱 26px 이상, 휴대폰 36px 이상으로 둔다. 범례 줄 높이는 18px이다.
- **범례의 반투명 바탕**: 여러 칸 화면에서는 범례가 봉을 가리지 않게 가격 패널의 위 여백을 26%로 잡는다(`scaleMargins.top`). 범례 줄마다 `--chart-bg` 78%의 바탕을 깔아 봉 위에서도 글자가 읽힌다.

**위쪽 막대**: 왼쪽에서 오른쪽으로, 활성 칸에 대한 것에서 화면 전체에 대한 것 순서로 놓는다.

1. 종목 버튼(활성 칸의 종목, 누르면 검색)
2. 봉 주기 9개(분 여섯과 일·주·월 사이에 간격)
3. 봉 모양 메뉴(캔들·바·라인·영역)
4. 지표, 비교, 로그 축
5. 빈 공간
6. 레이아웃 이름 메뉴, 새 레이아웃으로 복제, 칸 배치 5개
7. 동기화 토글(십자선, 스크롤)
8. 알림, 테마

봉 주기, 봉 모양, 지표, 비교, 로그는 **활성 칸**에만 적용된다. 활성 칸은 호박색 1px 안쪽 테두리로 표시한다. 1칸일 때는 테두리를 숨긴다.

**왼쪽 드로잉 도구**
- 차례: 선택·이동, 추세선, 수평선, 수직선, 사각형, 피보나치 되돌림, 텍스트, 구분선, 자석 모드, 되돌리기, 지우기.
- 켠 도구는 호박색 바탕에 먹색 아이콘이다. 단축키 글자를 아이콘 오른쪽 아래에 9px로 붙인다.

**오른쪽 관심종목**
- 열: 종목(이름, 코드, 30봉 스파크라인), 현재가, 등락률.
- 활성 칸의 종목 행에는 호박색 왼쪽 띠를 붙인다.
- 행을 누르면 활성 칸이 그 종목으로 바뀐다. 종목 연동이 켜진 칸들도 함께 바뀐다.
- 머리의 `›`로 28px 띠까지 접는다. 접힌 상태는 `UiState.watchCollapsed`에 둔다.
- 순서는 끌어서 바꾼다. 키보드로는 Alt+↑/↓로 바꾼다.

**칸 배치**: 목업 `.grid[data-arr]`. 칸 사이 경계는 1px `--line`이다.

| `Arrangement` | 배치 |
|---|---|
| `1` | 한 칸 |
| `2h` | 좌우 반반 |
| `2v` | 상하 반반 |
| `3` | 왼쪽 큰 칸(3/5) + 오른쪽 위아래 두 칸 |
| `4` | 2×2 격자 |

칸 사이 경계를 끌어 비율을 바꾸는 기능은 v1에 넣지 않는다. 고정 비율로 충분하다.

**상태 줄**: 연결 상태, 구독 수, 자동 저장 표시, 라이브러리 표기, 단축키 도움말 버튼이 있다.

### 2.2 연결 상태 표시

백엔드 계약의 `ConnectionStatus`(§8.3)를 그대로 보여 준다. 점 하나와 짧은 문장이다.

| 상태 | 점 | 문장 | 추가 |
|---|---|---|---|
| WebSocket 연결 중 / 끊김(브라우저↔서버) | 회색 | `서버에 다시 연결하는 중` | 칸 범례 옆에 `멈춤` 꼬리표 |
| `realtime: "live"` | 민트, 2.4초 맥박(움직임 줄이기 설정이면 멈춤) | `실시간 연결됨` | |
| `"live"`, 장 닫힘(20:00~08:00, 주말) | 민트, 맥박 없음 | `장 닫힘: 체결 없음` | 브라우저가 시각으로 판단 |
| `"reconnecting"` | 호박 | `키움에 다시 연결하는 중 (14:02부터)` | `since` 표시 |
| `backfilling: true` | 호박 | `끊긴 구간 메우는 중` | |
| `"halted"` | 빨강 | `키움 인증 실패: 서버 설정을 확인하세요` | 상태 줄 전체를 띠로 강조 |
| `watchlistPolling: true` | 그대로 | 끝에 `관심종목 일부 1분마다 조회` | |

- **장 닫힘 판단**: 장이 닫혀 있는지는 서버가 알려 주지 않는다. 브라우저가 한국 시각으로 판단한다. 공휴일은 모르므로 공휴일에는 "실시간 연결됨"으로 보일 수 있다. 사소해서 그대로 둔다.
- **구독 오류**: 칸의 구독에 `sub_error`가 오면 그 칸 범례 첫 줄 끝에 이유를 붙인다.
  - `realtime_limit` → `실시간 한도 초과: 조회 값만 보입니다`
  - `kiwoom_unavailable` → `키움 조회 실패: 잠시 뒤 다시 시도합니다`

### 2.3 범례(십자선이 가리키는 봉)

범례는 칸 왼쪽 위에 겹쳐 놓는다(목업 `.legend`). 줄 순서는 다음과 같다.

1. **머리줄**: 종목 연동 꼬리표, 종목 이름(650), 코드(지수는 시장 이름), 봉 주기
2. **가격줄**: 종가(크게, 등락색), 전 봉 대비 변화량과 %, 봉 시각
3. **OHLCV 줄**: `시 고 저 종 량`. 이름표 글자는 `--text-3`, 값은 `--text`
4. **가격 패널 지표**: 줄마다 색 견본 10×2px, 이름과 설정값(`이동평균 20`, `볼린저 밴드 20 2`), 값
5. **비교 종목**: 이름(`--text` 색)과 % 변화(등락색). 기준은 화면 왼쪽 끝 봉이다

- **지표 패널의 범례**: 각 지표 패널의 왼쪽 위에 한 줄로 따로 둔다. 예: `RSI 14 42.57`, `거래량 33만 — 이동평균 20 57만`.
- **어느 봉을 보여 주나**: 십자선이 차트 밖이면 마지막 봉(현재 봉)이다. 십자선 동기화가 켜져 있으면 다른 칸의 십자선이 움직일 때도 그 칸 범례가 그 시각의 봉을 보여 준다.
- **지표 줄 조작**: 지표 줄에 마우스를 올리거나 키보드 초점이 오면 숨기기·설정 편집·지우기 버튼 셋이 나타난다(목업에서는 1칸 화면의 `이동평균 20` 줄에 켜 두었다).
- **갱신 방식**: 범례는 React 컴포넌트가 아니다. 컨트롤러가 DOM 글자를 직접 바꾼다(§5.4). 십자선 이동과 체결 갱신이 초당 수십 번 일어나기 때문이다.

## 3. 상호작용 명세

### 3.1 종목 검색

- **열기**: `/` 또는 `Ctrl+K`, 위 막대의 종목 버튼, 휴대폰 아래 탭의 검색.
- **입력**
  - 이름, 코드 6자리, 초성을 받는다.
  - 결과는 입력할 때마다 갱신하고 최대 8개를 보인다.
  - 맞은 글자는 호박색 굵은 글씨로 표시한다.
- **키**

| 키 | 동작 |
|---|---|
| `↑` `↓` | 고르기 |
| `Enter` | 활성 칸에 열기 |
| `Shift+Enter` | 활성 칸의 비교 종목으로 넣기 |
| `Ctrl+Enter` | 관심종목에 넣기 |
| `Esc` | 닫기 |

- **초성 검색을 넣는다(제안·채택).**
  - 한국 종목명은 길고(`삼성바이오로직스`) 한글 입력기 전환이 번거롭다. 초성만 치는 습관이 국내 증권 앱에 널리 퍼져 있다.
  - 규칙: 입력이 모두 자음이면 종목명의 초성열에 대해 접두 일치를 먼저 보고, 다음에 포함 일치를 본다. `ㅅㅅ` → 삼성전자, 삼성전자우, 삼성SDI…, 신세계.
  - 순위: 코드 접두 = 이름 접두 > 초성 접두 > 포함.
  - 목업의 `V.search`가 이 규칙의 참조 구현이다. `desktop-search-dark.png`가 그 결과다.
  - 어디서 할지: 서버의 `GET /api/symbols?q=`에서 한다(§6 요구 1). 종목 목록은 서버 메모리에 있다. 브라우저가 수천 종목을 받아 둘 필요가 없다.
- **봉 주기 단축키와의 충돌**: 아무 글자나 치면 검색이 열리는 방식은 쓰지 않는다. 숫자와 D·W·M을 봉 주기 단축키로 쓰기 때문이다. 검색은 `/`로 연다.

### 3.2 키보드 단축키

차트 영역에 초점이 있고 입력칸이 아닐 때만 동작한다. `?`를 누르면 이 표를 그대로 보여 주는 도움말이 열린다.

| 키 | 동작 |
|---|---|
| `1` `3` `5` | 1분, 3분, 5분 |
| `Shift+1` `Shift+3` `Shift+6` | 15분, 30분, 60분(`event.code`로 판단해 자판 배열과 무관) |
| `D` `W` `M` | 일, 주, 월 |
| `[` `]` | 이전·다음 봉 주기 |
| `` ` `` 또는 `Tab` | 다음 칸을 활성 칸으로 |
| `I` | 지표 추가 대화상자 |
| `L` | 로그 축 켜기/끄기 |
| `Alt+A` | 알림 만들기 |
| `Alt+W` | 관심종목 접기/펴기 |
| `V` `T` `H` `Shift+V` `R` `F` `X` | 선택, 추세선, 수평선, 수직선, 사각형, 피보나치 되돌림, 텍스트 |
| `G` | 자석 모드 켜기/끄기. 그리는 동안 `Ctrl`을 누르고 있으면 잠시 반대로 |
| `Delete` / `Backspace` | 고른 드로잉 지우기 |
| `Ctrl+Z` / `Ctrl+Shift+Z`(`Ctrl+Y`) | 되돌리기 / 다시 하기 |
| `Esc` | 그리던 드로잉 취소, 선택 풀기, 대화상자 닫기 |
| `←` `→` | 십자선을 한 봉씩 옮기기(키보드로 범례 읽기) |
| `+` `−` / `Home` `End` | 확대·축소 / 처음·최신 봉으로 |

- **충돌 정리**: `Ctrl+1~4`는 브라우저 탭 전환과 부딪히고, `Alt+숫자`는 리눅스 Chrome 탭 전환과 부딪힌다. 그래서 칸 이동은 `` ` ``와 `Tab`으로 한다.
- **목업**
  - 왼쪽 도구와 위 막대 버튼의 툴팁이 이 표와 같다.
  - 단축키 중에서는 `/`, `Ctrl+K`, `I`, `Alt+A`, `Esc`만 동작한다.
  - 마우스로는 다음이 동작한다: 테마 버튼, 관심종목 접기, 십자선·스크롤 칩, 칸을 눌러 활성 칸 바꾸기, 칸 사이 십자선 동기화, 범례 지표 줄의 버튼 표시, 초성 검색 입력, 휴대폰 아래 탭.

### 3.3 지표 추가 대화상자와 지표 패널

**열기**: 위 막대의 `지표`, `I`, 휴대폰 봉 주기 줄 끝의 지표 버튼.

**구성**(`desktop-indicator-dialog-dark.png`)

- **머리**: 제목, `지표 / 비교 종목` 탭, 대상 칸(`칸 1: 삼성전자 일`).
- **왼쪽 목록**
  - 지표 종류 일곱 가지를 둘로 묶는다.
    - "가격 패널에 겹쳐 그림": 이동평균, 볼린저 밴드, 일목균형표
    - "아래 지표 패널에 그림": 거래량, RSI, MACD, 스토캐스틱 슬로우
  - 이미 띄운 수를 `4개 띄움`으로 붙인다.
  - 위의 찾기 칸은 이름과 초성을 받는다.
- **오른쪽 설정**
  - 고른 지표 종류의 설정값 입력을 보인다.
  - 기본값은 백엔드 §9.5 표를 따른다: 이동평균 단순 20, 볼린저 20·2, 일목 9·26·52·26, 거래량 이동평균 [20], RSI 14, MACD 12·26·9, 스토캐스틱 슬로우 5·3·3.
  - 색은 다섯 견본 중 아직 쓰지 않은 첫 색을 고른다. 굵기는 1·2·3이다.
- **아래 "이 칸에 띄운 지표"**: 지금 칸의 지표 전부를 보인다. 줄마다 놓인 패널, 설정 편집, 숨기기, 지우기가 있다.
- **바닥**
  - `닫기`와 주 버튼이 있다. 주 버튼 문구는 무엇이 추가될지를 말한다(`이동평균 20 추가`).
  - 추가해도 대화상자를 닫지 않는다. 이동평균 5·20·60·120을 연달아 넣는 흐름을 위해서다.

**키보드**: `↑↓`로 종류를 고르고, `Tab`으로 설정에 들어간다. `Enter`는 추가, `Esc`는 닫기다.

**검증**
- 설정값은 입력할 때마다 WASM의 `Spec.validate()`로 검사한다.
- 틀리면 입력칸 아래에 이유를 적고 주 버튼을 끈다. 예: "빠른 기간은 느린 기간보다 짧아야 합니다".

**같은 지표 종류 여러 개**
- 지표마다 브라우저가 UUID를 붙인다(§5.5 `chartSettings`).
- 이동평균 5와 이동평균 20은 서로 다른 지표다. 같은 설정의 지표를 또 추가하면 색만 다르게 하나 더 생긴다. 막지 않는다.

**설정 편집**
- 범례 지표 줄의 설정 버튼을 누르거나 선을 더블클릭하면 같은 대화상자가 그 지표의 편집 상태로 열린다.
- 이때 주 버튼은 `변경 적용`이다.

**지표 패널 관리**
- **기본**: 지표 패널 쪽 지표는 추가할 때마다 새 패널을 아래에 붙인다. Lightweight Charts의 pane 하나가 패널 하나다.
- **높이**: 패널 경계를 끌어 바꾼다(`layout.panes.enableResize`). 바꾼 비율은 `chartSettings.panels[].stretch`에 저장한다.
- **순서**: 지표 패널 범례의 메뉴에 `위로`, `아래로`, `패널 닫기`가 있다. `패널 닫기`는 그 패널의 지표를 지운다.
- **한 칸의 지표 패널 수**: 최대 4개를 권하고 막지는 않는다. 4칸 화면에서는 2개를 넘으면 가격 패널이 너무 낮아진다.
- **숨긴 지표**: 계산을 멈추고 시리즈를 `visible: false`로 둔다. 범례에는 흐린 글자로 남긴다.

### 3.4 비교 종목

- **넣기**: 지표 대화상자의 `비교 종목` 탭, 또는 종목 검색에서 `Shift+Enter`. 메뉴를 지표와 같은 곳에 두는 것은 #5의 요구다.
- **최대 3개**: 4번째는 넣을 수 없다. 대화상자의 추가 버튼이 꺼지고 `비교 종목은 3개까지입니다`라고 적는다.
- **축**
  - 비교 종목이 하나라도 있으면 가격 패널의 오른쪽 가격축이 `PriceScaleMode.Percentage`로 바뀐다.
  - Lightweight Charts는 이 모드에서 시리즈마다 **보이는 첫 봉**의 값을 0%로 잡는다. 그래서 "화면 왼쪽 끝 봉 기준 % 변화"가 따로 계산하지 않아도 그대로 된다.
  - 스크롤하면 기준이 따라 바뀐다. 범례의 %도 같은 기준으로 다시 계산한다(목업에서 확인: 범례 `+15.35%`, 축 라벨 `15.35%`).
- **지표 패널 축**: % 모드로 바꾸지 않는다. 가격 패널의 축에만 적용한다(목업 초판에서 모든 패널 축이 %로 바뀌던 실수가 있었다).
- **지우기**: 비교 종목을 모두 지우면 원래 축(일반 또는 로그)으로 돌아간다.
- **로그 축과 함께 쓸 때**: 비교 종목이 있는 동안 로그 버튼은 꺼지고 툴팁에 이유를 적는다. 로그 축을 쓰려면 비교 종목을 지운다.
- **그리기**: 비교 종목 선은 굵기 2, `--cmp-n` 색이다. 마지막 값 라벨(%)을 축에 보인다.
- **데이터**: 비교 종목은 같은 봉 주기로 `GET /api/bars`와 `subscribe`를 따로 한다. 계약에 따라 구독 하나다.
- **시각 맞추기**: 주 종목과 시각이 다른 봉(거래정지 등)은 Lightweight Charts가 시간축을 합쳐서 그린다. 따로 맞추지 않는다.

### 3.5 드로잉

**흐름**

1. **도구 고르기**: 왼쪽 도구나 단축키로 고른다. 커서가 십자로 바뀐다.
2. **점 찍기**
   - 두 점 도구(추세선, 사각형, 피보나치 되돌림)는 누르고 끌어 놓아도 되고, 두 번 클릭해도 된다.
   - 한 점 도구(수평선, 수직선, 텍스트)는 한 번 누르면 된다.
   - 텍스트는 찍은 자리에 입력칸이 뜬다. `Enter`로 확정하고 `Esc`로 취소한다.
3. **끝내기**
   - 다 그리면 선택 도구로 돌아가고, 방금 그린 드로잉이 골라진 상태가 된다.
   - 도구를 더블클릭하면 그 도구가 잠겨 계속 그린다. `Esc`로 푼다.
4. **자석 모드**(기본 켬)
   - 점을 찍을 때 마우스 x에 가장 가까운 봉으로 시각을 붙인다.
   - 가격은 그 봉의 시·고·저·종 중 마우스 y에 가장 가까운 값에 붙는다(#6).
   - 붙는 범위는 화면 거리 16px 안이다. 그보다 멀면 마우스 위치 그대로 둔다.
   - 붙을 자리에 작은 원을 미리 보인다.

**선택·이동·삭제**
- **고르기**: 선에서 6px 안을 누르면 고른다. 고른 드로잉은 끝점에 손잡이(원)를 보이고, 위에 작은 막대(색, 굵기, 알림 만들기, 지우기)를 띄운다. 목업의 추세선이 고른 상태다.
- **옮기기**: 몸통을 끌면 전체가 옮겨지고, 손잡이를 끌면 그 점만 옮겨진다. 옮길 때도 자석이 적용된다.
- **지우기**: `Delete`/`Backspace`, 막대의 지우기, 왼쪽 도구의 휴지통 중 하나로 지운다.
- **되돌리기**: `Ctrl+Z`. 기록은 브라우저 메모리에만 둔다(#6, ADR 0003). 새로고침하면 사라진다.

**저장**
- 다 그리거나 옮기기를 끝내는 순간(pointerup) 그 드로잉 하나를 `PUT /api/drawings/:id`로 저장한다.
- 되돌리기도 서버 쪽에서 보면 PUT이나 DELETE다. 지운 것을 되돌리면 같은 id로 다시 PUT한다.

**고정 방식**
- 점은 `DrawingPoint { t, price }`다. 봉 순서가 아니다.
- 그릴 때마다 `t`를 x 좌표로 바꾼다.
  1. 지금 봉 주기의 봉 시작 시각 배열에서 `t`를 이분 탐색한다.
  2. 두 봉 사이면 논리 index를 비율로 보간한다.
  3. 마지막 봉 뒤면 봉 주기 길이로 외삽한다.
  4. 첫 봉 앞이면 그리지 않는다. 과거를 더 받으면 나타난다.
  5. 논리 index → x는 `timeScale().logicalToCoordinate()`로 바꾼다.
- 그래서 일봉에서 그은 추세선이 60분봉에서도 같은 시각과 가격에 놓인다(#6 완료 조건).
- 자석으로 붙인 점의 `t`는 봉 시작 시각이다. 60분봉에서는 그날 첫 봉(08:00)에 해당한다. 사용자가 보기에 자연스럽다.

**종목에 붙는다**: 드로잉은 `symbol` 단위로 받는다(`GET /api/drawings?symbol=`). 같은 종목을 연 칸이 여럿이면 모두 같은 드로잉을 보인다. 한 칸에서 고치면 다른 칸도 곧바로 다시 그린다(같은 탭 안은 스토어 공유, 다른 탭은 `data_changed`).

**비교 종목이 있을 때**: % 축이라도 드로잉은 주 종목의 가격으로 고정한다. 좌표 변환은 주 시리즈의 `priceToCoordinate`가 % 모드를 고려해 해 준다.

**알려진 한계**: 액면분할 뒤에는 과거 드로잉이 옛 가격에 남는다(#6). 화면에서 따로 알리지 않는다.

### 3.6 칸 동기화 토글

| 동기화 | 위치 | 기본 | 동작 |
|---|---|---|---|
| 십자선 | 위 막대 칩 `십자선` | 켬 | 한 칸에서 십자선을 움직이면 다른 칸은 그 시각의 봉(없으면 직전 봉)의 종가에 십자선을 둔다. 봉 주기가 달라도 맞춘다 |
| 스크롤 | 위 막대 칩 `스크롤` | 켬 | 같은 봉 주기 칸끼리만 보이는 범위를 맞춘다. 봉 주기가 다른 칸은 따라오지 않는다 |
| 종목 연동 | 칸 범례 머리의 꼬리표 | 칸마다 | 꼬리표를 누르면 켜고 끈다. 연동이 켜진 칸끼리는 종목이 같다. 하나를 바꾸면 모두 바뀐다. 봉 주기는 따라가지 않는다 |

- **연동 그룹**: 백엔드 계약에서 종목 연동은 칸마다 `symbolLink: boolean`이다. 그래서 그룹은 하나다. 꼬리표는 켜짐이면 호박색 `A`, 꺼짐이면 회색 `·`이다. 여러 그룹은 확장 후보로 남긴다.
- **스크롤 동기화의 기준**
  - 시각 범위(`setVisibleRange`)로 맞춘다. 논리 index로 맞추면 안 된다.
  - 칸마다 받은 과거 봉 수가 달라 index가 어긋나기 때문이다.
  - 목업은 데이터 길이가 같아 논리 범위로 간단히 했다.
- **저장 위치**
  - 십자선 동기화는 `Layout.sync.crosshair`에 둔다.
  - 스크롤 동기화는 계약에 자리가 없다. `Layout.sync.scroll`을 요구한다(§6 요구 2).

### 3.7 자동 저장 표시

저장 버튼은 없다. 상태 줄의 한 곳에서 저장 상태를 보인다.

| 상태 | 표시 |
|---|---|
| 바뀐 뒤 1초 기다리는 중, 보내는 중 | `저장 중…` (회색) |
| 성공 | `✓ 자동 저장됨 14:32:08` |
| 실패 | `저장하지 못했습니다: 다시 시도` (빨강 아님, 호박색 버튼). 5초·15초·60초 간격으로 다시 시도한다 |

**보내는 단위와 시점**

| 대상 | 요청 | 시점 |
|---|---|---|
| 레이아웃·차트 설정 | `PUT /api/layouts/:id`, 레이아웃 통째 | 마지막 변경 1초 뒤(#3) |
| 드로잉 | 하나씩 `PUT`/`DELETE` | 즉시 |
| 관심종목 | `PUT /api/watchlist`, 전체 | 즉시 |
| 알림 | 하나씩 `PUT` | 만들기 버튼을 누를 때 |

- **탭을 닫을 때**: 보내지 못한 변경이 있으면 `visibilitychange`(hidden)에서 `fetch(..., { keepalive: true })`로 한 번 더 보낸다.
- **다른 탭의 변경**: `data_changed`를 받으면 해당 쿼리를 무효화한다. 지금 편집 중인 레이아웃이 바뀌었으면 덮어쓰지 않는다. 나중에 쓴 쪽이 이긴다는 계약을 따르고, `다른 창에서 이 레이아웃이 바뀌었습니다: 불러오기` 알림만 띄운다.

### 3.8 알림 만들기

7단계(#8)에서 쓴다. 목업 `desktop-alert-dialog-light.png`.

**여는 곳**
- 위 막대 `알림`(`Alt+A`). 활성 칸의 종목과 봉 주기로 열린다.
- 수평선 드로잉의 막대에서 `알림 만들기`. 가격 알림에 그 가격이 채워진다.
- 범례 지표 줄의 메뉴에서 `이 지표로 알림`. 지표 알림에 그 지표가 채워진다.

**입력과 계약 대응**(`AlertCondition`)

| 입력 | 값 |
|---|---|
| 종류 | `가격 알림` / `지표 알림` |
| 가격 알림 | 조건 `이상`/`이하` → `{ kind: "price", op: "gte"/"lte", target }`. 지금 가격을 옆에 보인다 |
| 지표 알림: 지표 | 이 칸의 지표 목록에서 고른다. 선이 여럿이면 선까지 고른다(MACD의 `macd`/`signal`). `LineRef { spec, line }` |
| 지표 알림: 조건 | `상향 돌파`/`하향 돌파`(값) → `crossValue`. `다른 지표와 교차` → 두 번째 지표 선택칸이 나타나고 `crossLine` |
| 지표 알림: 봉 주기 | 칸의 봉 주기. 바꿀 수 있다 |
| 반복 | `한 번 울리면 끄기`(기본, `once`) / `매번 울리기`(`every`) |
| 받을 곳 | `텔레그램`, `화면 안 알림`(둘 다 기본 켬) |

- **안내문**: 지표 알림은 봉이 확정될 때만 판단하고, 가격 알림은 체결 즉시 판단한다. 대화상자 아래에 이 두 문장을 늘 보인다. 헛알림이 없다는 것을 사용자가 미리 알게 하려는 것이다.
- **화면 안 알림**
  - `alert_fired`를 받으면 오른쪽 아래에 6초 동안 띄운다. 문구는 `AlertEvent.message` 그대로다.
  - 누르면 그 종목을 활성 칸에 연다.
  - 알림 목록(켜기·끄기, 울린 기록)은 위 막대 `알림` 버튼 옆 메뉴의 서랍으로 연다.
- **경고**: `warning: "realtime_limit"`인 알림은 목록에서 호박색 경고 아이콘과 이유를 보인다.

```
├──────────────────────────────┤
│시 … 고 … 저 … 종 … 량 …      │
│— 이동평균 5 …                │
│        (가격 패널)            │  1칸만. 드로잉은 보이기만 함
│──────────────────────────────│
│거래량 …                      │
│──────────────────────────────│
│RSI 14 …   [드로잉 보기 전용] │
├──────────────────────────────┤
```

**되는 것**
- **1칸**: 칸 배치 선택과 동기화 토글은 없다.
- **검색**: 아래 탭의 `검색`. 화면 아래에서 올라오는 시트로 같은 검색을 연다. 초성 검색도 된다. 칩 위의 머리줄 종목 이름을 눌러도 열린다.
- **관심종목**
  - 아래 탭의 `관심종목`을 누르면 전체 화면 목록이 된다. 행을 누르면 그 종목으로 차트 탭에 돌아온다.
  - 행 높이는 44px 이상이다.
  - 순서 바꾸기, 추가, 삭제는 할 수 있다. 길게 눌러 끌기, 왼쪽으로 밀어 삭제다.
- **봉 주기 전환**: 칩 여섯 개(5분, 15분, 60분, 일, 주, 월)를 둔다. 1·3·30분은 칩을 길게 누르면 나오는 메뉴에 둔다.
- **지표 전환**
  - 칩 줄 끝의 지표 버튼으로 시트를 연다. 이 칸 지표들을 켜고 끄며, 지표 종류를 기본값으로 추가하거나 지운다.
  - 설정값 편집은 데스크톱에서 한다. 휴대폰은 "보기 위주"이므로 입력 폼을 줄인다.
- **실시간 갱신**: 데스크톱과 같은 구독과 컨트롤러를 쓴다.

**되지 않는 것**
- **드로잉 편집**
  - 드로잉 primitive를 `editable: false`로 붙인다. 손가락 조작은 모두 차트 이동과 확대에 쓴다.
  - 차트 왼쪽 아래에 `드로잉 보기 전용` 꼬리표를 둔다. 드로잉이 그 종목에 하나 이상 있을 때만 보인다.
- **레이아웃(여러 칸)**: 없다.

**조작**: 끌어 이동, 두 손가락으로 확대, 길게 눌러 십자선, 십자선이 있을 때 탭하면 해제. Lightweight Charts의 기본 터치 처리를 그대로 쓴다.

**휴대폰 차트 상태의 저장 위치**
- 휴대폰에서 종목을 바꿀 때마다 데스크톱 레이아웃의 칸이 바뀌면 안 된다.
- 그래서 휴대폰 칸 하나의 상태 `{ symbol, period, chartSettings }`를 `UiState.phone`에 따로 둔다. 계약의 `UiState`는 아무 키나 받으므로 백엔드를 바꿀 필요가 없다.
- 처음에는 마지막 레이아웃의 첫 칸에서 복사한다.

**머리줄**: 범례의 머리줄과 가격줄은 휴대폰 머리로 올라간다. 칸 안 범례에는 OHLCV 줄과 지표 줄만 남는다.

### 5.2 상태를 어디에 두나

| 상태 | 주인 | 이유 |
|---|---|---|
| 서버 자료(레이아웃 목록, 관심종목, 드로잉, 알림, UiState, 종목 검색) | TanStack Query | 캐시·무효화·재시도. `data_changed` → `invalidateQueries` |
| 지금 편집 중인 레이아웃 | Zustand `layout` | 1초 디바운스 저장 전까지 즉시 반영해야 한다 |
| 활성 칸, 고른 도구, 고른 드로잉, 열린 대화상자 | Zustand `selection` | 저장하지 않는 화면 상태 |
| 드로잉 되돌리기 기록 | Zustand `drawingHistory` | 브라우저 메모리에만(#6) |
| 봉, 현재 봉, 지표 값, 십자선 위치 | **컨트롤러(일반 JS 객체)** | 초당 수십 번 바뀐다. React 상태에 두면 매번 다시 그린다 |
| 관심종목 현재가 | 관심종목 전용 작은 저장소(구독형) | 행마다 `useSyncExternalStore`로 자기 종목만 구독 |

- **브라우저 저장소**: 시세와 지표 값은 어디에도 영구 저장하지 않는다. TanStack Query 영속화 플러그인도 쓰지 않는다. localStorage에는 테마 하나만 둔다. 첫 화면이 깜박이지 않게 하려는 것이다. 원본은 `UiState.theme`이다. 근거는 ADR 0003의 "브라우저는 메모리에만"이다.

### 5.3 Zustand 스토어 나누기


### 5.4 차트 엔진 래퍼: 칸마다 명령형 컨트롤러

```ts
class ChartController {
  constructor(el: HTMLElement, deps: { socket: MarketSocket; indicators: IndicatorClient; sync: SyncBus; theme: ThemeTokens });
  // 칸의 설정을 맞춘다. 바뀐 부분만 반영(diff): 종목·봉 주기가 바뀌면 데이터부터, 지표만 바뀌면 그 지표만
  apply(cell: { symbol: SymbolCode; period: Period; settings: ChartSettings }): void;
  setTheme(t: ThemeTokens): void;           // 모든 시리즈·primitive 색 다시 적용
  setDrawings(list: Drawing[], editable: boolean): void;
  setActive(active: boolean): void;
  dispose(): void;                          // 구독 해지, 워커 엔진 해제, chart.remove()
}
```

**React와의 경계**
- `features/grid/ChartCell.tsx`는 `useEffect`로 컨트롤러를 만들고, 칸 설정이 바뀌면 `apply`만 부른다.
- 이 컴포넌트는 봉 데이터를 props로 받지 않는다.
- 범례와 지표 패널 범례의 DOM도 컨트롤러가 만들고 고친다(§2.3).

**데이터 흐름**(한 칸, 백엔드 §8.3의 권장 순서)

```
apply(symbol, period)
  ├─ socket.subscribe(sub, symbol, period) ──► bar/confirmed를 버퍼에 쌓기 시작
  ├─ GET /api/bars (최신 페이지) ───────────► bars + current
  ├─ upsert(bars, current, 버퍼)  → series.setData(전체)            ← 처음 한 번만 setData
  ├─ indicators.create(spec들, 확정 봉 열)   → 지표 시리즈 setData
  └─ 이후 WebSocket:
       bar        → series.update(bar)         ← React 렌더 없음
                    indicators.preview(bar) → 지표 시리즈 update(마지막 점)
                    범례가 마지막 봉을 보고 있으면 범례 DOM 갱신
       confirmed  → series.update(bar); indicators.pushConfirmed(bar)
       reload     → from 이후 버리고 최신 페이지 다시 받기 → setData
과거로 스크롤(subscribeVisibleLogicalRangeChange, 왼쪽 끝이 50봉 안으로 들어오면)
  └─ GET /api/bars?before=nextBefore → 앞에 붙여 setData, 보이는 범위 유지
     → indicators.create로 다시 만든다(EMA 계열은 앞이 바뀌면 덧붙일 수 없다: 백엔드 §9.2)
```

- **갱신 묶기**: 같은 프레임에 여러 메시지가 오면 `requestAnimationFrame` 한 번에 묶어 마지막 값만 `update`한다. 서버가 이미 구독당 초당 10회로 줄여 보내지만, 4칸에 비교 종목까지 열면 초당 100회가 넘을 수 있다.
- **시각 변환**
  - 계약의 `t`는 진짜 Unix 초다. Lightweight Charts는 UTC로 표시한다.
  - 그래서 시리즈에 넘길 때 `t + 32400`(KST)을 쓴다. 이 변환은 `chart/time.ts` 한 곳에만 둔다.
  - 드로잉 점과 알림 시각을 서버에 보낼 때는 반드시 원래 `t`로 되돌린다(백엔드 §13-8).
  - 목업은 처음부터 한국 벽시계를 UTC 초로 만들었다. 그래서 이 변환이 없다.
- **일·주·월봉의 time**: 정수 초를 그대로 쓴다. `BusinessDay` 객체를 섞지 않는다. 드로잉 좌표 변환과 칸 사이 시각 비교가 모두 같은 숫자 축 위에서 이뤄진다.

### 5.5 `chartSettings`의 모양(프런트엔드 소유)

계약은 `Pane.chartSettings: unknown`으로 두고 프런트엔드가 모양을 정하게 했다. 다음과 같이 정한다.

```ts
interface ChartSettings {
  v: 1;                                     // 모양 버전. 바꾸면 불러올 때 이주
  style: "candle" | "bar" | "line" | "area";
  scale: "normal" | "log";                  // 비교 종목이 있으면 화면에서는 %로 그린다(저장 값은 그대로)
  indicators: IndicatorConfig[];            // 그리는 순서
  compare: SymbolCode[];                    // 0~3개
  panels: { id: Uuid; stretch: number }[];  // 지표 패널 순서와 높이 비율. 가격 패널은 늘 맨 위
}
interface IndicatorConfig {
  id: Uuid;
  spec: IndicatorSpec;                      // 계약 §8.2 그대로. 알림에 그대로 넘긴다
  panel: "price" | Uuid;                    // 가격 패널 또는 panels[].id
  visible: boolean;
  style: { colors: string[]; width: 1 | 2 | 3 };  // colors는 토큰 이름("ind-2")으로 저장해 테마를 따라가게 한다
}
```

- **불러올 때의 검사**: 서버에서 받은 `chartSettings`는 경계에서 한 번 검사한다(zod). 모양이 틀리면 기본 설정으로 열고 콘솔에 남긴다.
- **크기**: 64KB 제한은 지표 수십 개로도 넘지 않는다.

### 5.6 WASM 지표를 불러오는 방식

- **빌드**: `wasm-pack build crates/indicators --target web --features wasm --out-dir web/src/wasm/indicators`.
  - 결과물(`indicators_bg.wasm`, JS 접착 코드)은 저장소에 커밋하지 않는다. `web` 빌드 스크립트가 먼저 만든다.
- **불러오기**
  - Web Worker 하나(`chart/indicators/worker.ts`, Vite `new Worker(new URL(…), { type: "module" })`)가 접착 코드의 `init(wasmUrl)`을 한 번 부른다.
  - wasm 파일은 Vite의 `?url` import로 해시 붙은 정적 파일이 된다. `vite-plugin-wasm` 같은 플러그인은 필요 없다.
  - 서버는 `.wasm`을 `application/wasm`으로 내보내야 한다. 그래야 `instantiateStreaming`이 동작한다(§6 요구 4).
- **워커 안의 상태**
  - `Map<engineKey, WasmEngine>`. `engineKey`는 `(칸, 지표 id)`다.
  - 메인 스레드는 봉 열을 `Float64Array` 여섯 개로 전송(transfer)한다.
- **메시지**

| 메시지 | 응답 |
|---|---|
| `create(key, specJson, cols)` | 선 전체. `Float64Array[]`와 `shift[]` |
| `pushConfirmed(key, bar)` | 없음 |
| `preview(key, bar)` | 선마다 마지막 값 |
| `futureStarts(period, lastStart, n)` | 일목 선행스팬용 미래 시각 |
| `dispose(key)` | 없음 |

- **현재 봉 갱신**
  - 체결마다 `preview`만 부르고 마지막 점만 `series.update`한다(#5 "그 봉에 걸린 값만 다시 계산").
  - 일목 선행스팬은 `shift` 뒤 미래 위치의 값이 바뀐다. 그 위치에 해당하는 빈 자리 시각으로 `update`한다.
- **일목균형표 선행스팬**
  - 선행스팬은 마지막 봉 뒤 25봉(`displacement − 1`)까지 그려진다.
  - Lightweight Charts의 시간축은 데이터에 있는 시각까지만 있다. 그래서 주 시리즈 끝에 `futureStarts`로 만든 빈 자리(`{ time }`만 있는 whitespace) 25개를 붙인다. 목업도 같은 방식이다.
  - 일목균형표를 지우면 빈 자리도 걷는다.
  - 현재 봉이 확정되어 새 봉이 생기면 빈 자리를 하나 밀어낸다.
- **타입**: `indicators` 크레이트의 `Spec`과 계약의 `IndicatorSpec`은 같은 정의다(ts-rs). 워커에는 `JSON.stringify(spec)`을 넘긴다.
- **목업과의 차이**: 목업의 `data.js` 지표 함수는 화면을 그리려고 만든 대역이다. 실제 앱에서는 쓰지 않는다.

## 6. 백엔드에 기대하는 것

`docs/design/backend.md` §8(브라우저 계약)과 §9(지표 크레이트 API)를 그대로 따른다. 이 문서의 타입 이름은 그 절과 같다. 계약을 새로 정의하지 않는다. 아래는 계약에 없거나 더 분명해야 하는 것만 적은 요구 목록이다. 코디네이터가 맞출 때 쓰도록 우선순위를 붙였다.

1. **초성 검색**(필수, 1단계)
   - `GET /api/symbols?q=`에서 `q`가 모두 한글 자음이면 종목명 초성열에 대해 접두 일치를 먼저, 포함 일치를 다음으로 찾는다.
   - 순위는 §3.1과 같다.
   - 응답 모양은 바뀌지 않는다.
2. **스크롤 동기화 저장**(필수, 6단계)
   - `Layout.sync`에 `scroll: boolean`을 더한다. 기본은 `true`다.
   - 백엔드 §7의 `sync jsonb` 칸에 들어가므로 스키마 변경은 없고 타입만 바뀐다.
3. **`Layout.panes` / `Pane` 이름**(권장)
   - 계약의 `Pane`은 용어집의 **칸**이다. 용어집은 칸에 대해 "패인"을 _Avoid_로 두었고, 프런트엔드는 Lightweight Charts의 `pane`(= 용어집의 **패널**)을 따로 쓴다.
   - 같은 코드 안에서 `Pane`이 둘을 뜻하게 된다.
   - 제안: `cells: Cell[]`(또는 `slots`)로 바꾼다. 바꾸지 않으면 프런트엔드는 `generated.ts`를 가져올 때 `type Cell = Pane`으로 별칭을 둔다.
4. **정적 파일**(필수, 1단계)
   - `.wasm`은 `Content-Type: application/wasm`으로 내보낸다.
   - 해시가 붙은 정적 파일(`/assets/*`)은 `Cache-Control: immutable`을 붙인다.
   - SPA 경로(`/layout/*`, `/alerts`)는 `index.html`로 되돌린다.
5. **`UiState`의 자유 키**(확인)
   - 프런트엔드는 `UiState`에 `watchCollapsed: boolean`, `phone: { symbol, period, chartSettings }`를 둔다.
   - 계약의 `[k: string]: unknown`으로 받아 주는지 확인한다(64KB 제한이 있으면 알려 달라).
6. **`chartSettings`에 담긴 `IndicatorSpec`의 검증**(확인)
   - 서버는 `chartSettings`를 그대로 저장한다고 했다. 알림을 만들 때는 브라우저가 `spec`을 꺼내 `LineRef`로 넘긴다.
   - 서버가 `Spec::validate`로 다시 검사하고, 틀리면 `bad_request`에 사람이 읽는 `message`를 담아 주기를 기대한다. 대화상자가 그 문장을 그대로 보인다.
7. **WebSocket `hello.protocol`**(확인)
   - 브라우저가 아는 `protocol`과 다르면 화면 위에 `새 버전이 있습니다: 새로고침`을 띄운다.
   - 서버를 다시 배포한 뒤 열려 있던 탭을 위한 것이다.
8. **분봉의 미래 시각**(확인)
   - 일목균형표를 분봉에 띄울 때도 `future_bar_starts`가 08:00~20:00 밖을 건너뛰는지 확인한다(백엔드 §9.3에 그렇게 적혀 있다).
   - 그래야 정규장 밖 봉을 따로 칠하지 않는다는 결정과 시간축이 맞는다.

계약에 이미 있어서 그대로 쓰는 것: upsert 규칙, `reload` 세 가지 이유, `confirmed` 보장, 관심종목 `quotes`, `data_changed`, `ConnectionStatus`, 레이아웃 복제를 새 id로 `PUT`하는 방식, 드로잉 점 `{ t, price }`, 알림 조건 타입.

## 7. 접근성 기본

### 7.1 키보드 조작

- 마우스로 하는 일은 모두 키보드로도 할 수 있다(§3.2 표). 예외는 드로잉의 자유로운 점 찍기다.
  - 대신 키보드 드로잉을 둔다: 십자선을 `←→`로 봉 단위로 옮기고, `↑↓`로 가격을 호가 단위로 옮긴 뒤 `Enter`로 점을 찍는다.
- **초점 이동 순서**: 위 막대 → 왼쪽 도구 → 칸 1…n → 관심종목 → 상태 줄.
  - 칸은 `tabindex=0`인 `section`이고 `aria-label`은 `칸 1: 삼성전자 5분`이다.
  - 왼쪽 도구는 `role="toolbar"`에 `aria-orientation="vertical"`이고, 화살표로 이동한다(roving tabindex).
- **초점 표시**: 모든 초점은 `:focus-visible`에서 호박색 2px 외곽선으로 보인다. 칸은 활성 칸 테두리가 그 역할을 한다.
- **대화상자**
  - `role="dialog"`, `aria-modal="true"`, 제목으로 `aria-labelledby`를 건다.
  - 열면 첫 입력칸에 초점을 두고 초점을 안에 가둔다. 닫으면 연 버튼으로 초점을 돌린다. `Esc`로 닫는다.
- **목록**
  - 검색 결과와 지표 종류 목록은 `role="listbox"`/`option`이고 `aria-selected`를 쓴다.
  - 입력칸에는 `aria-activedescendant`를 둔다.
- **화면 읽기 프로그램**
  - 범례는 십자선을 따라 너무 자주 바뀌므로 `aria-live`를 걸지 않는다. 대신 칸에 초점이 있을 때 `←→`로 봉을 옮기면, 별도의 숨은 `aria-live="polite"` 영역에 `2026-11-06 종가 85,400 하락 0.58%`를 한 번 읽힌다.
  - 화면 안 알림(`alert_fired`)은 `role="status"`다.

### 7.2 두 테마의 대비

WCAG 2.2 대비를 계산했다. 기준은 본문 4.5:1, 큰 글자·그래픽 3:1이다.

| 전경 | 다크(`--chart-bg` / `--bg`) | 라이트(`--chart-bg` / `--bg`) |
|---|---|---|
| `--text` | 13.75 / 14.32 | 16.06 / 14.49 |
| `--text-2` | 6.55 / 6.82 | 7.05 / 6.36 |
| `--text-3` | 4.85 / 5.05 | 5.27 / 4.76 |
| `--up` | 5.02 / 5.23 | 5.51 / 4.98 |
| `--down` | 5.30 / 5.52 | 5.65 / 5.10 |
| `--accent` | 8.47 / 8.82 | 5.25(`--bg`) |
| `--accent-ink` on `--accent` | 9.07 | 5.98 |

- **조정 이력**: 초안의 `--text-3`(다크 3.79, 라이트 4.03), 라이트 `--up`(`--bg` 위 4.49), 라이트 `--accent`(`--bg` 위 4.68)가 4.5에 못 미쳤다. 그래서 값을 고쳤다. 지금 표는 고친 값이다.
- **빨강과 파랑의 구분**
  - 상승 빨강과 하락 파랑은 서로의 밝기 대비가 1.06(다크), 1.14(라이트)뿐이다. 적록·청황 색약에서 밝기로는 구분되지 않는다.
  - 그래서 색에만 기대지 않는다.
    - 모든 등락 수치에 부호(`+`/`−`)를 붙인다(§1.3).
    - 캔들은 몸통 위치(시가·종가)로도 방향이 보인다.
    - 관심종목 스파크라인은 기울기로 방향이 보인다.
  - 확장 후보: "상승 봉 속 비우기" 설정.
- **지표 선**: 다섯 기본 색은 차트 바탕 위에서 모두 3:1을 넘는다. 이름과 색 견본이 범례에 함께 있어 색만으로 구분하지 않는다.
- **움직임**: `prefers-reduced-motion`이면 연결 상태 점의 맥박을 멈춘다. 그 밖에 저절로 움직이는 장식은 없다.

## 8. 용어·ADR 제안

GLOSSARY.md와 ADR은 고치지 않았다. 아래는 제안이다.

### 용어

- **십자선**(새 용어 제안): 차트 위에서 마우스나 손가락이 가리키는 시각과 가격을 보여 주는 가로·세로 선. 동기화의 대상이다. _Avoid_: 크로스헤어, 커서.
- **범례**(새 용어 제안): 칸 왼쪽 위에 십자선이 가리키는 봉의 시·고·저·종·거래량과 지표 값을 적은 글자 영역. _Avoid_: 레전드, 데이터 창.
- **활성 칸**(새 용어 제안): 위 막대의 봉 주기·지표·비교 종목 조작이 적용되는 칸. 한 레이아웃에 하나다.
- **종목 연동**(새 용어 제안): 연동을 켠 칸들이 같은 종목을 보이게 하는 것. 봉 주기는 연동하지 않는다. _Avoid_: 심볼 링크, 그룹 링크.
- **자석 모드**(새 용어 제안): 드로잉의 점을 가까운 봉의 시가·고가·저가·종가에 붙이는 것. _Avoid_: 스냅.
- **초성 검색**(새 용어 제안): 종목명의 첫 자음만으로 종목을 찾는 것.
- **연결 상태**(새 용어 제안): 키움 실시간 연결과 브라우저↔서버 연결의 상태를 함께 이르는 말. 백엔드 `ConnectionStatus`와 같다.
- **지표 패널 / 가격 패널**: 이미 **패널** 항목에 쓰였다. 따로 표제어로 두기를 제안한다. 이 문서는 두 말을 그대로 쓴다.
- **"멀티 차트"**: 과제 문구와 이슈 #7 본문에 남아 있지만, 용어집에서는 레이아웃의 _Avoid_다. 이슈 #7 제목의 "멀티 차트 레이아웃"을 "여러 칸 레이아웃"으로 바꾸기를 제안한다.
- **"패인"과 계약의 `Pane`**: §6 요구 3.
- **라이브러리 표기의 "TradingView"**: 용어집은 화면 이름으로 "트레이딩뷰"를 _Avoid_로 두었다. 상태 줄의 라이브러리 이름 표기는 라이선스가 요구하는 고유명사라 예외로 둔다는 한 줄을 용어집에 더하기를 제안한다.

### ADR

- **휴대폰 차트 상태를 레이아웃과 따로 둔다**(새 ADR 후보)
  - 휴대폰에서 종목을 바꿔도 데스크톱 레이아웃이 바뀌지 않게 한다. 상태는 `UiState.phone`에 둔다(§4).
  - 화면 동작에 관한 결정이고 되돌리기 쉬워서 ADR까지 갈지는 코디네이터 판단에 맡긴다.
- **ADR 0003 "브라우저는 메모리에만"**
  - 이 설계는 테마 하나만 localStorage에 둔다. 첫 화면이 깜박이지 않게 하려는 것이다.
  - 시세가 아닌 화면 설정이라 ADR의 뜻과 부딪히지 않는다고 본다. ADR에 "시세와 지표 값은"이라고 범위를 적어 두면 분명해진다.
- **ADR 0002 "같은 코드로 어긋나지 않는다"**
  - 브라우저는 과거로 스크롤할 때마다 EMA 계열 지표를 새 입력 길이로 다시 계산한다(§5.6). 그래서 화면의 지표 값이 스크롤에 따라 아주 조금 바뀔 수 있다.
  - 백엔드 §14의 제안과 같은 단서다. 프런트엔드는 따로 맞추지 않는다.

## 9. 열린 질문

1. **스토캐스틱 슬로우 기본값**
   - 백엔드 §13-4를 따라 5·3·3으로 두었다. 목업도 맞췄다.
   - 해외 관행 14·3·3으로 바꾸면 대화상자 기본값만 바뀐다.

   - v1은 지표 하나가 지표 패널 하나를 차지한다.
   - RSI와 스토캐스틱을 한 패널에 겹치는 기능은 미뤘다. `IndicatorConfig.panel`이 패널 id를 가리키므로 나중에 모양을 바꾸지 않고 넣을 수 있다.
3. **칸 경계 끌기**
   - 칸 배치 비율은 고정이다.
   - 끌어 바꾸려면 `Layout`에 비율을 둘 자리가 필요하다(계약 변경).
4. **휴대폰에서 1·3·30분**: 칩 대신 길게 누르기 메뉴에 두었다. 자주 쓴다면 칩을 늘린다.

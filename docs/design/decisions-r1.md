# 설계 1차 수정 결정 (코디네이터, 2026-11-08)

W4 교차 리뷰(`review-w4.md`)에서 코디네이터 담당으로 분류된 지적과, 사용자가 정한 사항을 모았다. 백엔드(`backend.md`)와 프런트엔드(`frontend.md`)는 **아래 이름과 규칙을 글자 그대로** 쓴다. 이 문서와 설계 문서가 다르면 이 문서를 따른다.

## 사용자가 정한 것
- **U1. 분봉은 최근 1년만**(ADR 0003)
  - 분봉 차트는 마지막 관측일로부터 1년까지만 보여 준다. 캐시에 그보다 오래된 분봉이 있어도 돌려주지 않는다.
  - 백엔드: 분봉 조회 하한을 두고, `nextBefore`는 그 하한에서 `null`이 된다.
  - 프런트: 과거로 스크롤하다 끝에 닿으면 "분봉은 최근 1년까지" 안내를 띄운다.
- **U2. 가격 알림은 교차로 판단**(용어집 "가격 알림", W4-34)
  - 가격이 정한 값을 **새로 넘어설 때** 울린다.
  - `op: "gte"`이면 직전 기준 가격이 `target` 미만이었다가 `target` 이상인 체결이 들어올 때 울린다. `lte`는 그 반대다.
  - 직전 기준 가격은 알림을 만든 순간의 현재가에서 시작한다. 그래서 만들 때 이미 넘어 있으면 다시 반대편으로 갔다가 넘어올 때까지 울리지 않는다.
  - 프런트: 만들기 화면에서 "이미 넘어 있음"을 알린다.

## 코디네이터 결정

### D1. 스냅숏과 실시간 갱신의 순서 (W4-08)
- **`seq` 번호**: 서버는 (종목, 봉 주기) 흐름마다 하나씩 늘어나는 `seq: number`를 붙인다. `bar`, `confirmed`, `reload` 메시지와 `subscribed` 메시지 모두에 붙인다.
- **`BarsPage.seq`**: REST 최신 페이지(`BarsPage`)에 `seq: number | null`을 더한다. 그 스냅숏이 반영한 마지막 `seq`다. 실시간이 없는 단계와 과거 페이지에서는 `null`이다.
- **브라우저의 처리 순서**
  1. `subscribe`를 보낸다.
  2. 그 구독의 메시지를 버퍼에 쌓는다.
  3. REST 최신 페이지를 받아 적용한다.
  4. 버퍼에서 `seq > page.seq`인 메시지만 차례로 적용하고 나머지는 버린다.
- **과거 페이지**: 확정 봉만 담는다. 이미 가진 봉보다 늦은 `t`를 덮어쓰지 않는다.
- **오래된 응답 버리기**(브라우저 내부): 칸마다 시리즈 세대 번호를 둔다. `reload`가 오거나 종목·봉 주기가 바뀌면 세대를 올리고, 이전 세대의 REST 응답과 WASM 결과는 버린다.

### D2. 브라우저 재연결 (W4-11)
- 브라우저와 서버의 WebSocket이 다시 연결되면(새 `hello`), 칸마다 시리즈를 **모두 비우고 최신 페이지부터 다시 만든다**. 과거로 스크롤해 받아 둔 구간은 버린다. 드로잉은 따로 저장되므로 영향이 없다.
- "`confirmed`를 빠짐없이 보낸다"는 보장은 **연결이 살아 있는 동안**에만 적용된다.

### D3. 단계별로 켜지는 기능 (W4-18)
두 설계 문서에 아래 표를 넣고, 각 절이 어느 단계에서 켜지는지 표시한다. 단계 번호는 이슈 번호다.

| 이슈 | 단계 | 켜지는 것 | 아직 없는 것 |
|---|---|---|---|
| #2 | 1단계 기반 | 1칸 고정, REST `/api/symbols`·`/api/bars`, 캐시, 키움 조회 대기열, 차트 설정은 브라우저 메모리에 | WebSocket, WASM, 사용자 자료 DB |
| #3 | 2단계 저장 | 사용자 자료 스키마, 기본 레이아웃 마이그레이션, 관심종목, `UiState`, 자동 저장. 관심종목 현재가는 REST 조회 | WebSocket |
| #4 | 3단계 실시간 | WebSocket, 구독, 현재 봉 집계, `seq`, 분봉 | |
| #5 | 4단계 지표 | WASM 지표, 비교 종목 | |

### D4. #2 완료 조건 (W4-19)
이슈 #2를 코디네이터가 고친다.
- 같은 날 대조를 마친 캐시는 과거 전체를 다시 받지 않고 바로 보인다.
- 다음 날 처음 열 때는 일봉 1회 대조 뒤에 보인다.

### D5. 종목 검색 (W4-20)
- **정규화**: 앞뒤 공백을 자르고, 안쪽 공백을 지우고, 영문은 대문자로 바꾼다. 빈 입력이면 서버는 `[]`를 돌려준다.
- **빈 입력일 때 화면**: 브라우저가 관심종목과 최근 본 종목을 보여 준다. 서버는 부르지 않는다.
- **초성 검색**: 입력이 모두 한글 자음(ㄱ~ㅎ)일 때만 쓴다. 종목명의 초성열과 비교한다.
- **순위**: 코드 완전 일치 > 이름 완전 일치 > 코드 접두 > 이름 접두 > 초성 접두 > 이름 포함 > 초성 포함.
- **같은 순위 안**: 지수 > 보통주 > 우선주 > ETF > 리츠 순, 그다음 이름 가나다순.
- **개수**: 최대 20개.

### D6. 지표 설정 검증 바인딩 (W4-24)
- **WASM 공개 함수**: `validateSpec(specJson: string): SpecValidation`
  ```ts
  type SpecValidation = { ok: true } | { ok: false; errors: { field: string; message: string }[] }
  ```
  `message`는 사람이 읽는 한국어 문장이다.
- **서버 검사**: 알림을 만들 때 서버는 spec과 `LineRef`의 조합도 검사한다(이동평균 지표에 `rsi` 선을 고르면 안 된다). 틀리면 `bad_request`와 한국어 `message`를 돌려준다.

### D7. 지표 알림의 계산 입력 (W4-26)
- 봉이 확정될 때마다 **가장 최근 N개의 확정 봉**으로 처음부터 다시 계산한다. N = max(warmup × 4, 500). 서버가 이전 계산 상태를 이어 가지 않으므로, 재시작해도 같은 입력이면 같은 결과다.
- 화면은 불러온 봉 전체로 계산하므로 EMA 계열 값이 알림 값과 아주 조금 다를 수 있다. 이 점을 문서에 그대로 적는다.

### D8. 이동된 선은 알림에서 제외 (W4-27) — 사용자 확정(2026-11-08)
- 이동량이 0이 아닌 선(일목 선행스팬 A·B, 후행스팬)은 v1 알림의 선택지에서 뺀다.
- 화면에는 비활성으로 보이고 이유를 적는다.
- 서버도 그런 `LineRef`를 거절한다.

### D9. 실시간으로 만든 봉으로 바로 알림 (W4-30) — 사용자 확정(2026-11-08)
- **빠른 알림**: v1은 실시간으로 만든 확정 봉으로 바로 판단해 알린다.
- **기록**: 알림이 울릴 때마다 (알림 id, 봉 시작 시각 `t`, 봉 출처)를 남긴다.
- **중복 금지**: 같은 (알림, `t`)로는 두 번 울리지 않는다.
- **소급 없음**: 나중에 봉 출처가 바뀌거나 끊긴 구간을 메우거나 재시작해도 정정하거나 다시 울리지 않는다.
- **알림 기록 화면**: 봉 출처를 보여 준다.

### D10. 이름과 용어 정리 (W4-21, W4-33)
- **이름 변경**: `Layout.panes: Pane[]` → `Layout.cells: Cell[]`, 타입 `Pane` → `Cell`. 코드에서 `pane`은 Lightweight Charts의 패널만 뜻한다.
- **동기화 설정**: `Layout.sync: { crosshair: boolean; scroll: boolean }`. 둘 다 기본값은 `true`다.
- **`UiState` 크기**: 64KB 제한을 적용한다. 서버는 모르는 키를 버리지 않고 그대로 왕복시킨다.
- **이미 반영된 제안 지우기**: 용어집과 ADR에 이미 들어간 것은 각 문서의 "용어·ADR 제안" 절에서 지운다. 봉 출처, 현재가, 구독, 활성 칸, 종목 연동, 자석 모드, 모의 키 흔적, ADR 0001·0002·0003 문구가 그렇다.
- **용어**
  - 진행 중인 봉은 "현재 봉", 그리지 않는 자리는 "빈 시각(whitespace)"으로 구별해 쓴다.
  - "과거 봉" 대신 "과거 구간의 확정 봉"이라고 쓴다.
  - '캔들·바'는 차트 형태 이름이고, 개념으로서의 봉과 구별한다.

### D12. 추가 결정 (프런트 1차 수정에서 나온 질문)
- **`reload`를 받으면**: 칸의 시리즈를 통째로 비우고 최신 페이지부터 다시 만든다. D2와 같은 방식이다. `from` 이후만 바꿔 끼우는 최적화는 하지 않는다.
- **#2의 `BarsPage`**: `current`는 키움 조회가 준 오늘 봉(진행 중 구간), `seq`는 `null`이다.
- **같은 순위 안 이름 순서**: 한글 음절이 라틴 문자보다 앞이다. 그다음 각각 가나다순, 알파벳순이다.
- **`AlertEvent`의 봉 필드**: 판단에 쓴 봉의 시작 시각은 `barT: UnixSeconds`, 출처는 `barSource`로 한다. `barSource` 값은 백엔드 `BarSource`의 직렬화 이름을 그대로 쓴다.
- **`future_bar_starts` 테스트**: 주봉과 월봉 경계(연말, 월말이 주말인 경우)도 테스트에 넣는다.

### D13. 백엔드 1차 수정의 확인 요청 처리
- **불완전한 봉의 알림**(D9 예외): 실시간으로 만든 봉이 불완전하다고 표시되면(`needs_verify`), 키움 조회로 교체된 뒤 판단한다. ADR 0005에 반영했다.
- **가격 알림의 기록 필드**: `barT`는 체결이 속한 1분 구간의 시작이고, `barSource`는 언제나 `realtime`이다. 그대로 받아들인다.
- **토큰을 장 밖에서 미리 발급**: 하루 한 번 장이 끝난 뒤 발급한다. ADR 0004 문구를 이에 맞게 고쳤다.
- **계약 추가**: `Alert.priceReference`(읽기 전용), `ApiError` `payload_too_large`, `ApiId::Ka10100`을 받아들인다.
- **스팩**: 코스닥 보통주로 분류한다.
- **`pushConfirmed`가 `Tail`을 돌려준다**: 프런트는 `preview` 없이 이 반환값으로 확정 순간의 최종 값을 쓴다.

### D14. 시세 캐시는 메모리에만 (사용자 확정, ADR 0003 개정)
- **Postgres `cache` 스키마를 없앤다.** 확정 봉은 서버 메모리에만 둔다. 서버를 다시 켜면 빈 상태로 시작해 차트를 열 때 키움에서 받는다.
- **메모리에서 내리기**: 시리즈를 보는 곳이 없어지고 10분 뒤에 내린다. 매일 07:45에는 모두 버린다.
- **없애는 것**
  - 수정주가 대조(adjust_checked)
  - 캐시 세대 번호(epoch)
  - 종목별 DB 쓰기 잠금
  - 캐시 구간(coverage) 테이블
  - 종목 목록 테이블. 종목 목록도 메모리에 두고, 서버를 켤 때와 매일 07:45에 키움에서 받는다.
- **남기는 것**: 출처 교체, 끊긴 구간 메우기, 조회 대기열, 같은 요청 합치기는 메모리 위에서 그대로 한다.
- **서버를 하나만 띄우는 장치**: Postgres advisory lock 대신 잠금 파일(`flock`)을 쓴다(ADR 0004).
- **Postgres**: #3(사용자 자료)부터 쓴다. #2에는 Postgres가 없다.
- **#2 완료 조건**: 서버를 다시 켜도 차트가 몇 초 안에 다시 뜬다(키움에서 다시 받음).

### D15. 사용자 자료는 SQLite (사용자 확정, ADR 0006)
- Postgres와 Docker를 쓰지 않는다. 사용자 자료는 `data/vally.db`(SQLite, WAL 모드, git 제외)에 둔다. sqlx의 sqlite 기능과 sqlx 마이그레이션을 쓴다.
- #3에서 처음 만든다. #2에는 DB가 없다.
- 스키마는 SQLite에 맞춘다.
  - `jsonb`는 JSON 텍스트로, `uuid`는 텍스트로, 시각은 정수(Unix 초)로 둔다.
  - 부분 유일 인덱스는 SQLite도 지원하므로 그대로 쓴다.

### D16. hoga-ops 근거로 확인한 실시간 동작 (docs/kiwoom.md 11절)
- **확인됨**
  - `_AL` 0B는 KRX와 NXT 체결을 한 흐름으로 준다. "차트는 언제나 통합 시세"를 유지한다.
  - `9081`은 문자열 `KRX`/`NXT`다.
  - 0B 필드는 명세대로다. 15의 부호가 체결 방향이고, 20은 실제 체결 시각이다.
  - 15:30 종가 단일가는 15:30:00대의 대량 체결 한 건으로 온다. 09:00 시가 단일가는 첫 체결 시각이 속한 분 봉에 들어간다(예: 09:02).
- **설계를 고칠 것** (#4에서 반영. backend.md는 #2 병합 뒤 고친다)
  - **20:00 경계**: 20:00:00~20:00:03 체결도 온다. 키움 REST는 이를 19:59 봉에 넣는다. backend.md §3.1의 "20:00 이후는 오지 않는다"는 틀렸다. 체결 창 끝에 몇 초의 유예를 두고, 그 체결은 19:59 봉으로 보낸다.
  - **0J 가격**: 0J 지수 가격은 100배 정수가 아니라 부호가 붙은 소수 문자열이다. REST 지수(100배 정수)와 파서를 따로 둔다.
  - **토큰과 세션**
    - 새 토큰을 받아도 WebSocket은 끊기지 않는다. 대신 옛 토큰으로 보낸 REST는 `[8005]`로 실패한다. 그래서 새 토큰은 모든 REST 요청에 즉시 적용한다.
    - 같은 앱키로 두 번째 LOGIN을 하면 기존 세션이 끊긴다(close 1000 'Bye'). 그래서 서버 하나 원칙(ADR 0004)을 지킨다.
- **아직 장중 확인이 필요한 것** (#4로 넘김)
  - 하루 끝의 0B 누적거래량(13)과 일봉 거래량의 관계

# W4 설계 교차 리뷰

검토 대상: 백엔드·프런트엔드 설계, 정적 목업과 스크린샷 8개, ADR 0001~0004, 용어집, `docs/kiwoom.md`, GitHub 이슈 #1~#12. 이슈는 `gh issue view N --json number,title,body,comments`로 읽었다. 이 리뷰의 기반 착수 대상은 **#2**다(현재 #12의 명칭은 “1단계: 기반”). 표의 `backend.md`·`frontend.md`는 `docs/design/` 아래 파일, `kiwoom.md`는 `docs/kiwoom.md`다. 문서의 줄 번호는 검토 시점 기준이다. 검토 중 다른 작업에서 반영된 ADR 0003의 최근 1년 제한과 용어집의 가격 알림 정의도 마지막에 다시 대조했다.

**높음**은 가격·봉·알림을 잘못 만들거나 핵심 계약을 깨는 문제, **중간**은 구현자가 서로 다른 동작을 선택하게 되는 누락·충돌, **낮음**은 범위·용어·불필요한 비용 문제다. 뒤 단계의 지적도 계약은 지금 정하되, 구현은 해당 이슈에서 한다. 코드가 없는 설계 검토이므로 실제 구현 결함으로 단정하지 않았고, 관측되지 않은 실행 결과는 “추측”으로 표시했다.

## 사용자 결정이 필요한 것

이미 알려진 “분봉 1년 한계와 ADR 0003”은 다시 올리지 않는다. 최신 ADR 0003 L17은 최근 1년만 보여 주기로 정했으므로, 백엔드 §6.3의 `reached_origin`뿐 아니라 캐시에 남은 오래된 봉에 대한 조회 하한도 그 결정에 맞춰야 한다. 다음 두 항목은 기술적인 이름 맞추기를 넘어 알림의 뜻을 바꾼다.

1. **조회 검증 전 확정 봉으로 즉시 알릴 것인가.** W4-30. 실시간으로 만든 봉은 뒤에 값이 바뀔 수 있다. 빠른 알림을 택하면 정정/소급 재발화 여부를 정해야 하고, 조회 검증 뒤 판단을 택하면 4회 대기열에 따른 지연을 받아들여야 한다. 제안: v1은 빠른 알림을 유지하되 판단 당시 봉 출처를 기록하고, 같은 알림·봉의 재발화는 막는다. 정확도에 대한 기대는 사용자 결정으로 남긴다.
2. **일목 선행·후행 선의 알림은 계산 시점과 표시 시점 중 무엇을 비교할 것인가.** W4-27. `spanA`를 ‘오늘 계산해 미래에 그리는 값’으로 볼지 ‘오늘 위치에 그려진 과거 계산값’으로 볼지에 따라 울리는 날이 달라진다. 제안: v1은 이동량 0인 선만 알림에서 고르게 하고 이동된 선은 후속 범위로 미룬다.

스토캐스틱 기본값, 일목 기본 이동량, 공휴일 미래 시각 오차는 설계가 이미 기본값/한계를 제시했으므로 새로운 사용자 결정으로 재등록하지 않았다. 나머지 지적은 코디네이터·구현 담당자가 기존 ADR과 범위 안에서 해결할 수 있다.

## 검토 증거와 경계

- 정적 목업은 스크린샷 8개와 `index.html`, `styles.css`, `app.js`, `data.js`의 관련 경로를 대조했다. 목업의 가짜 값·한국 벽시계 시각·일봉에서 만든 주봉은 명시된 대역이므로 그 자체를 ADR 위반으로 세지 않았다. 반대로 같은 길이의 가짜 시계열은 W4-08·11·28~29를 검증하지 못한다.
- 덮어쓰기의 비가환성은 로컬 Node에서 확인했다. 같은 `t`에 `c=100`, `c=105`를 Map upsert하면 적용 순서에 따라 결과는 105 또는 100이다. 210ms 간격 `[0,210,420,630,840]`도 1초 안에 5회다. 이는 키움에 접속하지 않는 작은 반례다.
- ADR 0001의 로그인 없음·공인 주소 거부, ADR 0004의 키 하나·시세 API 허용 목록·비밀값 출력 금지에는 명시적인 반대 설계를 찾지 못했다. 단일 실행자 수명은 W4-15~16의 보완이 필요하다. ADR 0003의 봉 주기별 독립 캐시·현재 봉 비저장·조회 출처 우선 규칙은 존재하지만, 실행 순서와 최신 문서 반영이 W4-01·04·06~10에서 어긋난다.
- `.env`와 다른 프로젝트는 읽지 않았고 키움에는 접속하지 않았다. GitHub는 이슈 읽기만 했으며, 이 파일 외 저장소 파일 수정·커밋·push·브랜치 생성은 하지 않았다.
